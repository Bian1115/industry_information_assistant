# 网页缓存过期清理实现与回归结果

评估日期：2026-10-02。评估对象：当前网页读取缓存的过期行为及后台清理。此次仅修改缓存清理，没有实现新的正文质量检查。

## 行为与配置口径

此前缓存超过 TTL 后只返回未命中，文件仍留在磁盘。现在读取到过期缓存会移除内存记录，并检查、删除磁盘上的过期版本。成功缓存默认 604800 秒，失败缓存默认 3600 秒，仍可通过原有环境变量调整。

后端启动时扫描清理一次；运行时由已有调度器每 10 分钟扫描。停机时无法执行清理，下次启动补清理。没有启动应用调度器的独立评测进程只具有读取时清理，不承诺无人访问时定时删除。

只扫描缓存目录内符合 SHA256 文件名格式的 JSON；未过期文件、研究归档、临时写入文件、符号链接不清理。损坏缓存无法确认 TTL，跳过；文件删除失败记录调试日志，其他文件继续清理。使用磁盘记录判断过期并检查文件版本，降低旧内存记录误删刷新缓存的风险；尚未进行多进程压力测试。

## 失败样例与局限

回归测试无失败。模拟删除权限失败时，无法删除的文件保留，其他过期文件仍删除。模拟旧内存记录与新磁盘记录不一致时，新磁盘文件保留。

间接推断：正常启动并持续运行的后端会定期清理过期文件。尚未评估：真实定时运行、实际释放空间、多进程并发压力及正文质量检查准确率。未重启正在运行的后端，源码改动将在下次后端启动时加载。

## 正文检查建议

程序负责 HTTP 状态、错误页面明确特征、HTML 正文区域提取、链接与标题列表特征、内容哈希重复、分句编号及原句一致性。推荐列表污染与内容完整性的复杂情况交给模型辅助分类；规则信号只能标记可疑，不应靠单个关键词拒绝整页。若调用模型，应传入待判定内容与块编号，并要求返回判定、理由及正文块编号，不能让模型重新生成所谓原文。网页类型检查与事实支持性核验需分别执行。

结论：20 项相关测试通过，缓存过期物理删除已实现；后台运行效果与正文质量检查仍需各自验证。后续将正文质量检查作为独立改动，使用正常文章、带推荐模块文章、纯推荐列表、登录页和预览页样本检查误拒与漏检。
