## 评估对象与数据口径

对象是新提示词、新JSON解析、四维百分制均分、60分通过条件、搜索/写作路由、章节绑定与新增章节、独立模型输入、前端展示，以及这些改动影响的已有测试。

本报告不评价新提示词在真实研究报告上的评分准确性。模型、搜索和原文结果主要使用固定替身；真实 Agent 方法、图节点、内存检查点与前端格式化代码实际执行。数据库集成测试没有启用。默认环境的来源范围测试曾调用真实DNS，固定条件复评将该单个测试的DNS结果改成公共IP替身，不发生页面抓取。

配置：四维各25%；0—100数字；Decimal四舍五入到两位小数；通过=均分≥60且无major/critical；未通过时显式补搜任务优先，否则修订；保留既有返工上限。阈值矩阵使用0、59.99、60、100，严重程度空/minor/major/critical，补搜开关false/true，返工轮次0/2，共64个组合。

关键边界的实际行为：

- 60分且无major/critical：通过；minor即使提出补搜，也不改变通过结果。
- 59.99分且没有问题：未通过，进入写作；Writer使用总评和原正文实际重写。
- 100分但有major：未通过；有补搜则搜索，否则直接写作，总分仍为100。
- 100分但有critical：major_issues；不把总分压低，也不冒充审核通过。
- 到达返工上限仍未通过：图返回revision_limit，不是passed。
- 新增章节：先把真实插入章号转换为内部ID，再加入大纲、绑定补搜和写作；插入后原章节显示编号变化不会串章。
- 当前轮问题替换上一轮问题；历史留档，模型重复使用ISSUE-001时不会读取上轮同名问题的补搜结果。

## 失败样例、修复和复评口径

1. 首次调用pytest时，虚拟环境没有安装pytest，测试入口中断。随后改用仓库现有unittest，未安装新依赖。
2. 新增的低分空问题测试首次失败：Writer重开章节前没有保存旧正文。旧的重开函数只在critic_feedback非空时保存正文。修复为Writer先复制drafts到revision_original_sections，再重开；后续新测试及总回归均通过。
3. 默认环境3项篇幅测试失败：测试假设REPORT_BODY_LENGTH_HARD_CHECK_ENABLED开启，本地实际配置关闭，因此程序按配置没有强制缩写。固定条件复评只在该测试类内开启开关，3项均通过。未把这3项解释为新审核逻辑缺陷，也未修改生产开关。
4. 默认环境来源范围测试报UnsafeURL：真实DNS结果触发内网/保留地址检查。复评只在该单个测试内将DNS返回值替换为公共IP，保留原安全检查，测试通过。该结果验证来源范围判断，不验证现实网络连通性。

首次失败和后续复评分别保留独立JSON、日志，没有覆盖第一次总回归结果。

## 已测量、间接推断和尚未评估

**已测量**：上述固定输入下的评分计算、字段拒绝、目标定位、图路由、Writer实际调用、新增章节输出、实际发送消息范围、前端渲染与构建。完整图使用真实节点逻辑，模型与搜索是替身。

**间接推断**：底层只发送系统规则和含三个输入的当前消息，且没有回放、契约追加或历史回读，所以三输入约束能在已覆盖的调用路径生效。均分由程序计算可消除模型总分算错，但不能保证模型给四项分数的判断正确。

**尚未评估**：真实模型评分一致性、审核召回率/误报率、实际搜索质量、真实报告改进幅度、端到端费用和时延、隔离PostgreSQL集成恢复、超长真实报告的模型容量边界。没有把这些未测量指标写成已改善。
