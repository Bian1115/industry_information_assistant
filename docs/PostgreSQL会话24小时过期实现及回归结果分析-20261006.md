# PostgreSQL 会话 24 小时过期实现及回归结果分析

## 日期、对象与口径

- 评估日期：2026-10-06，Asia/Singapore。
- 对象：PostgreSQL `chat_sessions` 的 24 小时 TTL，以及会话消息续期、访问过滤、级联删除、Redis 失效、附件文件删除和后台调度。
- TTL 固定为 86400 秒，按创建会话或最后一次写入新用户/助手消息计算。所有计算使用 aware UTC。
- 新增独立的 `expires_at` 字段与索引，避免后台摘要更新、改标题等操作修改 `updated_at` 后意外续期。查看历史、重复写入同一轮消息不续期。
- `expires_at <= 当前时间` 即过期，接口过滤立即生效。后台每分钟清理一批，最多 100 个会话，应用启动时补清理一批。物理删除可能晚于逻辑过期；积压超过 100 个时分多轮处理。
- 清理范围为会话、原始聊天消息、附件记录/文件、关联 Outbox 任务及 Redis 会话缓存。长期记忆沿用原有删除语义，仅解除会话和消息来源关联；独立研究运行、事件、智能体历史及图检查点未新增 TTL。

真实 PostgreSQL 验证显示：

- 到期边界删除会话及消息、附件、记忆任务，同时将长期记忆的会话/来源关联置空。
- 在消息写入的同一事务中刷新过期时间，回滚后消息和续期均不保留。
- 清理使用 `FOR UPDATE SKIP LOCKED`；另一个事务持有行锁时不删除该会话，释放锁后可以清理。
- 旧 `timestamp without time zone` 和现有 `timestamptz` 的回填均正确；在数据库时区为 Asia/Singapore 时，旧 naive 时间仍按 UTC 解释。
- 有消息会话按最后一条消息时间加 24 小时回填；空会话按创建时间回填。重复执行新增迁移不会覆盖已有续期时间；数据库默认值确保旧代码创建的新会话也具有初始期限。

## 失败样例与修复

首轮 14 个 PostgreSQL 测试均在创建隔离表时出现 `InvalidSchemaName: no schema has been selected to create in`。原因是临时 schema 创建时使用引号保留了 `TTL` 大写，而连接的未引用 `search_path` 将其转为小写。这属于测试环境配置错误，尚未执行对应 TTL 行为断言。

修正为小写技术前缀后，14 项复评全部通过；额外两项锁行为和迁移测试也通过。日志中的“模拟 Redis 不可用”和“扫描失败”是故障注入预期输出，对应断言通过，不能归为真实运行故障。
