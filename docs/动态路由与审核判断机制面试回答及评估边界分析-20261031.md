# 动态路由与审核判断机制面试回答及评估边界分析

分析日期：2026-10-31，Asia/Singapore。

评估对象：当前工作区的报告审核、补搜/修订路由、独立引用核验，以及可以用于面试的既有评估证据。本次只阅读源码和既有结果，没有运行模型、搜索或新的测试，没有重新标注历史意见，也没有修改业务代码。

## 1. 数据、配置和版本口径

以当前工作区实际文件为实现依据，工作区包含尚未提交的修改，不能把本报告描述为已发布版本说明。当前 Critic 使用四维百分制：可读性、全面性、深度、指令遵循度，各占25%。程序重算均分，均分不低于60且没有 major/critical 问题才判通过。60是当前工程规则，本次没有发现证明它为最优阈值的校准实验。

当前 Critic 只接收用户问题、研究大纲、完整报告，调用时隔离历史输入，temperature=0.2。它没有在这次审核请求中接收完整来源原文或独立核验结果；报告中显示的证据缺口判断与逐条原文支持性判断必须分开说明。

引用核验可配置：首跑没有显式配置时，解析函数按部署环境变量决定是否开启正文核验，变量缺省为 true；具体运行仍应查看保存的配置。失败处理策略默认 audit，即记录核验结果。它不会仅因某条引用核验失败就自动生成 Critic 补搜任务。delete 和 rewrite_once 是另行配置的处理策略，不应描述为每次运行必然执行。

## 2. 可直接口述的面试回答

我的动态路由分成两步：审核模型判断报告有什么问题，程序按照结构化结果选择下一步。动态路由就是每次审核后，根据当前报告的缺口，决定让搜索模块补资料、让写作模块修改，还是结束研究。

Writer 生成报告后，Critic 读取用户原始问题、研究大纲和当前完整报告。Critic 对每个问题输出类型、严重程度、具体章节、判断依据和修改要求，并给出 requires_new_search，也就是修复这个问题是否需要新资料。如果需要，它还必须给出能够直接执行的搜索词。程序检查字段是否合法、章节是否真实存在，再决定执行哪个分支。

我区分三种判断。第一是报告层面的证据缺口：报告是否回答了用户的核心问题，关键数字和结论是否交代依据，时间、地域、对象是否符合任务。第二是引用支持性：来源链接存在，不代表原文支持该结论，独立核验模块开启后，会从最终报告抽取论断，定位保存的来源原文，再判断原文是否支持、反驳或不足以支持论断。第三是论证缺陷：例如前后结论矛盾、把相关性当成因果、把局部样本推广到整体，这些由 Critic 结合完整报告判断。

例如，用户要求分析2025年的全国市场，报告却只有某城市2023年的数据。需要补齐全国数据才能完成任务时，Critic 应输出补搜要求；如果已有材料足够，只是作者把局部结果写成全国结论，就应让 Writer 修正适用范围。这是设计示例，不是本次新增实测案例。问题类型不能单独决定路由，关键是修复它是否需要新的外部信息。

程序根据四项评分计算均分；均分至少60且没有重要或严重问题才通过。未通过且仍有返工额度时，只要有明确补搜任务，就由 Scout 执行补搜，再经过分析、写作和复审；没有补搜任务，就直接让 Writer 修订后复审。达到返工上限仍未通过时，程序记录上限结束和未通过结论，不把停止运行冒充质量合格。

准确性上，我不会承诺模型百分之百正确。我通过明确审核标准、要求逐条给出依据和位置、程序检查字段和章节、独立引用核验、修订后重新审核来减少错误。但格式合法和路由执行正确，不代表语义判断一定正确。当前新版模型的识别准确性还需要固定真实报告、独立标注问题后测量，不能由程序测试通过率替代。

## 3. 各类判断与实际执行者

| 判断对象 | 执行者和输入 | 处理结果与边界 |
|---|---|---|
| 报告层面的证据不足 | Critic 读取原题、大纲、完整报告 | 输出 missing_source、content_omission、insufficient_depth 等问题；没有固定“找到几篇文章就足够”的验收规则 |
| 引用来源范围 | 程序读取报告链接及允许的网站范围 | 发现越界链接；不能由此证明页面真实可读或原文支持结论 |
| 引用定位与原文支持 | 独立模块从最终报告抽取论断，解析引用，定位保存原文，再调用支持性核验器 | 区分缺引用、无效引用、支持、矛盾、不足支持、执行失败；支持性不等于现实事实真假 |
| 论证缺陷 | Critic 对照用户问题及完整报告 | 提出逻辑矛盾、过度推断、缺失前提等意见，并指明修改位置；这些仍是待验证的模型判断 |
| 路由选择 | Critic 类中的程序逻辑读取分数、严重程度、显式补搜标记和返工次数，图按 phase 执行分支 | 通过优先，其次返工上限，其次补搜，否则修订；不从自然语言描述中猜测路由 |

当前审核每轮重新检查完整报告，用当前问题替换上一轮反馈，并保留历史记录。不要把旧版逐条 issue_reviews 关闭协议说成当前机制。

若审核已经通过，即使 minor 问题带有补搜建议也不会触发返工。若分数低于60但问题列表为空，程序仍进入修订；Writer 可依据总评和旧正文重新写作。若一个问题需要补搜、另一个问题只需调整表达，未通过时先走补搜分支，后续写作再处理修改要求。

## 5. 逐类分析、失败样例和局限性

程序层：64组分支通过说明确定的输入被正确执行，不能说明 Critic 生成的 requires_new_search 是合理的，也不能说明60分是经过实证优化的通过线。

证据不足判断：历史污水题中，要求补充财务分析有合理性，但强制提供统一行业成本比例超出了证据和任务边界。这说明审核模型可能把“可以增加的内容”误判为“必须补齐才能通过”。不能简单把缺失内容全部转换成搜索任务。

论证与修改验收：历史复查曾在 Writer 补入数字后认可问题解决，但数字出现并不证明来源支持、统计口径正确或适用条件成立。这类失败需要实质支持性核查，不能靠章节存在或字数增长判断修复成功。

引用异常：来源范围检查只是确定性规则；独立核验只覆盖抽取和定位成功的论断及保存材料。来源支持不代表来源本身真实可靠；核验超时、原文不可读和证据不足也不能一律当成事实错误。默认 audit 结果独立记录，不会自动改变 Critic 的通过结论。

样本边界：历史数据只有两个独立问题，六轮报告彼此相关。没有独立穷举全部真实缺陷，无法计算严重问题召回率或完整分类准确率。历史提示词、评分维度与当前版本不同，68.75%和75.00%均不能作为当前版本准确率。

## 6. 已测量、间接推断和尚未评估

- 已测量：既有报告中的64组程序边界结果，以及旧版16条意见、16次复查的独立标注统计。本次只检查了这些文件和当前源码。
- 间接推断：三输入隔离、明确审核维度、低温度调用及结构化输出有助于限制输入干扰和输出歧义；它们对真实准确性的贡献未通过本次实验测量。
- 尚未评估：当前四维版本的意见正确率、严重问题召回、补搜必要性判断准确性、多次调用一致性、误补搜成本、返工后的净质量收益，以及60分阈值的最优性。

## 7. 结论与下一步建议

面试应把“模型理解问题”和“程序执行分支”分开，并说明报告质量、引用支持和现实真实性是不同的判断对象。当前可以主张已有可执行的审核返工链路和固定输入路由验证，不能主张已保证模型准确判断、审核通过代表所有事实正确，或引用失败必然自动补搜。

下一步建议（尚未实施）：冻结一组真实报告及其原题，让独立评审标注全部重要问题和合理修复动作；测量模型提出的问题有多少成立、真实问题有多少被发现、补搜选择是否必要，并检查修订是否引入新问题。用单独的数据调整规则，再用保留样本验证，避免用同一批样例同时调提示词和报告效果。
