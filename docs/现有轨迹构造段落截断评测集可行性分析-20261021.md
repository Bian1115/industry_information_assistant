## 必须区分的三个问题

1. **分块导致段落分散**：一段分布在两个chunk中，两个chunk合起来仍完整。建议称为“段落碎片化”，不能直接判为内容丢失。可定义：全部chunk联合覆盖完整、但没有任何单个上下文chunk完整容纳该段的段落数 / 所有合格参考段落数，同时单列内容缺失。
2. **预算裁剪导致内容丢失**：原段只有一部分留在输出中，属于上一份方案讨论的段落截断。分子统计部分保留段落，整段遗漏另计。
3. **检索后模型只看到半段**：全部chunk可能完整，但最终选中的chunk只覆盖部分段落。需要实际召回、邻居扩展和最终提示词证据；分母可用“最终上下文涉及的参考段落”，不能把全库未召回的无关段落全部算截断。

当前父段落分块使用完整原句组装，长段可能按预算分片；单句或结构化单元超预算会报错。这只能说明实现意图，不能替代运行指标。父段落上下文层与原句引用层必须分开评估，否则引用层天然按句分块，会人为抬高碎片化比例。以完整段落容纳为目标时，还应把段落本身超过预算的样本单列，报告不可避免的分片与可容纳段落的碎片化比例。

## 可实施的评测集构造方案

1. 从231条非空 content 出发，按哈希去重得到210份候选正文。保留题号、URL、读取调用ID、历史路径、哈希和原文，不使用 sample。剔除或单列目录、验证页、乱码、纯链接等非正文，并记录排除原因。
2. 在冻结原文上标注正文段落、标题、表格、列表与代码块，保留字符起止偏移。人工确认含糊边界；网页抽取后的换行只是候选边界。由此产生的参考只代表已保存文本，不代表原网页完整金标。
3. 固定分块器版本和 tokenizer 名称、revision，以同一批输入分别回放字符预算和 token 预算。不同单位方案比较时同时报告实际 token 长度分布和重叠开销；不要把500字符与500token当成相同预算。
4. 保存全部chunk及来源跨度，分别计算父段落碎片化、分块后内容覆盖、句内切断、段落部分丢失、整段遗漏、超长单元错误。完整内容覆盖使用 source_spans 的并集，不能直接把重叠chunk长度相加；组装表格用多跨度，不能仅用 char_start/char_end 包络。
5. 若评估模型实际看到的上下文，需要额外回放检索和上下文组装，保存 query、候选chunk、选中ID、邻居扩展与最终输入。只回放分块器不能声称测到历史在线检索截断率。
6. 按题目、站点/文章及近重复内容分组划分开发与保留集，先去重再划分，避免同一网页不同片段泄漏。五题是已完成运行的选择样本，所得结论只适用于该候选语料。
7. 745组公开网页配对单独用于网页预算评测；先确认普通段落边界，再用实际前缀切点统计。旧代码与配置要随历史结果保存，回放当前代码的结果不能冒充当时的真实行为。

## 逐类失败样例与局限性

- 五题58条空正文：无法作为正常分块输入，保留为获取失败或空输出类别，不能按零截断的成功样本处理。
- 50条裁判 sample 为抽样：将它当原文会引入评审材料裁剪造成的伪截断，应改读 content。
- 五份历史缺少所检查的现行chunk定位字段：只能基于正文重新分块；未经额外定位或数据库补采，不能宣称还原了历史chunk。
- 公开网页58组前缀变短：尚未逐页确认是仅空白裁剪、整段裁去还是段中截断，没有真实段落失败率。
- 仅有旧 tracer 的 input_preview/output_preview 时，默认2000字符的日志预览可能自身被截断，应获取完整原文而不是给生产链路归责。本次五份原始历史不是这类预览字段。
- 本次未人工审定段落、未运行tokenizer和chunker、未测量真实检索上下文，不能给出段落截断改善幅度。没有构造失败的段落实例；以上是素材缺口与待复核类别。
