# 验收闭环、无依据数字补齐与引用核验误报问题说明

分析日期：2026-10-18，Asia/Singapore。

评估对象：已有Critic消融中三类问题的机制及当前代码状态。本次是同一运行的补充解释，只读历史结果和当前源文件，没有重新评分、调用模型、恢复实验或修改生产代码。与前次复盘的口径变化：明确区分运行工作副本与当前工作区，历史的逐字摘录关闭限制已在当前工作区移除；其修复效果尚未通过新实验验证。

## 一、验收闭环：模型说修好了，程序却仍把问题留在待办中

正常闭环应为：Critic列问题和验收条件 → Writer修改 → Critic逐项复查 → 真正解决的问题关闭 → 路由据此决定通过或继续修改。

历史实验的冻结代码要求复查给出的`report_quote`必须是当前报告中的精确子串。模型有时用省略号概括、多处内容拼接，或在摘录末附加“（sec_3）”。这些表达即使涉及实际修改，也不能通过字符串匹配，导致`resolved`被程序改成`unresolved`。旧问题仍开放会阻止总体`pass`，触发后续返工。

已测量：两题后续复查共16次关闭申请，其中15次因摘录定位规则未能生效。这是申请事件数，不是16个独立问题，也不代表15个问题实质上都修好了。新补搜任务、严重问题也会阻止通过，不能推断单独放宽摘录规则就一定减少一轮。

**当前状态更正**：当前`issue_workflow.py`关闭检查已只要求非空摘录和理由，不再要求摘录逐字出现在报告中；当前Critic提示词也明确“不要求与当前报告逐字匹配”。因此，上述逐字匹配阻塞是历史运行中的问题，不能继续描述为当前代码尚未修改的缺陷。当前协议能否可靠验收、避免误关以及减少返工，尚未通过新运行评估。

改进目标：让程序接收可解释的逐项验收结果，真正未解决的问题继续保留；把格式/定位失败与实质研究缺口分开处理。不能把“关闭得更多”本身作为修复成功标准。

## 二、无依据数字补齐：将“补充量化”变成了“必须给出数字”

污水题首次Critic要求提供至少一组行业公认的成本比例，即使缺少特定城市数据也建议补行业经验。Writer随后新增并保留了：管网投资占60%–80%、年运维占固定资产投资1%–3%、非开挖修复成本为开挖重建30%–50%、应急费用占年度运维预算10%–15%。公共首稿没有这些范围。

既有来源回查未找到这些区间的可追溯支持；引用的B站材料主要为行业概况和图表标题。最终报告却进一步建议将成本结构作为核定按效付费基价和预算分配的依据。风险在于数值看起来精确，证据却不足，且已被用于决策建议。这并不证明四组数字在现实中必然错误。

这次运行的引用核验配置为`audit`，只记录风险、不自动修订或阻止交付；因此“有核验记录”不等于问题已纠正。Critic第二轮把补出量级视为改进，说明验收条件本身也需要约束。

改进目标：有依据就给数据和口径；没有依据则给成本分解、公式、待采参数，或明确标为假设的示例测算。缺证时不强制补行业平均值，不把假设当统计事实。新增数字的来源支持性仍由引用核验模块检查，Critic负责整体逻辑、要求覆盖、整体时效和观点平衡，避免重复逐条NLI。

## 三、引用核验误报：引用存在，但抽取或绑定环节漏掉了它

已确认的失败样例：摘要写“苏州通过政府购买服务明确了全链条责任主体，而常德……”，复合句末放有苏州和常德两条来源。抽取器只截取前面的苏州短分句，绑定器只看摘录及紧邻尾部，未继承后面的句末链接，遂判`missing_citation`。人工回查已保存的苏州来源支持这个窄论断。这属于引用归属误报。

另一个机制问题是链接解析使用简单正则，不能识别`[标题[图]](URL)`这种带嵌套方括号的标签；污水报告实际引用标题含“[图]”。即使链接被识别，也仍需另行判断来源是否支持论断，解析成功不等于内容正确。

状态含义也混在一起：`invalid_citation`可由“有引用，但选句器未选到证据句”触发，不能直接解释为URL失效或伪造引用。应区分真正缺引、引用解析失败、来源内容不可用、证据选句不足，以及来源不支持论断。

改进目标：修正句内引用归属和Markdown解析，并拆开错误状态；不能简单把同段所有来源都分给每个论断。已有三篇完整核验的自动支持率约3.49%–7.59%，受上述环节影响，不能解释为其余92%–97%的事实都错误。现有定向样例没有提供整体误报率估计。

## 证据边界、结论及下一步

- 已测量/已核对：历史16次关闭申请及15次定位失败；数字进入修订稿的轨迹和已有来源回查；至少一个确定的引用归属误报；嵌套标签解析机制；当前与冻结代码的关闭条件差异。
- 间接推断：过硬的量化验收可能推动无依据补齐；定位失败可能增加返工成本。已有轨迹支持机制解释，但没有干预实验估计净影响。
- 尚未评估：当前关闭协议的实际效果、三类修复后的报告质量与token变化、核验器总体误报率；本次不新增模型用量。

结论：三项分别涉及验收状态、写作补齐约束、核验指标可信度。第一项的历史字符串限制在当前代码中已移除；其余发现不应靠扩大Critic职责解决。后续如实施修改，应先用已有样例离线验证，再在新的小规模配对运行中测质量与用量。本次仅解释问题。
