# HTML表格识别方案与选型分析

调研与分析日期：2026-10-21，Asia/Singapore。

建议采用“原始与渲染 DOM 多路召回 → 表格类型分类 → 确定性网格恢复 → 图像模型按需兜底 → 结构校验与证据入库”。对于已有 HTML 单元格的网页，优先直接读取源文字和结构；对于 CSS 模拟表格、动态表格和图片表格，分别增加专门通道。提高识别率的关键是覆盖不同页面形态，并防止表格在正文筛选、格式转换和预算裁剪中丢失。

## 分析对象与证据边界

- 对象：当前网页读取器的表格处理机制，以及可用于改造的开源项目、模型和论文。
- 数据与配置口径：读取当前工作区源码，查阅官方文档、作者仓库和论文正式记录；未调用业务读取器、未运行评测集、未训练模型。当前工作区含其他修改，本次只新增调研文件。
- 已测量：无性能实测；没有本项目召回率、准确率、时延或费用的新结果。
- 静态已核实：源码存在下述筛选条件；所列项目的输入类型与公开功能有来源支持。
- 间接推断：筛选条件可能造成相应类别漏检，新增通道可能改善覆盖；收益大小未知。
- 尚未评估：真实中文行业页面上的端到端效果、跨站泛化、模型间优劣、动态分页完整性和部署成本。
- 原始性能结果路径：不适用，本次未运行性能评估。可追溯的源码摘录、源码哈希、来源索引与静态发现记录保存在 [调研证据索引.json](../backend/eval/data/HTML表格识别调研-20261021/调研证据索引.json)。该文件是调研记录，不是模型运行结果。

## 先确定识别目标

“HTML 表格识别”至少涉及四个不同任务：发现页面内所有表格候选，判断是否为数据表，恢复行列与合并单元格，以及关联表头、单位、标题和脚注。建议分别衡量，避免文字都提取了但行列错位仍被计为成功。

| 页面形态 | 推荐处理 | 原因与限制 |
| --- | --- | --- |
| 原生 table/tr/td/th | HTML 解析器加网格恢复 | 标签已经提供结构，直接读取避免 OCR 与生成误差 |
| role=table/grid/treegrid | ARIA 行列语义加浏览器坐标 | 没有 table 标签也可能是数据网格；grid 只是候选信号 |
| div/span 配合 CSS Grid、Flex、display:table | 重复 DOM 子树、几何对齐、类型一致性联合判断 | CSS 布局本身不足以区分表格与卡片列表 |
| JavaScript、分页或虚拟滚动 | 渲染、可见交互、对应数据响应、完整性检查 | 一次 DOM 快照可能只有当前窗口内几行 |
| 图片、Canvas 中的表格 | 区域检测、表格结构模型、文字识别 | 输入为像素，需要视觉路线 |
| 布局表、导航菜单、商品卡片墙 | 分类后排除或保留为非表格对象 | 不能把矩形布局一律当成数据表 |

数据表类型至少覆盖关系表、键值/实体属性表、矩阵/交叉表，不宜只接受多行多列的关系表。小表、文本表、链接表也可能有业务价值。

## 推荐流水线

### 获取与候选发现

原始 HTML 在正文清洗前保存，并立即发现所有原生表格候选。正文提取与表格发现分开执行，之后按来源节点和文档顺序组合，避免正文提取器先删除表格。页面出现空网格、脚本加载迹象、预期行数与已取行数不符时，再走浏览器。

渲染通道保存 DOM、候选节点位置、必要的计算样式和局部截图。等待目标网格出现且短时间稳定；设置总时限，超时明确记录部分结果。iframe 应按 frame 枚举；开放的 Shadow DOM 应独立遍历，不能假定普通 HTML 序列化包含它们。Playwright 提供 [frame 操作](https://playwright.dev/docs/api/class-frame)和[网络响应观察](https://playwright.dev/docs/network)能力。

候选取多个通道的并集：原生 table，ARIA 表格容器，CSS table 布局，重复行子树加对齐坐标，以及图片/Canvas 表格区域。高召回阶段不以有无 th、数字密度、小尺寸或链接多为单独否决条件。图片检测必须能扫描疑似图像区域，不能只裁剪 DOM 已发现的表格，否则无法发现完全缺失 DOM 结构的图片表。

对于虚拟滚动，优先检查页面实际使用的数据响应并与当前筛选、排序、页码对应；字段完整但没有页面映射的 JSON 不能直接冒充页面表格。滚动采集要记录稳定行 ID、逻辑行号、列集合和覆盖区间，处理 DOM 节点复用。采集同一表时固定筛选和数据版本，防止拼接成不同时间的混合快照。无法确认总行数时标记完整性未知。

### 数据表分类

第一版用可解释规则评分；积累标注后比较逻辑回归或梯度提升树与规则的效果。候选特征包括行列数分布、相邻行结构相似度、列对齐程度、表头与 caption、同列数据类型、空值分布、链接比例、交互控件、附近标题、跨页重复模板。对金融数据中的超链接、只有文本的行业分类表，不能用单个负特征直接排除。

分别输出“是否为数据表”“表格类型”“是否与正文/当前任务相关”。一张真实但无关的表格仍应计为检测成功，再由检索阶段决定是否采用。设置接受、待复核、拒绝三个区间，阈值在开发集上调优；未校准的规则分数不可包装成概率。候选可以宽松，最终自动采用的证据要严格。

### 单元格结构恢复

原生 HTML 使用解析器构建 DOM，再按 HTML 表模型恢复占位网格。只读取属于当前表的行和单元格，嵌套表独立建对象并保留父子关系，避免子表文字混入父表每个格子。保持 thead/tbody/tfoot 行组与原始读取顺序，处理 rowspan、colspan、空格子和不规则行。

特别注意 rowspan=0 的标准语义是延伸到当前行组剩余行，不是 1。[HTML Standard](https://html.spec.whatwg.org/dev/tables.html)同时定义了 scope、headers 等表头关系。保留显式关联优先于模型推断；多级列头与行头都应映射到对应单元格。矩阵表不能只识别第一行列头。

合并单元格保存唯一原格与占据坐标；展开网格只引用原格，不把同一金额复制为多个独立数据点。保留原文与规范化值两个字段，避免 00123、—、空字符串、0、括号负数、百分比被混同。数值规范化必须记录地区与格式口径。

建议统一对象保存：table_id、source_url、snapshot_hash、frame_path、dom_path、bbox、caption、section_path、cells、header_links、footnotes、extraction_method、confidence、completeness。每格保存 row/col、rowspan/colspan、source_cell_id、text_raw、text_normalized 及来源坐标。字段名可保留英文技术名称。

复杂表保存结构化 JSON 与净化后的 HTML；Markdown 作为简单表的展示派生物。长表按行分块并重复关联表头、单位、标题，保留原行号。预算不足时保存整表到本地、返回可继续读取的片段及完整性标记，不能在单元格内截断后仍标记完整。

### 模型与视觉兜底

模型优先解决候选类型判断、复杂表头关系、CSS 模拟表格的节点归属；输入局部 DOM 和可选截图，输出节点 ID、行列归属和置信度。能从 DOM 取到的原文由程序回填，减少模型改写金额、年份、百分比的机会。节点范围外的文本、无来源的新格子必须拒绝或标记未知。

图像通道可用 Table Transformer 做表格检测/结构识别，另配 OCR 或 DOM 文字对齐；也可用 PaddleOCR 的表格产线。图像结构模型输出 HTML，不意味着它能直接理解输入 HTML 源码。截图定位成功后，应优先将 DOM 文字坐标与单元格区域对齐；纯图像才依赖 OCR。

最后校验结构冲突、表头关联、源文字覆盖、重复表和页数/行数覆盖。合计与百分比只作为异常提示，考虑四舍五入、脚注及隐藏行，不能据此自动改写数据。

## 开源项目与模型选择

以下是功能适配分析，不是本地性能排名。工程项目、研究代码和预训练模型的成熟度不能混为一谈。

| 项目或模型 | 已核实能力 | 本项目中的用途与边界 |
| --- | --- | --- |
| [pandas.read_html](https://pandas.pydata.org/pandas-docs/stable/reference/api/pandas.read_html.html) | 搜索原生 table，尝试处理 rowspan/colspan，输出 DataFrame | 快速基线和交叉核对；不能独自发现 CSS 模拟表，DataFrame 之外仍需保存来源与合并信息 |
| [Crawl4AI 表格策略](https://docs.crawl4ai.com/core/table_extraction/) | DefaultTableExtraction、自定义策略、结构化 tables 输出 | 适合作为抓取与抽取基线；阈值及最小行列配置需要校准，不能把项目宣传覆盖率当作本项目实测 |
| [WDC Web Table Corpora](https://webdatacommons.org/webtables/) | 网页表格语料、分类与抽取方法；2015 版包含关系表、实体表和矩阵表 | 参考类型定义、特征与训练数据；2012 版过滤小表和非最内层表的策略不宜照搬到高召回场景，历史语料不覆盖所有现代前端形态 |
| [DWTC extractor](https://github.com/JulianEberius/dwtc-extractor) | Dresden Web Table Corpus 的抽取实现 | 研究特征与大规模 HTML 抽取流程；作为历史研究实现评估，不默认承诺现代部署可用性 |
| [MarkupLM](https://github.com/microsoft/unilm/blob/master/markuplm/README.md) | HTML/XML 文本与 XPath 结构预训练，有公开权重 | 可微调节点分类或候选表格分类；不是专门训练好、开箱即用的全网页表格抽取器 |
| [Table Transformer](https://github.com/microsoft/table-transformer) | 从图像检测表格、识别结构，公开训练和推理代码 | 图片/Canvas/截图兜底；内容输出还需要 OCR 或其他文字提取，不能直接替代 HTML DOM 解析 |
| [PaddleOCR 表格结构识别](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/table_structure_recognition.md) | SLANet、SLANet_plus、SLANeXt 等图像表格结构模型与训练说明 | 与文字识别、检测组合处理图像表格；中文网页截图的实际效果仍需单测 |

若专门训练 HTML 模型，建议先做候选分类，再考虑 MarkupLM 节点分类。候选已经很准时，训练大模型做同样事情未必划算；主要漏点若是动态数据没加载，换模型也无法读取未获取的数据。MarkupLM 支持传入节点、XPath 和节点标签，见 [Transformers 文档](https://huggingface.co/docs/transformers/model_doc/markuplm)。处理长网页需按候选子树切片，中文覆盖需专门验证。

可从可靠原生 table 自动生成部分结构标签，再转换为 CSS Grid/Flex、扰动样式和合并关系生成训练样本；同时加入人工标注的真实非 table 网格、导航和卡片负例。合成数据与 WDC 自动标签只能作弱监督，最终测试集应人工复核，并按域名/模板隔离。

## 当前代码的逐类静态分析

[web_reader_service.py](../backend/app/service/web_reader_service.py) 的 _extract_html 使用 Trafilatura 原生 Markdown，随后调用 enrich_html_body，再进行输出预算控制。[web_content_selection.py](../backend/app/service/web_content_selection.py) 已包含源表恢复，不能将当前实现描述成只有正文提取。

| 源码条件或行为 | 可能影响的类别 | 建议 |
| --- | --- | --- |
| _source_tables 只遍历 table | ARIA、CSS、图片与 Canvas 表 | 增加独立候选通道 |
| 128 行跳过含嵌套 table 的外层表 | 外层有有效数据、单元格内另含子表 | 父子表分别建模；并非所有嵌套子表都会丢失 |
| 134 行限制行数、列数、非空格数和总格数 | 小表、空格较多或超大表 | 大小作为特征或预算分流条件，保留拒绝原因 |
| 142 至 144 行高链接比例过滤 | 企业名录、指标链接表 | 联合行列结构分类 |
| 155 行将 span 夹到 1 至 1000 | rowspan=0 及超长合并 | 先解释标准语义，再做资源限制，记录截断 |
| 137 行按非空格文本序列去重 | 文本相同但结构、标题或统计范围不同的表 | 加入形状、跨度、caption 和上下文，避免语义不同表被合并 |
| 165 行最多保存 64 张源表 | 多表报告和数据汇编 | 分页结果与显式完整性标记 |
| restore_source_tables 用词袋 F1 配对源表和 Markdown | 含大量重复年份、项目名和数值的近似表 | 候选阶段分配源节点 ID，优先按来源建立映射 |
| _excluded 依赖标签、属性和内联样式 | 复杂可见性及可交互展开的区域 | 渲染通道结合计算样式与状态判断 |

以上是对具体条件的机制推断，未统计发生频次，也没有证明它们是当前线上误差的最大来源。

## 失败样例设计

以下是后续应构造的机制用例，尚未执行，不是实测失败记录。

1. 单行两格的“总产值 / 100 亿元”实体属性表：检查小表是否能进入候选并被正确分类。
2. 外层数据表中某个单元格嵌入明细子表：检查父子关系与文字归属。
3. 原生表格使用 rowspan=0 且有多个 tbody：检查只跨当前行组。
4. 企业名录各格都是链接：检查是否被链接比例错误否决。
5. 由 div 构成的 10 行 5 列数据网格，以及外观相似的商品卡片墙：同时测试召回和误报。
6. 总计 1000 行但 DOM 仅呈现 20 行的虚拟表：检查完整性标记、滚动覆盖与行 ID 去重。
7. 两张正文文字相同但 caption 分别为“当期值”“累计值”的表：检查是否错误去重。
8. 纯图片表格且 DOM 没有 table/ARIA 标记：检查视觉检测是否有独立发现入口。
9. 多级表头同时包含“金额（亿元）”“增速（%）”，金额和增速位置交换：检查结构指标能否发现词袋无法发现的错误。

## 验收方案与核心指标

建议先标注约 300 至 500 页试点集，作为发现问题和校准成本的起点，不代表足以证明高达 99% 的召回率。分层覆盖中文行业报告、统计页、金融表、企业名录、参数表、动态表及无表负例；稀有困难类别单独增补。按域名和页面模板划分训练/开发/测试，测试集不能参与规则调优。冻结 HTML、浏览器版本、视口、交互步骤、DOM、必要截图与模型版本。

| 指标 | 口径与作用 | 本次结果 |
| --- | --- | --- |
| 候选召回率 | 进入候选的金标表 / 所有金标表，定位发现阶段上限 | 尚未测量 |
| 表格级 Precision/Recall/F1 | 固定一对一匹配规则后计 TP、FP、FN，重复预测计误报 | 尚未测量 |
| 单元格正确率 | 内容与行列位置联合匹配；原文和归一化分别报告 | 尚未测量 |
| 合并关系与表头关联 F1 | 核验 rowspan/colspan 及多级、行列头映射 | 尚未测量 |
| TEDS 或 GriTS | 辅助衡量结构保真，先规范化等价表示 | 尚未测量 |
| 端到端结构成功召回 | 完整且结构正确的表 / 所有金标表，不能只对已检出的简单表评分 | 尚未测量 |
| 完整性与运行指标 | 动态行覆盖、截断率、p50/p95 时延、浏览器与模型调用比例、单页成本 | 尚未测量 |

TEDS 来源见 ECCV 2020 论文；GriTS 代码与论文入口见 [Table Transformer 官方仓库](https://github.com/microsoft/table-transformer)。检测结果与金标按固定规则一对一匹配，未检出表格不能从端到端结构评分分母消失。微平均之外报告分类型结果与按域名聚类的置信区间，防止同模板大量页面掩盖泛化问题。

消融顺序：现有实现 → 原生表结构与过滤调整 → ARIA/CSS → 动态完整性 → 视觉兜底 → 学习型分类。每次只增加一层，报告新增召回、额外误报和成本。测试失败或中断同样保存原始预测、配置、失败原因与中文分析报告。

## 结论与实施优先级

第一阶段做独立表格对象、原生 HTML 网格解析、来源映射和完整性诊断，修正当前明确的覆盖缺口，同时建立人工金标。第二阶段扩展 ARIA/CSS 与动态网页采集，并用真实负例控制误报。第三阶段按困难页面占比引入图片结构模型或训练 DOM 分类器。

推荐起步组合为现有抓取通道加 HTML 解析器、确定性网格解析与独立表格存储；以 pandas.read_html 和 Crawl4AI 作为对照基线。只有数据证明需要时，再增加 MarkupLM 微调或视觉兜底。没有本地实测前，不承诺具体识别率，也不根据公开基准分数直接宣布哪种模型在本项目最好。
