# 研究页面401认证失败诊断

日期：2026-11-12，Asia/Singapore。对象：后端重启后，前端显示Request failed with status code 401。

## 结论与证据

HTTP 401表示请求没有通过身份认证。后端日志记录了`/knowledge-bases`、`/sessions/...`、`/research/stream`和`/research/runs/.../state`均返回401；请求在进入研究业务前被认证依赖拦截。当前`/hello`返回200，前端`/login`页面返回200。

后端`get_current_user_required()`在未收到凭证、凭证无法解码或凭证对应用户不存在时返回401。日志不区分这些原因，因此不能仅凭截图断定是过期或签名变化；本次未读取或保存浏览器登录凭证。

前端认证守卫只看本地保存的`isLoggedIn`。请求插件会读取本地token并附在请求头，却没有统一处理401并退出失效登录状态，所以页面仍显示研究工作台，并把认证失败呈现为研究中断。

原始诊断记录：[诊断证据.json](../backend/eval/data/研究页面401认证失败诊断-20261112/诊断证据.json)。原始日志：[后端启动日志](../backend/eval/data/后端重启验证-20261112-141501/后端启动日志.txt)。

## 处理方式与边界

已打开[项目登录页](http://127.0.0.1:5183/login)。用户通过原账号密码正常登录后，后端签发新的访问凭证，前端保存凭证，再新建研究任务。仅刷新当前研究页仍可能继续使用失效凭证。

已测量：相关业务请求401、服务健康接口200和登录页面200。间接推断：浏览器本地登录状态与后端认证结果不一致。尚未评估：用户重新登录是否成功，以及随后完整研究链路。

本次没有修改密码、生成替代用户凭证、关闭鉴权、修改源码或重新提交研究请求。下一步由用户在登录页完成登录；统一的401跳转和中文提示可作为后续界面改进。
