## 实现与用户可见行为

### 正文质量结论与执行失败分开

[scout.py](/Users/bxy/projects/industry_information_assistant/backend/app/service/deep_research_v2/agents/scout.py:801)保持明确质量判定的passed、partial、rejected语义。模型检查没有完成时，质量状态为uncertain；抓取成功状态与原始正文保留，`failure_category`不会被错误赋为body_quality_rejected。

模型复核记录新增`execution_status`、`error_category`、`error_type`、错误说明和耗时。分类包括input_budget_exceeded、invalid_response、model_timeout、model_rate_limited、model_connection_error、model_service_error及review_internal_error。token预算错误还记录实际输入token与预算；正文展示字符额度错误不会冒充token计数。已归档错误和取消仍按原有边界上抛。

有效模型结论明确rejected时，仍排除页面；声称通过却无有效正文块、JSON/状态/编号无效等归为检查输出错误。独立正文输入模式仍沿用同一个Scout和BaseAgent入口。

同时修改[_enrich_results_with_full_text](/Users/bxy/projects/industry_information_assistant/backend/app/service/deep_research_v2/agents/scout.py:998)：只有抓取成功且正文质量为passed/partial才写入full_content并标记reader_verified。检查未完成的页面保留读取尝试诊断，不进入已核验的raw_sources。

统计新增`body_reviews_failed`、`body_review_error_categories`、`body_review_error_details`、`urls_body_admitted`、`urls_body_pending`，区别抓取失败、正文拒绝和检查失败。按每个URL最后一次结果统计；重检成功后清除当前质量记录中的quality_review_failed信号，旧调用日志保留。

本层没有额外添加无限重试。统一模型入口已有的临时错误重试保持原行为；“再次检查同一页面可恢复”仅以模拟重检验证，不代表主图会自动重新执行所有失败检查。

### 写作开始就按用户总上限分配

移除没有调用方的旧`_section_target_chars`，正文、摘要/结论/展望、章节修订和已有成果编辑的预算提示统一来自[_writing_budget](/Users/bxy/projects/industry_information_assistant/backend/app/service/deep_research_v2/agents/writer.py:330)。

1. 优先读取本次任务的`active_constraints.max_body_chars`；用户未指定时才采用默认全文目标。
2. 为标题及报告结构预留按章节标题长度估计的额度，并留约5%的安全余量。
3. 分配摘要、结论和展望额度，分别以默认250、200、150为上限；小篇幅任务按可用空间缩小。
4. 将剩余额度平均分配给章节，每章上限为“默认500”与“剩余空间除以章节数”中的较小值。
5. 用户总上限较紧时，允许章节下限低于默认300；不让默认下限覆盖用户要求。

本次四章样例的2400字预算如下；结构额度随实际标题长度变化，非所有任务固定85字。

| 部分 | 字符额度 |
|---|---:|
| 执行摘要 | 250 |
| 四章正文，每章300—398 | 1592（按上限合计） |
| 核心结论合计 | 200 |
| 展望 | 150 |
| 标题与结构预留 | 85 |
| 安全余量 | 120 |
| 已分配总量 | 2397 |

默认每章300—500已同步到`ResearchConfig`、Writer类级默认及构造函数默认；默认全文目标7500保留为用户未指定时的分配参数，不再覆盖用户的2400上限。字数为项目现有正文字符口径，不是上下文token预算。

### 合稿后处理模型不遵守预算的情况

[_fit_report_to_budget](/Users/bxy/projects/industry_information_assistant/backend/app/service/deep_research_v2/agents/writer.py:919)在首尾与章节拼接后计数。未超限时不增加模型调用，并记录本版`not_needed/attempts=0`，避免沿用上一版缩写指标。

超限时最多请求两次整篇缩写，要求保留章节ID、顺序、关键事实、用户要求与有效引用，并同步更新章节正文及claims。候选结果在副本上组装与计数，缺章节、空正文或仍超限不提交；两次失败后清空对外报告字段并报错，不直接截断文本。原有来源范围检查、可选引用核验及最终交付篇幅检查继续执行。

`writing_budget`保存本次各部分分配；`body_length_repair`记录缩写前后字符数、上限、尝试次数及结果。它们随研究状态保存。修订章节时也采用任务预算，有硬上限时不再让旧稿55%的最低长度阻止必要缩写。

## 失败样例与恢复边界

没有实际失败的测试执行。以下为用例刻意注入的业务失败样例：模型超时、非法JSON/编号、无有效正文却声称passed、输入超预算、归档异常、取消，以及缩写结果缺章节或两次仍超限。测试确认这些情况分别被正确归类、阻止证据准入或阻止报告交付。

重检成功的机制用例由测试再次调用同一页面检查，证明失败状态不会锁死页面；它没有验证主图自动恢复策略。每章300—500是默认写作指导范围；任务总上限采用合稿计数及有界缩写保证，不能将提示词遵循程度当作已测量的真实模型质量。
