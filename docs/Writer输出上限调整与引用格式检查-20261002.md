# Writer 输出上限调整与引用格式检查

评估日期：2026-10-02。对象：Writer 最大输出提高至 6000 tokens；检查章节搜索的提前停止条件，以及 Writer 是否仅输出正文和原句编号。

## 实现与配置口径

已将 Writer 的模型配置、类及构造默认值、上下文策略默认输出上限统一为 6000。修改文件为 `backend/app/config/llm_config.py`、`backend/app/service/deep_research_v2/agents/writer.py`、`backend/app/service/context_policy.py` 和 `backend/app/service/llm_client.py`。

Writer 默认上限独立于通用 `LLM_MAX_OUTPUT_TOKENS=3000`；显式 `LLM_MAX_OUTPUT_TOKENS_LEADWRITER` 仍可覆盖。已在 `.env.example` 加入该专用配置。八个显式消融配置的 Writer 上限改为 6000；第一组原系统基线沿用部署配置，在新默认下同样为 6000。正文目标字数及摘要输出上限未变。

旧运行的冻结配置及工作副本未修改。恢复旧的 Writer=3000 快照时仍使用 3000；新上限用于新建配置及新运行。显式自定义 Writer 限制仍受尊重。

## 搜索提前停止检查

代码检查：`DeepScout._research_section` 先循环执行本章节规划的查询，收集结果后才读取正文并提取事实，没有每次查询后的证据充分性判断或因此触发的 `break`。存在报告级联网预算、查询数量上限，以及用于后续门禁的章节事实/全文覆盖统计；这些不等于按本章证据充分性提前停止。未修改搜索流程。

## Writer 引用格式检查

代码检查：Scout 已输出 `document_id` 和 `sentence_ids`，程序据此定位原句。Writer 输入通过 `format_claim_evidence` 携带这些定位信息和实际原句文本。

Writer 的章节、修订和首尾提示词，以及 `CLAIM_INSTRUCTIONS` 仍要求：

```json
{"claim": "原子论断", "evidence": [{"evidence_id": "fact_001", "quote": "来源原文中的连续原句"}]}
```

`evidence_id` 是事实编号 `facts[].id`，不是正文编号或原句编号；`normalize_claims` 保存 `evidence_id` 和 `quote`。因此目前 Writer 会再次输出原句文本。仅提供正文和原句编号的 Writer 输出协议尚未实现，本次按用户要求只检查，未修改引用协议。

## 局限性、结论与下一步

尚未评估真实模型的截断频率、成本、耗时和报告质量。结论：Writer 新运行默认输出上限已统一为 6000，并验证实际请求；查询时证据足够提前停止和 Writer 仅编号引用目前均未实现。

后续真实运行应保存 `finish_reason`、实际输出 token 及解析失败位置。若另行实施 Writer 仅编号引用，需要同步修改输出提示词、claims 解析及引用核验接口，由程序根据原句编号读取文本。
