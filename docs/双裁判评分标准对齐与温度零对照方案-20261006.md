# 双裁判评分标准对齐与温度零对照方案

分析日期：2026年10月6日。对象为开发集固定五篇报告的Qwen3-max与Claude-opus-5质量裁判，参照为既有复核四维评分。温度降低值得作为单独对照，但接近复核主要依赖评分规则、证据条件和独立验证。本批Qwen的平均正偏差达到2.5分，而两次评分平均绝对差为0.4分；优先应解决其对全面性和需求完成的宽松判定。

本次补充分析沿用2026年10月6日已完成的结果，不新增模型调用，不修改提示词、参数、既有复核或工作台。原始数据见[一致性汇总](/Users/bxy/projects/industry_information_assistant/backend/eval/data/五篇报告fewshot复评与复核一致性-20261006/一致性汇总.json)、[评估配置](/Users/bxy/projects/industry_information_assistant/backend/eval/data/五篇报告fewshot复评与复核一致性-20261006/评估配置.json)、[新质量评分](/Users/bxy/projects/industry_information_assistant/backend/eval/data/五篇报告fewshot复评与复核一致性-20261006/新质量评分.json)和[复核评分快照](/Users/bxy/projects/industry_information_assistant/backend/eval/data/五篇报告fewshot复评与复核一致性-20261006/复核评分快照.json)。逐题理由和历史逐条对照见[已有分析](/Users/bxy/projects/industry_information_assistant/docs/五篇报告fewshot复评与复核一致性分析-20261006.md)。

这里的重复差异混合了采样波动与输入变化：当前运行脚本将“本次重复编号1/2”放入裁判文本，两次提示词并非逐字相同。仅两次重复也不足以估计稳定性分布。温度零尚未做对照，不能根据这些指标量化其收益。

可按以下顺序对齐标准，所有规则仍需在独立报告上检验。

1. **将四维定义改成可逐项判断的评分表。** 深度检查机制解释、备选方案比较、反证和推导边界；全面性检查任务相关内容是否有实质论证及证据；可读性检查结构、重复和表述一致性；需求覆盖将核心交付、对象范围、时间、分母、精度及次要交付逐项列出。每项记录已完成、部分完成、未完成及正文位置，必要时记录证据不足。模型先输出这些判断和简短理由，再按固定权重与分档规则计算分数，减少直接凭整体印象给0至10分。权重和核心缺失的分档限制是待校准的设计选择，不宜直接宣布某个固定上限已经正确。相同缺陷对多个维度的影响应分别解释，避免统一扣分；证据较弱也不自动抹去可读性的优点。

2. **明确容易混淆的边界。** 提到多个主题不等于实质覆盖；提出路径不等于给出可执行方案；相似用户结构不等于同一个体的共同需求比例；承认证据不足应保留诚实性价值，但不能自动视为完成任务的核心量化交付。若用户明确允许以缺口分析及研究设计替代无法取得的数值，则应按这个授权评分。第49题Qwen需求覆盖两次给8分和6分，复核为3.5分，其理由正好跨越了这一边界。第35题Qwen全面性给9分，复核为5.5分：前者重视主题和政策工具数量，后者更重视各环节的实质证据及实施细节。这些是本批分歧诊断，不把真实正文或复核理由写入few-shot。

3. **补充完全虚构的成对样例，重点覆盖中间分档。** 现有样例的高低分区分仍不够细。可构造虚构的阅读与运动需求调查：报告只有分别参与两项活动的比例，没有同一受访者交叉数据。任务A要求共同需求比例，任务B明确允许无法估计时交付缺口与测量方案；同样的报告在两种任务下应得到不同的需求覆盖判定。另做章节相同但论证空泛与充分、列举机制与比较机制、提出建议与说明负责人及预算等对照。每对只改变一项条件，并解释分档变化。题材、数字、组织和文本全部独立虚构，不从五篇真实报告改写。样例顺序变化也可另设小规模稳健性检查。

4. **使裁判与复核获得可比的证据。** 本批裁判只看正文，复核还看完整来源和外部核查。若目标是复核同一标准，应考虑给两个裁判共同的任务要点清单和中性证据摘录，保留原始来源、统计口径及不确定性。材料中不能放复核分数、最终判定标签或暗示性点评。证据补充会改变评估协议，需另行与只看正文的版本比较，不能将其收益全部归于提示词或温度。继续沿用的历史逐条标签有自身误差，不能未经检查就作为唯一证据输入。

5. **必要时做输出分数校准，不改模型权重。** 可在更多独立复核报告上，按模型和维度拟合简单偏差修正、线性映射或单调映射，并同时保存原始分和校准分。数据需分为校准部分与未见测试部分；不能用这五篇拟合后，再用同五篇宣称一致性改善。Qwen全面性平均偏高3.3分，可读性偏高1.4分，因此给所有分数一律减2.5分也不能解决具体标准分歧。先检查各裁判校准效果，再决定合并权重；双裁判均分接近复核可能来自偏差抵消。本批均分MAE由1.1875降至1.0875，但±1分一致率由65%降至55%，不能宣布稳定改善。

温度方面，阿里云当前官方参数文档说明，较低temperature会使输出更确定，范围包含0，并建议temperature和top_p只设置其中一个。因此Qwen可将0作为稳定性对照候选；它能否降低分数误差，仍需测量。现有质量评分走的是温度0.3分支；同一源码中逐条判断的温度0设置不代表质量评分已设为0。[阿里云参数文档](https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions)

Claude不能直接套用同一配置。当前官方Messages文档明确：Claude Opus 4.6之后发布的模型不支持非默认temperature，1.0只为兼容而接受，其他值会返回400；对支持温度控制的旧模型，即使0也不保证完全确定。本项目使用中转服务的claude-opus-5，底层版本与中转参数处理尚未确认，不能凭请求成功就认定temperature=0已生效。[Claude Messages参数文档](https://platform.claude.com/docs/en/api/messages/create)

建议下一次按单因素对照推进：先冻结报告、证据、提示词和模型版本，让重复请求使用完全一致的文本，将重复编号放在日志中；对Qwen比较0.3与0，每篇每条件做3至5次重复，仅改变温度。Claude先确认底层版本和参数支持，再选择可执行的条件。记录请求参数、返回模型标识、完成状态和原始分数，分别比较重复评分标准差、平均绝对差、相对复核MAE、有符号偏差及±1分一致率；按报告汇总差异。若波动下降而MAE不变，应称为稳定性改善，不称为标准对齐。中转返回的同名模型标识也未必能证实底层版本固定。

固定五篇适合定位机制与失败边界。规则和虚构样例确定后，应在新的独立复核报告上验证，可先增加20至30篇作为实务起点，并覆盖不同主题、长度和证据缺口；这不是保证统计充分性的样本数。重要分歧可做第二次独立复核或多人复核，检查参照本身的稳定性。尚未评估温度零的实际收益、新规则的泛化效果、分数映射的有效性和中转参数是否被完整传递。

本批证据支持优先细化全面性及需求覆盖的完成标准，同时把降低温度作为独立稳定性实验；标准对齐、证据补充和温度调整分开验证，才可判断每项改动带来的收益。
