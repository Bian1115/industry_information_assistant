# 正文引用化阈值改造及机制验证

评估日期：2026-10-06。开始时间13:49:56（Asia/Singapore）；同一次验证在修正测试夹具后完成复核，历史失败记录保留。

评估对象：Agent内部历史输入、历史输出成果及工具记录的引用化触发逻辑。用户要求低于整体阈值时直接携带原文，达到阈值后遍历已完成历史，处理过的正文可全部引用化。

## 实现和配置口径

已修改[agent_context.py](/Users/bxy/projects/industry_information_assistant/backend/app/service/agent_context.py:352)与[input_history_view.py](/Users/bxy/projects/industry_information_assistant/backend/app/service/input_history_view.py:147)：

1. 在任何历史引用替换之前，计数本次完整输入，计算`offload_triggered = tokens_before_compression >= soft_threshold`。
2. 阈值以下保留历史输入、输出、工具原文；不因单段正文较长提前引用化，也不无条件沿用过去的外置标记。
3. 达到阈值后，遍历当前可回放的全部已完成历史，包括最新完成的一轮；输入正文与成果正文均可转为可回读的来源引用。一次触发后完成整批遍历，不因中途token下降就提前停止。
4. 全量遍历取消单段128/800-token筛选，仅保留可识别正文、正确来源、权限/哈希校验及“引用比原文更短”的约束。工具记录仍保留既有预览加回读标记的外置形式。
5. 当前输入、任务契约、未完成调用保持完整；不修改原始存储、原文哈希或已有摘要覆盖游标。已经被摘要覆盖的区域不重复回放。
6. 输入日志增加`offload_triggered`与`input_history.triggered`，记录是否跨过整体触发阈值。
7. 材料引用与成果/工具外置的独立开关继续生效；此处只调整触发时机与遍历范围。

沿用原有软阈值计算：`min(soft_token_cap, soft_ratio × 可用输入预算)`。默认`soft_token_cap=17000`、`soft_ratio=0.85`，本次未调整阈值数值、模型、会话摘要配置或回读限额，也未启动真实研究评测。
