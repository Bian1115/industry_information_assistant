# 摘要机制与引用核验机制简历STAR及指标口径分析

分析日期：2026-10-03，Asia/Singapore。评估对象：行业 DeepResearch 项目的上下文摘要生命周期与摘要引用核验机制。本次根据当前源码和已有真实回放结果整理简历表述，未重新调用模型或执行新评测；指标引用运行于2026-10-02晚至2026-10-03凌晨的五题实验。个人贡献用词需与本人实际负责范围一致。

## 补充：精简版及摘要轮次边界

补充日期：2026-10-03。根据用户要求补充轮次保存方式并压缩简历文字；只核对源码，不新增评测、不改变历史指标口径。

DeepResearch智能体历史摘要不是固定保存最近N轮：达到摘要阈值时，将上次摘要覆盖游标之后、当前调用及在途调用之前的连续已完成调用，与旧摘要增量合并。交错调用通过安全边界处理，避免拆开同一调用的输入与输出；当前请求和未覆盖的后续记录继续保留在输入中。这里的“轮次”指智能体调用，包括工具调用，不等同于用户与助手的一问一答。原始记录继续保存。

另一个用户会话短期记忆模块保留语义摘要与预算允许的最近完整问答轮次，数量受token预算和消息数限制，也不是固定N轮；不能与本报告五题智能体生命周期指标混用。

推荐精简表述：

- **摘要机制：** 针对长链路研究上下文超限，按token预算将最近未覆盖的已完成轮次与旧摘要增量合并，保留当前轮次及在途调用，结合工具正文外置与原文回读；5条真实轨迹回放中，单次输入token减少75.7%–96.9%。
- **引用核验：** 针对摘要引用错配与证据不足，构建分句编号、程序原文回读、Claimify原子拆解及NLI核验链，结合混合检索补证；5题回放中167个分句、470个证据窗口均通过定位检查，补检索使8条论断转为支持状态。

两条均保留STAR逻辑：问题背景与任务合并表达，技术动作列出实施方法，结果使用已有回放指标。定位检查通过不代表语义核验全部通过。

## 一、摘要机制：STAR展开版

- **S（背景）**：DeepResearch连续搜索和阅读网页产生大量工具正文及重复历史输入，长链路上下文超过模型窗口，直接裁剪又容易丢失用户约束、研究进度和来源入口。
- **T（任务）**：构建可追溯的上下文压缩机制，在输入预算内保留任务目标、研究发现、证据缺口及原文回读入口，支持后续研究持续使用。
- **A（行动）**：设计并实现“重复正文引用化—长工具结果外置—超阈值分块摘要”的分层流程；按tokenizer计数预留输出和安全空间，独立保留最新任务约束；使用独立模型将处理后的历史与旧摘要合并为任务意图、研究摘要、资源清单三栏目；通过版本与覆盖游标管理增量更新和复用，并保留原始事件与来源映射供按需回读。
- **R（结果）**：在5条真实研究轨迹的离线生命周期回放中，单次输入由3.52万–43.90万token降至8366–15388token，减少75.7%–96.9%，全部满足25744token输入预算；其中4题生成并提交摘要，1题仅外置即可满足预算，相同历史再次组装均新增0个模型请求。

### 可直接放入简历

**上下文摘要与记忆管理：** 针对DeepResearch长链路上下文超限问题，设计并实现正文引用化、工具结果外置及按预算分块合并的分层压缩机制，以三栏目摘要保存任务约束、研究进度与来源入口，通过版本和覆盖游标支持增量更新及复用；5条真实轨迹回放中，单次输入token减少75.7%–96.9%，全部满足输入预算，相同历史再次组装新增0次模型调用。

## 二、引用核验机制：STAR展开版

- **S（背景）**：摘要包含事实、数字与多来源信息，模型自行抄写引句容易改写原文、混淆位置；带有引用的论断也可能缺少语义支持。
- **T（任务）**：建立从摘要分句到来源原文的可追溯核验链，分别检查引用定位和证据支持，并对证据不足的论断补充检索。
- **A（行动）**：实现“程序分句编号—模型关联来源编号—程序恢复原句”的引用协议，利用摘要哈希、栏目及字符坐标校验绑定；引入Claimify筛选、消歧与原子论断拆解，按证据单元编号回读原文，通过本地mDeBERTa NLI判断支持、信息不足和矛盾；对证据不足项在本次实际摘要输入上建立临时索引，结合向量/词项检索、RRF融合及rerank补充证据后复核，保存论断、来源位置、核验状态与错误记录。
- **R（结果）**：5题离线核验中，167/167个摘要父分句完成编号绑定，470/470个最终证据窗口可恢复原文并通过输入范围检查；完成271条原子论断的核验记录，43条有前后记录的补检索中8条从非支持变为支持。语义核验仍有信息不足、矛盾及错误，5题整体均为incomplete。

### 可直接放入简历

**引用追溯与事实核验：** 针对摘要引用错配及论断证据不足问题，构建分句编号、程序原文回读、Claimify原子论断拆解与本地NLI核验链，结合向量/词项混合检索、RRF和rerank补充证据；5题回放中167/167个摘要分句完成绑定，470/470个证据窗口通过原文位置校验，43条有记录的补检索中8条论断转为支持状态。

## 三、数据与配置口径

题号为16、31、35、46、49。前四题来自`通用研究中文5题重跑-20261001-231000`，第49题来自`通用研究中文5题重跑-20261001-201500`。

生命周期组回放生产策略，审计关闭，在独立ReplayStore中记录提交及覆盖游标；未更新真实研究会话的摘要。引用组另外生成摘要并显式开启原子核验，前四题输入主要为已保存的上游中间摘要与任务约束，第49题按历史分批并核验最终合并输入。两组输出不同，不能将引用组结果当作生命周期提交摘要的语义审计。

生成及论断处理模型为qwen3-max；摘要输出上限3000token。本地NLI为`MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`，revision `8adb042d524ecd5c26d3e3ba0e3fbcf7e2d0864c`，最大512token，支持阈值0.85、矛盾阈值0.5，采用`any_support_no_contradiction_v1`。临时检索使用text-embedding-v4和qwen3-rerank，dense/lexical各40，RRF k=60，粗排60，精排12，邻居1；仅索引摘要实际输入，使用后释放内存索引。

## 五、失败样例与局限性

1. 第31题模型选出当前批次不存在的消息/证据句编号，严格校验拒绝绑定，记为error。程序拒绝非法引用已实现，模型编号选择全部正确尚未实现。
2. 第35题PAC-Net相关论断在一个窗口获支持0.9918，在另一混合窗口获矛盾0.8916；当前任一高分矛盾否决规则会放大NLI误判。
3. 第49题URL中的`-023-`在Claimify消歧后丢失。父分句可以准确恢复，但后续子论断改写仍可能失真。
4. 第46题“多地采取若干措施”的集合表述被拆解为各城市分别采取全部措施，子论断可能加强原句含义。
5. 摘要生成后的信息遗漏不能仅靠核验已抽取论断发现，需独立重要信息覆盖检查。

**已测量**：五题回放的输入token、预算达标、提交与复用；摘要分句绑定和证据窗口位置恢复；原子论断标签与有记录的补检索状态变化。

**间接推断**：程序恢复原句可减少模型抄写引句引入的定位偏差；混合检索能为部分不足项提供补充材料；分层压缩有助于在长链路研究中控制上下文大小。未做受控消融，不能将收益全部归因于单个组件。

**尚未评估**：人工金标下的引用精确率、核验准确率及召回率，端到端研究质量/成功率提升，多轮摘要误差累积，当前版本累计费用和延迟净改善。五题为小样本回放，位置100%通过不代表事实100%正确；单次输入减少不代表总费用减少；同一历史复用新增0请求不代表后续所有轮次无需摘要。

生产摘要采用先生成提交、可选审计的路径。本次生命周期审计关闭，不能写成“所有摘要核验通过才保存”；未验证删除失败论断、重写、复核、失败阻止提交的完整闭环。引用组五题均incomplete，不写“引用核验全部通过”“消除幻觉”或“事实准确率80.1%”。

## 六、结论与下一步建议

目前可写的贡献为分层上下文压缩、三栏目摘要及增量复用，以及编号引用、原文追溯、原子核验和证据不足时的补检索。建议下一步补人工标注的核验对照、Claimify标识及范围保真检查、支持/矛盾冲突复核，以及固定预算下的端到端压缩消融。取得独立数据后，再增加事实准确率、报告成功率或累计成本的改善表述。
