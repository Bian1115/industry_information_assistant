# Claimify 提示词来源与接入说明

日期：2026-09-29。

## 来源与许可

Dasha Metropolitansky、Jonathan Larson，*Towards Effective Extraction and Evaluation of Factual Claims*，ACL 2025，页 6996–7045，DOI：10.18653/v1/2025.acl-long.348。

- [论文正式版](https://aclanthology.org/2025.acl-long.348/)
- [作者论文 arXiv v2，附录 N.1](https://arxiv.org/html/2502.10855v2#A14.SS1)
- [论文页面标注的 CC BY 4.0 许可](https://creativecommons.org/licenses/by/4.0/)
- [Microsoft Research 方法说明](https://www.microsoft.com/en-us/research/blog/claimify-extracting-high-quality-claims-from-language-model-outputs/)

本项目直接提取作者论文附录 N.1.1、N.1.2、N.1.3 的 Selection、Disambiguation、Decomposition 系统提示词和用户模板，保留英文规则与全部示例；不是引用社区非官方实现。提取自 arXiv HTML 代码块，去掉页面的下载箭头，合并超过两行的空白；未翻译或删减语义规则。原始文本保存在 `backend/app/prompts/Claimify{筛选|消歧|拆解}{系统|用户}提示词.txt`。运行时追加适配指令，原文件不被覆盖。

## 实现与工程适配

默认策略为 `claimify-v1`。`backend/.env.example` 与运行时缺省值已更新；已经冻结的旧策略快照和显式指定 `incremental-v3`、`split-citations-v4`、`chunk-merge-v1` 的运行保持原有协议。旧摘要提示词保存在 `摘要正文生成与合并旧版.txt`。使用已有上下文配置文件的部署，需要显式将新运行的 `summary_strategy` 设为 `claimify-v1` 才会切换，既有运行不自动迁移。

1. 摘要模型读取历史，输出四栏目自然语言段落；不输出原子分句列表、JSON、来源编号或引用原句。分块与一次额外合并继续按完整请求 token 预算执行，只在最终合并后抽取一次。
2. 程序按中英文句边界分句，保存栏目内字符偏移。保护常见英文缩写、小数、URL 和路径；不是论文所使用的英文句子切分器的逐字复现。
3. 筛选采用前 5 句、后 5 句及栏目上下文；消歧和拆解采用前 5 句、后 0 句。上下文有省略时显式标记 `[...]`。不会仅因为句子以“目标/建议”等前缀开头就跳过筛选。
4. 三阶段保留论文语义规则，追加中文输入使用中文输出、精简 JSON 状态和结果协议；不要求输出自由文本思考过程。筛选只留下可核验内容；无法消歧的句子标记 `cannot_disambiguate`，不调用拆解；拆解得到可独立核验的论断。
5. 每阶段一次生成，格式错误最多修复一次，继续使用当前独立摘要模型配置和共享调用数、超时、输入/输出预算。与论文附录 D 的筛选/消歧各 3 次生成、至少 2 次成功、最多 2 次格式重试不同；本实现不声称复现论文精度或成本。
6. 摘要不再提供证据编号，引用阶段在本次新增原始来源和旧摘要的已校验来源池中选择引用，继续验证连续原句、真实来源、绝对偏移，并按原策略执行 NLI/字段/契约/覆盖核验。引用检索遍历完整候选批次，未引入按词面相似度丢弃候选的捷径。来源较多时调用开销会上升，达到预算就失败，不能静默截断或换回旧抽取器。
7. 核验修复输出仍是自然语言，随后重新执行 Claimify 和引用定位。失败时保留旧摘要和覆盖游标。

## 保存格式与读取兼容

摘要模型输出仅为自然语言。程序保存时追加 `## CLAIMS`，其 JSON 内容改为带版本的对象：

```json
{
  "version": "claimify-v1",
  "sentences": [
    {"section": "SUMMARY", "start": 0, "end": 14, "status": "extracted"}
  ],
  "claims": [
    {
      "section": "SUMMARY",
      "sentence_index": 0,
      "claim": "消歧拆解后的独立论断。",
      "references": [{"source_id": "原始编号", "quote": "连续原文", "start": 0, "end": 4}]
    }
  ]
}
```

以上是结构示意，偏移必须由实际文本计算。自然语言正文保持不变；消歧和拆解后，论断不必是正文的逐字子串。程序验证完整分句账本、状态、顺序、所属栏目及引用来源，避免沿用旧格式“一行正文必须等于一条论断”的错误假设。

`parse_summary()` 对外仍返回 `(parts, claims_list)`；旧 `CLAIMS` 数组以及 JSON 代码围栏仍可读取。`summary_reference_quotes()` 兼容新旧格式。新策略增量合并只把上轮正文传给摘要模型，旧引用作为独立证据池保留。

完整筛选/消歧/拆解结果记录在 `summary_claimify` 历史事件，模型调用仍记录 `summary_stage` / `summary_output` / `summary_stage_end`。核验报告注明 `verification_scope=extracted_claims_only`。无法消歧的句子保留在自然语言上下文及审计账本中，并通过 `needs_review`、`unresolved_sentence_indexes` 标明；不能把已抽取论断通过 NLI 等同于整段正文事实全部通过核验。

## 适用边界

“可核验”不等于“已证实”。Claimify 筛选与拆解质量依赖模型；来源定位只能证明引用真实存在，语义支持仍由配置启用的 NLI 判断。缺少信息、纯意见和计划可能被筛掉，原正文保留这些上下文。

本次验证使用确定性桩，不请求真实 LLM、NLI 权重或 PostgreSQL。尚未测量中文抽取 precision/recall、归属/否定保留率、真实消歧可靠性、调用时延和实际 token 成本。建议后续用实际历史摘要人工标注小样本，分别评估 entailment、coverage 和 decontextualization；不要将本次控制流测试通过率当作抽取准确率。
