日期：2026-10-02T17:32:21+08:00。本文件解释现有代码及已保存评估结果；设计建议尚未实现。没有新增模型调用、生产代码或配置变更。

## 1. 计划为何出现在摘要，如何被送入NLI

[摘要生成提示词](/Users/bxy/projects/industry_information_assistant/backend/app/prompts/摘要正文生成与合并.txt:4)明确规定四栏目：SESSION INTENT保留目标与要求，SUMMARY保留事实、结论、决策和限制，ARTIFACTS保留资源和访问状态，NEXT STEPS保留剩余任务、计划及待确认问题。因此计划出现是工作历史摘要的预期行为，不等于把计划写成已完成事实。之前所说“计划误入NLI”指核验通道错误，不是工作摘要不该有计划。

本次独立评估调用qwen3-max，把四栏目正文和实际输入消息一起交给[直接抽取提示词](/Users/bxy/projects/industry_information_assistant/backend/app/prompts/摘要论断与消息编号.txt:1)，返回section、claim、source_ids。提示词明确不执行Claimify，claim须连续摘自摘要，source_ids须为当前上下文编号；纯目标、要求、建议、待办不返回，但包含已发生事实时不能整体排除。

随后[位置绑定代码](/Users/bxy/projects/industry_information_assistant/backend/app/service/summary_claim_binding.py:67)检查结构、来源ID及摘要原文位置；不精确匹配时允许一次语义等价判定及定向修复。[逐条核验入口](/Users/bxy/projects/industry_information_assistant/backend/app/service/summary_claim_binding.py:146)对每条绑定claim执行相关证据选择、程序恢复原文及NLI。本轮未设置独立statement_type类型检查，也没有NEXT STEPS禁入事实NLI的程序路由。模型违反提示词把纯待办列进claims，只要来源和位置合法仍会被继续核验。

另一处不一致是生成提示词仍写“后续独立Claimify流程负责”，实际本轮实验走直接抽取路径。该表述应与实际流程统一，但不能据此断言所有失败由这句导致。生成正文、选择可核验论断、判断支持关系是三件事，保留计划与不对计划做事实NLI可以同时成立。

## 2. 类型应通过来源、语义和程序路由一起实现

建议分类对象为最小陈述，保留原文位置、说话人/来源、时间、对象、否定、条件和类型。模型只输出类型与来源，服务器根据类型选择核验路径，不让模型自行关闭核验。类型不清楚进入待复核，不能静默丢弃。

|类型|例子|核验方式|
|---|---|---|
|事实|论文报告在某数据集准确率92%|对原文检查实体、数据集、指标、条件，再做证据关系判断|
|计划|下一步读取A论文|保存待办状态；检查任务一致性，不证明未来读取已经发生|
|要求|用户要求一级全文来源|以最新版TaskContract和用户消息为依据检查保留|
|已发生操作|读取A论文返回403|查实际工具调用、结果、资源与事件记录|
|推断|据A/B结果推测共同需求存在|保存推断属性，核验前提和推导，不升级为直接实证|
|不确定|无法区分是否已执行|保留并复核，不用规则强猜|

“下周回读尚未获取全文的A论文”必须拆为计划“回读A论文”和进度/事实“A论文全文尚未获得”，分别处理。NEXT STEPS只是先验，不能整栏跳过事实；“某政策将于2027年实施”也不是研究助手的未来计划，仍应作为有归属的政策陈述核验。用户说“我认为准确率92%”只能证明用户提出该说法，不能证明论文真实准确率92%。

建议对象字段：statement_id、summary_span、original_text、proposition、type、subject、time_scope、polarity、conditions、speaker/source_kind、source_refs。若proposition为消歧后陈述，允许补全上下文明确的主语，须保留原文跨度并防止新增事实；它不是逐字原句，也不能替代original_text。当前连续原句schema与这种标准化命题需作显式区分。

## 3. 东莞案例：文字恢复正确，逻辑关系预测错误

待核验论断：东莞市已实践“厂网河一体化”治理框架，通过完善管网、推进雨污分流、集中处理污水、建立季度专家巡查考核机制，并明确淘汰分散式设施，转向集中式系统。

当前底层输入是premise=证据窗口、hypothesis=论断；NLI返回entailment、neutral、contradiction。模型softmax分类分数未经本任务校准，不是外部事实为真的概率。

实际三个窗口：

|窗口|内容|支持分|矛盾分|解释|
|---|---|---:|---:|---|
|1|东莞暂缓新建分散式站点、推动集中处理；同句还有上海和韶关|0.089|0.836|只涉及部分事实，并未明确否定其他措施|
|2|基本逐字复述待核验论断及模式解释|0.963|0.000|相对于输入确有支持；不证明外部真值|
|3|东莞答复、全国新闻、兰州机制、帮考网、龙岗公告组成的资源列表|0.006|0.992|无明确东莞未实施的反向事实；混入其他对象|

[真实原始记录](/Users/bxy/projects/industry_information_assistant/backend/eval/data/已有中文五题摘要与引用评估-20261002-151935/题目35/论断核验-claim_2a6ec8789dda4d3b.json)显示：资源列表因记录解析，被作为一个证据单元s0019选择；不是纯东莞原文。这是证据单元过宽、选择缺少精确关系控制的迹象。NLI把没有反向事实的清单判为0.992矛盾；较短的部分事实窗口也被判0.836矛盾。不能把“未覆盖剩余子命题”自动理解为“否定剩余子命题”。

[窗口选择代码](/Users/bxy/projects/industry_information_assistant/backend/app/service/summary_message_verification.py:225)为每个来源保留最高支持和达到阈值的最高矛盾。[聚合代码](/Users/bxy/projects/industry_information_assistant/backend/app/service/nli_verifier.py:156)矛盾优先：任一矛盾≥0.5即contradiction，之后才考虑支持≥0.85。故0.992否决0.963。保留可能反证是合理的；问题是把未经复核的分类高分等同于真实反证。

建议四步：

1. 把“整体框架、雨污分流、集中处理、季度巡查、设施退出”等复合内容分为最小命题，每条带完整对象和条件，不能一条证据只支持其中一部分就通过整体。
2. 证据按实体/字段保留最小必要上下文。混合列表可以做召回入口，实际核验只使用相关项与必要邻句；真实表格仍需保留表头、行标识、单位和条件。查询目标同时覆盖支持、否定、更正，不能只取支持内容。
3. 支持与矛盾同时出现时转conflict_needs_review。独立小上下文判断必须返回证据编号、同对象同条件是否成立、完整支持/部分支持/明确反证/无关/无法确定及简短理由；其输出也要校验，并用人工确认样本测量误判。真实同范围反向证据不能忽略。
4. 无支持但有“矛盾高分”先记contradiction_candidate；证据不足与运行错误分开。模型阈值及最终规则需校准，不能仅改成支持优先、提高矛盾阈值或对分数平均。时间/数据集不同通常不能直接判逻辑冲突；明确撤回/更正应按真实来源和版本处理。

12条矛盾中5条同时有高分支持，只能说明需要复核；不能因此认定5条全是假矛盾。原文定位解决可追溯性，相关性、完整支持、条件匹配和反证有效性仍需分别判断。

## 4. TaskContract之外增加独立的重要信息记忆

TaskContract解决“必须回答什么、遵守什么”；动态ResearchMemory解决“已发现什么、哪些证据不足、哪些操作已执行、接下来仍需做什么”。不要把助手生成的研究结论混入用户要求，使结论获得任务约束的权威性。

建议在每批新增历史/工具结果完成后、摘要生成前增量更新重要信息记忆。保存六类：研究发现及关键数值；必要条件与来源归属；证据质量限制；资源及读取/失败状态；假设、决策及依据；未解决问题和待办。字段至少包括稳定ID、任务关联、重要性与理由、原始来源编号/原句/位置/哈希、核验状态、active/superseded状态。原历史归档保持可回读；RAG可索引它，但不能代替明确must_keep清单。

[重要信息结构示例](/Users/bxy/projects/industry_information_assistant/backend/eval/data/已有中文五题摘要与引用评估-20261002-151935/重要信息保存结构示例-20261002.json)取自16题真实输入，CNN数字的来源是中间摘要，示例明确external_truth=not_checked，不能因存入记忆就升级为已验证研究事实。

保存与使用建议：

- must_keep：直接回答任务的指标、关键限定、真实冲突、严重证据缺口和未完成阻塞项；每次构造输入至少包含其紧凑内容。
- retrievable：辅助背景、已结束细节、长原文；保存数据库/文件及检索索引，在必要时回读。
- superseded：明确被新要求、真实更正或撤回替代；保留版本与关系，停止当作活跃结论注入，不能物理删除以掩盖冲突。

工作上下文可组装为最新版契约＋活跃必保留记忆＋叙述摘要＋最近消息；完整记忆和原文留在外部存储。要给活跃记忆设置预算；超限显式提示或扩大可控分批处理，不能把全部历史复制成另一个无界prompt。

生成后的两种检查方向不同：摘要论断→原证据检查新增/改写是否有依据；重要信息记忆→摘要或实际下一阶段上下文检查重要信息是否遗漏。被独立记忆直接注入下一阶段的项不必强迫摘要重复，但若业务要求摘要必须自包含，仍需补回正文。文字摘要字段覆盖与工作上下文保留率应分别统计。

发现缺失就把原始记忆项及来源发给摘要模型定向补回，再检查其他必保留项未被新修订挤掉。数字/单位/人群/年份必须在同一实体与来源条件下比较，不能靠字符串全局存在就判保留。单位变换需明确允许并可重算。

仓库已有[extract_ledger](/Users/bxy/projects/industry_information_assistant/backend/app/service/verification_checks.py:94)及[check_coverage](/Users/bxy/projects/industry_information_assistant/backend/app/service/verification_checks.py:142)，可复用扩展。它们已经存fact_id、字段、引句、来源位置和哈希，并限制助手陈述不能自动成为研究事实。但当前[正文优先生命周期](/Users/bxy/projects/industry_information_assistant/backend/app/service/summary_lifecycle.py:129)标记omission_check=not_run，直接实验也未接入这条线上清单覆盖检查。因此“代码存在”不等于“当前每次摘要已经检查遗漏”。接入新类型后要同步改覆盖检查对象，不能只检查排除了计划的事实claims。

## 5. 三个模型角色不能混淆

|角色|本轮模型|任务|
|---|---|---|
|生成与直接抽取/证据选择|qwen3-max|写摘要、返回claim及来源、绑定补充判断、选证据单元|
|内容保留评审|qwen-plus|摘要生成前编参考检查点、生成后检查保留/遗漏|
|NLI语义判定|MoritzLaurer/mDeBERTa-v3-base-mnli-xnli|证据窗口与论断的支持/中立/矛盾分类|

[评估配置](/Users/bxy/projects/industry_information_assistant/backend/eval/data/已有中文五题摘要与引用评估-20261002-151935/运行配置.json)冻结了模型名称。此前“评审模型也不能直接当裁判”主要指qwen-plus的内容保留评审；135条论断的NLI支持比例不是qwen-plus输出。

qwen-plus本轮问题有三类：一是把来源里的内容复制成不存在的摘要引句，16题CNN结果实际完全遗漏却判partial；二是仅看摘要局部，35题±20%阈值、30分钟、月度台账实际存在却判遗漏；三是参考检查点把局部来源限制扩为全局，如某个中间摘要的二手来源不足被当成所有材料均二手。15条引句无法精确定位含排版变化和拼接，不能说全部15条都属于语义幻觉。

建议让评审器只返回程序预先编号的摘要句/片段ID和逐项关系，而非自由生成quote。程序恢复文本并检查关键字段，复杂跨句项支持多个编号。must_keep标准先由任务关联和原来源形成，人工确认一小批固定样例；评审模型用于筛查和局部解释，最终指标要测与人工的一致性，不能靠换模型就假设问题消失。NLI也要独立校准，两个评审职责分开计错。
