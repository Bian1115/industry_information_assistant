## 通俗理解

网页通常把文章、菜单、推荐、广告和评论放在一起。正文抽取器要从中挑出作者文章，供搜索、RAG或研究智能体使用。这篇论文检验已有工具在多种语言上的表现，并检查评分标准是否公平；其贡献主要是评测与问题分析。

作者比较Readability、Boilerpipe、Trafilatura，并以整页转文字的html_text作基线。实验加入DAnIEL的英语476页、中文400页、波兰语274页、希腊语273页、俄语266页。参考答案中的读者评论会影响公平性：清理Dragnet评论后，Readability的平均F1从0.806变为0.896，html_text则从0.604变为0.501。因此，不能笼统说所有工具都提高。

下表为论文表3的逐页ROUGE-L F1均值，均是作者结果，本次未复现：

| DAnIEL语言 | Readability | Boilerpipe | Trafilatura |
| --- | ---: | ---: | ---: |
| 希腊语 | 0.962 | 0.961 | 0.868 |
| 英语 | 0.862 | 0.847 | 0.883 |
| 波兰语 | 0.862 | 0.861 | 0.800 |
| 俄语 | 0.840 | 0.750 | 0.759 |
| 中文 | 0.672 | 0.611 | 0.555 |

在这批数据上，Readability在四种非英语语言上领先，英语由Trafilatura领先；中文对三者都较难。中文Trafilatura的Precision为0.501、Recall为0.836，说明问题尤其体现在混入额外文字。论文同时指出，正文之外内容的占比不能可靠决定抽取质量。[来源：论文第3至5节及表1、表3](https://dias.users.greyc.fr/publications/sigir2025.pdf)。

这些分数衡量文本抽取重合程度，不能解释成“67.2%的URL一定能读成功”，也不能直接作为当前库版本或本项目的成绩。

## 评分怎样理解

Precision问“抽出来的内容有多少属于正文”，Recall问“应该保留的正文拿回多少”，F1综合两者。只提取第一段可能很干净但遗漏很多；把整页都留下可能不漏正文，却混入大量菜单。

一个自拟教学例子：金标有100个单位，输出120个单位，按相应匹配规则匹配到90个，则Precision为75%，Recall为90%，F1约81.8%。这不是本次运行结果。ROUGE-L基于顺序上的公共子序列；具体工具的分句、切词和Lsum聚合会影响数值。

表内的平均F1是先逐页计算再平均，不能用表内平均Precision和平均Recall重新算出完全相同的值。

## 怎样复现评测

以下是可执行的复现路线；2025年作者修改版代码尚未取得，当前不能保证逐数复现。

1. **准备固定页面和人工正文。** 使用DAnIEL的`html/`、`reference/`和`doc_lg.json`按页面标识配对，复核实际语言与正文边界。评论是否保留、标题是否计入、表格如何展开，都必须预先统一。当前公开映射不等同于论文过滤后的清单。
2. **同一份HTML交给各抽取器。** 评测抽取能力时使用保存的页面，避免重复下载导致页面变化。原始HTML分别交给各个适配器，避免某个适配器先修改DOM后影响其他工具。保存预测全文、版本、参数、异常和耗时。
3. **固定评分实现。** 论文称ROUGE-L；其继承的[WCEB上游评测源码](https://github.com/chatnoir-eu/web-content-extraction-benchmark/blob/36be6d9c4f96d3c613c21144c4d39e5d0cce93af/src/extraction_benchmark/eval.py)使用`rougeLsum`、`split_summaries=True`、不做词干化，并传入自定义tokenizer。[上游tokenizer](https://github.com/chatnoir-eu/web-content-extraction-benchmark/blob/36be6d9c4f96d3c613c21144c4d39e5d0cce93af/src/extraction_benchmark/util.py)按空白切分。必须确认2025年作者是否修改过中文切分或数据预处理，不能默认等同。自行做中文业务评测，可另报字符级或固定中文分词的结果，并明确它与论文数值不直接可比。
4. **先逐页，再逐语言汇总。** 每页保留Precision、Recall、F1及失败原因；有效金标页面的抽取异常或空结果留在分母。语言宏平均可先求各语言均值，再对语言等权平均；按页面汇总会受到样本量影响。要精确匹配论文表2，还需核对英语多个数据集的分组权重。
5. **检查最低分与意见不一致的页面。** 重点区分多保留了导航、漏掉正文、标签口径不一致、正文实际不在HTML中，以及切词造成的评分异常。不要只看总分。

[WCEB仓库](https://github.com/chatnoir-eu/web-content-extraction-benchmark)提供数据转换、抽取和评分命令，属于SIGIR 2023的上游框架；它不会自动完成2025年论文的DAnIEL筛选和评论清理。本次固定核查的上游提交为`36be6d9c4f96d3c613c21144c4d39e5d0cce93af`，提交日期晚于SIGIR 2025，不能当作作者当时的运行快照。

## 怎样接入正文抽取功能

可以先使用现成工具，无需训练新模型。Readability类规则大体通过文本长度、段落结构、链接密度等特征给DOM区域评分，选取主体并清理无关区域；不同语言和页面模板可能改变这些线索的有效性。

一个最小Python示例，依赖`readability-lxml`、`html-text`、`trafilatura`。代码仅用于说明接口，本次未执行：

```python
from readability import Document
import html_text
import trafilatura


def extract_candidates(raw_html: str, url: str) -> dict:
    candidates = {}

    # 各自读取原始HTML，独立记录错误，便于对照。
    try:
        article = Document(raw_html, url=url)
        main_html = article.summary(html_partial=True)
        candidates["readability"] = {
            "title": article.short_title(),
            "html": main_html,
            "text": html_text.extract_text(main_html),
        }
    except Exception as exc:
        candidates["readability"] = {"text": "", "error": str(exc)}

    try:
        candidates["trafilatura"] = {
            "text": trafilatura.extract(
                raw_html, url=url,
                include_comments=False, include_tables=True,
            ) or "",
        }
    except Exception as exc:
        candidates["trafilatura"] = {"text": "", "error": str(exc)}

    return candidates
```

这里的`include_tables=True`是面向本项目的配置选择，示例不等于论文配置。根据[上游适配器](https://github.com/chatnoir-eu/web-content-extraction-benchmark/blob/36be6d9c4f96d3c613c21144c4d39e5d0cce93af/src/extraction_benchmark/extractors/extractors.py)，WCEB使用Python `readability-lxml`加`html_text`；[Mozilla Readability](https://github.com/mozilla/readability)是另一种JavaScript实现，可以作为独立候选，不能直接互换后声称完成严格复现。

候选选择还需要独立实现和验证。不能直接选最长文本，也不能在没有金标时用真实F1挑选。可在开发集上校准导航比例、链接比例、异常页识别、段落连续性和表格保留等信号，再在留出域名上验证。保存主体HTML有助于复用表格渲染与原文引用。

## 在本项目中的落点

本节是2026年10月17日工作区静态核查后的工程建议，未实现、未评测。

- [web_reader_service.py的_extract_html](../backend/app/service/web_reader_service.py#L567)在找到`article/main`或任意`table`时优先生成BeautifulSoup结果；只有`content`为空时才尝试Trafilatura。建议让Readability与现有方案分别产生候选，质量不合格时允许有界回退。某页存在表格，不足以证明整个body都是正文。
- [_read_uncached](../backend/app/service/web_reader_service.py#L380)在正文过短时主要触发浏览器回退。长导航也可能超过长度门槛，后续应按质量失败原因决定是否重新抽取或渲染。
- 先取得正确页面或渲染DOM，再选正文；PDF、Office附件、扫描图应单独解析。正文选择不能从验证码、登录页或缺失的HTML中恢复原文。

建议链路为：下载与格式判断 → 必要时渲染 → 同一HTML生成正文候选 → 质量选择 → 保留段落、表格与来源 → 分块入库。这是应用设计，不是论文已经验证过的组合算法。

## 逐类失败分析与局限性

以下是机制分析或自拟例子；本次没有作者逐页失败文件，没有重放项目历史页面。

| 失败类型 | 例子与含义 | 应对方向 |
| --- | --- | --- |
| 混入噪声 | 正文外又带上推荐文章列表 | 提高主体选择精度，独立检查导航污染 |
| 丢失正文 | 只取到开头，后文分散在多个DOM区域 | 检查候选区域合并、分页与渲染状态 |
| 金标不一致 | 参考答案含评论，但任务要求排除评论 | 修订标注协议，保留清理前后对照 |
| 输入无目标正文 | 页面只有验证提示，或正文由脚本后加载 | 归因于访问或渲染，分别处理 |
| 评分口径不适配 | 无空格中文整段被当作一个token | 核查tokenizer，另报适配中文的补充指标 |
| 结构丢失 | 纯文本保住数字却丢掉表头与单位对应关系 | 增加表格单元格与引用保真检查 |

**已测量：** 作者论文中公布的历史指标，本次仅转录核查。**已核查：** 当前上游适配器、评分器与本项目两个读取函数。**间接推断：** 候选抽取和质量回退可能改善部分噪声页。**尚未评估：** 本项目收益、当前版本排名、成本延迟、表格保真和端到端URL可用率。

DAnIEL以新闻为主，各语言也对应不同站点与页面模板；结果不构成“语言本身导致全部差异”的受控因果证明。没有作者筛选清单、依赖快照和逐页结果，当前路线只能支持有明确口径的重建评测。

## 结论与下一步

实际可采取的下一步是建立一个保留原始HTML与人工正文的中文开发集，对照当前方案、`readability-lxml`和固定版本Trafilatura；同时保留英文与正常页面，检查误伤。先做同HTML抽取对照，再做完整URL链路对照，分别报告正文F1、URL可用率、正常页误拒、耗时和表格保真。只有完成这些配对实测，才能判断是否值得切换或增加回退。
