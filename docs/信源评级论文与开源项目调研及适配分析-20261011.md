## 逐项分析

### 1. RA-RAG：适合把可靠度接入检索与答案聚合

- 论文：*Retrieval-Augmented Generation with Estimation of Source Reliability*，**EMNLP 2025 主会**。[发表记录](https://aclanthology.org/2025.emnlp-main.1738/)
- 官方仓库：[ml-postech/RA-RAG](https://github.com/ml-postech/RA-RAG)，GitHub 识别许可证为 MIT。核验发现主运行程序、可靠度计算模块与实验脚本。
- 核心方法：交叉核验多来源回答，估计来源可靠度，再选择可靠且相关的来源，用加权多数投票聚合答案。
- 对当前项目的适配判断：最值得优先研究其“来源可靠度影响阅读、检索和聚合”的设计。接入仍需定义来源身份及粒度，并适配现有证据记录。
- 作者明确说明的局限：交叉核验材料少的专业主题较难处理；可靠度在离线阶段计算，需要更新。主实验侧重短答案问答，长篇研究报告不是已充分验证的场景。[作者论文方法与局限性](https://arxiv.org/html/2410.22954v4)

### 2. 新闻来源关系图：适合建立域名可靠度库

- 论文：*Reliability Estimation of News Media Sources: Birds of a Feather Flock Together*，**NAACL 2024 主会长文**。[发表记录与作者指标](https://aclanthology.org/2024.naacl-long.383/)
- 官方仓库：[idiap/News-Media-Reliability](https://github.com/idiap/News-Media-Reliability)，GitHub 识别许可证为 Apache-2.0。提供 Common Crawl News 处理、关系图构建、可靠度计算、标签数据和预计算分数。
- 核心方法：根据新闻来源之间的网页链接关系估计连续可靠度。作者报告与记者评分的 Spearman 相关系数为 0.80、分类 macro-F1 为 81.05；二者不能解释为任一新闻事实的正确概率。
- 工程特点：可先研究预计算域名分数，再考虑重建图。README 说明完整原始图未放入仓库，需要生成；原复现环境使用 Python 3.7，大规模抓取和依赖适配有额外成本。
- 适配风险（机制推断）：新站点和关系稀疏的来源可能难评级；批判性引用与支持性引用的语义不同。中文机构、券商、公众号与学术期刊覆盖仍需单独验证。

### 3. LLM 媒体画像：适合借鉴明确的评级标准

- 论文：*Profiling News Media for Factuality and Bias Using LLMs and the Fact-Checking Methodology of Human Experts*，**ACL Findings 2025**。必须保留 Findings 标识。[发表记录](https://aclanthology.org/2025.findings-acl.45/)
- 官方仓库：[mbzuai-nlp/llm-media-profiling](https://github.com/mbzuai-nlp/llm-media-profiling)，GitHub 识别许可证为 MIT。
- 核心方法：多组提示词提取媒体画像，将 LLM 回答交给文本分类器预测事实性和政治倾向；还提供少量零样本案例。它不等于一次提示词直接输出已经校准的 0–100 可信度。
- 核验结果：仓库提供数据、结果与地区／流行度分析 notebook；本次固定提交的完整文件树中，未发现完整画像生成、模型训练和推理入口。应定位为研究材料，不能按现成服务估算接入成本。
- 适配判断：可以参考其标准化问题和分维度处理方法，但涉及政治倾向的维度不应直接替代行业或医学证据质量。事实性标签也继承其参考评级体系的口径。

### 4. 历史媒体画像基线：适合复现来源级分类

- 论文：[Predicting Factuality of Reporting and Bias of News Media Sources（EMNLP 2018）](https://aclanthology.org/D18-1389/)；[What Was Written vs. Who Read It（ACL 2020）](https://aclanthology.org/2020.acl-main.308/)。均为主会论文。
- 共享官方仓库：[ramybaly/News-Media-Reliability](https://github.com/ramybaly/News-Media-Reliability)。提供标签、已计算特征及 SVM 训练程序，组合文章、Wikipedia、社交媒体等信息预测来源的事实性和偏向。
- 适配判断：适合了解任务定义、构建可复现基线；年代较早，历史特征不代表今天媒体的状态。本次没有确认可从当前互联网重新完整采集同样特征。
- 开源边界：GitHub API 未识别许可证，核验文件树中未发现 LICENSE 文件。代码公开与明确授权复用需要分别记录；这不影响阅读论文和参考实验设计。

### 5. 来源可信度与引用支持度联合评测：适合验证改造收益

- 论文：*Assessing Web Search Credibility and Response Groundedness in Chat Assistants*，**EACL 2026 主会长文**。[发表记录](https://aclanthology.org/2026.eacl-long.115/)
- 官方仓库：[kinit-sk/web-search-analysis](https://github.com/kinit-sk/web-search-analysis)。提供采集、来源处理、检索分析与 groundedness 评测程序；GitHub API 未识别许可证，文件树未发现 LICENSE。
- 评测设计：分别测量引用来源的可信度，以及答案是否得到所引用正文支持。作者数据包含五类主题的 100 个论断。[方法与指标](https://arxiv.org/html/2510.13749v2)
- 对当前项目的价值：评级模块上线后，可以参考其联合评测方式，防止把“引用了可靠媒体”误当作“每个结论都有证据支持”。它依赖外部评级资料，不是自动为任意未知网站评级的替代方案。
- 原实现成本：README 的 groundedness 流程使用量化 Llama 3.3 70B 和检索模型，采集流程依赖 Selenium；直接复现有环境要求。本次未测量替换判定模型后的效果。

## 相邻项目与选型边界

[OpenFactCheck（EMNLP 2024 System Demonstrations）](https://aclanthology.org/2024.emnlp-demo.23/)可以用于事实核查和事实性评估，但其主要对象是论断、回答、模型和核查系统。不能将它列为直接的媒体来源评级器。[当前官方仓库](https://github.com/openfactcheck-research/openfactcheck)已经重定向到新组织，本次 GitHub 识别许可证为 AGPL-3.0；没有据旧介绍写成 Apache 许可。

总体上，**发布主体身份、来源历史可靠性、文档证据质量、引用是否支持论断、论断是否为真**是不同问题。媒体政治倾向应与事实性分开处理。源站可靠度可以作为先验，但不能取代具体证据检查。

## 失败样例与中断记录

本次没有运行效果测试，**不存在新增实测失败样例**。以下为选型时应加入未来测试集的机制推断案例：

| 假设案例 | 可能失效的位置 | 后续验证办法 |
| --- | --- | --- |
| 多家媒体转载同一篇错误稿件 | 跨来源共识把同一个上游误当作多个独立证据 | 记录转载与原始出处，按独立上游去重 |
| 公司官网宣传自身产品疗效 | 官方身份被误解为研究结论可信 | 分别核验发布主体与研究证据，并检查利益关系 |
| 高评级媒体的一篇文章引用了已撤回研究 | 域名分数覆盖具体页面的证据缺陷 | 追溯原研究和状态，再检查页面是否准确描述 |
| 冷门中文行业站没有外部评级和足够引用边 | 图模型或模型已有知识不足 | 将未覆盖标为 unknown，测量覆盖率与拒绝评级率 |
| 答案忠实引用低质量网站的错误断言 | groundedness 高，但来源质量与事实性低 | 同时记录来源评级、引用支持度与独立事实核验 |

原始记录抓取中，Idiap 仓库 API 先发生 SSL EOF 中断，第一次重试又发生读取超时，之后使用 curl 成功取得固定提交及完整文件树。同一运行保留失败和重试记录，未改变核验口径。网络抓取失败不作为方法效果失败。

## 局限性

这是一轮定向检索，不能保证覆盖所有最新论文。没有根据星标量给质量打分，也没有把论文配套代码视为已经验证的生产组件。各论文的数据、标签与指标不同，不能直接横向排列数值大小。代码许可元数据不自动证明第三方数据拥有相同许可。

医学论文质量、研究偏倚和证据确定性需要研究级口径；上述新闻评级实验没有验证这部分。任何接入顺序都是基于机制的建议，不是本地效果结论。

## 结论与下一步建议

如果目标是改造现有检索和证据链，优先研究 **RA-RAG**；如果目标是维护媒体域名评级库，优先研究 **NAACL 2024 的关系图与预计算数据**。ACL Findings 2025 更适合提供画像思路和标注参考。EACL 2026 的方法适合作为改造前后的评测设计。

建议先保留可追溯的发布主体身份和原始出处，分别存储来源可靠性、文档质量及引用支持度；未知来源允许 unknown。随后构建覆盖官网、媒体、报告、论文、转载和未知站点的人工标注集，测量分类精确率／召回率、未知覆盖率、来源排序一致性、引用支持率和误导结论率。对评分进行校准之前，不应将其展示为事实正确概率。

本次只新增调研文档和机器可读核验记录，没有改动业务评分机制。
