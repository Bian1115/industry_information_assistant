# 智能体历史摘要改进论文与开源项目调研

## 调研日期与范围

日期：2026-10-05，Asia/Singapore。目标是改善 LeadWriter 的长任务工作记忆，包括细节保留、重复压缩损失、章节间信息选择以及来源回读。核对论文、会议记录、作者仓库和官方文档；未复现外部系统或比较其本项目性能。

项目当前使用三栏目累计摘要，默认上限 3000 token；结合旧摘要与增量历史生成下一版本，超预算时组批后合并。原始历史已保存，提供 `_history_read` 受控回读；当前 Claimify 后续审计关闭。摘要基于处理后的历史视图，部分资料正文已经引用化或外置。

从代码结构推断，值得进一步验证的因素是：单份累计摘要混合不同章节及同会话其他主题；旧摘要再次合并时细节可能退化；精确原文已保存，但粗粒度来源目录可能不足以让 Writer 快速定位缺失信息。以上是设计层面的风险推断，不能代替本项目实测。引用核验检查保留下来的论断是否有支持，与遗漏信息的测量是不同问题。

## 优先参考的论文

### 1. ReadAgent — ICML 2024

完整题名：**A Human-Inspired Reading Agent with Gist Memory of Very Long Contexts**。

- [会议论文](https://proceedings.mlr.press/v235/lee24c.html)
- [作者项目页及提示词演示](https://read-agent.github.io/)

核心机制：将原文划分为记忆片段，生成短 gist；模型阅读 gist 后按需查回原文。摘要与原文共同构成可恢复的阅读机制，方法主要基于提示词，不要求专门训练摘要模型。

适配理由：Writer 的关键数字、条件和引句需要准确复用。本项目已有原文保存与回读接口，可进一步建立“章节/证据片段 → gist → 原文位置”的索引，让 Writer 先选择需要的片段，再读精确原文。优先解决“摘要丢掉了细节，但原文难找回”的问题。

局限：论文主要测试长文阅读理解，不是多智能体研报写作；回读次数和片段划分仍需用本项目任务验证。

### 2. ACE — ICLR 2026

完整题名：**Agentic Context Engineering: Evolving Contexts for Self-Improving Language Models**。

- [论文及 ICLR 2026 注记](https://arxiv.org/abs/2510.04618)
- [作者开源仓库](https://github.com/ace-agent/ace)

核心机制：将上下文组织为持续演化的 playbook，通过生成、反思、整理形成结构化增量更新。局部更新、去重与细化有助于避免反复整体改写导致的 brevity bias 和 context collapse。

适配理由：可以把 Writer 的术语定义、统计口径、已决定的报告结构和审核反馈保存为有稳定编号的条目；新增或更正某一项时只更新对应条目，减少对仍有效信息的重复改写。相比再修改通用摘要提示词，这提供了更直接的状态更新结构。

局限：论文重点包括跨任务经验和策略积累；其中经验 playbook 的思想可迁移，但不能把所有研究事实转换成未经核验的经验。事实证据、写作决定和可复用技巧仍须保留各自来源与状态。

### 3. AgentFold — ICLR 2026

会议题名：**AgentFold: Long-Horizon Web Agents with Proactive Context Folding**；2025 arXiv 初稿题名使用 **Proactive Context Management**。

- [ICLR 2026 会议下载目录](https://iclr.cc/Downloads/2026)
- [会议版 PDF](https://openreview.net/pdf/9a7a36e880bf0debe14bf234275484321e7b0d64.pdf)
- [可访问的作者初稿全文](https://arxiv.org/html/2510.24699v1)
- [论文所指项目仓库](https://github.com/Alibaba-NLP/DeepResearch)

核心机制：保留最新交互的完整记录，把更早历史组织为多尺度摘要块；通过细粒度压缩或多步 consolidation，有选择地折叠单步及已结束子任务。完整系统通过轨迹构造与 SFT 学习折叠行为。

适配理由：Writer 可以将“某章已写完”“某轮修订已结束”作为记忆组织边界，保留当前章节所需的细节，压缩已结束阶段的过程噪声。可借鉴多尺度分块和选择性更新，减少所有章节挤入同一累计摘要的负担。

局限：论文任务以网页信息查找为主，完整收益依赖训练与整套 agent 协议。不能把论文指标归因于换一段摘要提示词。会议版页面的实时打开受到 OpenReview 浏览器验证限制；会议身份由官方会议目录及官方索引 PDF 内容交叉确认。项目仓库与论文关联不等于本次已经确认完整 AgentFold 训练和推理代码均可复现。

### 4. A-MEM — NeurIPS 2025 主会

完整题名：**A-Mem: Agentic Memory for LLM Agents**。

- [NeurIPS 主会论文](https://proceedings.neurips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html)
- [作者记忆系统仓库](https://github.com/agiresearch/A-mem)
- [作者论文实验仓库](https://github.com/WujiangXu/AgenticMemory)

核心机制：将记忆组织为带上下文描述、关键词和标签的笔记，并建立相关记忆之间的链接；新记忆加入时可更新相关历史记忆的上下文表示。

适配理由：同会话多轮写作可按主题、章节、口径和时间组织记忆，选择当前章节有关的笔记，而不是每次注入所有累计信息。对于“不同主题混入摘要”“同一统计口径多处更新”的场景较有启发。

局限：更偏长期记忆组织；增加笔记生成、链接、索引和检索成本。模型更新笔记可能发生漂移，原始证据应继续不可变保存。本项目的短期 Writer 工作记忆可先用较简单的章节索引，不必立即引入完整记忆图。

## 优先参考的工程实现

### 5. LangMem — LangChain 官方开源项目

- [仓库](https://github.com/langchain-ai/langmem)
- [摘要接入指南](https://langchain-ai.github.io/langmem/guides/summarization/)
- [短期记忆 API](https://langchain-ai.github.io/langmem/reference/short_term/)

提供 `RunningSummary`、`summarize_messages` 和 `SummarizationNode`，支持触发阈值、摘要预算、旧摘要延续及剩余消息保留。官方指南建议将完整消息历史与模型摘要视图保存在不同 state 字段中。

适配理由：项目已有 LangGraph，适合参考其节点边界、状态字段隔离、预算参数和工具消息处理，或作为可比较的工程基线。

局限：其常规摘要也采用滚动摘要；单纯更换库不会自动解决语义遗漏或重复压缩。它最有价值的部分是实现规范与边界处理，而不是已证明比本项目摘要更准确。

### 6. Letta / MemGPT — 有状态 Agent 开源项目

- [仓库](https://github.com/letta-ai/letta)
- [官方有状态 Agent 与记忆说明](https://docs.letta.com/v1-sdk/concepts/stateful-agents)

采用持久化消息、可编辑的 memory blocks 和上下文外历史；核心记忆进入模型上下文，消息即使被移出窗口仍可检索。

适配理由：Writer 可以把必须持续保留的用户写作要求、术语、统计口径和未处理审核问题组织为小型记忆块；一般历史再参与压缩，精确细节按需检索。可进一步明确摘要和可编辑工作状态的职责。

局限：完整迁移涉及 Agent 运行时和数据模型，工程范围较大。建议先参考记忆层次和 block 更新规则，保留现有 PostgreSQL、LangGraph 与证据系统。

## 补充阅读与评估工具

- [ReSum: Unlocking Long-Horizon Search Intelligence via Context Summarization](https://arxiv.org/abs/2509.13313)，2025 预印本：通过周期性摘要把历史变成紧凑推理状态，并用 ReSum-GRPO 训练模型适应摘要后的继续推理。与当前“摘要后接续”机制接近，但本次未确认最终顶会录用身份，不将其标注为已录用顶会论文；也不把其他同名 ReSum 的数学推理论文混为一篇。
- [LongMemEval](https://github.com/xiaowu0162/LongMemEval)，ICLR 2025：用于检查信息抽取、跨会话推理、知识更新、时间推理和无答案时弃答。它是评估基准，不是摘要算法；可为工作记忆验证设计提供参考，但仍需增加 Writer 的章节修订和原文引用任务。

## 面向本项目的建议顺序

1. 先参考 **ReadAgent + ACE**：章节记忆条目包含来源位置，按需回读精确原文；对稳定条目执行增量添加和更正，避免每次重写全部记忆。
2. 参考 **AgentFold**：在章节完成、修订完成等边界压缩过程噪声；当前写作片段保留足够细节。
3. 参考 **Letta**：明确常驻约束、可编辑工作状态、摘要索引与不可变原文的层次。
4. 用 **LangMem** 作工程实现对照，再视跨主题长期记忆需求决定是否引入 **A-MEM** 的链接和索引。

建议给每条 Writer 记忆保存：稳定编号、所属章节/主题、类型（事实/决定/要求/待确认）、时间及状态、原始来源与文本区间。明确更正记录才能更新数字和状态，摘要中的事实仍需回到证据源验证。这是从论文机制与本项目代码推导出的改进建议，本次未实施，也未实测收益。

后续对照应使用相同真实轨迹、当前写作要求和输入预算，独立测量关键信息保留率、来源回读成功率、修订要求延续及报告质量。原始验证结果及本次配置改动边界见 [仅Writer历史摘要配置验证结果及分析-20261005.md](仅Writer历史摘要配置验证结果及分析-20261005.md)。
