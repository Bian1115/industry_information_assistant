# 检索正文分批提取实现与预算回放

评估日期：2026-10-02。评估对象：DeepScout 初搜、深搜/来源追溯、审核补搜的正文事实提取输入。此次是代码机制回归和归档输入回放，没有请求在线模型或重新运行评测集，也没有重启服务。

## 问题与口径

Scout 原有历史输入引用化、工具原文外置和历史摘要已经生效。第 46、49 题失败时，当前正文材料本身依然超过输入预算：当前 prompt 分别为 30,104、28,369 tokens；连同历史等最终输入为 32,776、30,624 tokens，冻结输入预算均为 25,744 tokens。历史压缩不会删除当前任务里的正文，因此继续压缩历史不能解决这两次失败。

此次只将正文提取变为独立批次。各批携带当前研究问题、章节或检索任务、启用的假设、输出格式和冻结任务契约；不回放历史材料，不允许在本批提取过程中追加历史回读。每批的原始输入、输出和上下文记录仍通过原历史服务归档。其他 Scout 推理调用继续使用原有引用化、外置、摘要和历史回放机制。上下文策略快照不被改写，记录额外标明 `input_mode=evidence_batch` / `history_mode=independent_extraction`；后续消融对比应把这一代码机制作为所有组的共同条件，不能直接与旧运行混作相同实现。

分批使用本地 Qwen tokenizer 和同一份完整消息包装计数，计入系统提示、任务、假设、JSON 输出格式及冻结契约。预算取当前运行冻结配置并扣除实际输出预留和安全余量；模型发送前再次计数。正文质量准入、正文哈希、程序分句及原句编号继续沿用现有实现。

## 实现行为

1. 初搜、深搜、补搜统一调用 `backend/app/service/deep_research_v2/evidence_batches.py`。
2. 处理全部质量合格、编号及正文哈希有效的原句，取消这三条提取路径原先每页 12,000 字展示上限。只选择完整原句，不重新编号，不改动程序保存的原文。
3. 每批按完整请求预算装入原句；同文档跨批次尽量重叠上一条相邻原句，若重叠导致当前句不能放入则取消重叠。重叠句仍计入预算。
4. 每条事实必须绑定本批实际展示的精确 URL、正文编号和原句编号。检查编号归属，不执行事实是否被原句语义支持的引用核验，也不改变已有引用核验开关。
5. 程序生成跨批唯一事实编号，再重映射假设关系。模型每批都返回 `f_1` 不会混淆关系；同批重复的模型事实编号不用于关系映射。相同 URL、正文编号和事实文本合并支持句和数据点。这里是精确文本去重，不是模型语义去重。
6. 每批记录计划、输入 token、完成或失败信息。失败或缺少有效 `extracted_facts` 时抛出错误，不跳过该批并返回不完整分析冒充成功；所有批次完成后才把可见原句编号交给入库。
7. 若任务/契约等固定输入本身超限，或单条完整原句加固定输入仍超限，在发送模型前抛出 `ContextBudgetExceeded`。不会静默截断原句，也不能承诺任意长度任务都能完成。

代码入口：

- `backend/app/service/agent_context.py`：完整消息包装复用，独立提取 ContextVar 和上下文记录。
- `backend/app/service/deep_research_v2/agents/base.py`：无历史运行身份时的提取输入检查，拒绝独立批次追加历史回读。
- `backend/app/service/deep_research_v2/agents/scout.py`：三条正文提取路径接入。
- `backend/test/test_检索正文分批提取.py`：17 项机制测试。
- `backend/eval/scripts/回放检索正文分批预算.py`：只读归档的可复现预算回放。

## 尚未评估与结论

已经验证这三条正文提取路径的完整消息预算、全部合格原句覆盖和程序编号关系合并。没有评估真实模型提取质量、跨批推理损失、JSON 输出是否会被模型输出上限截断、最终报告质量或实际费用。独立批次保留当前假设和任务，且使用相邻句重叠，但仍不能替代真实任务上的质量评估。

分批解决单次输入容量问题，不保证累计 token 更少。完整正文覆盖比旧展示窗口范围更大，会增加提取材料；第 46、49 题回放的累计输入分别为 49,662、69,785 tokens，这不是实际付费调用记录。后续若要降低总费用，应单独评估检索质量、无关正文过滤及精确证据去重效果，不能把缩小单次输入当成累计成本下降。

下一步可在单独运行目录重跑第 46、49 题，比较提取事实数量、证据定位完整性、实际 token/耗时与最终报告质量。本次没有启动该在线评测，也未改变原运行目录。
