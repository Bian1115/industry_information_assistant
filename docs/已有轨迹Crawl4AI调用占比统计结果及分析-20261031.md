# 已有轨迹Crawl4AI调用占比统计结果及分析

评估日期：2026-10-31，Asia/Singapore。评估对象：本地已导出的研究工作历史，以及此前固定五题35、31、46、16、49。方法：离线读取原始工具事件、去重计数，并对固定五题补充历史源码路径分析；没有重新抓取网页或调用模型。

**全量归档中，4,726条非缓存正文读取返回有1,553条明确采用Crawl4AI，比例为32.86%。这是可直接确认的使用比例，也是这些有返回记录的非缓存读取中实际调用比例的下限，不能当作包含所有失败尝试的精确调用率。**

此前固定五题的直接记录为120/289＝41.52%；结合五份完全相同的历史读取器源码，至少158/289＝54.67%的非缓存读取进入过Crawl4AI兜底函数。后一个数字属于代码路径推断，不等同于服务端实际执行次数或成功率。

## 数据、配置与计数单位

- 扫描`backend/eval/data/`下500份文件：文件名为`智能体原始历史.json`或以`工作历史.json`结尾，包括最终、累计、恢复和中断历史。总计读取1,733,008,609字节，360份含正文读取事件。列表格式及`messages`封装格式均已检查，无未支持结构遗留。
- 仅选择`kind=tool_raw_result`且`payload.tool_name=v2_web_fulltext_read`的原始事件。每个`payload.value[]`元素代表一次URL读取返回；一批工具调用可能读取多个URL，因此页面返回次数与批次数分开统计。
- 脚本按`tool_name + call_id`去重。`call_id`是工具执行器为一次调用生成的UUID。重复导出还必须具有完全一致的原始payload SHA-256。共合并1,679个原始结果副本，冲突为0。
- 53个调用编号在历史恢复或导入后关联到多个`run_id`，不能把这些归档视为重新联网。输出保留全部已知归属，逐运行表的主归属仅用于浏览。168个读取调用没有已知`run_id`，保留调用编号及上下文定位，不臆造研究运行身份。
- 最终识别992个正文读取工具调用编号，其中983个保存了原始结果，共5,220条URL返回。其余9个只有输入、派发和错误事件，无法确认批内实际完成的URL数，单列而不凭候选列表补造读取次数。
- 这批返回记录的时间范围为2026-09-29 21:23:32至2026-10-18 00:22:48（Asia/Singapore）。它覆盖本地导出的试跑、完整运行、消融和恢复实验，不代表2026-10-31版本的在线流量分布，也不代表数据库中未导出的全部历史。
- 分子取`extractor`包含`crawl4ai`的条目。包括`crawl4ai-sidecar`及`crawl4ai-sidecar+trafilatura`，无论最终`fetch_status`是否成功。`from_cache=true`表示后端复用了先前读取结果，不能算本次重新请求浏览器。
- 本次没有统计搜索次数、模型调用次数、网页重抓基准、公开网页基准或缓存文件中的页面数；不把模型文本中提到Crawl4AI当作调用事件。历史回放保存的原始工具副本只计一次。

## 为什么记录比例低于实际尝试比例

后端读取器先尝试静态下载与正文提取；遇到正文不足、HTTP 403/5xx或超时时，程序可能调用`WebReaderService._read_with_crawl4ai()`。只有浏览器结果满足替换条件，最终返回的`extractor`才会变成Crawl4AI。浏览器失败或结果没有被选中时，最终记录可能仍保留静态读取器或空标记。

本次还找到26行明确的Crawl4AI失败控制台日志，其中包括服务返回500和无详细消息的失败。这些日志缺少完整`run_id/call_id`关联，而且未覆盖全部成功调用，不能把26直接加到分子，也不能根据它们还原全量精确调用率。

固定五题的五份历史`web_reader_service.py`源码SHA-256完全一致：`90259441e15e1f18514f9ba67f6af9e86afb95f48131ce033f4463ee82b6e893`。因此对这五题额外分析确定的代码分支：

| 进入浏览器函数的证据 | 非缓存条目数 | 证据类型 |
| --- | ---: | --- |
| 最终读取器明确是Crawl4AI | 120 | 直接记录 |
| 未采用Crawl4AI但最终HTTP状态为403或502 | 29（403共24，502共5） | 历史代码在该错误分支必定尝试调用浏览器函数 |
| 未采用Crawl4AI、非PDF静态正文不足500字符，且无空字符清洗记录 | 9 | 历史代码的短正文分支推断；排除清洗导致正文变短的情况 |
| 合计 | 158/289＝54.67% | 对进入浏览器兜底函数的下界推断 |

这里的“调用函数”指主后端执行`_read_with_crawl4ai()`。函数可能因依赖、连接或服务错误没有让浏览器成功工作，因此54.67%不是浏览器服务成功执行率。本次没有把这套历史版本的条件直接套到所有其他版本。

## 失败和口径样例

1. **采用了浏览器结果但正文被拒绝**：`16-page-016`，`https://www.baiten.cn/so/s/EP16185390.8`，读取器为`crawl4ai-sidecar`，原始状态为`failed`，错误为`error_or_login_page`。它应计入Crawl4AI采用次数，但不能计入成功正文。
2. **未保留Crawl4AI标记仍可能尝试过浏览器**：`16-page-014`，ResearchGate图页，错误为`HTTP 403: Forbidden`，最终读取器为空。按该运行冻结源码，后端会在403分支尝试浏览器，再保留失败结果。这说明仅数`extractor`会漏掉调用。
3. **缓存结果不代表本轮再次联网**：`16-page-010`的一个后续返回，`https://www.x-mol.com/paper/1767630501405495296`，读取器仍为`crawl4ai-sidecar`且`from_cache=true`。它计入结果来源占比，从本次非缓存调用口径中排除。历史记录还可能保留与成功状态不一致的旧错误文本，不能只按`error`是否为空判定状态。

样例文件保留每条的原始历史路径、序号、调用编号和返回位置；本次未访问这些URL。

## 复核过程和边界

2026-10-31同一统计任务先因缺少运行编号、随后因恢复归档的多运行归属而中断预扫描，均未输出一个可用比例。随后用全局调用编号与原始结果哈希确认身份，完成初步统计。初步结果保留在[已有轨迹Crawl4AI占比统计-20261031](../backend/eval/data/已有轨迹Crawl4AI占比统计-20261031/)。

同日完整复核补读56份`messages`封装历史，发现167个原始工具结果副本，全部已出现在初步统计中；5,220条独立返回及分子分母不变。完整复核还加入五题历史代码路径推断。两个目录均保留，未覆盖初步结果；以带“完整复核”的目录为本报告依据。

**已测量**：全部匹配历史文件的原始工具返回、同调用结果指纹一致性、缓存与状态分布、固定五题302条与旧索引逐条匹配、26行失败日志；独立复算5,220条身份唯一，Crawl4AI读取器标记与`browser_`恢复标记逐条一致。

**间接推断**：五题158次进入浏览器函数的下界；全量32.86%仅是已有非缓存返回中调用占比的可确认下限。53个调用在多个运行归档中的归属代表恢复或复制，不是53次新增联网。

**尚未评估**：全量Crawl4AI精确请求数、每个失败/未采用的浏览器尝试、9个中断批次内的真实页面请求数、浏览器服务端成功率及耗时、数据库未导出的历史、当前版本上线后的流量比例、正文质量改善幅度。

## 结论和下一步建议

对“目前已有轨迹”的稳妥表述是：**全部本地导出轨迹中，有返回记录的非缓存正文读取至少32.86%明确使用了Crawl4AI；此前固定五题为41.52%，结合其历史源码可推断至少54.67%进入浏览器兜底函数。** 不宜把32.86%或41.52%写成含全部失败尝试的精确调用率。

若后续需要精确调用率，应由主后端在每次浏览器函数开始时记录`browser_attempted`及原因，提交HTTP请求时记录`browser_request_sent`，完成或失败时记录服务结果，并保留`run_id + call_id + URL读取编号`。缓存返回单独记录。这样统计程序才能分别计算尝试率、实际请求率、成功率和结果采用率。本次只新增离线统计脚本与报告，没有修改生产工具或新增埋点。
