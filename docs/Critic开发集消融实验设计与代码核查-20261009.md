## 1. 推荐结论与要回答的问题

采用两组配对比较：A 保留 Critic 和最多两轮返工；B 跳过 Critic，Writer 首稿完成后直接交付。其他组件、预算上限和输出要求保持一致。

先做五题首轮的同首稿分叉，回答“给定相同初稿，审核返工能改善多少，付出多少额外成本”；再做每题独立会话、六轮真实追问的完整开发集，回答“持续使用或关闭 Critic 对最终成果及累计成本有什么影响”。两阶段分别汇总，不能混成一个收益数字。

主比较估计的是审核返工链的整体效果，包括新增计算和新增证据的收益。若还要证明优于普通再写一次，可补充 C 组通用自修订；它不是主实验的必需项。

## 4. 第一阶段：五题首轮同首稿分叉

1. 五题各取第 1 轮问题，每题独立新会话。用冻结源码和配置完成 `plan → research → analyze → write`。
2. **在完整 write 节点已提交、review 尚未执行时冻结。**首稿包含 Writer 本来就会执行的篇幅处理、基础检查和可选引用处理；分叉不能选在这些操作之前。
3. 冻结完整图状态、Agent 工作历史及摘要游标、会话证据存储、来源正文、工具响应、引用审计、搜索及 token 预算账本。新框架的证据可能位于会话 RAG，只有研究状态 JSON 不足以构成可回放输入。
4. 从同一冻结点复制到隔离的运行、会话、历史存储、证据存储和预算账本。A 继续完整审核返工；B 执行明确的未审核完成分支。不得共用可写的游标、计数器或反馈列表。
5. 对照两份最终报告、修改过程和新增证据。A 的补搜照正常策略执行并记录，因此两组初始证据相同，最终证据不要求相同。

首轮得到五个配对、十份最终报告，公共前缀只实际生成五次。若某个前缀失败，该题标记为“未能进入配对”，保留失败消耗和原因，不伪造无 Critic 的完成结果。

至少一轮完整五题用于探索；正式下结论前建议再独立生成一轮五题首稿，并重复两组分叉。重复生成与重复评分是不同的操作。每个配对的公共前缀共享，跨生成重复不共享首稿。

### 公共前缀成本怎么计

设公共前缀耗时/消耗为 P，A 分支为 RA，B 分支为 RB：

- 每组逻辑上的完整研究成本：`CA=P+RA`，`CB=P+RB`。
- Critic 返工链额外成本：`CA−CB=RA−RB`。
- 关闭后的节省比例：`(CA−CB)/CA`，分母包含公共前缀。
- 整个实验实际消耗：`P+RA+RB`，公共前缀只算一次。

耗时采用阶段单调时钟，分叉克隆及评测准备开销单列。共享首稿阶段估计的是拼接的完整路径耗时，不是两条独立在线服务的实测延迟；第二阶段再测真实端到端耗时。评估裁判调用及证据复核消耗与研究生成消耗分开。

## 5. 第二阶段：正式开发集五题六轮

五题独立会话，每题六轮。A、B 使用相同固定用户请求，**各自继承本组上一轮的交付成果**，不把 A 的报告灌给 B。不同题之间不共享会话；不使用五题串成一个 30 轮会话的长上下文压力模式。

每组计划 30 次用户轮，共 60 次。与第一阶段不同，两组从头独立运行；前序报告、路由和后续首稿可以不同，这是持续启用 Critic 的累计效果。记录每轮实际 `execution_plan`、父研究、复用成果、补搜、摘要与正文长度，帮助解释差异。

- 主要质量终点：每题第 6 轮最终稿，五个题级配对；第 5 轮作为篇幅压缩前的辅助终点。
- 过程终点：30 轮交付情况、每题完成轮数、前序约束/证据/反证保留，以及各轮严重缺陷。
- 成本终点：各题六轮累计实际消耗和耗时，不能只看末轮。
- 同题失败后，依赖其结果的后续轮标为未执行，不由运行器编造父成果；失败消耗保留。一个题失败不取消其他题。

30 个轮次有依赖关系，不能当 30 个独立样本进行显著性检验。应按题汇总；五题两次生成重复也不等于十道独立任务。

正式问题截止 2026-09-27，2026-10-09 运行时应统一各阶段研究日期上下文。Critic 当前用运行当天日期；后续实现应将“审核当天”和“资料截止日”分开记录，明确按问题截止日审查证据，避免把截止日之后的材料用于研究结论。不得仅修改 A 的时间口径。

## 6. 质量、失败及成本指标

### 独立质量评分

复用现有四维评分框架及虚构 few-shot：深度、全面性、可读性、需求覆盖，分别 0–10 分，等权平均。正式多轮问题为改写任务，须根据该轮完整有效要求编制检查项；不能直接照搬官方原题细则，或称为官方排行榜成绩。

沿用已有 Qwen/Claude 双裁判配置，各对每篇独立评分两次，参数在运行前冻结，保留请求中的实际模型与参数。先取每个模型两次均分，再取两模型均分；同时保存各模型结果及分歧，不用均值掩盖反向判断。不向裁判提供组名、Critic 分数、反馈或旧评分；输入包含完整报告、参考文献和有效用户要求。评分中的证据风险只作为复核线索。

第一阶段十份报告需要 40 个有效质量响应；两轮独立生成则 80 个。第二阶段若仅对十份第 6 轮稿评分，也是 40 个响应；增加第 5 轮则再加 40 个。逐事实核查另外统计，不能宣称 40 次调用包含完整事实审计。

### 核心指标与分母

| 指标 | 计算和解释 |
| --- | --- |
| 质量差值 | 每题 `ΔQ=Q_A−Q_B`；报告四维差值、题均值、中位数和每个裁判的差值 |
| 配对胜平负 | 预设差值在 ±0.3 分内为实践上的近似平局；同时保留未阈值化差值。这是设计阈值，不是已验证噪声范围 |
| 需求覆盖 | 运行前冻结有效需求；完整/部分/未覆盖分别统计，关键需求单列；诚实说明缺证不自动等于未覆盖 |
| 严重缺陷 | 每篇经独立证据复核的 critical/major 数量及“含至少一个严重缺陷”的报告数；比较原始计数及每千字符密度 |
| 引用与证据 | 重要可核查事实的引用覆盖；完整支持/部分支持/矛盾/不可判断分别报告，保留总数及可判断分母 |
| 修正率 | 独立确认的首稿缺陷中，最终稿确实修复的数量/可追踪缺陷数量；删除核心内容需同时记需求损失 |
| 改坏率 | 首稿正确且重要的信息中，被删掉、改错或失去必要限定的数量/可追踪正确重要信息数量 |
| Critic 问题有效性 | 每轮反馈针对该轮待审稿复核，有效/误报/待核实分开；不拿最终稿判断首轮反馈是否正确 |
| 交付 | 计划、启动、写作成功、最终单次交付分别计数；交付成功不等于质量合格 |
| 时间与调用 | 初稿/审核/补搜/分析/修订/交付分别记录耗时、模型请求、输入/输出 token、搜索与读取次数 |
| 费用 | 优先实际 usage；价格表需在运行时核对并冻结。缺 usage 或未知价格不能当零；搜索费用缺失时明确单列 |

引用支持须独立抽取两组全文，不能仅使用 Writer 自报 claims 或 Critic 找出的 issues 作为分母。首稿错误也须独立确认：只检查 Critic 的问题列表能估计问题有效性，不能算错误召回率；若未穷尽标注，应明确“固定样本内检出率”。无法判断不当作错误，也不当作完整支持。

同一稿件的错误位置、命题和类型保留，必要时另汇总错误家族，避免同一问题在多次审核中重复计数。不得把 `resolved=true`、内部 `quality_score` 或 `quality_verdict=pass` 当作独立修复和质量证据。

5. 当前 `finish()` 会重新赋予 `citation_verification_status()`，可能覆盖此前真实审计结果。实现前需核对并在两组共同终态逻辑中保留实际核验状态，不能只修 A 或 B 造成观测口径差异；本次未执行验证该覆盖影响的测试。

7. `create_agents()` 未必把角色配置中的采样参数用于每次请求；Critic 实际审核调用写有 temperature=0.2、max_tokens=16000。运行冻结除角色配置外，还需保存实际请求参数及提示词指纹。

## 9. 冻结配置、运行与分析原则

- 冻结实际工作区源码及提示词哈希，不能只用 HEAD 表示当前大量未提交修改。两组同一源码，通过开关改变路由。
- 冻结角色模型、实际采样、输出长度、最多两轮返工、总搜索上限、各阶段及全任务预算、来源范围、缓存、重试、上下文策略、会话 RAG 和引用处理。
- 总搜索 20 次是当前代码允许的默认上限；实际配置以运行快照为准，包含初搜与补搜。不得为 A 临时扩容，或给 B 删除上游限制。
- 在线端到端两组按题配对调度，交替先后顺序；并发和缓存策略相同且完整记录。相同 seed 不承诺供应商输出确定性。
- 不复用不同源码/配置的历史完整轨迹作为主对照。若历史首稿不能恢复完整证据与历史，另做离线报告比较并注明边界，不能伪称真实恢复实验。
- 预先冻结需求清单、严重程度和判定阈值，分析时不根据有利结果修改。重复评分失败可按同一请求指纹重试并保留记录；生成失败保留首尝试，不只统计成功重跑。
- 质量差值以两组都有最终稿的配对计算，另外报告全部计划样本的交付状态和失败消耗。缺失稿不填 0 分，也不从成功率分母中消失。
- 输出逐题差值、裁判重复波动、误报/改坏以及成本拆分。五题只作探索，不能宣称统计上已经证明无质量损失；如给区间，按题聚类且明确小样本局限。

## 10. 预设决策口径

实践上的质量差异门槛先设为 0.3 分（10 分制）。这只是便于决策的设计值，运行前可明确修改，运行后不能为了结论改动。

- **倾向保留 Critic**：多个题/生成重复出现超过门槛的独立质量提升，或减少经证据复核的严重缺陷，且没有明显新增关键错误或需求损失。必须一起报告额外成本。
- **值得继续验证关闭或按需审核**：多数配对差值接近门槛内，关闭后显著减少本轮实测耗时/消耗，且未发现新增严重缺陷。五题仍不能证明“质量不变”或生产可直接删除。
- **优先优化审核策略**：增益只集中某些缺陷，而存在大量误报、无效补搜或改坏。可另测限定缺陷类型、单轮审核或按风险触发，不从本次两组结果直接宣称这些策略有效。
- **结论不确定**：裁判分歧大、重复生成方向相反、关键证据不可判断或配对缺失。保留完整结果，不按平均分强行决策。

如果关注“Critic 的专业反馈是否优于多算一次”，新增 C 组：同首稿起点、相同时间/搜索/token 上限、最多两轮通用自修订，自主判断是否补证据，不接收 A 的反馈或新增来源。比较 A−C，并报告实际预算差异。只有上限相同不能称为严格等实际成本；若要做成本匹配，应另行冻结固定额度或成本曲线协议。

开发集结论用于选择实现；最后用预留的新任务验证，不能将开发集调参后的结果称为独立测试集泛化收益。
