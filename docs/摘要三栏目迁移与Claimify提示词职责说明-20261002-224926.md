## 对提示词的意见和依据

代码中已有两种审计顺序。开启 `atomic_citations` 后，`audit_prose_atomic` 先请求模型返回候选论断及相关消息编号，`verify_atomic_output` 绑定摘要位置，再由 `extract_bound_claims` 调用 Claimify 筛选、消歧、拆解，随后分别为子论断选择证据和运行 NLI；不足时再检索。关闭该开关时，仍保留其他旧路径。因此不能把“后续必定执行 Claimify”写成所有运行的统一保证。

建议及本次处理：

- 正文生成提示词只说明忠实压缩职责，不要求输出论断、引用或自行完成原子化；继续保留“独立核验阶段”的职责说明。
- 候选论断及引用定位提示词明确本阶段保持摘要连续原句、不执行 Claimify 处理；开启原子论断链路时，后续 Claimify 再处理，并为各原子论断分别选择证据和核验。
- 初次返回的 `source_ids` 是相关消息候选池，可以包含支持或反对消息，不等于所有原子论断都已得到支持。证据原句及位置仍由程序恢复，本次没有改成让该模型返回 quote。
- 保留覆盖全部可核验内容的要求。Claimify 只处理成功绑定的候选，无法自动补回候选提取阶段遗漏的事实。缺少证据的候选应保留并返回空来源数组，不提前删除。

这些规则避免候选模型先改写、消歧后无法绑定摘要原句，也避免把父论断的所有候选引用机械地当成每个子论断的有效支持。提示词更清楚并不证明模型一定遵守；这是工程设计判断，尚未测量准确率改善。

## 未完成事项并入 SUMMARY

未完成事项是任务上下文中的进度和状态信息，可以归入 SUMMARY。删除单独的 NEXT STEPS 栏目不会意味着删除已有待办，也不会使计划自动变为研究事实。

当前新摘要固定为三个正文栏目：

| 栏目 | 保存内容 |
| --- | --- |
| SESSION INTENT | 当前目标和有效要求。 |
| SUMMARY | 事实、结论、决定、限制，以及上下文明确记载的尚未完成或解决事项；保留归属、提出者和原有状态。 |
| ARTIFACTS | 文件、资源、路径、变更及失败结果。 |

例如历史明确写有“用户要求回读论文 A，尚未完成”，SUMMARY 应保留这一状态。历史仅指出“论文未提供置信区间”，摘要不能由此自行新增“下一步做稳健性实验”。纯待办仍不进入普通事实核验；若同一段含已发生事实，不能因位于 SUMMARY 或带任务前缀而整体跳过。

本次修改正文生成提示词、旧分句生成提示词、直接生成 CLAIMS 的旧策略提示词、格式修复提示词、解析器、渲染器和测试夹具。新正文生成及提交严格要求三栏，不再生成 NEXT STEPS。

文件：[现行正文提示词](../backend/app/prompts/摘要正文生成与合并.txt)、[统一栏目规则](../backend/app/service/summary_sections.py)、[自然语言解析](../backend/app/service/claimify.py)、[保存摘要解析](../backend/app/service/agent_context.py)、[旧分句协议及合并视图](../backend/app/service/summary_citations.py)。提示词版本号同步更新，冻结的运行配置及历史结果没有迁移写回。

## 旧摘要与引用兼容

旧四栏摘要仍可读取，其引用账本、分句序号和字符位置按原栏目校验，不在校验前挪动文本。向下一次生成提供合并视图时，旧 NEXT STEPS 正文追加到 SUMMARY；原 SUMMARY 为 None 时直接替换为已有待办，不混入空占位符。

旧列表型引用保留原始来源编号，渲染新合并视图时把旧待办栏目归入 SUMMARY。Claimify 账本型和未核验正文型摘要先校验旧结构，再生成三栏正文视图。历史原文、原引用和旧审计结果不被覆盖，未核验标记也不被提升为已通过。

原子化路径读取旧摘要时仍可处理旧栏目中的已发生事实，保留父论断及其原位置；新生成摘要只使用三个正文栏目。
