## 最优先的三篇

### Provence

论文将上下文裁剪建模为序列标注，并提供与文档重排统一的方案，依据查询保留相关信息。它比普通摘要更贴近“哪些原句该进入证据”的需求。正文见[ICLR正式论文](https://proceedings.iclr.cc/paper_files/paper/2025/file/5e956fef0946dc1e39760f94b78045fe-Paper-Conference.pdf)，代码见[作者仓库](https://github.com/naver/bergen/blob/main/scripts/provence/readme.md)。

项目改造建议：抓取正文先去导航和推荐列表，再对句子进行相关性筛选，并保存source_id、句子位置和原文。不应把论文里的跨领域效果当作已验证的中文网页效果；需检查中文适配、关键数值和限定条件的保留情况。这是基于论文机制提出的工程映射，论文没有直接研究本次淘豆网页面故障。

### Attribute First then Generate

先选择相关来源片段，再组织它们支持的句子，最后逐句生成。这些预选片段同时成为输出的细粒度引用。论文在多文档摘要和长答案问答中验证了方法。[ACL论文及PDF](https://aclanthology.org/2024.acl-long.182/)，[作者代码](https://github.com/lovodkin93/attribute-first-then-generate)。

项目可保存短证据句和稳定编号，让Writer引用编号；quote由程序从证据库回填，避免Writer反复输出整段原文。编号回填是本项目改造建议，不是原论文的全部实现。该论文研究的是归因与生成质量，并未证明能解决3000 token上限下JSON截断；输出容量、结构解析和截断后的重试策略仍需单独处理。

### Budget Aware Tool Use

Budget Tracker在Agent循环内展示工具预算的已用量和剩余量，BATS进一步据此调整搜索和核验策略。研究包括BrowseComp、BrowseComp-ZH、HLE-Search等信息搜索任务，因此比只研究数学推理token长度的论文更贴合本项目。[论文最新版本](https://arxiv.org/html/2511.17006v2)，[作者提交页及录用说明](https://arxiv.org/abs/2511.17006)，[官方代码](https://github.com/google-research/budget-aware-agent)。截至本次查询，COLM状态来自作者原始来源的录用声明，本次未取得独立会议录用列表。

项目映射建议：每次补搜前展示总token余量、搜索次数、阶段剩余秒数及完成分析、写作、复审的估计成本。资源不足时优先必要证据、缩减可选范围或保全未完成草稿。原论文主要展示工具预算感知，不直接给出本系统摘要、写作和返工之间的最佳token比例，也不能保证成本预估永不超限。

## 另外四篇的阅读用途

[Sufficient Context ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/file/33dffa2e3d2ab74a783d1a8c292f66d9-Paper-Conference.pdf)适合补足评估：把“来源是否含有足够信息”和“Writer是否使用正确”分开。信息充分性不是来源真伪判定；充分但错误的材料仍可能产生错误答案。将其按报告子问题评估是项目扩展，不能直接套用问答准确率。

[CompAct EMNLP 2024](https://aclanthology.org/2024.emnlp-main.1194/)适合借鉴query-focused增量压缩和early termination。它处理的是检索文档，不是任意多Agent历史。需把压缩器自身耗时、输入输出token和后续调用节约一起计入总成本，不能只报告压缩后文本短了多少。

[MAST NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/b1041e52d3be19f0a9bc491657488e4a-Abstract-Datasets_and_Benchmarks_Track.html)提供14种失效模式，正式PDF附录详述任务规范违背、任务偏离、推理行动不一致、错误核验。将第31题映射到相关模式是本次分析判断；论文没有专门验证“模型自选代表国家变为用户硬要求”的解决方法。保留要求出处、区分用户要求和规划选择是本项目建议。

[LongLLMLingua ACL 2024](https://aclanthology.org/2024.acl-long.91/)适合作为查询感知输入压缩的参考与对照。主模型阅读视图可以压缩，引用证据仍应返回未改写的原始连续片段，两者分开保存。

## 对工程实现的建议和证据边界

建议顺序为正文清洗与去重、句子相关性筛选、证据充分性判断、先选证据再生成、带预算的补搜与修订。先在保存的故障来源和开发集上验证；线上长报告不宜直接照搬论文逐句调用流程，应计算额外时延和token成本。

用户要求来源混淆和输出截断还需工程约束：要求必须关联用户原话与出处，规划示例不能升格为用户硬要求；JSON解码约束不能替代足够的输出长度。上述论文支持相关设计方向，不证明已经修复本系统或能在同一预算下达到等同报告质量。
