# 正文质量检查与编号证据实现及回归

评估日期：2026-10-02。对象：当前网页读取、Scout 事实提取、原句回读及 Writer 输入。口径：离线机制测试，HTTP 和模型调用使用模拟结果；另外回放上一轮第 35 题保存的污染正文。没有执行新的端到端研究，也没有重启现有后端。

## 实现后的流程

```text
网页/PDF 读取结果
  → 程序提取正文、检查明确错误和污染信号
  → 不确定页面由 Scout 做一次有界模型检查
  → 对通过或明确标记为部分正文的内容分句、编号、保存
  → Scout 输出事实 + document_id + sentence_ids
  → 程序检查正文版本、句子编号、本次展示范围
  → Writer 接收准入事实及对应原句
```

核心模块：[web_document.py](../backend/app/service/web_document.py)。接入点：[web_reader_service.py](../backend/app/service/web_reader_service.py)、[scout.py](../backend/app/service/deep_research_v2/agents/scout.py)、[evidence.py](../backend/app/service/deep_research_v2/evidence.py)、[writer_claims.py](../backend/app/service/deep_research_v2/writer_claims.py)、[writer.py](../backend/app/service/deep_research_v2/agents/writer.py)。

## 正文质量检查

程序保留既有 HTTP 错误分类，补上内容级准入：错误及登录页面典型标题和短提示、推荐列表标题与上传信息组合、导航或短标题列表特征、预览及付费提示。HTML 提取前去除导航、侧栏、页脚及明确的推荐模块，再交给 trafilatura 或 BeautifulSoup 提取。可以明确分离的文章尾部推荐模块会被剔除；单独出现“推荐”字样不拒绝整篇文章。

读取到的实际页面标题与检索目标标题没有词项重叠时标记为不确定，而非直接拒绝。不同 URL 内容相同也仅标记为不确定，允许模型判定合法转载。模型检查发生在分句前，最多展示 12000 字符的完整文本块，输出上限 1500 token；返回状态、理由和保留的块编号。保留块必须来自实际展示内容，程序按原顺序取回，模型不生成替代原文。未展示或未保留的部分不被声称已确认，保留部分标记为 partial。模型选定内容还会经过明确错误规则复查。

状态为 passed、partial、uncertain、rejected。只有 passed 和 partial 进入新编号证据库。模型失败、非法 JSON、未知块编号或明确拒绝都关闭本页准入。失败分类及 body_quality 记录在 web_reader_attempts 中，供排查。

缓存中的旧 success 记录也会重新进行内容检查；HTTP 错误后浏览器恢复的结果不能绕过规则检查。旧检查点来源按需进行规则检查，已知污染内容不能仅凭非空文本继续通过来源门禁。

## 分句和事实结构

每份通过检查的正文保存：document_version、由 URL 和正文内容生成的 document_id、content_sha256，以及 sentence_index。句子索引包含 id、block_id、start、end，位置为字符偏移，左闭右开。正文保存一份，原句按偏移回读，不在每条事实内重复保存正文。

中文按句末标点分句；英文处理常见缩写及小数；URL 查询标点不会拆碎 URL；表格逐行编号。相同句子在不同位置获得不同句子编号。原文内容改变时文档编号改变，回读时校验哈希、文档编号和索引，防止旧编号指向新内容。同一运行再次读取相同 URL 时沿用已保存的编号正文。

Scout 的初搜、深搜和补搜都使用编号正文，并要求事实返回：

```json
{
  "fact_id": "f_1",
  "content": "提取出的原子事实",
  "source_url": "输入提供的URL",
  "document_id": "输入提供的正文编号",
  "sentence_ids": ["s000012", "s000013"]
}
```

模型只选择支持句编号，程序提供对应原句。一条事实可绑定多句；编号为空、重复、未知、错绑正文、正文检查未通过，或句子未在本次输入展示，都不能进入新的编号事实库。来源数据点关联到事实，不能用其他来源的事实编号获得准入。假设关系的原文引句必须存在于事实选中的支持句中，允许连续支持句的真实连续引用，禁止跨未选择句子拼接。

Scout 的正文输入默认最多 12000 字符，按查询词项选择完整句子及相邻上下文，保留原编号并明确提示未展示部分，不再机械地裁剪正文开头。读取器原有的最长 30000 字符提取上限仍适用；这不代表读取完整原始 HTML 或完整长 PDF。

## Writer 与历史兼容

Writer 只接收通过来源门禁的事实，事实列表显式展示事实 ID。原文包按支持句分组，同一来源的不同事实不会错误共用第一个事实的片段。original_sentences 含全部已定位支持句及偏移；兼容字段 original_excerpt 为第一条支持原句，不把中间未选择内容或不相邻句子拼成连续引用。

新编号事实不再使用来源开头 1600 字符。历史没有句子绑定的短正文保持兼容读取；历史长正文不猜测证据片段，也不替旧事实伪造支持句编号。网页来源及假设关系恢复为单份原文和事实引用的规范结构，不再保存重复的来源 URL、快照别名和派生快照副本。

定位状态明确标记为 located_not_semantically_verified。正文类型检查和原句存在性检查不等于“原句支持事实”的语义核验；本次没有新增 NLI 或最终报告事实支持性核验，也没有将 claims 标记为已验证。
