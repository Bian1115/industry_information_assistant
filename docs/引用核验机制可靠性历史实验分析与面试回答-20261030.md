# 引用核验机制可靠性历史实验分析与面试回答

分析日期：2026-10-30，Asia/Singapore。

评估对象：论断抽取是否保持原义、引用证据是否定位准确并支持论断、NLI支持性判断的可靠性。对应面试问题“引用核验自身的机制可靠性怎么样，抽取的论断准确吗，引用的证据是否准确，NLI模型判断的准确率怎么样”。

本次读取历史报告与机器可读结果，按逐条记录复算计数，并核对当前源码。未重新调用模型、未新增语义标注、未重跑研究任务，也未修改业务代码。下文的“当前实现”指本次读取的工作区代码，不表示已检查部署进程或线上效果。

## 1. 可直接口述的面试回答

我把引用核验拆成三个环节验证：从报告里抽取可以单独检查的事实陈述、找到对应来源原文、判断原文能否支持完整陈述。历史实验说明它能帮助发现问题，但还不能保证事实全部正确。

第一，论断抽取方面，历史五篇报告整理了511条事实论断，其中510条能够定位回报告原文，回定位率是99.80%。这个数字说明结果可追溯，不代表抽取语义准确率，也不证明所有事实都抽全了。历史摘要实验就出现过把“提升60.38%”改成“提升至60.38%”的错误，数字没变，意思却变了。目前还没有人工穷尽标注的论断集合，所以我不会声称抽取准确率达到99.8%。

第二，证据方面，要区分“找对保存的原文”和“原文完整支持结论”。历史296条论断与来源关系中，285条定位有效，占96.28%；但293条带引用论断里，严格完整支持的只有143条，占48.81%。另外63条因为乱码、导航页或材料不足等原因无法判断；排除这些后，完整支持率是62.17%。所以引用存在、位置正确，只是必要条件。目前程序让模型返回证据句编号，再由程序从保存的来源内容中取回原句，能控制证据的出处，但模型仍可能漏选或选错相关句。

第三，NLI就是让模型判断“给定原文是否支持这句陈述”。当前用Qwen3-max执行这项任务。历史生产模块在230条带引用且参照可判断的论断上，与Codex独立复核的通过/不通过一致率为78.26%。模型判通过的169条里，131条确实被复核为完整支持，支持精确率77.51%；复核认为完整支持的143条里，模型通过131条，支持召回率91.61%。但是，对87条未完整支持的论断，模块只识别出49条，问题检出召回率56.32%，说明发现细微问题的能力仍有限。

典型漏放是来源写“未来还会建设”，报告却写成“已经建成”；还有原文统计19—33岁人群，报告改成20—33岁，却保留原百分比。38条误放行中37条属于部分支持，1条属于直接矛盾，不能把它们全部说成现实中的假事实。后续我已在实现上改成从最终报告独立抽取论断，并按编号取回证据原句；这些改造有机制测试，但真实质量增益还没有重新测量。下一步要用人工标注，分别验证抽取、选句和判断，重点检查时间、分母、范围与结论强度。

上述质量数字来自历史离线回放，参照是助手复核，不是人工金标，也不是当前版本的线上准确率。

## 5. 失败样例与分层归因

1. **抽取改变原义。** 旧摘要诊断中“提升60.38%”变成“提升至60.38%”。前者表示相对增幅，后者表示最后达到的数值。来源定位和数字匹配都不能发现全部这类错误。五篇报告抽取另有31-body-137新增原文未明确写出的“文物机构”限定的语境风险，不能把能够回定位等同于完全保真。
2. **模型选取了可定位但不可读的材料。** 冻结数据中35-body-002等来源包含被误作文本的DOC二进制内容，仍可具有有效来源定位与哈希字段。哈希用于确认文本是否相同，不会确认文本是否有用。
3. **计划被改成实施结果。** 31-body-131写“中国科技馆通过大数据生成能力成长图谱”，原文是未来“还会”实施；参照partial，模块supported。
4. **统计范围改变。** 49-body-009将19—23、24—28、29—33岁三组求和，却写成20—33岁并保留73%；参照contradicted，模块supported。这里讨论的是冻结文本的范围不一致，本次没有新增医学或市场事实核查。
5. **证据不足被当成相反证据。** 46-body-028被模块判contradiction，历史复核却认为保存材料支持该论断。不能将片段未明说某条件自动当作否定该条件。
6. **来源支持也可能传播来源本身的错误。** 31-body-115引用的二手报道将博物馆地点写为苏州，模块和复核都判来源支持；历史馆方核查指向扬州。这里沿用保存的历史核查，未重新检索。它说明“报告忠实于来源”与“来源符合现实”是两个层次。

历史38条误放行中，主因互斥归类为：时间/计划/状态10条，统计量/年龄/分母8条，范围/条件/强度13条，技术细节/具体属性7条。该归因来自历史复核说明，不等于已经测量每种机制的因果贡献。

## 6. 当前实现如何控制问题

1. 程序在最终报告形成后，把段落、列表、表格行等交给独立抽取模型。模型返回可独立检查的陈述及其报告原句；程序检查每个输入单元均有结果，并检查原句在相应单元中唯一出现。当前逻辑不以Writer自报清单作为最终审计的完整分母。
2. 程序从报告实际引用的来源中检索候选内容，并为原句或结构化片段编号。模型只选编号；程序从已有来源内容取回选中的原文，再将原文和论断交给核验模型。模型不能用自己改写的文字充当证据。
3. 程序保存来源、编号、位置及内容哈希，便于复核人员追查具体输入；非法编号、不可回读、调用失败等不能被记成支持。
4. `get_nli()`当前只接受qwen3-max。Qwen接收证据与论断，返回支持、信息不足、矛盾及分数/理由；没有把整个智能体对话作为该次判断输入。
5. `all_claims_checked`仍为false，因为程序保证处理了所有输入单元，不保证模型提取了每个单元里的全部事实。默认失败动作是audit，即记录审计结果；本文的“误放行”表示核验标签通过，不表示当时自动删除、阻止或发布了内容。

上述机制不能解决模型漏抽、漏选、语义误判或来源本身错误。2026-10-17的回归验证了控制流程，真实质量提升仍待评测。

## 7. 如果追问“为什么换模型”

可回答：旧mDeBERTa方案暴露了中文复杂论断误拒、漏放，以及512 token输入限制；同批741条带来源样本改用Qwen核验方案后，与保存的最终语义复核标签一致率从49.80%提升到83.67%。但当时同时改变证据组合和标签口径，Qwen核验器与参照裁判还共享模型，所以这是整套方案的机器标签一致性改善，不能说模型本体准确率提高33.87个百分点。

这批741条实验与230条生产模块对照不是同一统计口径：前者含正文、搜集事实及预审论断，后者仅为最终正文中带引用且参照可判断的条目；不能把83.67%与78.26%解释为同一指标前后下降。

## 9. 局限性、结论与下一步

**已测量：** 历史冻结输入的论断定位、引用定位、支持标签、模块与助手的分歧；本次已按逐条结果复算主计数，未改变判定。后续机制回归的计数来自历史记录，本次未重跑。

**间接推断：** 独立正文抽取可以减少对写作者自报清单的依赖，编号回读可以约束证据出处，时间、统计分母和范围检查可能改善细微误放行。没有受控因果实验支持具体提升百分比。
