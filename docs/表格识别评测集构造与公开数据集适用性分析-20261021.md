# 表格识别评测集构造与公开数据集适用性分析

分析日期：2026-10-21，Asia/Singapore。评估对象：网页正文中的表格识别、表头保留、按行分块及最终入库覆盖。性质：公开资料调研、当前代码静态核查与评测协议设计。**本次没有构造完成标注集，也没有运行新的识别率评测，所有建议样本数均为计划数。**

## 结论

公开数据可以复用，但需要按输入形态选择。当前项目优先采用 WebMainBench 的冻结网页和参考正文，补充 WikiTableQuestions 的原始页面与表格 HTML，再加入人工标注的中文业务页面及机制样例。PubTables-1M、PubTabNet 更适合独立的 PDF／图片表格轨道，不能直接把它们的视觉检测成绩当成本项目 Markdown 分块成绩。

识别、结构、分块和入库应分别计分。特别是复杂表格超预算时，当前逻辑会使整篇网页没有 chunk，虽然原文仍保存；只统计“发现过表格”会漏掉这一使用损失。

## 公开数据集逐类适用性

| 数据集及一手资料 | 官方提供内容 | 本项目适用方式 | 局限 |
| --- | --- | --- | --- |
| [WebMainBench 官方仓库](https://github.com/opendatalab/WebMainBench)、[数据卡](https://huggingface.co/datasets/opendatalab/WebMainBench) | 网页 HTML、正文参考；545 样本子集有人工校准的 `groundtruth_content`，包含表格文本和结构评测协议 | 最适合 HTML 到正文、再到表格 chunk 的真实网页轨道；已有本地冻结输入可直接复用 | 不是逐张表格边界／表头／分块标注集，须补标；元数据含表标签不能代替逐表金标；本仓库已用过的页面只能作为已见回归数据 |
| [WikiTableQuestions 官方仓库](https://github.com/ppasupat/WikiTableQuestions) | 独立表格 HTML、CSV／TSV、完整原始网页，以及被选表格的索引等元数据 | 补充真实网页表格和列头；保留原始 HTML 中可表达的结构，构造冻结的正文识别样本 | 原任务是问答；被选中的表不是整页所有表的穷尽标注。测整页时必须补标其他目标表，或只在明确裁剪的目标片段内评分；CSV 首行被当作列头，不能据此验证全部原始复杂表头 |
| [PubTables-1M 官方仓库](https://github.com/microsoft/table-transformer) | 575,305 张含表页面，947,642 张标注表；行、列、单元格、列头等位置与文本，包含 PDF／图像坐标 | 后续 PDF／图片表格检测、结构和表头识别轨道，可采用 AP／AR、GriTS 等对应任务指标 | 与当前字符串边界识别不是同一输入任务；从坐标重建 HTML 的适配层也必须单独核验 |
| [PubTabNet 官方仓库](https://github.com/ibm-aur-nlp/PubTabNet) | 超过 568k 张表格图片及对应 HTML 表示，提供 TEDS 实现和数据入口 | 图片转表格的结构识别；也可把标注结构改造成独立的复杂结构机制样例 | 表格图片裁剪本身不能衡量整页定位、导航误报或 chunk 入库；从其标注构造 HTML／Markdown 后属于派生测试，不是官方原任务成绩 |

以上“适合本项目”的判断是基于任务输入与标注形态的分析，并非四个数据集上的实测效果排名。无需为了当前任务下载完整的百万级视觉数据。

## 三层评测，避免把不同错误混成一个识别率

| 轨道 | 固定输入与调用范围 | 回答的问题 | 主要输出 |
| --- | --- | --- | --- |
| A：边界识别诊断 | 冻结的中间正文（Markdown／内嵌 HTML）；独立记录打包之前的识别事件，不受 chunk 预算影响 | 已存在于正文的表格是否找到，起止位置是否正确 | 每表位置、类型、表头位置、解析异常；表级 Precision／Recall／F1、边界精确匹配率 |
| B：完整网页链路 | 冻结 HTML → 生产正文提取 → 真实预算分块 | 原网页中的目标表格最终是否有可用 chunk | 提取遗漏、结构损坏、解析异常、预算拒绝分开归因；端到端表格覆盖和数据行覆盖 |
| C：持久化入库 | 在隔离的临时数据库中调用实际 `SessionEvidenceStore.ingest()`，随后读取文档和 chunk | 原文与 chunk 是否存储，单表失败是否波及普通段落 | 原文保存率、网页零 chunk 率、普通正文保留率、错误记录完整性 |

轨道 A 需要独立的评测观测入口／只读诊断，不能把增大预算后的 `chunk_document()` 成功率当成无预算检测率。本次未实现该入口。轨道 C 可使用测试会话和隔离数据库；无需调用 embedding API 即可验证存储状态。

先固定离线 HTML，不重新访问原 URL。若另测在线可达率、浏览器渲染和 OCR，单列轨道与分母。WebMainBench 输入中的 `cc-select` 等标注信息必须移除，金标只交给评分器。

## 第一版样本构造建议

计划先建立 **300 个文档／片段样本：200 个真实样本和 100 个机制样本**。一页可以包含多张表，表数量在完成标注后另行统计。

| 来源 | 计划数 | 建议组成 |
| --- | ---: | --- |
| WebMainBench 冻结页面 | 100 | 人工确认约 50 个有目标表格页面、50 个无目标表格页面；按可获得的语言和难度分层，不足时记录缺额，不按预测好坏替换样本 |
| WikiTableQuestions | 50 | 独立原始页面／目标片段；同一个页面及其多题只计为一个来源组；整页穷尽标注或明确裁剪范围 |
| 新采集的中文业务公开页面 | 50 | 计划 30 个有表、20 个无表，覆盖统计公告、行业数据、公司公告与产品参数等；冻结 HTML、URL、日期和哈希 |
| 人工机制样例 | 100 | 下表 10 类各 10 个；变体共享来源组，明确标记为合成数据 |

机制样例包括：标准单层表头、无表头、多个表头层级、合并单元格与空值、表题和单位注释、相邻多表、普通含管道符文本、围栏代码中的表格示例、需要按行切分的长普通表、超预算复杂表与前后普通正文混排。还应在这些组中交叉加入中文／英文、转义 `\|`、行内代码、CRLF、无末尾管道、纯文字数据行等变体。边界损坏输入的金标为显式解析失败或可恢复状态，不能随意充当正常表格成功样本。

上述配额用于诊断，不能直接估计线上真实分布的成功率。先分别报告真实样本、合成样本和各类别指标。需要线上总体估计时，另用连续采样的业务流量，并按实际分布汇总。

已反复用于本项目开发的 WebMainBench 页面只能标记为已见回归。其余新样本按域名／页面模板／源表分组划分开发与测试；同表的中英文改写、长短变体、不同预算运行不能跨组。真正的最终泛化验收应额外留出未参与调参的新域名页面，冻结后只运行最终方案。不能把既有 545 页重新随机划分后称为未见测试。

## 标注规范

每个样本保存：`sample_id`、来源数据集及版本、`source_group_id`、URL、冻结输入路径与哈希、语言、是否合成、用途／划分、目标表格列表、明确排除的代码／布局／导航区域、标注与复核记录。

每张表保存：`gold_table_id`、正文内的表体起止偏移 `[start,end)`、表题／表头／分隔行／正文行／注释各自的 spans、行列坐标、单元格原始文本、`rowspan/colspan`（原输入存在时）、表头层级与每个数据格所属表头路径、单位及来源。表格边界主指标只包含表体；表题和注释另评分，避免空白与注释约定改变检测成绩。

目标按任务语义确定：保留有信息价值的统计表、参数表、实体属性表；导航布局、围栏代码演示和普通含 `|` 的散文为负例。单格表、键值记录等边界类别应显式标记，主指标和分层指标分别报告，不得自动按“至少 2×2”删除所有特殊表格。

至少由两名标注者独立标注试标集和最终测试集，再裁决分歧；记录边界一致率和表头分歧。公开原标注可以作为初稿；**不能运行当前生产表格识别器来生成它自己的标准答案**。LLM 可辅助起草，但须人工对照原始结构复核。对纯 Markdown 无法确定的合并关系标记未知，并另外保存原 HTML 结构，不能把猜测当金标。

## 核心指标及匹配规则

本次以下指标均为**尚未测量**。

1. **表级 Precision／Recall／F1**：`P=TP/(TP+FP)`，`R=TP/(TP+FN)`，`F1=2PR/(P+R)`。多表页必须一对一匹配；一张表切成十块仍按一张表计。重复预测是额外预测，漏表是 FN。主报跨样本微平均及分类分层值。
2. **边界质量（轨道 A）**：在同一冻结正文内，按表体字符区间 IoU 做最大权重一对一匹配，主阈值建议 0.8，0.5 为补充诊断；阈值先在开发集冻结。另报边界完全一致率以及表体字符覆盖的 Precision／Recall，区分少量偏移与吞并邻文。IoU 阈值为本项目建议协议，不是官方通用标准。
3. **跨表示表格匹配（轨道 B）**：原 HTML 和预测正文的字符偏移不可直接比。使用独立解析并归一化的单元格文本及结构，一对一匹配；可预注册词元 F1≥0.5 为候选阈值，重复内容与近似表格人工复核并做阈值敏感性分析。检测到同一表不等于单元格完整。不能把目前评分脚本中宽松的 0.1 诊断匹配阈值直接拿来宣称严格检测成功。
4. **表头与结构**：表头范围 Precision／Recall／F1、表头层级与数据格所属表头路径正确率、单元格文本及坐标匹配、适用时 TEDS／GriTS。结构指标不替代检测指标，无法还原结构必须计入覆盖缺口，不只报成功表格上的均值。
5. **chunk 表头保留**：有明确表头且已生成 chunk 的适用块中，完整带入正确表头的块占比；同时报告分母、未生成 chunk 的表格数量和端到端覆盖，防止“拒绝全部表格但表头保留率很好”的幸存者偏差。无表头表另报虚构表头率。
6. **数据行覆盖**：每张表成功入库的不同原始数据行数量／金标数据行数量，再汇总微平均；重复注入表头和重复行不增加分子。另报意外重复行、缺行、跨表混合和单元格被截断情况。
7. **入库与故障影响**：原文保存率、具有目标表格的页面中零 chunk 的比例、超预算复杂表所在页面普通正文的保留率、错误类型与原因记录完整性；原文保存率与可检索 chunk 覆盖分开报告。
8. **负例表现**：无目标表格页面误报率，以及代码示例、导航布局、管道散文等负例的 FP 数。纯负样本不人为赋“表格 Recall=100%”；无预测且无金标的表级 P／R 记 N/A，并继续计入负例误报统计。

chunk 重组时先按同一文档的表身份归组，再用原始行 spans 的并集计算覆盖；不能简单取最小／最大字符偏移，因为每块重复表头和注释会让范围看似完整。以网页为聚类单位做 bootstrap 置信区间；同源预算变体不当作独立样本。结构超时或无法评分须列出数量和原因，不得无说明剔除。

已有 `backend/eval/scripts/评估公开网页读取质量.py` 包含表格文本、关系和树编辑诊断，可复用部分评分逻辑，但还需补充人工边界金标、表级精确率、负例、分块和入库观测。其提取保留指标不能替代这些新增指标。

## 失败样例与归因计划

以下为**待构造／待运行的样例设计**，不是本次运行结果：

| 样例 | 可能暴露的问题 | 计分与归因 |
| --- | --- | --- |
| 正文前后各有普通段落，中间插入超预算的合并单元格长表 | 边界识别成功，但整篇网页分块中止 | 轨道 A 可为识别 TP；轨道 B／C 的该表未形成可用证据，普通段落丢失另计；记录预算拒绝 |
| 无分隔线的两行数值管道表 | 无表头表漏识别，或首行被误当表头 | 计表格 FN、首行缺失或表头误判 |
| 两张紧邻的相似表，年份和数值大量重复 | 合并成一张表，或跨表匹配错位 | 一对一匹配；禁止同一预测同时覆盖两张金标表而计两个 TP |
| 围栏代码中的 Markdown 表格 | 示例被误当实际数据表 | 负例 FP，不能算成表格召回收益 |
| 表头、单位说明和脚注在分片后被丢弃 | 数字仍在，但含义不完整 | 检测可成功，表头／注释保留和数据关联失败 |
| HTML 有结构表，但正文变成散文或内嵌 HTML 未被分块器识别 | 上游抽取丢结构或下游不支持该表示 | 先确认中间正文，再分别标记提取遗漏、表示差异与解析未识别 |

当前代码可静态确定：`pack_structured()` 对要求整表保留且超预算的表抛 `ValueError`；`chunk_document()` 不返回部分结果；`SessionEvidenceStore.ingest()` 捕获这一异常、保存原文与 `rag_chunk_error`，该网页不生成 chunk。此为代码路径分析，没有新的样本级影响率或线上事故频率。

## 局限、证据边界与下一步

- **已测量**：本次没有新增效果测量；没有新的识别率、结构分、入库成功率或置信区间。
- **已核查**：公开数据集一手说明、仓库现有输入路径、当前识别／分块／存储代码以及默认预算配置；输入指纹见机器可读记录。
- **间接推断**：WebMainBench 对网页链路最贴近，WikiTableQuestions 可补充真实表格；超预算异常可能造成检测成功但检索不可用的差异。实际频率尚未知。
- **尚未评估**：300 样本的可获得性和分布、双人标注一致性、逐类 Precision／Recall、真实 tokenizer 下预算影响、全链路入库覆盖及任何线上总体收益。

下一步先试标 30 个不同结构样本，确定目标表格口径与匹配阈值，再冻结 300 样本清单、补齐独立金标并实现三轨道运行器。先跑 1024 token 主配置，再做预算敏感性分析；真实、合成、已见回归和新留出样本分别汇总。每次运行另建中文结果目录和报告，保留逐表匹配、异常和 chunk 定位。实现若需改变生产异常策略，应另行明确需求，不能在评分器里偷偷跳过失败表格或恢复旧处理路径。
