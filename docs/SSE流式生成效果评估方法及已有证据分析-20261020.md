# SSE流式生成效果评估方法及已有证据分析

- 分析日期：2026-10-20，Asia/Singapore。
- 评估对象：深度研究的 POST SSE、事件账本补齐、首次发起及恢复时的报告显示、最终交付一致性。
- 数据与配置口径：解释评估方法，读取2026-10-08历史机器结果，参考2026-10-12机制分析，并有限核对当前工作区源码。未启动服务或浏览器，未调用模型或搜索，未执行新评测，未修改业务代码。
- 本次分析依据：[分析依据及历史指标摘录.json](../backend/eval/data/SSE流式生成评估方法分析-20261020/分析依据及历史指标摘录.json)。包含历史聚合字段摘录、所用本地文件SHA-256、当前源码片段及外部规范来源。
- 工作区存在大量既有未提交修改，历史结果不代表今天版本；本次新增独立报告，不覆盖原始评测。

## 结论与证据边界

SSE效果应从用户能否及时看到有用内容、正文能否持续更新、异常后是否完整恢复、最终交付是否一致四个方面评估。报告事实准确性、引用质量、任务完成度属于内容质量，另外评估；SSE负责承载和展示生成结果，本身不能证明内容正确。

本项目优先关注：**正文首次可见时间、章节到达后的显示延迟、完成前正文可见率、事件缺失、过程章节重复、故障恢复、终态交付一致性**。仅确认HTTP成功、收到事件或最终报告存在，都不足以证明流式体验有效。

| 证据等级 | 本次范围 |
| --- | --- |
| 历史已测量 | 2026-10-08受控Chrome、历史事件回放及确定性Agent图执行的原始结果；本次只摘录，不新增运行样本 |
| 当前源码观察 | 恢复投影仍对`section_content`追加字符串；共享读取器仍按`data:`行解析JSON；HTTP账本接口每页上限2000。相关源码片段与哈希已保存 |
| 间接推断 | 上述源码结构使章节重放、协议事件块和分页缺口成为优先测试对象；不能据静态代码认定今天浏览器必然出现全部历史问题 |
| 尚未评估 | 今天版本端到端表现、真实模型生成延迟、内容质量、公网与生产代理、并发性能、优化收益及生产SLA |

## 指标及判定口径

| 维度 | 核心指标与计算方法 | 判定重点 |
| --- | --- | --- |
| 初始反馈 | 操作开始到首个有业务意义的进度DOM可见；另记请求到首个完整SSE事件 | 心跳、HTTP头、空文本不能冒充业务反馈或正文 |
| 正文首显 | 操作开始到第一段有效正文DOM可见，按运行统计P50/P95 | 明确测正文还是进度；深度研究需要规划和检索，不能直接套聊天首token口径 |
| 生成与显示分段 | 首章生成、事件提交、完整事件接收、正文DOM可见分别打点；显示延迟为正文可见减对应事件接收 | 生成慢、事件提交慢、到达慢、页面更新慢分别定位 |
| 渐进显示 | 完成前正文可见率＝完成前已有有效正文的成功运行数／具备提前正文事件的成功运行数；另列全部运行中的成功/失败及可评估数 | 还应检查后续章节是否在对应事件到达后及时显示，不能只提前显示一段就算全程通过 |
| 连续性 | 相邻有效正文更新间隔、每章到达至显示延迟、超过约定等待窗口的次数 | 分阶段统计；整章事件有正常生成空窗，不能把每个无正文间隔都叫网络卡顿；心跳不算正文更新 |
| 事件完整性 | 固定核对上界后的已提交序号集合E与同一运行、同一页面投影代次成功应用集合A比较；缺失率＝\|E−A\|／\|E\| | 单独报告总账本条数、未完成运行及完成事件缺失；前缀100%覆盖不代表任务完成 |
| 传输与业务去重 | 同一run/seq重复应用次数；同一报告版本/章节在过程正文中重复出现次数 | 新seq可能仍代表同一章节的重跑或复用；合法修订替换章节，不应追加成第二份 |
| 故障恢复 | 在规定观测窗内完整恢复的运行数／注入故障运行数；另报恢复网络到首个增量事件、到完成的P50/P95 | 超时留在分母；自动恢复、刷新后手动继续分开；补齐耗时与节点重算耗时分开 |
| 终态一致 | 成功运行的账本终态、完成事件、服务端报告、浏览器报告及有效终态检查点正文一致，交付记录唯一 | 在业务持久化层要求唯一终态交付；历史重放可合法重复接收完成事件，但页面不能产生额外报告 |
| 性能及成本 | 并发连接数、事件/字节吞吐、队列积压、CPU/内存、断线重连量及恢复额外模型调用/token | 同样负载下比较；不能把模型生成吞吐直接归因于SSE |

正文首显建议以可见DOM为主要自动化口径，并保留代表截图/浏览器trace。DOM提交和`requestAnimationFrame`不能冒充精确像素呈现时间。需要像素级结论时须另外识别浏览器合成帧。

浏览器内耗时用单调时钟；刷新前后不能直接相减两个页面的`performance.now()`。服务端发送到客户端接收的跨机时间需要时钟校准及误差范围；未校准时分别报告各端局部耗时。提交到接收包含数据库后处理、序列化、代理缓冲和浏览器解析，不应命名为纯网络延迟。

本项目以整章`section_content`为重要正文载体。若没有模型token级埋点，不应把首章DOM时间叫模型TTFT，或从SSE帧数换算token/s。

## 如何构建测试及逐类判定

先准备固定事件夹具：每条包含run、seq、事件类型、章节ID、章节版本及唯一正文标记，保留事件输入、预期中间状态和最终正文。借助正式路由、真实数据库及真实页面测量，确定性Agent替代真实模型和搜索，可隔离传输与页面问题并减少外部费用。真实模型端到端另设一组。

| 场景 | 操作 | 必须核对的结果 |
| --- | --- | --- |
| 正常首次发起 | 从聊天输入进入正式研究入口，按固定节奏逐章发送 | 首章在完成前可见；后续章节持续显示；不是仅测试恢复入口 |
| 弱网及大报告 | 固定延迟/带宽，增加章节及事件载荷 | 到达/显示延迟、积压、正文更新连续性、内存及最终一致；保留网络配置 |
| 同seq重复 | 重复发送同一run/seq事件 | 同一投影代次只应用一次，无重复正文 |
| 同章节新seq | 新seq重放同章节，包含`restored`及合法修订 | 重放不叠加正文，修订更新正确章节及版本 |
| 序号缺口 | 丢一个/多个事件、超过2000条缺口、最后完成事件缺失 | HTTP分页补齐到固定上界；处理失败不提前提交应用游标；末尾无新帧也能恢复终态 |
| 真断线及刷新 | 首章显示后切断socket，再恢复网络；单独测试真实刷新 | 记录真实网络错误、租约处理及补齐；过程无重复，终态唯一；显式继续动作单列 |
| 静默及异常 | 长时间无业务事件、异常EOF、持续409、补齐请求失败、事件应用失败 | 有明确等待/错误状态，按产品恢复预算处理；应用失败不跳过事件；主动暂停不被误恢复 |
| 协议与分片 | UTF-8跨块、CR/LF/CRLF、多行data、注释心跳、多个事件粘在一个网络块、截断尾帧 | 先还原SSE事件再解析业务JSON；保留输入和明确预期，不把网络块当事件 |
| 实际部署与并发 | 走实际反向代理/TLS/HTTP协议，分级增加并发，测试慢客户端及双页面 | 正确性指标不退化，延迟/内存/重连压力可解释；订阅中断与任务执行的关系符合产品要求 |

协议用例依据[WHATWG事件流解析规范](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)：UTF-8、CR/LF/CRLF换行、多行data聚合及空行事件边界。项目当前使用自定义POST流和`after_seq`；原生EventSource的自动重连与`Last-Event-ID`行为不能直接算作本项目已具备的能力。协议格式与JSON业务字段分别断言。本次未变更旧格式约定或新增兼容层。

优先复用已有入口：

- [浏览器测量脚本](../frontend/scripts/SSE浏览器测量.cjs)：真实页面操作、首显、网络故障与正文检查。
- [隔离评测服务](../backend/eval/scripts/SSE浏览器隔离评测服务.py)：回放及确定性图执行。
- [指标汇总脚本](../backend/eval/scripts/汇总SSE浏览器评测.py)：事件缺失、重复及交付核对。
- [历史评测配置](../backend/eval/data/SSE浏览器真实链路评测-20261008-194700/评测配置.json)：旧测试的环境说明，仅作为复现参考。

每次运行使用新的中文结果目录，保存源码快照/哈希、配置、发送计划、事件账本、浏览器日志、预期投影、截图/trace及逐案结果。结果不只写一个总分，而应保留按场景、入口、运行和故障类型的明细。

## 比较优化前后效果的实验设计

1. **先做机制回归**：固定五题夹具、固定事件内容/顺序/发送计划及故障位置，分别测试首跑与恢复。每种配置重复若干次，报告样本量、全部失败及超时。这里比较传输、投影和恢复，不引入随机模型输出差异。
2. **再测实际部署性能**：同一机器及代理配置、同样并发、载荷、事件频率和观测窗，比较正文首显、显示延迟、资源占用及恢复。按运行报告P50/P95；事件级延迟另列，不能把同一运行的数千事件当成数千次独立任务。
3. **最后测真实生成体验**：固定问题集、模型、检索及生成配置，记录生成/提交/接收/显示分段耗时及额外调用成本。内容质量单独评审。比较一次性与流式显示时，可先回放同一生成轨迹隔离显示收益，再做真实运行确认。

首显改善可写为`(基线首显−新版首显)/基线首显`，前提是相同入口、场景、起止口径及可比样本；同时列出失败率，防止通过排除慢失败样本制造改善。无需强求SSE使总生成时间下降，首显提前、过程可见、故障后可恢复本身就是需要验证的收益。

正确性验收可要求本次全部夹具的永久事件缺失为0、重复应用为0、非法章节叠加为0、最终交付一致。失败/未完成用例单列，不能通过缩小E集合或只选成功样本达到门槛。性能阈值依据产品等待预算和部署实测确定；本报告不虚构统一毫秒SLA。

## 局限性与下一步建议

本次没有运行新测试，没有估计今天版本的任何通过率或延迟收益。历史数据是小样本本机机制证据，不覆盖真实模型、生产代理和并发；不同复评配置不能合并成生产稳定性结论。当前有限源码核对也不能代替完整端到端复测。

下一轮先复测首次发起的正文渐进显示及恢复时的章节幂等，再补充大缺口、完成事件缺失、真实断线、长静默和补齐失败。正确性通过后，再在实际部署链路采集性能并加入真实模型分段耗时。最终报告至少同时给出正文首显、完成前正文可见率、缺失/重复、故障恢复及最终一致性，避免用一个“成功率”遮盖体验缺陷。
