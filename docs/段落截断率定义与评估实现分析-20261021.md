## 2. 建议指标定义

以下是本项目建议采用的明确口径，不宣称为统一行业标准。

对固定参考正文的每个普通段落分类：

| 状态 | 定义 | 统计去向 |
| --- | --- | --- |
| 完整 | 段落内容全部保留，允许事先约定的纯格式变化 | 完整段落 |
| 部分保留 | 部分实质内容保留，部分实质内容丢失 | 部分缺失段落；确认预算切断原因后计入预算截断 |
| 整段遗漏 | 全部实质内容未保留 | 遗漏段落，不混入段落截断分子 |
| 无法判定 | 对齐不可靠、来源版本不一致等 | 单列未知，不按完整或遗漏处理 |

对于直接前缀裁剪的预算实验，段落截断率 = 被切断的段落数 / 裁剪前普通段落总数。完整段落保留率、整段遗漏率使用相同分母。无普通段落时记为 null，不记为 0。

配套报告：

- 页面截断率：发生预算内容丢失的页面数 / 有有效预算前正文且完成测量的页面数。
- 段内截断页面占比：至少有一段被切断的页面数 / 同一批完成测量的页面数。
- 输出所涉及段落中的截断比例：截断段落数 /（完整段落数 + 截断段落数）；无输出时为 null。
- 完整段落保留率、整段遗漏率、正文字符或 token 召回率，以及无法判定数、读取失败数。

全量汇总优先使用段落数加总后的微平均，同时按页面长度和页面类型分层；如提供页面等权宏平均，必须另行标明。未知段落存在时，T/N 只是确认截断比例，应同时报告未知比例，必要时给出 T/N 到 (T+U)/N 的范围。

示例（人为构造，未执行）：参考有 10 段，前 6 段完整，第 7 段保留一半，后 3 段未返回，则段落截断率为 10%，整段遗漏率为 30%，完整段落保留率为 60%；输出所涉及段落中的截断比例为 1/7。若在第 6 段结束处裁剪，段落截断率为 0%，但仍遗漏 40% 的段落，因此不能只优化一个指标。

## 3. 预算截断评估实现

1. 冻结同一页面输入和抽取版本，执行一次抽取。截取预算函数的直接输入作为 `before`，直接输出作为 `after`。不要重新抓取网页获得所谓完整版；不要把门禁拒绝后的空输出当作预算截断。
2. 解析 `before`，保留普通段落的字符区间 `[start, end)`，区间不含段首段尾空白。优先复用抽取时的块边界；Markdown 需使用有源位置映射的块解析器，单次换行不能自动视为新段。标题、列表项、代码块、表格分别分类，不能靠空行正则把表格切成普通段落。
3. 对当前保留前缀的预算函数，先验证 `before.startswith(after)`。使用实际返回长度 `cut=len(after)`，不能直接使用配置上限，表格保护可能使输出超出该上限。前缀关系不成立时，记录为需要对齐或阶段混杂，不能继续套用切点算法。
4. 对每个普通段落按下列规则判定；这里只适用于前缀截取，不适用于摘要、重排、头尾拼接或内部删除。

```python
def classify_paragraph(start, end, cut):
    if end <= cut:
        return "完整"
    if start >= cut:
        return "整段遗漏"
    return "截断"  # start < cut < end
```

5. 保留每个段落的状态、起止偏移、截断位置、丢失字符数和边界上下文，汇总配套指标。若存在多个预算环节，分别测量每个环节，并通过原段落 ID 计算端到端结果，避免重复计数。
6. 在既有评估脚本中增加逐段测量，在汇总脚本中增加分子、分母和分层结果；这只是建议，本次未修改这两个脚本。

## 4. 抽取质量评估需要独立参考

上述预算前后比较只能发现预算引入的损失。抽取器一开始就漏掉的半段，在预算前文本里已经不存在，无法通过这种比较发现。

评估端到端段落完整性，应准备人工确认的正文段落及来源位置，依次比较参考正文→抽取全文→预算后正文→最终接纳输出。采用允许一对多、多对一的顺序文本对齐，保留重复段落位置。空白与排版可以规范化，但不得删除数字、单位、否定词、条件或标点来掩盖实际丢失。

抽取阶段的中间文字缺失建议标为“段落部分缺失”，只有证据支持时才归因为“截断”。完整输出仅因重新分段，不应判为内容截断。模糊匹配阈值需用人工标注校准，不默认使用任意相似度阈值；歧义交由人工复核，并单列无法判定。模型可辅助复核，不能仅凭“读起来不完整”作为确定标签。

## 5. 逐类检查与失败样例

以下均为待实施的构造用例，不是本次已测结果。

| 用例 | 预期分类或风险 |
| --- | --- |
| 短页未超预算 | 所有普通段落完整 |
| 切点落在段落间空白 | 无段落截断，后续段落整段遗漏 |
| 切点落在段落中间 | 当前段截断，后续段落整段遗漏 |
| 切点在同一段某句句号之后 | 仍可能截断该段后续句子，不能用末尾句号判断完整性 |
| “增长 20%，但仅适用于海外业务。”只保留“增长 20%” | 条件丢失；截断可能改变含义，需展示缺失文本 |
| 表格跨越预算上限 | 使用实际切点；表格另评，不纳入普通段落分母 |
| 同一段被换行或拆成两块但内容齐全 | 内容完整，不因排版判截断 |
| 重复段落、乱码、仅空白变化 | 需要位置与规范化策略，不能只用子串匹配或长度差 |
| 动态页只取得部分 DOM | 属于获取/抽取完整性问题，预算评估无法自行发现 |
| 读取失败或质量门禁拒绝 | 单列失败/拒绝，不能记录为零截断的成功页面 |

## 7. 结论与下一步

当前已有页面长度变化信号，但没有证据表明已实现段落级截断统计。建议先在预算函数前后增加直接阶段快照和段落区间统计，以低成本量化预算造成的段内切断；随后用人工段落参考评估抽取阶段的部分缺失。两类结果分别报告，始终配合整段遗漏率、完整段落保留率和召回率，避免把大量丢弃整段但没有半段的输出判为高质量。
