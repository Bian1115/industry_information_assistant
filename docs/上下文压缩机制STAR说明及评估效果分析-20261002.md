# 上下文压缩机制STAR说明及评估效果分析

分析日期：2026-10-02（Asia/Singapore）。评估对象：项目 DeepScout 长链路研究上下文管理，以及已有五题摘要、引用和生命周期评估。

本次工作为源码核对、已有评估复核和指标派生，未重新调用模型、运行研究任务或执行机制测试。下文测试与模型结果均引用历史运行，不能视为本次新测结果。

## STAR表述

**S（背景）**：项目需要连续执行搜索、网页读取、分析和追问。工具正文及其在历史提示词中的副本不断累积，历史输入可达到数十万 token，超过本轮配置的 32768 token 窗口。直接裁剪旧历史容易丢掉用户约束、关键数字、证据缺口和后续回读资源。

**T（任务）**：设计一套能在模型输入预算内持续工作的上下文压缩机制，同时保留当前任务要求、已有研究进度和原文追溯入口，并分别验证压缩程度、摘要信息保留和引用语义支持。

**A（行动）**：采用“原始事件留存、重复正文引用化、长工具结果外置、按需分块摘要、版本与游标管理”的分层方案。使用实际 tokenizer 计数，为模型输出和安全余量预留空间；在压缩历史前固定最新任务契约和当前请求。旧输入中的已保存正文替换为来源引用，达到软阈值后外置全部已完成的超长工具记录，保留预览和回读编号。处理后仍达到摘要阈值，才将已完成的连续调用按完整请求预算组批，生成包含任务目标、研究结论与限制、资源清单、下一步的摘要，并与旧摘要合并。摘要读取处理后的视图，避免重新吞入已外置正文。通过格式和长度检查后提交新版本及覆盖游标；后续复用摘要与未覆盖历史，原文继续保存，可按权限和哈希回读。另提供独立引用审计路径，由模型选择消息和证据单元编号，程序恢复真实原句，再进行 NLI 判定。

**R（结果）**：在 2026-10-02 的五题真实生命周期回放中，最终单次输入由 3.52万–43.90万 token 降至 8366–16219 token，整体减少 75.7%–96.8%，均低于 25744 token 预算。4题生成并提交摘要，1题仅外置后就低于阈值，无需摘要；同一输入再次组装均无新增 API 请求。独立摘要质量实验中，助手诊断性复核的 51 项检查点有 38 项完整保留（74.5%），重要检查点完整保留为 31/38（81.6%）。135 条论断全部定位到摘要文本，但自动 NLI 支持仅 75/135（55.6%），且存在误拒绝和执行错误。因此已证明输入预算控制和摘要复用可行，内容保真与端到端研究收益仍需完善和对照验证。

这段表述适合面试使用。“我设计并实现”等个人归属措辞，应以实际负责范围为准；仓库本身不能证明个人贡献归属。

## 实现与数据配置口径

1. **预算与指令保护**：`backend/app/service/context_policy.py` 和 `agent_context.py` 按 `min(max_input, context_window - output_tokens - safety_tokens)` 计算预算。本轮 DeepScout 为 `32768 - 6000 - 1024 = 25744`；软阈值17000、摘要阈值24456。最新任务契约位于系统包装，当前请求独立保留；历史内容标记为资料。默认回放对象是 DeepScout，不宜表述为五个智能体都采用相同历史回放。
2. **事件留存与隔离**：`agent_history.py` 按 run、agent、context_key 隔离历史与来源读取。记录保留序号、调用编号和内容哈希；摘要存储使用期望版本及覆盖游标条件更新，防止旧结果覆盖新版本。原始事件继续留存，外置主要改变模型回放视图。
3. **材料引用化与外置**：`input_history_view.py` 只对满足栏目、逐字匹配和最小 token 条件的旧输入正文进行替换，不会无条件删除所有长文本。`agent_context.py` 达软阈值后外置全部已结束超长工具记录，包括最新已结束轮次；当前默认长记录阈值800 token、预览400字符。在途调用保持完整。
4. **分块、合并与追溯**：`summary_history_view.py` 保存处理后派生来源快照与原来源映射。`summary_hierarchy.py` 按完整请求预算组批，单条放不下才分片，保留连续字符区间；必要时只允许一次额外分批合并，仍超限则报错。`summary_lifecycle.py` 使用独立摘要模型，正文输出上限3000 token，四栏目为 SESSION INTENT、SUMMARY、ARTIFACTS、NEXT STEPS。覆盖范围只包含安全边界内已结束的连续调用；当前调用和在途调用形成屏障。提交成功才推进游标，最终输入仍超限会显式报错。
5. **生成和审计分离**：当前默认生命周期先提交格式/大小合格的正文，内容状态为 unverified，再按开关执行审计。生成和审计分别计时。已有本轮生命周期评估中 Claimify、NLI 审计关闭，不能说生产摘要均经语义核验才保存。策略名 `claimify-v1` 也不代表 Claimify 实际启用。
6. **独立引用实验**：2026-10-02 的135条论断走“论断及消息编号→摘要位置绑定→相关证据单元选择→程序恢复原文→NLI”路径，Claimify四阶段调用为0。自动评估使用 qwen3-max；参考检查点和内容评审使用 qwen-plus；本地 NLI 为固定 revision 的 mDeBERTa，最大512 token，支持阈值0.85、矛盾阈值0.5，聚合规则为 any_support_no_contradiction_v1。阈值未经本数据人工标注校准。

## 完整研究运行的局限与成本

旧配置的2026-10-01夜间研究运行启动4题：35写作JSON失败、31补搜耗尽累计token、46研究阶段超时、16用户停止，49未启动。没有最终交付报告，31有首轮草稿。4题提交24次摘要、summary_error为0，但已记录总token为1573253，摘要占1022097（64.97%）。这是包含输入与输出的usage占比，不是费用占比。

该冻结运行仍使用有限早期外置，区别于随后全量外置的当前实现，不能将其直接当作当前版本端到端结果，也不能声称新版本已消除这些失败。它说明“摘要能提交”和“最终报告能完成”必须分开评价。

独立摘要、核验、评审及生命周期评估合计178次实际API请求，prompt 794602、completion 85219 token；未冻结价格，不报告金额，也不将其当作五次正常线上研究的成本。

## 结论和下一步

**已测量**：已有五题生命周期回放的输入压缩、预算达标、摘要提交和相同输入复用；独立摘要的文本定位、自动NLI标签、诊断性内容保留；旧配置研究失败及usage开销。

**间接推断**：先外置再判断摘要有助于减少不必要摘要；仅引用定位无法防止遗漏；自动NLI失败不都等于摘要事实错误；高摘要开销可能挤占研究与返工资源。这些是有样例支撑的工程判断，尚无受控消融证明普遍收益。

**尚未评估**：当前版本相同预算下无压缩、仅外置、外置加摘要的最终任务质量与成功率对照；多轮摘要误差累积；原文回读后的证据闭环；人工校准的引用精确率和召回率；生产提交摘要逐条质量；外部事实真值；真实累计费用和延迟的净收益。

建议先显式保留数字、单位、条件、来源归属和证据缺口，对遗漏定向修订；区分事实、要求和计划，校准NLI阈值及矛盾聚合；冻结当前代码、模型、问题与总预算后运行三组对照，测最终报告完成、关键约束覆盖、原文回读、累计token和耗时，并保留失败与中断结果。

对外可据实说“完成了可追溯的分层上下文压缩，五题回放单次输入减少75.7%–96.8%，均满足预算”，应同时说明保真仍在优化，尚不能声称最终研究成功率或费用改善已得到验证。
