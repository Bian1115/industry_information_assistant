# Writer首尾论断编号继承实现及离线验证

评估日期：2026-10-06（Asia/Singapore）。验证开始时间：21:25:12。评估对象：Writer首尾整合的章节论断索引、证据继承和后续引用核验接口。

## 实现与配置口径

开始修改时，工作区已经存在以章节原段落 `source_quotes` 关联已有声明的继承逻辑。本次在此基础上增加明确的 `source_claim_ids` 接口。修改范围为两个业务源文件、新增13项针对性测试，并调整两个既有测试对整合提示词字段的断言。

1. 程序按大纲顺序为当前章节论断分配本次调用内的 `C1、C2…` 编号。索引只包含当前章节仍能定位到正文的论断；删除的章节、空正文、过期定位及旧首尾声明不会进入索引。
2. 模型输入包含章节正文、当前问题及要求、首尾字数预算和紧凑索引。索引只展示编号、章节编号、论断文本，不展示来源原文、文档编号或原句编号。
3. 模型为每条首尾事实声明返回 `claim`、`report_quote`、`source_claim_ids`。多个依据可同时引用；保留时间、数值、范围和限定条件，不新增事实或提高结论确定性。
4. 程序使用构造提示词时的同一份索引快照，复制对应章节声明的原文证据编号，合并去重，并保存 `source_claim_refs` 供追溯。模型额外返回的证据编号不进入继承结果。
5. 缺失/未知编号、来源论断缺少证据、已有绑定错误以及首尾正文定位错误均保留为 `binding_errors`。按配置启用的核验器继续按文档和句子编号读取原句、检查首尾新论断；继承本身不代表支持性核验通过。

为兼容已有输出，未返回编号字段的旧结果仍可使用原段落关联。明确返回空编号或错误编号时，不回退到段落匹配来绕过错误。编号仅在本次整合调用有效，不构成跨轮稳定ID。

已测量的机制结果：

- 新索引不含来源原句及其编号，不修改章节声明；索引的内部证据副本与原声明相互隔离。
- 同一段落包含多个论断时，只继承明确选择的论断证据；多章节依据保留各自证据，重复编号和相同证据去重。
- 未使用的原文材料增加时，整合提示词保持相同；首尾流程未调用全量原文证据格式化函数。
- 原句核验能够从继承编号回读原始句子。NLI返回不支持时，核验结果仍为拒绝；存在绑定错误时，即使替身NLI返回支持，也按无效引用处理。
- 原段落兼容、报告组装、事件/状态序列化、修订生命周期及引用失败处理的已有回归通过。
- 六个相关源文件与测试文件均通过AST语法检查。

## 失败输入样例

以下为预期被识别的负例，不是测试执行失败：

- `source_claim_ids: ["unknown"]`：记录未知编号，证据为空。
- `source_claim_ids: ["C1", "unknown"]`：保留C1的可追溯证据，同时记录未知编号；开启核验后不能仅凭C1通过。
- `source_claim_ids: []` 且同时提供旧 `source_quotes` 或伪造原句编号：记录缺失依据，不使用旧字段兜底。
- 已有声明定位文本不在当前章节中：不进入索引，避免用过期正文声明作为来源。
- 继承了正确编号，但NLI替身返回不支持：核验仍拒绝，验证继承没有绕过支持性检查。

## 局限性和边界

已测量：57项离线机制回归、输入材料隔离、继承和核验数据流。间接推断：通过索引选择依据可以减少重复段落输出，并使首尾证据继承更明确。

尚未评估：真实模型选择论断编号的准确率、改写时保留限定条件的效果、实际token变化、整合输入在大型报告上的容量，以及30+轮真实会话是否完成。NLI替身用来验证程序分支，不证明真实语义判断质量。

旧检查点的章节声明如果没有 `report_quote`，仅当论断文本逐字出现在当前正文中时进入新索引；无法定位的声明不会猜测绑定。是否启用实际引用核验仍遵循已有配置。本次聚焦首尾整合，整篇编辑及字数硬检查触发的缩写路径仍使用各自的既有证据输入方式。

## 结论与下一步

已实现“首尾事实 → 本次章节论断编号 → 原文证据编号”的继承，并通过离线回归。整合模型使用章节正文和紧凑论断索引即可选择已有依据，原句留给程序按编号回读核验。

后续真实运行应分别记录索引大小、整合请求输入tokens、首尾依据覆盖率、无效编号比例、继承后支持性核验结果及交付质量，才能判断容量和质量收益。
