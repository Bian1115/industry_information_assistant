# 正文引用核验接入点与消融实现说明

日期：2026-10-06，Asia/Singapore。对象：当前项目的引用核验调用位置、正文失败处理及固定中文五题消融实现。此次沿用35、31、46、16、49题；改写后仍不通过只记录失败并正常交付。

## 当前接入点

| 位置 | 调用与配置 | 行为与范围 |
|---|---|---|
| Scout初次检索、补充检索 | `agents/scout.py` 两处调用 `verify_stage_citations(state, "scout_facts")`；`scout_facts` 默认false | 核验编号事实与原文的支持性，仅审计，不改事实库。 |
| Writer合稿与Critic要求的修订 | `agents/writer.py::_synthesize_report()`；默认 `report_claims=true` | 所有修订再次合稿后核验新版本；本次通过统一 `_verify_and_repair_citations()` 增加可选删改。 |
| Writer用户编辑已有成果 | `agents/writer.py::_edit_existing_report()` | 编辑通过正文/来源范围检查后核验新版本，调用同一失败处理入口。 |
| 智能体研究内历史摘要 | `agent_context.py` → `summary_lifecycle.py` → `summary_atomic_citations.py`，或历史 `summary_citations.py` | Claimify分句/抽取、引用定位、临时补检索、NLI审计；是否执行由冻结的摘要/Claimify配置决定。当前部署Claimify默认关闭，不等于所有摘要都在核验。 |

`nli_verifier.py` 是共用的语义核验底层，不是另一个业务接入点。`quality_pipeline.evaluate_report_gate()` 只检查报告非空和来源网站范围，不能作为引用支持核验；Critic的内容审稿也是独立环节。会话层 `session_summarization.py` 的自然摘要没有自动接入该正文核验。

本次实验不修改Scout和摘要处理策略，避免混入额外因素。

## 新接入的正文策略

在 `/research/stream` 请求中增加以下对象即可冻结本次运行的策略：

```json
{
  "citation_verification": {
    "scout_facts": false,
    "report_claims": true,
    "report_failure_action": "rewrite_once"
  }
}
```

`report_failure_action` 可选 `audit`、`delete`、`rewrite_once`。新请求缺省仍为审计；删改策略要求正文核验打开，技术续跑沿用既有冻结配置。已有检查点缺少本字段时兼容为审计。

- `audit`：记录支持/矛盾/缺证据/非法引用等状态，正文保持原样。
- `delete`：删除失败论断所在的段落、列表项或表格行，同时移除该单元的全部声明。它会连带删除同段正确事实，实验单独计算这个损失。
- `rewrite_once`：每个目标单元仅改写一次，使用程序回读的原文；可以从原有证据编号选择子集，禁止新增来源和句号。模型可以主动删除无法支持的内容。再核验一次；仍失败记录 `remaining_failed_claims` 并保留改写稿，不抛异常、不循环、不自动转入删除组。

Writer新增 `report_quote`：包含论断的正文原段落/列表项/表格行，逐字复制并保留引用。程序只采用精确且唯一的定位；历史未提供该字段时尝试精确匹配claim。某个章节存在未能定位的声明时，该章节保留原样并记录定位失败，不模糊猜测删改。

核验未完成、审计哈希不对应当前报告、格式/证据校验失败或改写后核验执行失败，均保留可交付原稿并记录状态。正文删改之后同步更新章节、摘要/结论/展望、claims、引用目录、报告哈希、基础门禁及篇幅记录；新版本不能沿用旧版本通过状态。修改结论时清除旧文本的假设映射。处理失败不会升级为研究异常。

## 实验、指标及原始记录

运行入口：[运行正文引用核验消融.py](../backend/eval/scripts/运行正文引用核验消融.py)。使用同一报告、同一保存来源、同一首次核验决策构造三个组。长报告按引用对数量分批，不截断末尾论断。相同输入通过缓存复用，避免删除组额外重判未改动事实。

历史Writer只声明221条论断，五篇独立正文抽取共有511条事实。本实验固定已有独立抽取及原段落定位，检验后处理策略本身；生产Writer仍只覆盖自己的声明，不能把本实验当成生产全文核验或端到端收益。

基线及未改动事实复用已有开发集逐条支持判定；改写单元由另一个评估提示重新抽取全部外部事实再裁判，包括Writer可能漏声明的新事实。引用支持率沿用历史单源人工复核覆盖规则，不能直接平均不同分母。核验器与支持裁判同属Qwen模型家族，属于模型评估，不是人工金标。

至少同时读取：来源完整支持事实精确率、引用支持率、原已支持事实保留率、重要已支持事实保留率、全部原事实保留、事实数量、正文长度、核验残留失败、真实API usage和耗时。核验器自评分数和通过率不作为收益结论。

原始运行目录：[正文引用核验消融-20261006-170312](../backend/eval/data/正文引用核验消融-20261006-170312/)。具体逐题指标、失败样例、结论及建议在[五题消融结果及分析](五题正文引用核验消融结果及分析-20261006-170312.md)，持续写入同一运行的中文报告，历史独立评估不覆盖。此次证据子集验证修正及引用支持率口径补充保存在[补充复评口径记录.json](../backend/eval/data/正文引用核验消融-20261006-170312/补充复评口径记录.json)，修正前原稿核验、改写状态及指标亦单独保留。
