# 表格与字段记录证据切分改造及验证

评估日期：2026-10-02（Asia/Singapore）。对象：当前直接消息引用核验中的证据单元切分与NLI二次装包。用户要求短表整表保留、长表切分保留表头、字段记录保留字段名与记录边界。

## 代码改造及数据口径

新增summary_evidence_units.py，接入summary_sentence_evidence.py的编号阶段，以及summary_message_verification.py的NLI窗口阶段。普通正文继续确定性分句；选择模型继续只返回source_id/sentence_ids，不返回原句。提示词说明编号单元也可为表格或记录。当前直接引用入口及离线回放流程已使用；生产摘要生命周期未切换，没有引入RAG或Claimify调用，没有改变NLI阈值与聚合策略。

1. Markdown表格识别表头和分隔行，按完整数据行装包。若整个表连同论断可放入NLI预算则整表保留；否则每片重复实际输入中的原表头。紧邻表格的“表1/Table 1”说明和“注/Note/Markdown脚注”保留在各片。
2. 管道或逐行字段记录识别字段名、值、显式记录标签、重复起始字段和注册编号边界，空字段保留。支持字段和值同列的形式；包含原文中的注册编号/记录标识时重复保留，缺失时不虚构。注册机构开始的新记录不继承前面的无编号状态变更日期。
3. 过长记录按完整字段分组；单字段过长时只切字段值，每片重复原字段名及记录标识，优先沿句子或词边界。无空格的超长字段保留字符片段，并显式记录field_fragmented，不丢尾部。单个Markdown数据行连同表头仍超容量则明确报未完成，不任意截断单行或猜测列映射。
4. 工具JSON中的转义换行/制表符仅用于识别结构，原始消息不修改。表头与数据行分别记录source_spans。组装引用标记quote_kind=assembled_source_spans；start/end仅为覆盖范围，不能用于假装这是连续原文。程序通过各原文片段加换行重建NLI输入并验证。
5. NLI二次装包也保留表头/字段标签，以实际本地tokenizer计算“证据+论断+特殊token”长度，最大512。不再将结构化单元交给普通句子/字符窗口而丢掉表头。

复用上一轮题25两个疑难论断、同一份摘要与实际消息输入。摘要和论断不重新生成，不改变引用消息候选范围。真实qwen3-max选择单元编号，实际本地mDeBERTa核验。2次模型请求，最终两条均完成选择与NLI，无编号错误/超时；整体仍有信息不足项而标为核验未完成。

## 失败情况、局限性与结论

已测量：结构化切分的机制与边界测试、同源真实长记录的两条集成样例、实际token容量、原文片段溯源和分类变化。间接推断：记录级切分减少了把不同内容放在同一NLI窗口里的干扰，但两例不能证明总体准确率提高。

尚未评估：人工表格/记录边界标注、完整开发集、NLI校准、相关证据召回率与复合论断多证据推理。当前识别Markdown表格和常见字段记录，未实现HTML DOM、跨行合并单元格或复杂多层表头解析。未提供的表头不会从隐藏历史中补取；无法识别的格式继续作为正文处理。超长表格单行仍有明确未完成边界；长字段片段也可能缺少足够语义上下文。

改造已完成当前授权的直接引用回放范围。后续应补人工相关性和结构真值标注，区分切分错误、选证据错误及NLI分类错误，再决定是否接入RAG。
