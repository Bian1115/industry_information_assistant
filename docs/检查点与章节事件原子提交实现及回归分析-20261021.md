# 检查点与章节事件原子提交实现及回归分析

- 实施及评估日期：2026-10-21，Asia/Singapore。
- 评估对象：节点检查点及其完成事件、Writer章节任务结果及其完成事件、提交后的SSE发送与恢复重放。
- 数据与配置口径：本地Python 3.13.0及现有LangGraph/PostgreSQL依赖；模型、搜索、向量服务使用确定性夹具。新增事务测试和既有存储测试使用独立PostgreSQL schema，结束后删除；不修改业务schema或用户运行数据。
- 图协议：`single-main-v6-atomic-events`。仅当前协议允许未完成运行续跑，未增加旧格式兼容层或数据迁移。
- 原始结果目录：[检查点事件原子提交回归-20261021-01](../backend/eval/data/检查点事件原子提交回归-20261021-01/)。

## 实现结果与适用边界

已实现两类原子提交：节点完成通知随完整图检查点提交；章节正文事件及完成观察随章节task返回值提交。两类写入都复用检查点保存器的同一个psycopg连接、游标和租约事务。事件写入、执行产物写入或提交前租约校验任一失败，整个事务回滚，包括事件序号计数。

事件账本兼任事务发件箱，不新增独立发件箱表。提交成功后仅发送唤醒通知；SSE发送器重新按序读取已提交账本，合并实时进度和产物完成事件。即使提交后未推送，恢复入口仍可读取原事件编号补发。章节恢复复用已保存产物及事件，不再生成新编号的`restored`章节事件。

**最终报告交付仍是独立的业务事务。** `node_completed`表示执行节点已保存；`research_complete`表示最终报告完成业务交付。后者继续由现有`delivery.py`将报告、运行交付状态及完成事件同事务保存，并在图已结束但交付尚未完成时补偿。本次没有把聊天消息、记忆任务等业务交付副作用并入LangGraph检查点事务，也不会提前发送正式交付完成事件。

## 新增11项逐类验证

| 测试场景 | 已测量结果 |
| --- | --- |
| 检查点写入后事件INSERT失败 | 检查点、blob、事件和序号一起回滚，不发送提交通知 |
| 重复保存及后续快照再次包含同一事件 | 只保留原事件ID与seq，不重复分配序号 |
| 章节事件INSERT失败 | 章节pending write、事件与seq一起回滚；重试保存成功后同ID重复保存不追加事件 |
| 节点结果已写pending writes但完整检查点未提交 | 尚不发送节点检查点完成通知；完整检查点保存后才产生对应事件 |
| 同task提交不同结果及不同事件意图 | 拒绝为未保存候选结果追加新事件，保留原任务结果 |
| 同task保留相同事件意图但修改正文 | 仍拒绝提交，避免复用事件掩盖任务结果冲突 |
| 写入完成后、提交前租约失效 | 全部回滚，不唤醒SSE |
| 复用同一事件ID但改变事件内容 | 拒绝新快照，保留原账本及序号 |
| 无后续进度事件时完成事务 | 提交通知及时唤醒SSE；关闭消费者时取消事件泵，无残留发送回调 |
| Scout完成后后继节点失败并恢复 | Scout只执行一次，原完成事件ID与seq保持不变 |
| 第三章失败后重建Writer恢复 | 第一、二章各生成一次，第三章调用两次；最终仅三条章节正文事件，已完成章节沿用原ID/seq |

## 失败样例及修正

首次完整回归唯一错误发生在既有`test_saved_section_is_checked_and_reused_with_new_graph`：夹具用`example.com`正文替换了初始来源，但保留原夹具的其他允许域名，实际逐章检索得到空证据，Writer按已有保护抛出`InsufficientEvidenceError`。失败发生在章节模型调用前，并非事务提交阶段。

修正仅对齐该测试夹具的`allowed_domains`与实际正文域名，未放宽生产检索范围或证据保护，也未增加旧机制兼容。修正后的完整138项回归全部通过。首轮失败的机器结果和日志保留，没有覆盖或从统计中删除。

故障注入测试里的“事件写入失败”“租约失效”“后继节点失败”“第三章失败”均是预期测试输入，不代表线上新发生故障。报告中的通过表示这些输入获得了规定的回滚或恢复行为。

## 局限性、结论及下一步

**已测量**：真实PostgreSQL事务回滚、持久化记录与序号、确定性图恢复及账本发送器；既有HTTP恢复和终态补偿回归。**间接推断**：原编号重放可避免本次章节恢复重新编号所引起的重复展示；前端仍需遵守已有seq去重和快照游标规则。**尚未评估**：真实浏览器首显/过程DOM、生产代理和公网、并发吞吐、真实模型/搜索费用以及真实进程SIGKILL后的窗口行为。

本轮结果支持节点及章节完成事件的事务提交契约，不等于完整业务交付与图检查点已合并为一个事务，也不证明生产SLA。测试采用确定性Agent和本地隔离数据库，没有重启业务服务、运行付费研究或部署变更。

下一步可在实际浏览器中复测首次发起、章节后断网及刷新补发，核对原seq只应用一次、正文在完成前可见、最终报告唯一。上线前应确认同库和search_path配置，并明确旧版本未完成运行需重新发起。
