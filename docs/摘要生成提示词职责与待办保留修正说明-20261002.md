# 摘要生成提示词职责与待办保留修正说明

修改及验证日期：2026-10-02。评估对象为当前正文生成提示词及四栏目摘要提交机制。本次仅修改现行提示词，未修改核验代码、Claimify开关或历史评测档案。

## 修改内容

现行文件：[摘要正文生成与合并.txt](../backend/app/prompts/摘要正文生成与合并.txt)。

1. 删除“后续独立的 Claimify 流程负责分句、筛选、消歧和拆解”的表述，改为说明论断抽取、证据定位和支持关系判断属于独立核验阶段。提示词不再承诺必定运行 Claimify；实际是否核验仍由运行配置决定。
2. 明确摘要模型的职责是忠实压缩已有关键信息，禁止补充研究结论、新建议或后续计划。
3. 将 NEXT STEPS 限定为上下文明确记载、尚未完成或解决的待办、计划和待确认问题，要求保留提出者及原有状态。禁止根据任务目标、信息缺口或常识自行规划，也禁止扩展已有待办。没有明确记录时填 None。
4. 补充信息追溯及状态规则：合并重复信息不能引入新行动、方向、推断或承诺；只有明确完成、取消或更正记录才能更新已有事项状态，不能仅因未见结果就推断已完成。

## 为什么保留 NEXT STEPS 栏目

原提示词“剩余任务、计划和待确认问题”需要模型阅读上下文后提取、归纳，但没有明确限定必须来自已有记录，存在自行扩展计划的空间。这个风险是对提示词的分析，并不是对每一条历史计划来源的逐条证明。

已明确存在的未完成事项也是继续任务所需的关键信息。例如用户要求回读某篇论文但尚未完成，摘要需要保存这一事项。应删除的是摘要模型自行制定计划的职责，而非把已有未完成信息全部丢弃。

当前 [claimify.py](../backend/app/service/claimify.py) 的 SECTIONS 和 parse_prose 要求 SESSION INTENT、SUMMARY、ARTIFACTS、NEXT STEPS 四栏目，直接删除最后栏目会导致格式检查失败。因此本次保留协议、收紧内容范围。若未来改为三栏目，需要同时迁移解析、生成修复及历史摘要兼容逻辑。

| 没有明确的待办、计划或待确认问题 | NEXT STEPS 填 None。 |
