评估日期：2026-10-06（Asia/Singapore）。评估对象：LeadWriter 单章修订时构造的当前事实与原句证据输入。离线验证结束时间：21:58:49。

## 需求与实现范围

本次按用户澄清，仅使用关联到当前章节的证据，不按审核问题 ID 扩大材料范围。代码修改限于单章修订的材料选择及其格式化辅助函数，未启动或恢复此前的真实模型开发集运行。

- 单章修订事实按 `related_sections` 筛选；删除“所有补搜事实都可用”及“没有章节关联时回退到全局最后20条事实”的逻辑。
- 本章已关联事实对应的原句使用现有文档/原句绑定和去重逻辑，保留整条支持句及已有编号。
- 原章节引用可能没有对应事实或缺少事实的章节关联，因此保留能定位到当前章节正文的已有声明，按声明的精确文档/原句编号读取原文。不因来源 URL 相同而扩大到整个文档或其他事实。
- 已有声明的定位沿用当前章节论断索引规则：优先使用 `report_quote`；缺少该字段时，论断文本必须逐字出现在当前章正文中。过期定位、其他章声明不参与当前章材料选择。
- 回读原引用仍经过来源质量、正文版本、内容哈希和原句编号门禁。有效定位不等于事实支持性已核验。
- 修订提示词允许使用本次事实或原句证据中明确提供的 URL，兼容只有原章节引用而没有补搜事实的情况。

## 逐类分析

1. **同来源跨章节原句**：第一章的 f1 使用 s000001、s000003，第二章的 f2 使用 s000002、s000003。修订第一章时只提供 f1 及其两条原句，不因两条事实共享文档而展示第二章的 s000002。
2. **补搜材料范围**：关联第一章的补搜事实进入第一章输入；第二章补搜事实及缺少章节关联的事实被排除。即使未关联事实的 `critic_issue_id` 与当前审核问题相同，也不因此进入本章输入。
3. **无关联材料**：本章没有关联事实或可定位的原引用时，证据视图返回空 facts/documents，并提示缺少补充证据；不会回退到全局材料。
4. **保留原章引用**：即使原引用没有对应事实，仍能按当前章声明回读原句。同一来源的未被本章引用的其他原句不随之进入；重叠原句不重复展示。
5. **全局审核反馈**：全局反馈仍可触发逐章修订，但每次调用使用各自章节的证据范围，没有把所有补搜事实一起传入。
6. **状态和生命周期**：材料格式化没有修改原始 facts/raw_sources；既有章节声明替换、参考文献更新、其他章正文保留及字数预算修订回归通过。

## 失败样例与处理

本次没有测试执行失败。以下是验证中应被排除的负例：

- 第二章补搜事实，仅因 `is_supplementary=true` 而尝试进入第一章。
- 无章节关联的补搜事实，即使审核问题 ID 匹配。
- 本章没有材料时，使用全局最近事实填充。
- 原声明的 `report_quote` 已不在当前章节正文中。
- 原引用的来源质量为 rejected，或引用不存在的 s999999 原句。
- 文档编号不是字符串；引用不会被重新引入。
- 其他章节的声明或同来源未选择原句，借由共享来源扩大输入范围。

## 局限性与边界

**已测量**：离线当前修订提示词的章节隔离、原引用精确回读、去重、来源/编号门禁、状态不变，以及相关 Writer 回归。

**间接推断**：减少无关章节的重复原句输入，有助于减少当前修订材料体积和跨章节材料干扰。这里没有把字符数当作 tokens，也没有据此推断可多跑多少轮。

**尚未评估**：真实模型修订质量、真实 tokenizer/供应商 usage 的 token 变化、开发集多轮容量、同一章必要材料本身超预算时的处理，以及历史回放对总输入的影响。验证码页和脚本污染问题不由本次修改解决。

旧状态如果既没有事实的章节关联，也没有可定位的本章引用声明，则无法可靠确定其材料归属，本次选择保持证据不足而不猜测。未编号历史短来源仍沿用既有 legacy_sources 规则；不新增句子编号，也不声称其文本已通过语义支持性核验。
