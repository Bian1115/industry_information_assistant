# 网页检索读取链路评估方法与现有结果分析

分析日期：2026-10-18，Asia/Singapore。评估对象：研究任务经查询生成、搜索、候选选择、网页获取、正文抽取、质量准入到证据交付的链路。

本次为评估方法设计及已有结果复核，未启动项目的搜索或网页读取效果评测，也未调用浏览器、OCR、模型裁判或业务回归；外部资料通过联网查询核对。下文已有数字来自两个明确冻结的历史运行，不能合并成当前部署的端到端分数。

建议以**固定预算下的关键需求证据覆盖率**作为任务层主指标，再以检索相关性、有效正文获取率、正文及结构保真、误接纳与误拒、延迟和成本定位损失。HTTP 成功、返回非空、程序准入以及可用证据应分别记账。

## 数据、配置与原始材料

1. 业务轨迹：2026-10-08 对五个已完成历史研究任务的分析，含 77 次搜索、57 个读取批次、289 个按题去重 URL 和 36 项冻结需求。Qwen3-max 初评并经 Codex 部分复核，**没有独立人工金标**；50 页正文采用抽样。五题预算口径不同，且只选择已完成任务，不能用来评价公平消融或总体任务成功率。
2. 公开网页基准：2026-10-18 冻结版 `trafilatura-native-markdown-v1`，WebMainBench 545 页及 WCXB dev 分层 200 页；745 次离线读取，正文评分使用 739 页有效参考，6 页空参考保留状态但排除正文质量均值。该运行冻结 HTML，禁止网络，不执行真实浏览器兜底；生产预算为 30000 字符、最短正文 500 字符。
3. 当前源码观察：`DeepScout._update_web_reader_stats` 按唯一 URL 的最后一次尝试统计 `urls_total`、`urls_success`、`urls_body_admitted`。这些是程序状态，不能充当独立正文质量金标。参数观察只代表工作区默认值，实际部署配置需在正式运行时冻结。

## 核心指标与计算口径

| 层次 | 主指标及分母 | 诊断作用 |
| --- | --- | --- |
| 搜索 | Precision@5：每条查询前 5 个唯一 URL 中相关条目数 / 5，再跨查询宏平均；不足 5 条的位置计不相关 | 前排结果是否有用 |
| 搜索排序 | 共享标注候选池 nDCG@10，相关性按 0—3 级标注 | 有用页面是否靠前；与候选池覆盖一起报告 |
| 候选选择 | 实际选择页面所覆盖的金标需求数 / 搜索候选池可支持的金标需求数；无可支持需求时单列 | 找到的资料是否被选中，能隔离读取策略的遗漏 |
| 在线读取 | 有效正文唯一 URL 数 / 全部尝试唯一 URL 数；完整、部分可用分别报 | 真实能取得多少目标页面内容；超时、403、404、拒绝均留在分母 |
| 正文抽取 | 每页正文词元 Precision、Recall、F1，跨页宏平均；补充连续片段或顺序指标 | 漏掉正文与混入导航、广告的程度 |
| 结构与关键事实 | 表格单元格、行列及表头对应；关键数值、单位、时间、对象和限定条件保留率 | 文本仍在时，证据意义是否被破坏 |
| 质量准入 | 异常页误接纳率 = 被接纳异常页 / 全部金标异常页；正常页误拒率 = 被拒正常页 / 全部金标正常页 | 污染是否被拦住、正常资料是否被误伤 |
| 证据交付 | 正确交付证据数 / 全部交付证据数；每条绑定 URL、原文定位、时间与适用范围 | 从原文到事实或证据包是否产生错配、概括过度 |
| 整体链路 | 固定预算下充分支持的关键需求数 / 运行前冻结的关键需求总数 | 最终是否取得研究任务所需资料 |
| 效率 | 搜索、单页读取、整任务 P50/P95；每项充分覆盖需求的总成本 | 是否通过大量调用或等待换取质量 |

检索标签建议：0=无关，1=仅背景，2=有实质相关内容，3=直接提供所需答案或资料，grade≥2 计入 P@5。搜索标题/摘要相关性与打开后正文支持性应分开标注；仅看摘要无法确认时记未知，并报告未知比例或上下界，不补猜标签。相关性、来源权威性和时效性也分开记录，避免用官方域名替代实际相关性。

nDCG 使用固定增益 `2^grade−1` 和 `log2(rank+1)` 折扣。比较 A/B 时，将两者前排结果、独立人工补找来源合并去重后盲标，用同一池计算 IDCG。无相关文档的查询单列并说明聚合规则。若只按每次返回的 10 个候选构造 IDCG，只能称“返回候选内 nDCG”，它无法衡量遗漏的优秀资料。全网相关网页总数未知时不宣称全网 Recall；只能报告明确金标集合或候选池内的 Recall，并说明判断不完整的偏差。[排名检索评估](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html)、[不完整相关性标注的影响](https://www.nist.gov/publications/retrieval-evaluation-incomplete-information)。

正文指标必须区分门禁前与最终输出；拒绝导致最终输出为空时，在有有效参考的总体质量中计零。另报已接纳页面上的条件质量，防止只看接纳样本掩盖损失。中文与英文固定不同的适用词元规则，词元 F1 只能说明文本重合；`1−Precision` 不能直接称为语义噪声率。

关键需求应拆到可以独立核对的事实或子问题。每项要求给出支持原句、URL、位置和适用范围；充分、部分、缺失分开，主覆盖率只将充分支持计入分子。统计全量已读取正文的可支持覆盖，以及实际交付证据包的覆盖，二者差值有助于定位事实提炼损失。来源重复转载不得当作多份独立佐证。

## 如何建立数据集和开展比较

采用三条互补轨道，分别回答不同问题：

1. **离线正文轨道**：复用冻结的 WebMainBench 545 页和 WCXB dev 分层样本，测抽取、清理、字符预算和门禁。仅向读取器提供去掉金标标记的 HTML，参考正文只交给评分器。WebMainBench 有校准 Markdown 和结构指标；WCXB 有七种页面类型，适合检查非文章页面。官方评分与本地诊断分数分别保留，不能混成排行榜分数。[WebMainBench](https://github.com/opendatalab/WebMainBench)、[WCXB](https://github.com/Murrough-Foley/web-content-extraction-benchmark)。
2. **在线读取轨道**：首轮可用约 150—200 个跨网站业务 URL，覆盖中文/英文、新闻、政策、列表、动态网页、短公告、表格、文本/扫描 PDF、登录/验证码及软 404。冻结 URL 清单，在接近时间窗配对调用完整读取路径，保存实际字节与渲染结果；独立核验当时能访问的目标内容。网页变化、失效及不可判页面单列。这个数量是排查问题的起点，不能保证统计充分性。
3. **完整检索读取轨道**：首轮约 30—50 个真实研究任务，依据原始需求提前标注原子子问题、时间范围及证据要求。用共享供应商、同一模型/提示版本、检索范围及总预算比较单查询/单轮基线和当前查询分解、多轮补搜方案。预算同时约束搜索调用、读取页数、模型用量或时间，报告实际用量；多轮逻辑调用数不能直接当成上游付费请求数。

离线 A/B 应对同一 HTML 配对；在线 A/B 应交替或随机顺序、重复访问并分别标注冷缓存与热缓存，减少时变和缓存的影响。公开 dev 用于开发，保留 test 和新域名作为独立验证；用过的业务五题只能作为开发及失败回归材料，不再声称独立测试。

正式标注采用盲标，抽取有代表性的比例由第二位人工复核并裁决分歧，正常页与异常页都要覆盖。LLM 可以初标，但输出标签、判定理由、原文匹配与人工修订分别保存；不能用线上门禁本身的标签评价门禁准确率。不得把原始页面中的指令当作裁判操作指令。

对查询与页面报告分层结果和样本量；研究任务应按任务先算覆盖率再宏平均，避免子问题多的任务支配主分数，另报需求微平均。A/B 差值可按任务配对 bootstrap 给出 95% 区间；同域页面、同题子查询存在相关性，不视为大量独立样本。少量任务时区间通常较宽，不能凭小幅均值提升下结论。按预算画“已覆盖需求数—累计调用/时间/成本”曲线，可比较补搜的边际收益。

延迟从调度到最终可用输出，包括重试与回退；每 URL 与批次耗时分开，失败/超时率和截止时间一起报，成功请求的分位数单列。成本包括失败重试、浏览器/OCR、模型提炼和搜索等相关开销；账单缺失时只报调用与 token 等资源，不推称实际费用。零覆盖任务仍计入总成本，不能从单位有效证据成本中删掉。

## 现有结果复核及逐类分析

### 历史业务五题

| 指标 | 已存结果 | 可解释边界 |
| --- | --- | --- |
| AI 初评 P@5 | 66.49% | 77 次调用的标题/摘要相关性估计，不是人工验证的当前线上表现 |
| 返回候选内 nDCG@10 | 0.8567 | IDCG 来源仅为各自返回候选；不能与共享标注池的新分数直接比较 |
| 程序抓取成功率 | 65.40%，189/289 | 程序状态成功，不等于可用正文 |
| AI 可用正文率，含部分 | 51.56%，149/289 | 正常可用 104，部分可用 45；没有独立人工校准 |
| AI 充分证据需求覆盖率 | 58.33%，21/36 | 历史需求微平均，五题预算不同；不是公平 A/B 效果 |

逐题的 P@5 / 充分覆盖率分别为：市政污水 61.54% / 50.00%，博物馆教育 76.00% / 62.50%，房地产 83.53% / 85.71%，非接触感知 61.43% / 66.67%，正畸医美需求 50.00% / 28.57%。不同任务存在难度及预算差异，不能据此因果归因为某个模块，但可以用低覆盖任务优先建立回归案例。

读取批次历史 P95 为 30.664 秒，单页 P95 未测。程序成功率与 AI 可用率的差异提示程序状态不足以代表内容质量；AI 标签还需人工校准，不能将两者相减直接认作已确认的误接纳率。

### 冻结公开网页基准

| 数据集 | 有效正文评分页 | 门禁前 P / R / F1 | 最终输出 F1，未接纳计空 |
| --- | --- | --- | --- |
| WebMainBench545 | 545 | 92.27% / 73.34% / 77.85% | 70.14% |
| WCXB 分层200 | 194 | 82.31% / 58.14% / 62.14% | 59.22% |

WCXB 门禁前 F1：文章 93.13%、文档 87.89%、服务 67.83%、产品 53.93%、论坛 44.79%、集合 44.26%、列表 41.36%。按类型等额抽样的均值不能代表真实业务流量均值；这些结果显示应加强列表、多区块和论坛读取的分层诊断。

57 页多行多列表格的严格单元格 F1 为 52.17%，行内相邻关系 F1 为 45.27%，列内相邻关系 F1 为 47.16%。正文里能找到数值不保证“哪个年份、哪个对象对应哪个数值”仍可恢复。该结果混合词典、参数等多种表格，并非行业财务表专项分数。

WebMainBench 放宽预算后的词元 Recall 为 77.08%，生产预算为 73.34%，48 页发生截断。正文漏失同时来自抽取和预算；不能把所有缺失都归因于 30000 字符限制。以上是冻结版本的离线结果，不是今日实时站点成功率，也不是当前工作区所有后续改动的重新评测。

## 失败样例与定位方法

| 已有案例 | 已有观察 | 新评测应该如何发现 |
| --- | --- | --- |
| 中文短新闻 `WebMainBench-4326f7b6-8d26-475f-875a-12197eb8ab33` | 正文约 460 字符，F1 约 96.8%，离线未通过 500 字符门槛 | 同时看门禁前质量、最终输出及正常短页误拒；线上兜底是否恢复另测 |
| 论坛 `WCXB-0524` | 遗漏部分帖子并混入用户档案片段 | 按论坛单列正文 Recall、必含片段与噪声残留 |
| 词典定义表 `WebMainBench-0aa9f0da-dc0a-436b-bb63-692843f02ef4` | 词语仍在，但表格行列损失 | 对关键单元格及表头关系评分，不能只看全文词元 |
| 历史市政污水需求 | 有应急调度功能原句，缺少应急投入或资金成本安排 | 将“应急管理”与“对应成本”拆分核验；相关背景不自动算充分支持 |

前三例原文、参考和指标可由上述公开基准样例文件及其 `逐页结果/<样本编号>/` 目录追溯。第四例见业务需求与事实证据及历史逐题报告；本次没有独立重裁这些案例。

正式分析按查询生成不足、候选遗漏或排序差、相关页未选择、网络访问失败、动态渲染失败、正文漏抽/污染、字符截断、门禁误判、事实提炼丢失/错配分别归因。沿需求记录每一步证据，不将所有问题归给搜索或读取。浏览器补救收益应以同 URL 静态与完整链路的配对结果测量，报告净变化及额外耗时，不能只用触发率证明收益。

## 测量边界、结论和下一步

**已测量/核查**：本次读取并核对两个历史运行的机器可读汇总、配置及历史报告，复用其计数和指标；核查当前统计字段。历史基准证明冻结 HTML 条件下正文与结构的保留状况；历史五题提供 AI 标注的开发材料。

**间接推断**：现有结果提示正文遗漏、非文章页面、表格结构及短页门槛值得优先改进；固定预算需求覆盖适合作为链路主指标是针对研究任务的设计建议，并未通过本次新消融证明其业务收益。

**尚未评估**：当前部署的独立人工金标 P@5、共享候选池 nDCG/Recall、在线浏览器与 OCR 的净收益、当前读取有效率、单页真实 P95、实际账单及公平预算下的端到端提升。没有本次新失败样例或性能结果。

下一步按顺序执行：先复用现有 289 URL 和 36 项需求建立人工复核开发集；再以接近时间窗补跑并保存新页面，新增独立任务/域名；最后运行配对消融，在同预算下比较需求覆盖、有效正文率和效率。每次运行保留中文命名目录、冻结输入/配置/源码指纹、逐项标签、失败和 usage，另建中文日期报告，不覆盖历史记录。只把已经按相应口径实测的数字写成效果提升。
