# 评估体系搭建动机、实现、效果及面试回答

分析日期：2026-10-16，Asia/Singapore。

评估对象：本项目的报告质量评分、论断级引用核验、调用追踪及离线对照评估能力，以及面试中能够成立的效果表述。

本次工作为既有结果分析与指标复算，未调用评分模型、未重新生成报告、未重新标注、未执行网络事实核查或当前版本端到端评估。历史评估日期主要为2026-10-06至2026-10-12。本次新建报告和机器可读核对结果，不覆盖历史数据。

当前README定位为医学文献研究助手，但下述30份参考报告和五份自研报告来自通用研究链路。它们不能证明医学专项质量、医学证据等级判断或临床正确性。

## 一、可以直接讲的面试回答

这个项目是一个多智能体研究助手，需要经过问题拆解、多轮检索、文档读取、证据整理、写作和审核。我搭建评估体系，主要是因为这类开放式研究任务没有唯一标准答案，而且报告写得流畅、引用很多，也不代表内容有依据。如果只看最终报告或者Agent自己的评分，很难判断一次修改是否有效，也很难知道问题出在检索、证据还是写作环节。

所以我把评估分成三个层次。

第一层是报告质量。我参考DeepResearchBench的逐题细则，从全面性、洞察力、指令遵循和可读性评价，而不是只给一个笼统总分。为了验证评分器，我从基准中固定抽取30份参考报告，共758条细则，让Qwen和Claude分别独立评分，每个模型每题评两次，再先取模型内部均值、最后等权融合。评分要求输出细则分数、理由和正文摘录，程序检查细则是否完整、分数是否合法，再按官方权重汇总。另用预先冻结、不给裁判查看的独立GPT评分交叉验证。

第二层是论断级证据评估。我将报告里的事实论断与引用来源、原文位置绑定，分别检查能不能定位到证据、证据能不能完整支持论断。这里会区分完整支持、部分支持、不支持、矛盾和无法判断，尤其检查时间状态、适用对象、统计分母和条件限定。有引用只是入口，不能直接当作正确。

第三层是过程和组件评估。我记录模型调用阶段、耗时、token、失败和JSON解析情况，结合检索、正文读取、摘要与恢复等专项脚本分析失败。离线对照会保存题目、配置、报告和原始证据；针对固定轨迹的修改，可以用同一输入回放，减少把输入变化误当成优化效果的问题。

效果上，我会分开讲评分器的可靠性和系统本身的短板。在完成双裁判的26题上，相对独立GPT评分，总分平均绝对误差是0.286分，满分10分，22题的差异在正负0.5分内。另一个五任务样本覆盖511条事实论断，在230条带引用且可判断的论断上，引用核验模块的完整支持识别F1是84.0%。不过，对证据未完整支持项的检出召回只有56.3%，说明仍存在漏放行。

评估的实际价值，是把这些问题具体定位出来。比如原文说“未来计划构建”，报告写成“已经构建”；或者数字本身没抄错，却把女性消费者内部比例改成全部用户比例。这样的错误靠可读性评分很难发现，却直接影响报告可信度，因此后续优先改进方向就是完整限定条件核验和证据质量处理。这些结果来自通用研究链路的离线样本，参照也是模型复核；我不会把它写成人工金标准确率或医学事实准确率。

使用第一人称时，应与本人实际负责的工作对应。仓库存在代码和评估记录，本身不证明某项工作的个人作者归属。

## 二、为什么需要评估体系

| 业务难点 | 单看最终报告的不足 | 对应设计 |
| --- | --- | --- |
| 开放式研究没有唯一答案 | 文本相似度不能直接代表研究覆盖和洞察 | 逐题细则、分维度评分、逐条理由 |
| 表达流畅可能掩盖证据问题 | 引用存在不等于引用支持；支持也不等于现实真实 | 论断—引用—原文定位与支持标签，现实核查单独记录 |
| 多Agent链路长 | 总分不足以定位检索、读取、写作或审核故障 | 调用追踪、原始轨迹、组件专项评估 |
| 模型有随机性和尺度偏差 | 单次或单模型评分可能改变优化判断 | 双模型、重复评分、独立参照与分歧分析 |
| 修改存在质量和成本权衡 | 删除无支持段落可能同时损失重要事实 | 固定输入回放，同时观察支持率、内容保留和消耗 |

这里的价值是建立可追溯的比较依据。当前证据没有证明“搭建评估体系本身让研报质量提升某个百分比”，也没有测量人工审核时间节省。

## 三、如何实现与配置口径

### 1. 报告质量评分器验证

- 样本：从DeepResearchBench的100题中以种子20261007抽取30题，18篇中文、12篇英文，使用官方参考报告及758条逐题细则。它们不是本项目生成的30篇报告。
- 四维：全面性、洞察力、指令遵循、可读性。每条细则0—10分，维度内按细则权重归一化，再按官方维度权重汇总。
- 裁判：历史冻结配置为Qwen3.8-max、Claude-opus-5，各题各模型两次；先在模型内均分，再对两个模型等权平均。
- 参照：独立GPT评分先冻结，裁判不可见。参照不是人类金标；阅读采用结构浏览与按标准定位补读，存在长段落截取，未做全篇外部事实审计。
- 输出：`criterion_id`、`score`、`reason`、`evidence_quote`，以及优缺点、待核查事实风险。检查细则集合、数量、分数范围和理由完整性；Claude格式修复须保留原始数字且完成流接收。
- 完成度：Qwen有效评分60份、Claude54份，共114/120份；完整双裁判26题、657条细则。61、22、31、84四题不计入完整双裁判主指标，不能当作低分或已完成。
- few-shot：历史示例是构造的尺度锚点，不是经人工验证的金标。没有已完成的锚点校准前后配对实验。

实现见[双裁判脚本](../backend/eval/scripts/DeepResearchBench参考报告双裁判一致性.py)及[格式校验](../backend/eval/scripts/Bench评分格式校验.py)。该实验使用逐细则绝对评分，不应冒充官方榜单的完整RACE/FACT成绩。

### 2. 论断级引用核验评估

- 自研报告样本：第16、31、35、46、49题于2026-10-03生成的五份冻结报告，共511条正文事实论断、293条带引用论断、296组论断—来源关系。
- 参照：2026-10-07独立模型复核。模块预测来自2026-10-06冻结生产模块的离线回放；原五条轨迹在线核验关闭。
- 主分类：仅比较230条有引用、参照可判断的论断；143条完整支持，87条未完整支持。模块自身的unknown仍纳入，按未通过或待复核处理。
- 排除项：218条未绑定行内引用，计入覆盖分析；63条带引用但参照unknown，计入无法判断率，不强行赋予真假标签。没有把这些论断从整体分析中删除。
- 支持性与现实真假分别记录：二手材料可能完整支持错误陈述；证据缺失也不能直接认定陈述现实为假。

固定轨迹对照见[正文引用核验消融脚本](../backend/eval/scripts/运行正文引用核验消融.py)：固定初稿和证据，比较仅审计、失败单元删除和一次改写，同时保留重要事实与原已支持内容的保留指标。脚本支持这类实验，不代表本次重新运行或验证了收益。

### 3. 追踪与离线运行

[追踪器](../backend/eval/runtime/tracer.py)与[数据模型](../backend/eval/models.py)保存模型、Agent、阶段、轮次、token、耗时、成功状态、异常、JSON解析及输入输出预览。上下文通过contextvars传递，后台队列写库，以降低评估埋点对主流程的影响；队列满可能丢记录、预览默认截断，不能宣称完整无损审计。

[评估目录说明](../backend/eval/README.md)区分运行时旁路、CLI、配置、测试和原始结果。Runner调用真实研究入口，保存结果、实际运行标识和状态；其按题续跑与图节点恢复是不同机制。组件脚本覆盖检索/读取、摘要、恢复等不同对象，不能把机制测试通过率当成端到端质量分。

## 七、面试追问补充

**为什么不用BLEU、ROUGE？** 开放式研究存在多种合理组织和表述，文本重叠难覆盖研究深度、指令交付和引用支持。这里采用逐题细则与证据关系判定；不是声称文本重叠指标在所有任务中无用。

**为什么用双裁判、各评两次？** 希望观察单模型的重复波动和不同模型的尺度差异，降低只依赖一次输出的风险。不同模型可能共享偏差，平均也可能掩盖分歧，因此保留细则理由并与独立参照比较。不能声称已经证明“相对单裁判误差降低X%”，除非在同一完成子集作明确配对分析。

**为什么还需要独立GPT参照？** 评分器也是待验证组件；需要外部于这两位裁判的比较依据。先冻结参照并隔离分数，有助于避免参照泄漏，但GPT仍不是人类真值。未来需要领域专家标注和仲裁。

**0.286分证明了什么？** 它是26份参考报告的评分差异，不是自研报告生成质量，更不是事实错误率。MAE是平均绝对距离；CCC补充观察尺度与位置是否一致。评分器均分接近参照，不代表每个细则都接近。

**84%的F1证明了什么？** 在230条有引用且可判断的离线样本上，以完整支持为正类的F1。它不代表事实准确率、幻觉检出率、全部511条论断的效果或实际在线表现。如果业务目标是拦截证据不足，56.32%的未完整支持检出Recall更直接反映短板。

**怎样证明一次修改有效？** 后续应固定任务、模型、预算、评分口径，做同题配对对照；区分端到端重跑和固定轨迹回放。分开保留开发集与未见测试任务，同时报告质量、内容保留、失败、延迟和实际消耗。本项目已有相关对照脚本，但本次没有新增实验，也不宣称已经完成医学独立测试集验证。

**间接推断：** 分层评分、细则理由和原文定位有助于诊断链路问题；限定条件、分母和时间状态是重要改进方向。该结论基于保存的分歧和案例，不是效率提升或质量改进的因果实验。

**尚未评估：** 人类/领域专家金标一致性、医学专项与临床正确性、独立任务测试集泛化、当前代码的新端到端效果、评估体系带来的质量增益或人力节省、上述改进方向的配对消融收益。30题双裁判也尚未全部完成。

结论：面试中可以突出“把开放式研究质量拆成报告质量、论断证据和过程组件三个层次，并验证评分器和分析失败”。效果主数字采用26题MAE0.286分和230条完整支持F1约84.0%；同时能解释未完整支持检出Recall56.3%的短板。避免“人工金标准确率”“医学事实准确率84%”“自动降低幻觉X%”等现有证据不支持的说法。

下一步优先对50条支持判定分歧进行领域人工仲裁，按任务划分开发/测试集；补充医学问题、原始文献证据与专家判定；针对时态、分母、范围、跨片段证据及读取损坏做固定输入对照，并同时观察误放行、误拒、重要事实保留、时延和实际消耗。
