# SSE公开测试资源调研及适用性分析

- 调研/评估日期：2026-10-12，Asia/Singapore。
- 评估对象：Server-Sent Events（SSE）的公开测试用例、异常事件流、机器可读观测数据及压测基准；结合本项目深度研究链路判断适用性。
- 数据/配置口径：读取公开项目说明、固定提交的源码和目录、第三方历史JSONL观测；查阅本地既有SSE报告及浏览器夹具。未启动服务、未执行协议或浏览器测试、未调用模型。
- 原始证据目录：[SSE公开测试资源调研-20261012](../backend/eval/data/SSE公开测试资源调研-20261012/)。

## 结论与证据边界

有公开可复用资源，其中WPT提供可执行协议测试，badhttp提供事件流场景及带参考输出的JSONL观测，sse-bench提供压测程序及CSV汇总。它们的用途不同，不能把资源存在等同于本项目通过测试。

本次检索未找到覆盖本项目“POST流、run_id/seq补齐、章节幂等、正文首显、终态交付”的统一公开标注数据集；这是本次检索范围内的结论，不证明全球不存在此类数据集。SSE传输评测通常更需要可控事件序列、期望输出和故障条件，问答内容本身不能作为传输正确性的判定标准。

- **已测量**：本次仅进行公开记录的读取和静态计数。badhttp的`family=sse`共112行，其中98行客户端历史观测、14行curl控制记录，涉及14个场景；这些是第三方数据，不是本项目实测。本次阅读4份WPT具体测试源码。
- **间接推断**：根据资源接口与本地既有链路说明，判断协议用例、故障场景及压测方法的适用性。
- **尚未评估**：本项目接入这些资源后的通过率、故障恢复成功率、首显时间、P95延迟、吞吐、峰值内存及生产代理行为。

## 逐类资源分析

### 1. Web Platform Tests：优先用于标准兼容

来源：[eventsource公开目录](https://wpt.live/eventsource/)、[源码仓库](https://github.com/web-platform-tests/wpt/tree/master/eventsource)。固定源码提交为`ddb25fdfff7766af4cd75eac3fb3b6ac206140ce`。

目录包括换行、多行data、BOM、注释、event/id/retry、MIME、重连及请求行为测试。本次具体阅读`format-newlines.any.js`、`format-field-data.any.js`、`eventsource-reconnect.window.js`、`format-data-before-final-empty-line.any.js`，核对其输入与断言。

这是协议测试套件，有明确预期输出，适合建立解析器测试。现成测试面向浏览器原生EventSource；本项目使用POST+fetch，需要抽取事件流输入与相关断言，适配自定义读取器。原生EventSource重连行为不能直接替代本项目after_seq及租约逻辑。通用帧解析与JSON业务解析应分别断言。

### 2. badhttp：公开故障场景及机器可读数据

来源：[场景目录](https://badhttp.dev/sse)、[JSONL数据](https://badhttp.dev/clients.jsonl)。本次下载筛选得到98行客户端观测和14行控制记录；原始行均标注`CC0-1.0`。来源标注观测日期为2026-10-05，属于第三方历史捕获。

可用于研究截断、断流、静默、UTF-8分片、多行data、CR换行、大帧及恢复边界。数据保留实际事件、参考输出与差异。应区分自动重连客户端与单响应读取器，避免把接口设计差异算作错误。该资源适合作为小型公开案例库，不能代表浏览器DOM或本项目端到端可靠性；接入后须本地复测。

### 3. sse-bench：性能工作负载与CSV汇总

来源：[sse-bench](https://github.com/n1snt/sse-bench)。固定源码提交为`81731c5010b61ebb96712dfc4b692738b98b4d6d`。

说明提供HTTP/1.1、HTTP/2、HTTP/3的并发、速率、载荷及重连工作负载，事件带序号和校验信息，公开提交ALL.csv、RECONNECT.csv汇总。适合参考吞吐、延迟、资源占用及重连测量方式。其自带服务器及Go客户端不覆盖React投影、模型生成或数据库事件账本，应在本项目环境重新测量。

## 失败样例与局限性

以下为应纳入测试的输入或场景，本次未在本项目重跑：

| 场景 | 判定重点 |
| --- | --- |
| 多行data与CR/LF/CRLF混合 | 先按事件块聚合，再解析业务内容；合法SSE字段不能被误判为独立JSON |
| EOF前末帧没有空行 | 严格SSE应丢弃未完成事件；本地既有EOF兼容约定需要显式记录 |
| UTF-8字符跨网络分片 | 还原完整字符，不引入替换字符 |
| 首章到达后断网，再按游标恢复 | 已提交事件补齐、页面章节幂等、最终正文一致 |
| 同章节以新seq重新发送 | 传输序号去重之外，仍需验证业务产物幂等 |
| 完成事件之前出现超过2000条缺口 | 分页补齐追到终态，失败时不提前推进应用游标 |

本地[现状报告](SSE当前实现不足及优化评估分析-20261012.md)已经记录多行data、CR换行及章节重放探针的问题。本次仅引用其测试需求，不新增复评结论。

检索范围有限；WPT目录存在不代表已经运行全部用例。badhttp为小样本历史观测，未包含真实浏览器；公开在线服务可能变化或受网络影响。压测数值受硬件、协议和部署配置影响，不能直接横向比较本项目。多行data在协议层合法，但最终数据是否满足本项目JSON契约仍需单独验证。

## 下一步建议

优先建立“WPT协议输入与断言＋项目业务事件夹具＋真实浏览器故障注入”的评测组合。协议层覆盖换行、字段、分片及EOF；项目层复用[浏览器测量脚本](../frontend/scripts/SSE浏览器测量.cjs)和[隔离服务](../backend/eval/scripts/SSE浏览器隔离评测服务.py)，补充新seq同章、快照叠加、分页缺口及终态丢失。

逐场景记录样本量、解析匹配数、缺失事件、重复应用、章节重复、恢复成功数、正文首次可见时间和最终报告一致性；再按真实部署协议与代理配置测量吞吐和延迟。结果应标注公开用例移植或自建业务夹具，保留来源版本、事件输入、期望输出与原始运行结果。
