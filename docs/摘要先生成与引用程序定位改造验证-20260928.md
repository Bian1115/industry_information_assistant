# 摘要先生成与引用程序定位改造验证

评估及复评日期：2026-09-28。评估对象：摘要主流程、最终引用定位、可选在线遗漏检查、旧冻结配置兼容。本次修改按用户确认实施；没有重启或停止主任务采集进程，没有修改其冻结策略、原始轨迹或真实.env，没有调用付费模型或重新搜索。

## 问题与最终行为

开发集第一题此前5次摘要尝试均在候选摘要生成前执行fact_extraction，并因模型给出的字符位置错误而失败。该步骤是后来加入的在线遗漏检查前置清单，并不是用户要求的“先生成摘要，再为最终分句补齐引用”。

新规则为 `verification-v2`：

```text
原文 → 摘要生成／分块合并 → 最终全部分句
     → 补齐来源编号和连续原句 → 程序精确定位
     → 字段与NLI支持核验、置信度 → 保存
```

默认 `coverage=false`，不执行fact_extraction、不使用旧在线事实清单。`key_fields=true`仍检查已输出数字和当前要求，但不隐式触发抽取。`omission_check=not_run`，不能把未检查遗漏当作通过。离线人工事实保留率和遗漏率评估不受该开关影响。

仅显式开启 `coverage=true` 时，在摘要和引用补齐之后抽取原文清单、检查覆盖；抽取器只接收原始记录，不从候选摘要倒推事实。它仍是可出错的在线辅助组件。启用后失败会阻止新摘要提交，沿用受控修复及总预算；默认主流程不依赖它。

引用中的 `source_id` 是来源记录编号，`quote` 是连续原文，`start/end` 是完整来源的字符区间。唯一匹配由程序计算，即使模型附带错误位置也使用精确匹配结果。不存在、跨来源或改写的引句仍拒绝；重复或重叠出现时必须消歧，不随便取第一个。原句、来源权限、范围与哈希检查保留。

## 逐类结果与失败场景

1. 主流程顺序：v2默认先summary_merge再citation_completion；key_fields开启且传入旧事实清单时仍不抽取、不做覆盖检查。NLI置信度字段保留在结果中。
2. 可选检查：显式coverage开启后，顺序为摘要、引用、fact_extraction、coverage_check；抽取请求只有record，没有候选摘要。
3. 字段检查：800人改写成80人时，即使关闭在线遗漏检查也被既有输出字段核验拒绝。
4. 位置：唯一引句自动计算绝对位置；重复引句无有效定位、跨来源匹配和编造引句均拒绝；重叠片段同一位置去重，文本中的重叠重复位置不误判为唯一。
5. 真实错误回放：对第一题5次抽取输出中的15个引句，程序均能在当次输入中找到正确位置；全部旧模型位置均不正确。这只验证字符串位置，不验证其statement、必要性、医学真实性或其他字段。
6. 配置：真实旧运行快照反序列化后哈希保持一致，仍为v1且coverage=true。8份新预设通过支持性预检和哈希往返，均为v2且coverage=false。
