# 网页候选链接评级与优先读取排序方案

2026-10-17范围调整：用户已确认首期仅保留来源可靠性、时间口径和可获取性，当前方案见[网页候选链接三维评级与排序方案](网页候选链接三维评级与排序方案-20261017.md)。下文保留此前五维提案，不作为当前首期实施范围。

## 目标与推荐方案

为每个章节维护一条可解释、可更新的阅读队列：根据候选与任务的匹配程度、证据适配性、已有来源背景和获取条件，先读最值得投入读取预算的URL；读取后根据实际正文更新剩余队列。

推荐采用“规则约束＋来源证据记录＋模型结构化重排＋多样性选择＋读取反馈”。来源可靠性与阅读优先级分别保存。前者允许未知，后者仍可根据任务相关性决定先后。首版输出优先级等级与排名，不把模型自报的0—100分当成已经校准的质量概率。

本方案替换当前 `candidate_source_score()` 的固定域名／标题加分，不恢复已经停用的写作前事实提炼。用户当前请求是设计方案，本次没有修改业务代码。

## 一 读取前可以判断什么

读取前的信息包括研究问题、章节任务、搜索查询、URL、标题、摘要、网站名、搜索引擎给出的日期，以及此前已核验的来源和读取记录。首版不为了排序先下载全部候选正文。

| 维度 | 读取前依据 | 判断与理由 |
| --- | --- | --- |
| 任务相关性 | 对象、指标、地域、时间、章节问题与标题／摘要的对应 | 优先解决当前任务，避免“权威但无关”的链接挤占额度 |
| 证据适配性与直接性 | 已核实发布主体、文献登记、原发布目录、摘要中的数据出处 | 查原始统计优先对应统计发布；查研究综述优先合适综述；不是所有任务都优先单篇原始研究 |
| 来源可靠性 | 在适用主题、时期和主体范围内的独立背景证据 | 不能因gov、edu、PDF或“官方”字样直接判为可靠 |
| 时间与口径匹配 | 文献年份、统计期、版本和有效时间线索 | 研究2024年数据应匹配统计期；发布时间更新不自动意味着更适用 |
| 可获取性 | 同URL或同站点具体路径／格式的近期读取记录 | 已读到正文的候选可优先；一次超时、缺记录或PDF格式不能直接判差 |

实际页面完整性、支持句、方法质量和具体论断真实性，仍由读取后的模块检查。搜索摘要中的内容只是排序线索，不可直接写入研究事实或标为正文已验证。

## 二 来源记录应当保存依据

来源身份、发布主体类型、文档类型、可靠性分别记录。例如某大学的活动新闻可以确认由大学发布，但不因此成为学术研究；公司官网说明自家产品规格具有直接性，却不能单独证明优于竞品。

`SourceProfile` 至少包含主体／账号／子域及路径范围、身份核验状态、适用领域和时期、`reliable / questionable / unknown`、理由、证据引用、核验时间与策略版本。

身份可以依据已核验的官网归属、登记记录和机构发布目录。可靠性须依据相关的纠错记录、可核实的历史事实问题、编辑和方法透明度等独立材料，不从主体类别直接映射高低。单篇论文的问题不自动外推成整个机构的问题；公开利益关系应影响相应论断的取材方式，不单独等同于来源不可靠。

背景依据保留原文或API响应、URL、时间、内容哈希、句子编号或JSON字段定位。模型输出的证据ID必须对应实际存档，相关片段还须能支持该项判断；仅ID存在不够。无法满足时保持未知。

来源记录按实际主体和适用范围复用，不让根域评级自动覆盖个人主页、用户托管区或不相关子域。来源背景证据与研究正文分开存储，不能自动变成报告引用。用户限定网站时，背景调查也遵守范围限制。

首版使用已核验的有限来源记录；未覆盖的来源返回未知。后续只对接近读取前列且有调查价值的主体增加有界背景调查，同一主体去重，搜索／API／正文读取全部计入预算。不要对每个URL启动多轮背景研究，否则排序本身可能比读取更贵。

## 三 评级与排序的具体流程

```text
章节任务及搜索候选
  → 范围检查与精确去重
  → 附加已有来源依据和读取历史
  → 模型输出候选特征与相对次序
  → 程序校验并执行多样性选择
  → 小批读取
  → 依据实际正文更新后续队列
```

### 1 规则只承担确定的约束

继续使用现有来源范围及读取安全检查；丢弃无效URL和已确定的精确重复候选。URL归一化只移除已知不影响文档身份的跟踪信息，不随意删除查询参数或改写路径。

不同URL是否属于转载或同一上游，要有标题、摘要、来源说明或已有记录支持。只觉得相似时先标疑似重复，不做不可恢复的删除。

对仅有主题不符迹象的候选降到后列；模型无法确定的保持待核实。未知来源不进入黑名单。来源问题或论文撤稿也不是任何研究问题下都必须不读：研究撤稿事件时，该文及其撤稿通知可能正是必要材料。

### 2 模型比较候选 不自由猜信誉

每个章节批量输入任务约束和候选表，让模型比较，而不是逐URL孤立生成“可信度0.95”。输出候选ID、相关性、证据适配理由、时间匹配、待核实项、依据ID和排序理由。

来源可靠性由已核验记录作为只读字段输入。模型不能凭自己的记忆补机构背景、把类型改成高信誉，也不能引用没有提供的依据。标题和摘要作为不可信数据处理，不执行其中的指令。

比较顺序为：先比较当前任务匹配程度；在相近相关性候选中比较证据适配与直接性、适用范围内的来源依据；再比较时间口径和可获取性。有明确且相关的负面证据时降低优先级，并说明影响范围。信息不足时允许无法比较，保留搜索引擎原次序作为稳定兜底。

首版不预设一套声称可靠的任意权重。来源类别不直接进入信誉加减分表；排序理由也不能只写“是政府网站，所以可靠”。在拿到独立标注后，可以将这些特征训练为排序模型，权重在开发集选择，在留出任务上验证。

模型输出由程序检查ID唯一、候选不丢失／不新增、字段和依据有效。超时或结构失败时使用现有搜索次序与确定性约束回退，标记未完成模型排序，不伪装为评级成功。候选放不下一批时先分组筛选，再统一比较晋级项，不直接拼接不同批次的自评分数。

### 3 等级表达阅读行动

| 阅读等级 | 含义 | 行动 |
| --- | --- | --- |
| 优先读取 | 任务匹配高，证据用途和直接性有明确线索，没有已知的相关严重问题 | 先占用读取额度 |
| 探索读取 | 相关性较高，但主体、出处或来源背景有待核实 | 保留有限读取名额，防止新站和冷门材料始终被排除 |
| 候补读取 | 间接相关、疑似重复、时间口径不符或存在相关问题 | 前列不足或任务需要交叉核对时再读 |
| 本轮不读 | 范围外、无效、确定重复或足以判断与本次任务无关 | 保存原因；不将本轮决定升级为永久网站评级 |

“优先读取”不代表已认证可靠。一个有充分直接性线索但缺乏独立信誉证据的来源，可以在可靠性仍为未知时排到前列。

## 四 阅读额度要兼顾独立性和未知来源

以单章节6次读取尝试为初始实验配置，可分配4次给高优先级候选，1次补充独立来源或未覆盖的子问题，1次探索高相关但背景未知的候选。名额不能重复计数；缺少合格候选时按已公开的回补规则分配，不为凑数读取无关页面。

首轮同一发布主体／独立上游原则上最多2次，规则可随任务调整。例如核对同一公司的不同年度披露可以需要更多原始文件；不能为了来源数量而放弃关键材料。不同域名不自动视为独立来源，反对材料也不因立场不同被扣分。

先读3项，再用剩余额度处理失败、补齐时间／指标和独立性缺口。目标正文不可用时继续候补；出现同上游转载时降低其余重复项；发现真正原始出处时将其加入候选，并经过同一范围、排序和预算流程。后续只更新新的候选依据，不用“与首篇一致”作为可靠性的加分依据。

当前默认实验仍限制为6次读取尝试，失败也消耗尝试额度，不把“直到拿到6篇可用正文”作为隐性扩容。实际项目还需遵守报告总预算、并发和时间保护。来源背景调查、重排及读取分别记录耗时和费用。

## 五 排序例子

假设任务为“查某行业2024年中国市场规模及统计口径”，以下是虚构的设计用例，不是实测结果：

| 候选 | 已有线索 | 预期处理及理由 |
| --- | --- | --- |
| 已核实发布者的2024年原始报告 | 原发布目录能匹配对象、地域和口径 | 优先读取，直接性与任务适配较强；不因此声称报告中的数值已核实 |
| 有适用来源依据的媒体解读 | 明确引用同报告，有背景解释 | 可作补充，原报告通常先读；同上游不算独立证据 |
| 政府站2020年其他统计指标 | 域名身份明确，但年份和指标均不符 | 后列或本轮不读，官方身份不能弥补不相关 |
| 陌生行业站的相关原始调查 | 摘要说明样本和统计期，身份未知 | 分配探索读取，读取后核验调查和主体 |
| 多个文库站的同报告搬运页 | 有充分线索表明同一上游，可能仅预览 | 保留可访问的必要备选，不占满首轮额度 |

这里不输出想象的分数或性能提升。该例检验的是策略应满足的相对次序和未知处理。

| 位置 | 建议改动 |
| --- | --- |
| 新增 `url_ranking_service.py` | 接收章节任务、候选与来源记录，输出有理由的完整队列和候补 |
| 新增来源记录服务 | 身份与可靠性证据分别存储；支持未知、范围和版本 |

| `scout.py:_enrich_results_with_full_text` | 在范围过滤后调用新排序，并分批调度读取及更新候补 |
| `web_reader_service.py:read_many` | 继续负责一次批次的读取；反馈调度放在Scout／排序服务，避免两处控制预算 |
| 研究状态和会话证据存储 | 记录候选、排序版本、来源依据版本、读取决策与真实结果，并支持恢复 |
| `ToolRuntime`及事件 | 分别记录排序、来源调查和网页读取的执行状态、用量与降级原因 |

候选记录建议包含 `candidate_id / original_url / canonical_key / section_id / search_rank / provider / snippet / profile_ref / priority_band / rank / reason_codes / evidence_refs / unknown_fields / read_status`。来源标签与阅读等级分别展示。

缓存键至少包含章节任务、候选集指纹、来源记录版本、模型与策略版本。换章节应重新比较，不能把一个URL在前一个任务的高优先级原样复用。恢复时沿用已存队列和已消耗额度，输入依据改变则生成新版本，保留旧决策。

## 七 如何验证是否更可靠

### 数据与基线

先建立30—50个真实研究查询的开发／留出候选集，每题保留10—20条原始候选，包括从未被旧规则读取的项。题目覆盖政策、统计、企业披露、媒体、学术、转载和未知来源。只评历史已引用网页会产生选择偏差。

冻结搜索响应、任务、时间点和当时可用的来源记录。读取前排序器只能看这些材料；人工在读取后独立标注实际正文的相关性、证据适配、原始出处、正文可用性和重复上游。标注人员不看算法排名，至少双人标注争议样本并复核。

按问题／转载家族分开开发集与测试集，并单列未见发布者和时间外样本，避免同一篇报告的转载跨集合泄漏。来源依据也要按时间冻结，不能把后来的调查结果用于声称当时已经知道的评级。

比较搜索引擎原顺序、当前规则、仅元数据模型重排、加入来源依据和多样性的新方案；分别消融来源依据、未知探索和读取反馈，判断具体收益。所有组保持相同候选池、读取尝试预算及总体资源上限，额外来源调查和模型开销单独列出。

### 指标与验收

| 指标 | 回答的问题 |
| --- | --- |
| nDCG@6及成对排序一致性 | 值得读取的候选是否更靠前；实际增益标签独立定义，不能把算法自评分当金标 |
| 每6次尝试取得的可用且相关正文数 | 有限读取额度是否更有效 |
| 独立上游数和章节要素覆盖 | 是否被同一报告转载占满、是否漏对象／年份／指标 |
| 高价值候选漏选率和未知来源命中 | 是否因缺信誉记录而漏掉有价值的新来源 |
| 评级理由支持率及身份误报率 | 解释是否有真实依据，是否把自称官方当作核验 |
| 排序耗时、总耗时、token和费用 | 排序收益是否值得额外开销 |

按题做配对比较并报告不确定区间，不能把同题多个URL当作互相独立的样本扩大显著性。先设定可接受的漏选、时延和费用边界，再在开发集选参数；在留出集核验，不用同一批数据反复调参后宣称可靠。

报告引用支持率可作为后续端到端指标，但要区分搜索没有召回、排序未选、网页读取失败和Writer误用四种原因。排序器只能优化候选池内的选择。

## 八 失败案例与实施顺序

当前没有实测失败样例。以下为需要纳入验收的风险用例：

| 用例 | 应有处理 |
| --- | --- |
| 标题含“官方权威报告”，域名归属未核实 | 不因标题直接给高信誉；保留身份待核实 |
| 大学域名的活动新闻 | 分类为相应文档，不自动成为研究证据 |
| 主域有信誉记录，子域为用户托管区 | 不自动继承不适用的评级 |
| 多家网站转载同一份错误材料 | 合并独立上游，重复不当作共识加分 |
| 新站无背景记录但提供细分原始调查 | 探索读取，保留未知信誉 |
| 时间字段实际为抓取／更新日期 | 不当作统计期或研究发表日期 |
| 可靠站点当前读到验证码 | 本次正文拒绝／待核实，不因此永久降低网站信誉 |
| 已撤稿论文成为“撤稿原因”查询对象 | 允许作为研究对象读取，显示状态并查对应通知 |

先实现候选合同、元数据重排、多样性与决策日志，以现有规则为对照；再补可追溯的来源记录及有界调查；最后在相同预算下加入读取反馈并验证。首期无需训练大型评级模型，也无需恢复旧的事实提炼。

## 研究依据与适用范围

[Media Background Checks，EMNLP Findings 2024](https://aclanthology.org/2024.findings-emnlp.283/)研究检索和汇总来源背景信号，可借鉴依据收集方式，不能把背景摘要直接当成已校准来源分数。

[RA-RAG，EMNLP 2025](https://aclanthology.org/2025.emnlp-main.1738/)将来源可靠度与相关性共同用于材料选择，并通过跨来源信息估计可靠度。这里借鉴分开处理两类信号的思路；该论文不是已经验证本项目“未读候选URL排序”的成品。

[Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)提供登记文献的元数据与部分更新信息，可用于候选文献匹配；元数据存在不等于研究可靠。[NLM说明](https://pubmed.ncbi.nlm.nih.gov/disclaimer/)明确区分数据库收录与单篇质量背书，[撤稿和更正关联政策](https://www.nlm.nih.gov/bsd/policy/errata.html)可作为学术状态核查接口设计的依据。未查到撤稿信息应标为未完成或未取得信息，不能直接写成“从未撤稿”。

这套方案的可靠性应由上述项目内评估建立。现有源码和论文支持其设计动机，不提供本项目的准确率或提升幅度。
