# 信源评分写作参考与读取筛选边界分析

- 分析日期：2026-10-17（Asia/Singapore）。
- 评估对象：旧模型可信度分数是否让Writer优先采用高分证据；读取前是否按来源质量拒绝读取URL。
- 数据／配置口径：静态阅读当前工作区和已取得的Git版本 `HEAD`、`58af4e9f`。这些历史版本证明旧机制曾如何实现，不等同于2026-10-16改造前完整源码快照。本次未请求模型、未抓取网页、未运行效果评测、未修改业务代码。
- 原始结果：[静态检查记录.json](../backend/eval/data/信源评分写作参考与读取筛选边界核查-20261017/静态检查记录.json)，包含当前／历史片段、版本、行号与SHA-256。

## 结论

旧模型评分发生在读取正文后的事实提取阶段。已检查的旧Writer把可信度数字放入提示词，供模型参考；没有在这条取材路径实现按该分数排序、过滤或计算证据权重。因此不能直接说“高分证据一定被更多采用”。

用户设想的机制是读取前的来源筛选。项目读取前确实有一套规则分数，但它只决定读取顺序，没有以低分为理由直接拒绝读取URL。读取后的正文准入则判断页面是否可用，不能代替来源可靠性评级。

## 逐阶段分析

| 阶段 | 当前／历史实现 | 实际作用 |
| --- | --- | --- |
| 读取前 | `candidate_source_score`规则分数 | 确定先尝试读取哪些候选 |
| 读取后、事实提取时（旧机制） | 模型返回 `source_type`、`credibility_score` | 提供类别和可信度标签；与事实提炼共用调用 |
| 写作时（已检查旧版本） | 事实文本后拼接“可信度: 数字” | 给模型上下文参考，没有显式数值权重 |
| 正文读取后 | 正文规则与不确定页面模型复核 | 拒绝导航、错误／验证码等不可用正文，不判断来源信誉 |
| 当前RAG取材 | 词法、向量、RRF、相关性精排 | 判断片段与问题相关程度，没有使用旧的可信度分数加权 |

### 1. Writer确实看过分数，但没有强制优先机制

Git版本 `58af4e9f` 的 `agents/writer.py:448–460` 先按章节关系选事实，没有关联时取前10条，然后格式化为：

```text
事实内容（来源: 来源名称，URL: 网址，可信度: credibility_score）
```

同文件第539行将这些内容放进章节提示词的“相关事实”栏目。当前HEAD历史版本也存在同样格式化代码。已检查的章节提示词和取材代码没有“按可信度降序选取”“低于某分拒绝”“可信度乘相关性”等实现。

能直接确认的是模型收到过评分数字。模型可能受其影响，但是否更常引用高分材料、影响有多大，没有实测证据。当前新研究已不再调用旧事实评分路径，Writer直接读取原文证据。

### 2. 读取前的低分只是排序，不是阈值淘汰

当前 `quality_pipeline.py:26` 的规则将指定域名记为-100，政府／教育域名加80，部分标题关键词加50，PDF后缀加20，文库等关键词扣30。

`scout.py:938–947` 仅执行降序排序，并把全部范围内候选和读取额度传给工具；没有按分数阈值删除候选。

`web_reader_service.py:754–775` 的 `read_many()` 按顺序选择前 `limit` 个非空、去重后的URL，没有检查上述分数。因此“低优先级”并不保证“绝不读取”。

**根据代码推导的例子，非实测：**只有3个不同的范围内候选，读取额度为6，其中一项为-100。该项仍会被选中尝试读取；如果候选很多且额度为6，它才可能因为排在后面而未被选中。被选中不保证请求成功或正文准入。

读取前确实会进行来源范围过滤等检查，但那是用户允许范围及请求条件，不是来源信誉分数阈值。

### 3. 可以分别设计读取决策和写作决策

如要实现用户设想，应明确两个不同用途：

- 读取前：根据候选URL、标题、摘要及已有来源记录判断是否值得读取，减少明显无关或有充分依据排除的候选；证据不足应保留未知状态。
- 读取后：结合实际正文、出处及独立依据判断可靠性，再决定写作引用的优先顺序、限定措辞或补查要求。

读取前只有候选信息，无法判断尚未读取正文的完整性和具体论断支持性。写作时也不能让高来源分数替代原文支持判断；高信誉网页上的无关片段仍不能证明目标结论。这里是架构边界说明，本次没有新增筛选或加权实现。

- 网页实测、模型调用和效果评测运行数均为0。
- 本次没有新增实测失败样例。上面的低分URL仍被选中例子属于代码规则推导。

- 间接推断：提示词数字可能影响模型偏好；阅读预算可能使低优先级候选未被读取。
- 尚未评估：Writer真实采纳偏好、来源分数准确性、URL筛选效果和独立评级服务收益；没有验证线上部署状态。

建议产品说明将这几个概念分别称为“候选阅读优先级”“来源可靠性”“正文可用性”和“片段相关性”。若后续实现评级，应显式规定它影响哪个阶段和哪些决策，不能仅输出一个分数就声称已完成阅读过滤或写作加权。
