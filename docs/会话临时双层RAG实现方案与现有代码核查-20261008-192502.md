## 总体设计：一份原文，两种召回视图

临时表示数据生命周期，不能仅把所有数据放在当前Python进程的内存里。跨20多轮、服务重启和断点恢复都需要相同证据编号与可恢复存储。

建议使用已有PostgreSQL保存不可变正文、结构树、chunk元数据、证据空间状态和删除任务；Milvus新增独立的临时证据集合，保存chunk向量及用于检索过滤的字段；Redis只缓存热点视图。集合按应用复用，不能每个会话都新建集合。两层通过unit_type选择不同单元，同一表格单元可被两层检索，正文和表格无需各复制两份。复用连接能力，但现有通用MilvusService的schema与过滤接口不足以直接承载新协议，需要独立适配器。

逻辑结构为：会话证据空间 → 不可变来源正文版本 → 来源小节 → 段落 → 原句；表格挂在对应小节/段落位置，使用独立table_id。报告章节ID与来源小节ID分别命名，避免二者混用。

研究状态逐步改为保存evidence_space_id、corpus_revision、相关chunk/fact/claim引用及当前稿，按需在后端取原文。不得在召回结束后又调用全量formatter把整个库补回模型输入。后台核验可以读取完整来源，给模型的材料始终经过本轮视图与预算。

## 生命周期与TTL

建议默认采用idle模式：expires_at＝最后一次成功写入的新会话消息时间＋86400秒。若用户继续发问并得到回答，整个证据空间续期，旧证据不会因插入较早而单独过期；检索、标题更新、摘要、重试和索引构建不能续期。可另配absolute模式：创建证据空间后固定24小时，后续发问不延期；这种口径会使超过24小时的长会话失去早期证据，需明确配置。

会话结束用显式close操作定义，例如新增POST /sessions/{id}/close；一轮研究完成、SSE断开、暂停、失败或浏览器切换都不代表整个会话结束。用户明确结束或删除会话，证据空间立即关闭；过期判断在每次召回和按ID回读时执行，不能等待定时任务后才拒绝读取。

关闭先以事务标记closed并增加generation，将待清理资源清单写入Outbox。取消或阻止关联运行继续写入；异步抓取/embedding结果提交前复核generation，防止关闭后重新写出证据。随后幂等删除该用户/会话的正文、chunks、向量、缓存、内部含原文的消息/摘要、研究检查点及关联原文文件。失败的删除任务重试，记录purge_pending/purged和延迟。关闭后的读写从业务层立即拒绝，物理存储清理由后台完成，二者分别记录。

当前网页缓存默认保留7天且按URL缓存。临时会话模式应使用会话作用域的缓存路径/键，或绕过全局正文缓存；不能删除另一个活跃会话拥有的共享缓存。临时证据不写入永久知识库或长期记忆。可保留已交付报告正文及来源URL，但原句回读随证据过期；含完整原文的引用附件不能当作普通报告元数据永久保留。

生产原文日志也必须纳入该生命周期。评测机器归档按照项目AGENTS.md另行保留并标记evaluation_archive，不能宣称它们随生产会话TTL删除；本次仅设计，不删除已有实验归档或旧检查点。

TTL由应用层会话状态决定，不直接套最新Milvus实体TTL。Milvus当前官方文档标注实体级TTL适配3.0.x；集合TTL按插入时间＋时长计算，不能直接表达本方案的会话滑动续期。[Milvus官方TTL说明](https://milvus.io/docs/set-collection-ttl.md)。现有项目配置2.3.3，因此先使用已有版本能兼容的过滤/按ID删除方案，在线兼容性需实现时验证。

## 文档入库与metadata

Scout获得准入通过的正文后，先保存不可变正文版本，再进行结构解析。顺序是识别标题和表格、建立段落树、对非表格文本分句；不能先通用分句再尝试恢复被拆碎的表格。以document_id、正文哈希、chunker_version和原文位置生成稳定chunk_id。同URL正文变动创建新document_id；旧报告引用仍指向旧版本，不能覆盖或重新编号。

每个chunk包含以下元数据：

| 字段 | 用途 |
|---|---|
| user_id、session_id、evidence_space_id、topic_id | 用户/会话隔离、当前主题与回到旧主题的范围控制 |
| document_id、content_sha256、source_id、source_url、title | 精确定位哪份来源正文版本，保留原始来源关联 |
| chunk_id、unit_type、parent_chunk_id、source_section_id、heading_path | 小节、段落、原句或表格的层级关系 |
| paragraph_ids、sentence_ids、ordinal、prev/next_chunk_id | 定位原段、邻句扩展、顺序回读 |
| char_start/end、source_spans、page/bbox（可用时） | 连续正文偏移；表格多片段位置；PDF页与区域 |
| table_id、row_range、column_ids、header_spans、note_spans | 原表归属、数据范围、原表头/单位/脚注 |
| created_at、corpus_revision、chunker_version、embedding_version | 增量构建、重试幂等及恢复一致性 |
| status、evidence_space_generation、expires_at | 过期/关闭控制；expires_at以证据空间状态为权威，chunk副本需同步 |

来源小节ID不能替代报告outline ID；paragraph_ids允许一个父chunk包含多个完整短段落。偏移相对于冻结的规范化正文，不冒充未经提取的原始HTML/PDF字节位置。表格source_spans可能不连续，回读时标记为由原文片段组装，不能称连续原文引用。

## 第一层：改写后的研究材料召回

链路为当前用户原话 → 会话话题关系/指代判断 → 最新resolved_query与有效要求 → 选择目标报告/主题 → 段落或小节召回 → 本轮研究计划。摘要用于追问理解，来源原文用于研究证据，两类材料不能相互替代。

小节较短且不混入表格正文时可以整节作为chunk；长小节按完整段落分组，初始目标400—800token、可配置上限1024。表格始终独立。对长段落只沿句边界分片并保留所属paragraph_id，不能仅按字符截断。

先按用户、会话、证据空间有效状态、主题、来源范围、时间/地域与允许的正文状态过滤，再使用BM25＋向量召回、RRF融合、rerank，按token预算装包。可从两路各40候选、融合60、精排8开始，研究材料总预算8192token；大任务按章节拆分，不以固定top-k代替token预算。过滤和最终回读都要验证会话可读状态，防止索引延迟造成过期访问。

纯字数/措辞/格式编辑直接以选中的已有稿和当前要求为主，不默认回读全库；需要确认原有论断时使用已绑定引用或第二层召回。补证先查询临时库，存在明确缺口再给Scout外部搜索；新增章节先给Architect规划，再按子问题调用此层。组合操作可以分阶段执行。新主题不改写无省略的完整query，也不自动带入旧主题证据；用户回到早期主题时才恢复其topic_id。

Agent内部不重复做会话追问改写。Architect/Scout可以为各自本轮子任务生成检索问题，但使用相同、已提交的当前任务与有效要求。检索记录必须保存query、task_version/turn_id，检验其不是前一轮任务。

## 第二层：逐论断召回与引用绑定

第一层提供段落上下文，Writer产出草稿及原子论断后，对新增/改变的每条claim查询句子或表格单元。正文支持原句编号；表格支持结构单元编号。首先查本轮相关正文及该论断已关联的父chunk，再在缺证据时扩大到同一会话/主题的有效来源；不能永久限于第一层命中文档，否则可能漏掉反证。

使用论断中的实体、指标、数字、单位、时间、条件作为查询，同时允许召回支持、否定、修正和限定条件。按需要扩展同一段落中前后1句，确保比较对象、否定词、日期和代词先行词完整。建议每条论断精排3—5个候选单元、证据预算1200—2000token，批量核验还要限制整次请求总预算。

保留已有document_id＋sentence_ids协议，新增table evidence_unit_ids或统一的版本化引用协议。模型只选择实际展示的编号，程序按编号从冻结正文恢复准确原句/表格；不使用模型返回的quote作为证据。表格单元再映射到原行/表头/脚注位置，必要时兼容旧行级sentence_ids。

召回相关不是核验通过。原文绑定检查、语义核验以及表格数字/单位/行列对应检查都在此之后。若论断缺乏证据，标为insufficient/unknown，修订或删除论断，确需新增研究则回Scout补搜；不能给一个最近邻引用强行交付。未改变的论断可以复用原绑定及版本一致的核验结果，但文本变动不能直接继承“通过”。对于旧正文编辑，新草稿没有任何证据支持时不能借旧报告本身新增事实。

## 表格在两层中遵守同一协议

小表保留整表；大表沿完整数据行分组，每块包含原表题、全部必要表头（含多级表头）、单位及相关脚注。两层引用相同table chunk，第二层不能把一行数据剥离表头后作为普通句子。每块保留table_id、原始row_range、header_spans/body_spans/note_spans；重复表头不算新增记录或独立证据。

单行连同表头超出预算时默认明确报出结构化块超长并换装包策略，不能静默截断单元格。需要列方向分片时，应单独实现保留行主键、指标列、单位、原列坐标的策略并验证。Markdown可复用现有切分器；HTML rowspan/colspan、PDF缺失表头/OCR需专门解析，现有文本读取器不能保证恢复其结构。解析失败记录原因并回读/补取，不把丢失列关系的结果当成可靠表格。

## 输入预算与增量索引

每次模型调用前，按照当前模型输入上限计算system、有效任务、当前稿、历史摘要、候选证据和序列化开销；预留输出与安全余量。证据可用预算取配置上限和请求剩余预算二者较小值。优先移除低相关候选、合并重复句、拆分章节/核验批次；不能截断原句或表格。仅历史压缩无法解决“当前证据prompt”自身超限。

抓取后按正文哈希判断是否已入库；只嵌入新增或变更chunks，embedding/rerank缓存按会话、内容哈希和模型版本隔离并共用证据空间TTL。不在每轮重建所有向量。保存corpus_revision与索引状态，断点恢复可重建缺失向量；索引失败显式记录，可使用有预算的词法候选，不能降级为全量证据发送。关闭generation能阻止正在构建的旧索引复活。

## 失败样例、验证指标与局限性

已确认的失败样例是第24轮：摘要已采用，但全量当前证据材料使请求超限。方案目标是减小当前材料视图，并保持证据召回与引用质量；实际改善幅度尚未测量。

实施后记录：每轮corpus/chunk/表格数量、新增与复用向量数量；两层候选数、最终命中单元、去重后证据tokens、当前总输入/剩余预算/溢出原因、延迟和模型调用成本；论断有证据比例、编号合法率、核验支持/矛盾/证据不足比例、表头保留率及原文回读一致性；TTL不可读时间、实际删除延迟、残留资源与重试数；服务重启/断点恢复一致性、跨用户/会话误召回和关闭后复活次数。

检索Recall@k需要人工标注相关原句/段落，不能只凭相关性分数或NLI结果冒充召回率。应比较原全量输入与两层RAG在同一题/轮次上的tokens、回答要求满足情况和引用正确性。输入保留比例＝本轮选中证据tokens/同口径全量证据tokens；输入缩减率＝1－该比例，这与历史摘要压缩率分开记录。

必要机制验证包括：24小时临界点与显式结束；正常第N轮完成不删除；新消息续期但检索不续期；不同会话相同URL不串库；版本改变不破坏旧引用；带否定/跨句条件的召回；多级表头和长表拆分；并发关闭与embedding入库；索引不可用时不回退全量prompt；旧检查点恢复与TTL后不能复活。

已确认：上述源码能力、缺口、项目声明版本以及此前失败记录。间接推断：限定本轮材料和句子引用视图有望减少超限；删除清单统一才能满足临时证据生命周期。尚未评估：两层RAG召回率、表格解析准确率、在线存储兼容性、TTL完整清理、延迟/费用、改造后的回答质量及30+轮容量。

结论：建议实施绑定会话的临时双层RAG，并同步完成输入预算、句子/表格引用协议和全副本生命周期。单独加向量检索或设置集合TTL不足以解决当前全量prompt与会话结束后证据残留的问题。
