## 数据与配置口径

冻结抽取后的正文版本，标注问题、标准答案、必要证据及其原文位置。标注证据必须独立于待比较切分器，不能把现有 chunk ID 当作跨策略金标准。表格证据包括必要的行列标题、单位、时间与注释；允许标注多个等价的充分证据集合，避免只奖励其中一处重复表达。

原文位置以文档版本和位置共同标识，不能将不同位置的同一个词视作同一证据。采用同一 tokenizer；位置映射困难时可以使用字符位置指标，但需明确其不是 token 指标。排除空白等内容的规则须固定。

比较切分策略时固定语料、问题、embedding、精排模型、检索配置和生成配置。主比较使用相同的最终上下文 token 上限 B，并记录实际使用量；Top-K 作为补充，因为块大小不同会使相同 K 对应不同输入量。记录候选召回、精排、邻居扩展和最终预算选择各阶段指标，避免错误归因。

当前设置类默认 chunk 上限为 1024 token，上下文预算为 8192，引用预算为 2000；这些仅是源码默认值，运行时可被环境变量覆盖，也不代表最优参数。实际评测必须保存有效配置。

## 核心指标

定义 G 为某问题金标准证据的原文 token 位置集合，R_B 为预算 B 内最终返回内容映射出的原文位置并集。位置集合去重；重复输入另计成本。

| 层次 | 指标 | 定义与用途 |
| --- | --- | --- |
| 切分本身 | 原文覆盖率 | 某检索层全部块覆盖的原文有效位置数 / 应保留原文有效位置数；检查漏内容。两层分别计算，父子块不能重复累计。 |
| 切分本身 | 原子证据完整保留率 | 可在至少一个单块中完整找到的局部证据单元数 / 标注单元数；用于检查边界破坏。跨文档推理不要求全部信息挤进一个块。 |
| 切分本身 | 表格结构完整率 | 保留必要数据行、行列标题、单位及注释的可独立解释表格块数 / 被检查表格块数；需人工金标准或可靠结构标注。 |
| 切分本身 | 原文回读成功率 | 可按 source_spans 正确恢复来源片段的块数 / 被检查块数；仅允许事先规定的连接符与格式规范化。 |
| 切分本身 | 入库失败率、超限率 | 按文档和证据分别统计；超长单句或整表被拒绝时必须计入，不能只评成功入库样本。 |
| 检索主指标 | Token Recall@B | `|G ∩ R_B| / |G|`：必要证据找回多少。 |
| 检索主指标 | Token Precision@B | `|G ∩ R_B| / |R_B|`：返回原文中有多少是标注证据。 |
| 检索综合指标 | Token IoU@B | `|G ∩ R_B| / |G ∪ R_B|`：同时反映遗漏与无关内容。 |
| 检索主指标 | 完整证据命中率@B | 预算内覆盖至少一套完整充分证据的问题数 / 可回答问题数；检查多证据题是否只找回一部分。 |
| 检索辅助指标 | Hit@K、MRR、nDCG@K | 分别观察是否命中、首个相关结果的位置、分级相关性的排序。跨切分器比较时需注意块数量和相关标签变化，不作唯一依据。 |
| 效率 | 重复率、实际输入 token、索引体积、延迟 | 重复率可用 `1 - 唯一原文位置数 / 输入中原文位置出现总数`；合成元数据单独计入实际输入成本。延迟记录 P50/P95。 |
| 端到端 | 答案正确率、证据忠实度、引用支持率 | 固定生成模型与提示词，验证检索改善是否真正帮助回答；不能把生成结果的全部差异归因于切分。 |

Token Precision 的去重集合口径不会充分惩罚 overlap 重复，因此必须配合重复率和实际输入 token。表头重复可能有必要，不以最低重复率单独判优。

G 非空而 R_B 为空时，Recall 和 IoU 为 0；Precision 可按约定记为 0 并标记空返回。无答案问题不进入上述 Recall 分母，另评错误证据返回和拒答表现。逐题计算后报告均值、各类别结果和样本数，必要时提供配对 bootstrap 差值区间。

## 逐类分析设计与失败样例

以下是待验证的示例，不是本次观察到的失败。

| 类别 | 示例失败 | 优先观察 |
| --- | --- | --- |
| 普通事实 | 数值所在句保留，但主体在上句且未取回 | 局部证据完整性、完整证据命中率 |
| 条件与否定 | “增长 20%”被取回，“仅限海外市场”遗漏 | 证据 Recall、答案与引用支持率 |
| 跨段、多来源 | 找到公司 A，漏掉比较所需的公司 B | 完整证据命中率，不能只看 Hit@K |
| 表格 | 返回“120”，缺年份、单位或列标题 | 表格结构完整率、必要证据覆盖 |
| 长句与大表 | 无法切分导致整个来源不能入库 | 入库失败率、有效正文覆盖率 |
| 重复与 overlap | 多块包含同一证据，消耗预算后漏掉其他证据 | 重复率、实际输入 token、Recall@B |

项目上下文层分别检查 paragraph/table/record，引用层检查 sentence/table/record。原子证据单块完整性与检索后的组合完整性分开报告，邻居扩展恢复的信息不能冒充原始单块已完整。

## 局限性与下一步

块内语义相似度、主题一致性、长度分布可以辅助诊断，但没有唯一理想切分；高相似度不能证明答案证据完整。边界 Pk/WindowDiff 等指标只有在具备适合任务的人工分段金标准时才有意义，通常不作为本项目首要指标。

Token 指标依赖证据标注质量，可能低估有用的解释背景；完整证据命中率依赖充分证据集合定义。LLM 判断需要人工抽检。正文抽取缺失与切分缺失应分别统计：切分评估以冻结正文为输入，不能据此证明原始 HTML/PDF 无损。

建议先建立覆盖普通事实、边界条件、表格、多证据问题的小型人工集，用于调试；再在独立测试集比较方案。优先采用“结构与回读质量达标，在同预算下提高完整证据命中率和 Recall，再比较 Precision/IoU 与成本”的选择规则，不预设通用合格阈值。最低实施集合为完整证据命中率@B、Token Recall@B、Token Precision@B、表格结构完整率和实际输入 token；覆盖率、失败率、回读成功率作为工程检查。

## 方法参考

- [Chroma：Evaluating Chunking Strategies for Retrieval](https://www.trychroma.com/research/evaluating-chunking)：采用 token 级 Recall、Precision、IoU 比较切分与检索。本文的固定预算、结构检查和分层方案是针对本项目的建议。
- [Ragas：Context Precision](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/context_precision/)：其上下文相关性与排序评估口径不能直接等同本文基于原文位置的 Token Precision；使用时需明确具体实现。
