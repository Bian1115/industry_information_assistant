# 会话任务句子编号溯源实现及回归分析

## 日期、对象与口径

评估日期：2026-10-07，时区Asia/Singapore。本次评估对象是会话任务的句子编号溯源及非阻断执行机制。使用当前工作区代码、构造模型返回、模拟数据库/父图和内存图运行离线回归；没有调用真实模型或写入真实业务数据库，没有启动或恢复主线程的32轮实验。

用户确认的口径：程序对本轮query分句；模型引用句子编号；引用仅用于离线溯源，不检查引用文本是否逐字包含在原文中，也不因编号缺失、不存在或格式异常而改变执行计划。任务类型、要求值、目标报告和契约版本等业务检查仍执行。

## 实现与数据流

1. `query_sentence_index()`生成S1、S2等编号，保存原文、Unicode字符起止位置、turn_id、query_sha256和分句版本。分句保护URL、反引号代码、代码块和中文引号，原文不改写；它是确定性规则，不是语言学句法分析。
2. 会话任务模型提示词提供程序分句，operations及requirement_changes使用可选`source_sentence_ids`；模型schema不再要求或展示quote。旧任务的quote字段仍可读取，但只保存作兼容溯源，不参与会话执行校验。
3. `task_source_trace()`记录reported_sentence_ids、resolved_sentence_ids和诊断warnings。缺失、未知编号、异常类型或重复编号只使溯源status变成issues，不把任务status改成clarify/fallback，不把edit/augment改成replan。
4. 会话要求提交显式使用`validate_quotes=False`，取消后续补丁阶段的逐字引用门槛；合法数值、字段类型、add/replace/remove语义和契约版本检查继续执行。提交记录带source_quote_check=false和source_trace。旧的非会话任务补丁入口仍默认保留原引用检查，未扩大本次修改范围。
5. 保存模型未经清理的raw_response、parsed_response、句子索引和validation_error。解析失败或核心任务结构失败时也保留原始响应；没有调用任务判断模型的首轮同样保留句子索引。
6. 图入口重校验保留turn_id。审计数据经现有session_task_metrics进入研究状态、检查点及报告交付元数据；HTTP澄清的references_data也保存session_task_metrics。因此模型输出错误后转入澄清时仍可溯源。

主要记录位置：

- `research_context.task_trace`和`research_context.task_metrics.task_trace`。
- `research_state.session_task_metrics.task_trace`、`research_state.session_task.source_trace`。
- `research_contract.contract_update.source_trace`。
- 报告或澄清助手消息的`references_data.session_task_metrics.task_trace`。

编号是否能定位与操作是否符合用户意图是两种指标；本次不会因为引用能定位而宣称模型正确理解了要求。

## 失败样例与行为

|场景|在线结果|离线记录|
|---|---|---|
|编号S1/S2存在|正常edit，要求提交为1200字|source_trace.status=resolved，保存原文位置|
|编号S999不存在|仍正常edit及提交要求|unknown_sentence_id，status=issues|
|编号数组缺失/为空|仍正常edit及提交要求|missing_sentence_ids|
|编号为null、字符串、对象或混入数字|仍按有效业务任务执行|invalid_id_list或invalid_id_type，保留原始值|
|编号重复|仍按有效业务任务执行|duplicate_sentence_id|
|旧quote改写、为空或类型异常|不因quote阻断路由/要求提交|legacy_quote保留，不检查原文包含关系|
|与第15轮类似的“上一轮”补证追问，引用错号但任务结构完整|ready/augment|引用问题只进溯源诊断|
|模型返回坏JSON或核心任务schema错误|原有降级/澄清仍执行|raw_response和validation_error保存|
|任务字段值为非法字数、未知操作或目标报告不在候选中|仍拒绝业务任务|这些是业务问题，不是引用问题|

对历史第15轮的意义：移除了当时“quote必须逐字来自本轮原话”这一阻塞条件。该轮失败前的模型原始JSON没有留存，本次第15轮风格测试使用构造的模型返回，不能宣称已经复现并恢复真实第15轮。

## 局限性、结论与下一步

**已测量**：编号/原文位置确定性、引用异常不阻断、会话要求提交、重校验保留turn_id、成功与失败原始响应记录、首轮索引保存、模拟HTTP澄清元数据，以及72项相关机制回归。

**间接推断**：本次改造可消除引用格式错误触发的任务退回或澄清链路。它不解决真正的目标歧义、模型错误改写、错误要求值或已偏题历史报告本身。

**尚未评估**：真实模型是否给出正确的句子编号、引用是否支持对应操作、实际数据库持久化、32轮对话是否能完成，以及回答正确率。分句规则的变化需要更新分句版本；句子编号须结合本轮标识与query哈希解释。

结论：编号溯源已与会话在线执行解耦。编号缺失、无效和旧quote不匹配不再阻断有效业务任务；其诊断及原始模型输出保留供离线评估。下一步可在主线程获授权的真实实验中分别统计溯源可定位率、操作与原话的一致性、任务完成率和多轮要求保留，不能以编号有效率代替回答正确率。
