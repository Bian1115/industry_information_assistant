## 当前提示词与编号的实际含义

当前正文生成提示词明确要求只输出自然语言四栏目，不输出 CLAIMS、来源编号或原句。后续 Claimify 完成分句、筛选、消歧、拆解。引用补齐是另外一次模型任务，输出 `section`、`claim`、`references`，每条引用包含 `source_id` 与 `quote`。因此，当前实现并不是让 Claimify 拆解提示词同时完成历史证据定位。

`service/agent_history.py` 的 `_message()` 将数据库历史记录的 `row.id` 转成 `source_id`，并保存 `seq`、`kind`、`call_id` 等信息。`service/agent_context.py` 的回放类型包括模型输入、模型输出、模型错误、工具输入、工具输出、工具错误。工具记录原文当前来自 payload 的规范 JSON 序列化，模型记录则取 content。因此，摘要链路的编号是历史事件 ID，搜索输出只是其中一种事件。

一轮对话可能包含多次模型或工具调用，仅有轮次编号不能唯一定位证据。建议用稳定的消息或事件 ID 定位，轮次和序号用于展示与排序，再增加证据句 ID、原文偏移和来源哈希。文献或搜索源 ID 可以作为独立元数据保留，不能与历史事件 ID 混为同一套编号。

`service/summary_citations.py` 当前 Claimify 路径为每条论断设置整个受限来源池作为候选，并按预算遍历片段补齐引用；此处没有按论断做 BM25、向量召回或重排。候选数量增大会增加引用补齐调用量。源码支持候选子集引用，旧文档提到的“所有候选都必须补齐”问题已不代表当前实现。

## 为什么改编号措辞不足以解释全部失败

既有第一题补充分析记录的直接异常为引用原句不在提供的连续片段中。模型将来源逐词换行改为空格，导致严格字符匹配失败；该运行还未执行到 NLI。该分析另外发现分块否定结论混入全局摘要，以及规划对象被描述成用户指定对象。前置定位失败、来源角色错误和摘要语义问题是不同问题。

最新五题的原始配置为 `claimify-v1`，但 `semantic_verification` 为 false。第35题原始运行结果记录超过 300000 token 预算；既有轨迹分析指出该题尚未进入引用补齐阶段。该运行不能被归类为 NLI 判定不支持，也不能通过改引用编号措辞解释。其他题还受到系统休眠、连接和执行租约影响。

当前 `nli_verifier.py` 在引用带有来源类型信息时，会对 SUMMARY 中仅引用助手历史、任务输入或一般工具记录的研究事实执行 `source_not_research_evidence` 拒绝规则。若目标改为核查“摘要是否忠实保留对话”，必须显式区分这类核验与“研究事实是否有文献支持”。不能只让模型多选对话消息，却继续用研究证据门禁判断所有摘要内容；也不能取消来源区分后把助手陈述当作医学事实。

## 建议的证据定位与摘要提交流程

以下为设计建议，尚未实现或实测。

1. 固定本次摘要输入快照。证据库限定到该会话、智能体或子任务、实际输入范围及旧摘要的来源祖先；不引入后来消息或无关会话。
2. 保留不可变原始记录，建立句子或短段落索引。每条保存事件 ID、轮次或序号、角色、记录类型、证据句 ID、原文偏移、哈希，以及工具输入输出关联。
3. 为每个 Claimify 论断召回相关证据。可采用关键词与向量的混合召回，再按相关性重排；重排不能仅筛选支持证据，还要保留反对证据。候选规模以实际召回率、费用和时间验证后确定。
4. 给模型提供证据句 ID、真实句子及必要相邻上下文。模型选择编号，程序从不可变快照取回 quote 和偏移；不让模型重新抄写原文或计算字符位置。同一句出现多次时，证据句 ID 应指向具体出现位置。
5. 对证据集合核验支持、反对或信息不足，保留说话者、时间、否定、条件、数值和观点归属。需要多条材料联合支持的论断不能只逐对独立判断；用户后续更正也不能简单算作历史自相矛盾。
6. 信息不足时先在本次输入及可回读祖先范围内扩召回、补邻接上下文或检查指代。召回遗漏不等于原文没有支持。网络补充的新知识不能反过来证明旧摘要忠实于旧输入。
7. 对确实无依据的新增断言删除或改写一次，再重新抽取并核验受影响内容。关键用户要求、已完成操作、失败状态与待办不能为了提高通过率被静默丢弃；需要同时检查任务约束及重要内容覆盖。来源真实但文字表述不准时优先纠正表述。
8. 全部要求通过后提交新摘要、引用关系、核验结果和覆盖游标，再从主模型窗口移出旧历史。原始记录继续外置保存；临时索引可回收或重建。失败保留旧状态并返回阶段明确的错误，避免相同材料无界重复摘要。

可直接采用的引用补齐协议草案：

```text
任务是检查摘要论断相对于指定历史输入的忠实性。
final_claim 是固定的待核验论断。
candidate_evidence 提供程序预先编号的历史证据句及必要上下文。
只选择与论断有关的证据句编号，包含支持、反对或解释指代所必需的句子。
只输出 {"evidence_ids": ["输入中已有的证据句编号"]}。
不得输出新的编号，不重新抄写原句，不使用摘要自身充当原始证据。
没有相关证据时返回空数组；空数组只表示本批未找到证据。
程序负责根据编号取回原文、来源记录、偏移和哈希；语义判定由后续核验完成。
```

字段迁移需同步解析器和存储。为兼容旧代码，可以继续使用 `source_id` 表示事件记录 ID，在内部额外维护 `evidence_id` 与轮次信息，无需仅为措辞修改强制重命名所有字段。

## 今年可借鉴的会议论文

### VeriTrail ICLR 2026

[VeriTrail: Closed-Domain Hallucination Detection with Traceability](https://arxiv.org/html/2505.21786v2) 与当前问题最贴近。[作者机构页面](https://www.microsoft.com/en-us/research/publication/veritrail-closed-domain-hallucination-detection-with-traceability/)确认 ICLR 2026；预印本首版是2025年，会议年份是2026年。

重点阅读3.1.2、3.1.3、3.1.4及附录C.2。论文使用 Claimify 抽取最终输出论断，把多次生成过程表示为有向无环图。程序给来源句子编号，模型选择支持或反对论断的句子编号，程序取回对应原句；随后沿来源节点向前追溯。论文还强调证据句脱离上下文可能产生指代歧义。它并不等同于混合检索加重排；将其编号选择和来源追溯机制接入项目 RAG 是本报告的工程建议。

论文标签为 Fully Supported、Not Fully Supported、Inconclusive，与 NLI 的支持、矛盾、中立不能直接一一对应。

### CiteGuard ACL 2026 主会

[CiteGuard: Faithful Citation Attribution for LLMs via Retrieval-Augmented Validation](https://aclanthology.org/2026.acl-long.282/)。重点阅读2.2，新增动作包括论文内全文查找、检索原论断的更多上下文以及跨论文正文片段搜索。它主要解决科学文本应引用哪篇论文，不能直接当作多轮对话摘要核验的实证结果。可以借鉴“找正文证据，而不是只看题名和摘要”以及补上下文的动作设计。

### HARIS ACL 2026 主会

[Coordinating Search-Informed Reasoning and Reasoning-Guided Search in Claim Verification](https://aclanthology.org/2026.acl-long.119/)。方法协调高层验证推理和低层搜索，证据不足时提出事实问题并迭代细化检索；实验使用 EX-FEVER 和 HOVER。适合借鉴跨多条记录构建证据链，但不是专门研究历史消息的字符位置定位。本次核对官方会议页和摘要，PDF获取失败，未完成全文细节核查。

### GAVEL ACL 2026 Findings

[GAVEL: Evidence-Contract Debate with Mechanized Scrutiny for Provenance-Grounded Fact-Checking](https://aclanthology.org/2026.findings-acl.1789/)。该论文属于 Findings，不列作 ACL 主会。它把原子论断绑定到句子或表格单元，再用程序验证标识符和引用片段，可参考4.2和4.3。项目可以单独借鉴确定性引用校验机制，无需因此引入整套多智能体辩论。
