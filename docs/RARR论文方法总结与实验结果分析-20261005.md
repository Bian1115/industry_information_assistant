## 1. 论文讲什么

RARR全称为Retrofit Attribution using Research and Revision。它为已经生成的文字增加一个检索与修订阶段：核查文字中的事实，找到来源，对与证据冲突的部分进行小范围修改，最后输出修订文字及证据集合。

其任务定义是Editing for Attribution：输入原文`x`，输出修订文本`y`和证据报告`A`。目标同时包含：

- **归因/来源支持**：`y`的内容能由`A`中的证据支持。
- **保留**：尽量保留`x`的意图、结构、风格和其他内容。

这两个目标必须一起看。只优化来源支持，可以把一整段回答替换为检索页面上的一句话，甚至直接抄一段来源文字；支持率可能很高，但回答原来的作用丢失了。

与常见RAG的流程关系：

```text
常见RAG：问题 → 检索资料 → 根据资料生成回答
RARR：已有回答 → 生成核查问题 → 检索证据 → 判断冲突 → 最小修订 → 证据报告
```

这意味着它可以接在不同模型或RAG系统之后，不要求改造原始生成器。它仍会依赖核查模型的能力和检索结果质量。

一个重要边界是：**归因不等于真实正确**。有来源支持，只代表某个来源提供了支持；来源可能过时、不可靠，或与其他来源冲突。论文明确把这两件事分开，见第1节脚注2及第9节。

## 2. 怎么实现

### 2.1 用LLM生成全面的核查问题

CQGen（Comprehensive Question Generation）读取整段原文，生成覆盖不同事实点的问题。对话任务还输入历史上下文，帮助解释代词与省略表达。

例如，原文包含某电视剧的首播日期和播出频道，就分别询问首播时间、首播频道，而不是把整句带着日期和频道直接送入搜索框。

论文使用6个人工示例做few-shot提示，采样3次后取问题并集。这里的示例放在提示词中，不更新LLM参数。核查问题把待验证的属性留成未知，比直接搜索带有错误结论的句子更容易找到纠正证据；论文也讨论了直接搜索原句带来的确认偏差。

### 2.2 搜索网页、切分证据、重排

论文主实验对每个问题执行以下操作：

1. Google Search检索5个网页。
2. 从网页中用4句话的滑动窗口提取候选证据，遇到标题时断开。
3. 用问题与证据的相关性模型`S_relevance(q,e)`进行排序。
4. 每个问题保留最相关的1段证据。

论文相关性模型是按MS MARCO训练设置微调的T5-large。注意，相关性排序只能说明证据适合回答问题，不能直接证明原文陈述被证据蕴含。

### 2.3 一致性判断：先决定是否需要编辑

初始化`y = x`，逐个处理检索得到的`(q,e)`。

一致性模型输入当前文字`y`、核查问题`q`和证据`e`，比较两者对问题给出的答案。论文用few-shot提示，让模型先说明原文和证据的答案，再做一致性判断。

公开提示包含“支持”“冲突”“不相关”的示例，执行器只在判为冲突时开启编辑。证据不相关、没有回答问题时，原文可能被保留。因此，“没有修改”不能解释成“核查通过”。

这个门控能减少不必要修改。它也是论文最重要的实现细节之一：如果每遇到一条证据都要求重写，模型可能被不相关资料带偏。

### 2.4 用LLM进行最小修改

仅在发现冲突时调用编辑模型。输入仍是当前`y`、`q`和`e`，提示模型先指出错误片段，再生成修订文字。

处理下一条证据时使用已经修订的`y`，而不是每次回到原始`x`。因此这是依次处理证据、累计修订的流程。

论文使用编辑距离保护：修改超过50个字符，或超过原始文本长度的一半，就拒绝此次编辑。严格保留有利于局部纠错，但会限制需要整体重写的情况。

### 2.5 压缩最终证据报告

处理过程中可以用到多于5段证据，最终报告最多保留5段。

论文通过穷举证据子集最大化问题覆盖：

\[
\operatorname{Cover}(A)=\sum_i\max_{e\in A}S_{\mathrm{relevance}}(q_i,e),\qquad |A|\le5.
\]

意思是：每个问题在选出的证据中找最相关的一段，再将各问题的分数相加。它希望用较少证据覆盖更多事实点，而不是简单保留检索分数最高的5段。

最终证据报告是证据集合，不能自动理解为每个事实都有严格的一一绑定引用。任务定义允许添加文本与证据的对齐信息，但论文的报告选择目标使用问题相关性作为覆盖代理。

### 2.6 概念伪代码

以下用于解释流程，没有在本项目中实现或执行：

```python
def revise_with_rarr(original, context):
    questions = union_of_3_question_generations(original, context)
    retrieved = []
    for question in questions:
        pages = search(question, top_k=5)
        candidates = four_sentence_windows(pages)
        evidence = most_relevant(question, candidates)
        if evidence is not None:
            retrieved.append((question, evidence))

    revised = original
    for question, evidence in retrieved:
        decision = agreement(revised, question, evidence, context)
        if decision == "disagreement":
            proposal = minimal_edit(revised, question, evidence, context)
            distance = levenshtein(revised, proposal)
            if distance <= 50 and distance <= 0.5 * len(original):
                revised = proposal

    report = maximize_question_coverage(retrieved, max_evidences=5)
    return revised, report
```

代码中的空证据处理是为解释完整流程而加入的工程防护，不应误认为公开执行器已实现同样的回退。

## 3. 论文主实验与公开代码的区别

| 项目 | 论文主实验 | 本次读取的作者公开代码 |
|---|---|---|
| 核查与编辑模型 | PaLM 540B | 默认`text-davinci-003` |
| 搜索 | Google Search | Bing API |
| 证据重排 | T5-large，MS MARCO设置 | `cross-encoder/ms-marco-MiniLM-L-6-v2` |
| 问题采样 | 3次；温度0.7 | 默认3次；温度0.7 |
| 一致性与编辑温度 | 附录D写所有生成任务温度0.7 | 两个工具函数均固定0.0 |
| 编辑幅度保护 | 超过50字符或原文长度一半拒绝 | 只有编辑距离比率条件，默认`max_edit_ratio=100`；没有50字符条件 |
| 报告大小 | 至多5段 | 默认选择`min(5,证据数)`段；设置`prefer_fewer=True`才比较更小的集合 |

源码入口是`run_editor_sequential.py::run_editor_one_instance`，依次调用`question_generation`、`search`、`agreement_gate`、`editor`和`evidence_selection`。输出保留问题、检索结果、每次一致性判断、逐步修订与最终证据。

公开执行器的比率检查是`distance(current, proposal) / len(current) <= max_edit_ratio`。默认100意味着该条件允许极大的修改，不能当作论文的50%限制。严格复现论文需要单独对齐这个参数及绝对字符阈值。

公开代码使用当年的OpenAI Completion调用方式，并提供用LLM生成模拟证据的演示开关。模拟证据不是外部证据，不能用于归因评估。本次只检查源码，没有验证这些旧API的当前可用性。

## 4. 怎么评估

### 4.1 数据与配置口径

论文使用3类任务，分别测试：

- Natural Questions（NQ）：知识问答中的事实陈述。
- StrategyQA（SQA）：推理链中间事实的来源支持和推理保留。
- QReCC：依赖历史对话上下文的知识问答。

共有6种数据集与生成模型组合，每种150个开发样本、150个测试样本：NQ/PaLM、SQA/PaLM、QReCC/LaMDA，以及3个数据集各自的GPT-3版本。主表展示前3组，GPT-3结果放在附录。数据全部为英文。

主实验为单次运行；附录仅对NQ/PaLM补充了3次随机运行的自动指标方差分析。人工标注试点阶段每例3人，正式标注阶段每例1人。

### 4.2 指标定义

1. **AIS**：逐句人工判断整句信息是否完全得到证据支持，计算比例。它不是“事实准确率”，也不是“有URL的句子比例”。
2. **auto-AIS**：先做句子去上下文化，再对每个句子取最佳证据的NLI蕴含概率，最后求平均：`avg_sentence max_evidence NLI(e,s)`。这个NLI模型用于自动评估；论文运行时的一致性门控用的是LLM，二者不能混为一谈。
3. **Pres_intent**：是否完全保留原文意图，人工判断，完全保留记1，否则记0。
4. **Pres_Lev**：`max(1 - Lev(x,y)/len(x), 0)`，字符层面的保留程度。
5. **Pres_comb**：`Pres_intent × Pres_Lev`。
6. **F1_AP**：来源支持与保留程度的调和平均。主表1使用人工AIS和Pres_comb；消融表2使用auto-AIS和Pres_Lev，不能直接跨表比较同名F1。

编辑前后的AIS都依据该系统输出的证据报告计算。不同系统有不同证据报告，因此“编辑前支持率”可能不同；不能将它当作原文固有的真实正确率。

## 5. 核心结果与逐类分析

表中数字来自论文表1，均按0到100表示。本次未重新测量。

| 任务及原文生成器 | RARR人工AIS，前→后 | 原意完全保留 | 字符保留Pres_Lev | 综合保留Pres_comb | 人工F1_AP |
|---|---:|---:|---:|---:|---:|
| NQ / PaLM | 35.4→43.4 | 90.0 | 89.6 | 83.1 | 57.0 |
| SQA / PaLM | 24.5→31.5 | 92.6 | 89.9 | 84.6 | 45.9 |
| QReCC / LaMDA | 13.2→28.3 | 95.6 | 80.2 | 78.1 | 41.5 |

### NQ：适合局部事实纠错

RARR的人工来源支持率提高8.0个百分点，原意完全保留率90.0%。EFEC来源支持率提高到48.3%，高于RARR，但综合保留只有10.4%，其F1_AP为17.1%。这体现出RARR的优势在于兼顾回答内容与来源支持。

论文图6中，原文描述印度第七届中央薪酬委员会时把报告提交年份写成2016。RARR改为2015，保留人物和委员会介绍；EFEC删减为一句简短介绍，LaMDA则转向薪酬调整内容。该示例说明只修正必要事实的意义。

### SQA：能修事实，但逻辑未必随之修复

RARR人工来源支持率提高7.0个百分点，综合保留84.6%。EFEC来源支持率达到51.7%，但原意完全保留仅6.0%，综合保留3.8%。

RARR较好地保留推理链的文字，却不保证推理链仍然有效。论文下游测试没有发现SQA答案准确率提升；所有修订系统的答案准确率均略有下降，最多2.6个百分点。不能把中间句子更有证据解释为最终推理更正确。

### QReCC：上下文重要，支持率仍有大幅提升空间

RARR人工来源支持率从13.2提高到28.3，增幅15.1个百分点；完全保留原意95.6%。不过修订后仍远低于100%，不能描述为已解决对话幻觉。

EFEC在这一组来源支持率48.7%，高于RARR，但综合保留23.7%，低于RARR的78.1%。两者采用不同取舍。论文也承认LaMDA没有专门优化原文保留，因此这些实验不是对所有系统能力的全面排名。

### 消融：问题生成与一致性门控为何有用

论文表2的NQ自动指标中，完整RARR的auto-AIS为54.9，Pres_Lev为89.6；去掉一致性门控后分别为50.6、82.6。强制逐证据编辑既增加修改，也可能降低来源支持。

直接以整篇原文作搜索查询时，NQ的auto-AIS只从45.4提高到47.2。以单句为查询的部分综合指标接近完整方法，但在排除Wikipedia的检索环境下下降更明显，并存在顺着原句错误结论寻找支持的确认偏差。

这些数字是特定英文数据集和当年模型的结果，不能当作更换模型、语种或领域后的效果保证。

## 6. 失败样例

### 6.1 检索到重播资料，改坏原有事实

论文图7d：原文描述电视剧《In the Heat of the Night》在NBC的早期播出。检索证据是MeTV的观看页面，RARR据此把频道改成MeTV，却保留原来的年代。它没有识别“首播”和“多年后重播”的语境差异。

分析：证据主题相关，不代表对同一时间、事件角色或属性有支持。需要比较实体、时间和事实范围。

### 6.2 改了前提，没改依赖前提的结论

论文图7e：原文认为Homer Simpson一只手有5根手指，因此一只手能数到5。RARR把手指数改为4，后文仍说一只手足够。

分析：局部修订提高了事实句的来源支持，但造成前提与结论不一致。需要追踪修改影响的推理步骤，重新检查依赖关系。

### 6.3 没有证据时保留幻觉

论文限制部分指出，RARR更倾向于保留无法归因的陈述，而不是删除。由于门控主要由冲突触发，检索无结果或证据不相关时，错误内容可能原样留下。

分析：至少应区分“支持”“冲突”“信息不足”。信息不足不能自动标为支持；对重要事实可考虑补搜、降低断言强度或标记未核实。这些是工程建议，不是论文已实现或已验证的能力。

## 7. 局限性与结论边界

| 边界 | 本次可以说什么 |
|---|---|
| 已测量，论文报告 | 表1和表2指标、3类任务表现、论文图示失败样例；这是作者实验，未在本地复测 |
| 已检查，静态材料 | 方法、附录参数及公开源码的模型、温度、重排和编辑阈值差异 |
| 间接推断 | 适合作为报告生成后的局部核查修订层；处理长报告需要额外分段、状态和引用对齐；多次调用会增加延迟和成本 |
| 尚未评估 | 当前模型/API上的可运行性、中文及行业/医学领域效果、本项目收益、长文规模成本、端到端引用准确率及推理一致性 |

其他限制包括：

- 来源支持不保证来源可靠或信息最新，原实现没有系统解决证据冲突。
- 论文实验以英文短篇输出为主；论文明确指出长文和诗歌不是现有实现充分支持的对象。
- 严格限制编辑距离，会妨碍纠正整体错误的前提。
- AIS按句子评估，多事实句必须全部支持才能得到人工正标签；自动指标取单条证据的最大蕴含概率，对联合证据支持的处理有限。
- 证据报告用相关性优化覆盖，不能保证每句都被真正蕴含。原始公开选择函数返回的精选证据仅保留`text`；完整检索结果中的`url`仍在其他输出字段中。集成时应保留来源身份与引用映射。
- 每个问题增加一次搜索和一致性调用，冲突时还要编辑；没有本地成本或延迟测量。

## 8. 对项目的启发与下一步建议

对研究报告系统，最值得借鉴的是“生成后的证据核查与最小修订”。可以先挑选实体、日期、数值、比较关系和结论等重要事实，再生成中立核查问题，检索原始来源，并只修订被明确证据否定的部分。

但不能仅在报告末尾加几个链接就称为完成核查。建议把事实与证据片段的绑定、一致性判定、修订记录以及未支持事实一起保留；对修订影响到的下游结论再做检查。分段处理长报告、冲突证据优先级和无证据回退也需要单独设计。

若后续复现，先对齐论文与公开代码的差异，再以一个中文小样本集测量：事实/句子的证据支持率、引用蕴含、原意保留、误改率、未支持内容残留率、推理一致性、调用成本和延迟。每次结果另建中文报告，保留逐样本机器可读记录。

本次结论：RARR证明了“先生成，再研究和小范围修订”能提升来源支持并保留大部分原文；它提供可组合的后处理架构，但没有证明来源支持等于事实真实，也没有解决完整推理正确性或所有幻觉。
