## 测量方式与配置

使用Chrome `154.0.8037.98`、Playwright 1.62.1、1800×1100视口、headless模式；运行真实App及聊天页，服务端复用正式研究路由、事件持久化、租约、交付事务和PostgreSQL检查点。隔离端口为5187/18765，真实登录通过禁用评测账号的依赖注入替代，登录与鉴权安全不在本次范围内。未修改生产前端的业务代码；埋点只由独立Vite配置转换源码。

四种回放场景复用既有开发集事件内容，以每条约25ms节奏写入新的隔离运行账本并发送。事件账本样本长度依次为200、192、231、123、176。第26题使用已成功重试轨迹；第28题历史没有完成事件，夹具从已保存终态正文补充合成交付，文件标明`fixture_synthetic`。**第28题回放完成不表示旧运行已经修复或交付成功。** 回放时刻全部重新打点，未使用历史事件timestamp计算网络延迟；回放节奏不代表原模型的生成节奏。

真实图场景用确定性Agent替代规划/检索/分析/写作/审核中的模型与搜索，执行正式图和节点检查点。写作按4章发送，每章间隔1.25秒；终态正文约2500字符，仅作为机制夹具。首次发起补测通过聊天输入框按Enter发送，经过正式`/research/stream`及首跑解析分支；多轮上下文使用确定性输入，隔离进程关闭`SESSION_EVIDENCE_ENABLED`，没有创建缺失的会话证据表或修改全局.env。

弱网在页面加载完毕后设置150ms延迟、128KiB/s下载、64KiB/s上传。断网在首章可见后切断真实HTTP socket，并使Chrome Offline持续3秒；必须看到网络错误及后续增量SSE才能计入断线恢复。仅设置Offline的准备验证未使已建立的流断开，已明确排除。刷新使用真实`page.reload`，页面读取快照与事件后点击“继续本次研究”；刷新不会被算成无需操作的自动恢复。

浏览器使用`performance.now`和`performance.timeOrigin`记录时间，每个页面有独立ID；跨刷新使用epoch时间关联，未直接相减两页的performance.now。每案通过7次真实HTTP时钟请求选最小RTT样本校准服务端时钟，记录±RTT/2的误差估计。DOM可见性检查同时验证文本、几何范围与样式；rAF与Chrome合成帧截图提供显示佐证。[MDN performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)、[MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)、[Chrome网络模拟](https://developer.chrome.com/docs/devtools/network/reference)支持这些边界：rAF发生在绘制之前，DOM时间不能冒充精确像素呈现时间。

## 指标定义

| 指标 | 分子、分母或时间边界 |
|---|---|
| 首个进度/正文DOM时间 | 页面动作开始→包含唯一进度/首章标记的可见DOM出现；动作开始包含自动化点击/发送耗时 |
| 首帧SSE时间 | 真实Axios流请求发起→浏览器解析出首个完整事件 |
| 发送到接收到达延迟 | 校准后的浏览器epoch−本次帧发送边界epoch；包含服务端序列化/日志、HTTP与代理缓冲、浏览器调度与完整JSON解析，不能单独称为纯网络RTT |
| 接收到正文DOM批次延迟 | 完整事件收到→对应序号的正文DOM批次观察；无DOM变化的事件不计为渲染样本。另记录首个章节事件→首正文时间以发现未投影 |
| 已提交事件覆盖 | 最终账本序号集合E与浏览器已应用集合A比较，缺失为E−A；运行未交付时覆盖已有前缀不能代替研究完成 |
| 同序号去重 | 同一run、同一投影代次中重复序号帧接收2次、应用1次；刷新或点击继续新建投影后重放旧历史是合法的重建，不算重复副作用 |
| 过程章节重复 | 完成前正文DOM中唯一首章标记出现次数>1；区别于同序号重复，新的seq也可能指向同一逻辑章节 |
| 缺口补齐时间 | 检出gap→被故意丢弃的seq通过HTTP账本进入投影；计入真实HTTP请求和处理耗时 |
| 断网恢复时间 | Chrome重新online→首个增量SSE/完成DOM；完成时间包含未提交节点重跑，不等于纯事件补齐时间 |
| 刷新恢复时间 | reload导航DOMContentLoaded→完成DOM，包含随后点击继续与节点重跑；此边界与断网online不同 |
| 交付一致性 | 恰好1条助手报告、1条research_complete、运行completed；正文SHA-256在检查点、助手消息和浏览器投影一致，完成事件checkpoint_id一致 |

### 1. 首次发起收到了章节，当前工作台没有逐章更新

### 3. 主评测题目28断网后持续409

[原始失败结果](../backend/eval/data/SSE浏览器真实链路评测-20261008-194700/题目28-真实断网/测量结果.json)记录真实断线错误`ERR_INCOMPLETE_CHUNKED_ENCODING`及Offline时的`ERR_INTERNET_DISCONNECTED`。重新online后反复POST恢复，服务端409，账本停在8条，30秒内没有交付；[原始网络/浏览器日志](../backend/eval/data/SSE浏览器真实链路评测-20261008-194700/题目28-真实断网/浏览器测量日志.json)和[服务端日志](../backend/eval/data/SSE浏览器真实链路评测-20261008-194700/题目28-真实断网/服务端测量日志.jsonl)保留全部请求。原脚本将timeout放在waitForFunction的第二参数，因此实际观测窗是默认30秒，并非原意的60秒，已在复评改正。

新增可复用入口：[隔离评测服务](../backend/eval/scripts/SSE浏览器隔离评测服务.py)、[浏览器测量脚本](../frontend/scripts/SSE浏览器测量.cjs)、[独立Vite配置](../frontend/tests/SSE浏览器评测配置.ts)、[交付复核与聚合脚本](../backend/eval/scripts/汇总SSE浏览器评测.py)。服务输入需设置`SSE_EVAL_OUTPUT`、`SSE_EVAL_DATASET`、`SSE_EVAL_SOURCE`、`SSE_EVAL_RETRY`；复评通过`SSE_EVAL_FROZEN_APP`使用完整后端快照。浏览器参数可指定`8:normal`、`8:disconnect`、`8:fresh`等，追加批次须使用新的中文前缀和汇总文件名，不复用旧目录。

主评测后端在正式测试前启动，期间没有热重载；初始记录至主评测磁盘service.py/graph.py存在并行变化，磁盘快照不能完整证明已经加载的模块版本。复评因此使用`复评后端源码快照/`固定完整后端；测量脚本分别留在`源码快照/`与`复评测量脚本快照/`，没有将不同口径合并为一个生产版本通过率。主评测开始至复评冻结之间，service.py又有并行磁盘改动；复评以20:11左右冻结的完整后端源码为准，冻结至结束所记录的生产文件哈希一致。隔离关闭了会话证据扩展，故不代表该扩展或其他新增功能已经得到验证。生产前端业务源码在测量期间的哈希一致，哈希明细见配置。

## 局限性与下一步

1. 本次为本机headless Chrome机制测量，启用trace、截图、DOM埋点和数据库日志会增加开销。每场景5案只能描述样本，不能建立生产P95/SLA或稳定成功率。回放、首跑、不同清理配置必须分开比较。
2. DOM可见时刻、rAF和首显后的第一个已采集合成帧提供浏览器渲染证据，但没有自动识别全部帧中的首个正文像素；精确像素呈现时刻仍未评估。所有截图文件已落盘，并人工核对了首次正文和重复章节代表帧。
3. 没有调用真实模型/搜索API；确定性Agent模型调用计数为0，隔离服务记录的外部HTTP尝试为0，不追加模型/搜索费用；本机计算和约600MB证据存储成本未计入。故本次不回答真实生成延迟、报告质量或生产资源成本问题，也没有重跑5题完整研究基线。
4. 优先让首跑与恢复共用同一报告投影；收到section_content后即时更新工作台，并按section_id维护有序章节集合。需要区分未提交节点重试与真实内容修订，可增加章节版本/写作代次，并替换对应章节，避免把有新seq的同一章节再次拼接。
5. 保留断网测试中的真实网络错误、上游关闭和租约释放证据。下一轮在实际部署代理链路复测异常断开、租约409等待上限及完成事件丢失，不能仅依赖开发代理通过。
6. 两项UI修复后复用本评测：要求首次发起在完成前出现正文，任意恢复过程中首章标记最多1次，最终账本/报告/完成事件/检查点保持一致。真实用户从点击到首章的总时间可在后续正常研究中埋点采集，复用已有模型轨迹，不必为每题每位置另跑完整基线。
