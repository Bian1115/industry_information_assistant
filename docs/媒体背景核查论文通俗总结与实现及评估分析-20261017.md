## 1. 先说明本次分析的边界

本次是论文研读、作者代码静态核查和本项目接入方案分析，没有执行模型评测或修改业务代码。

- **已测量／直接核查**：作者仓库树内有 6,709 个背景档案文件；默认查询配置有 42 项；检查了生成、评估、依赖源码和本项目现有接口。这里只是文件及代码核查，没有测量模型效果。
- **作者报告、未独立复现**：下文引用的背景事实召回率、错误率和人工偏好结果全部来自原论文。
- **间接推断**：只允许追加档案可能固化初始幻觉；缓存有望降低重复开销；增加来源背景可能补充当前引用核验的不足。这些是机制分析，不是本地收益证据。
- **尚未评估**：中文媒体、行业及医学信源的覆盖，档案事实精度，当前项目端到端报告质量变化，实际成本与延迟，当前检索服务及历史模型的可用性。

作者代码按提交 `d54879563a13c90bb1613c64f392980b0b266397` 核查，提交时间为 2025-08-29。本文描述的是这一版本，不假定它与 2024 年论文实验环境完全一致。

## 2. 用好懂的话解释这项工作

平常的检索增强问答是：搜到文章，读文章，再写答案。这里容易漏掉一个问题：**写文章的人是谁，他为什么这样说？**

Media Background Check（MBC）可以理解为一份“媒体背景档案”。它记录所有权、收入与资助来源、主要受众、编辑立场，以及具体的失实报道、纠错等历史。模型回答问题时，同时看到文章和这份档案，就能更有依据地说明应该怎样使用这个来源。

下面是虚构案例，仅用于解释机制：

> 某公司赞助的行业网站称“自己的技术效果最好”。背景档案揭示了资助关系。系统因此把它当作企业相关方的说法，继续寻找独立测试，而不会仅凭这篇文章认定技术领先。

这里有两个独立问题：

1. 文章是否真的支持报告写出的论断？这是引用支持性问题。
2. 文章提供的证据是否足以让人相信该论断？这还涉及利益关系、研究方法、时效与独立交叉验证。

MBC 为第二个问题补充背景；它本身也需要证据。立场、出资方或一次历史错误都不能单独决定当前报道真假。

## 3. 作者代码怎样实现

核心入口是 [`generate_media_background_checks.py`](https://github.com/MichSchli/MediaBackgroundChecks/blob/d54879563a13c90bb1613c64f392980b0b266397/generate_media_background_checks.py)。它主要组合现成模型和搜索工具，没有训练一个新的媒体真实性分类器。

```text
输入媒体名
  → 语言模型凭已有知识生成初始背景档案
  → 读取查询配置，搜索媒体相关背景
  → 下载网页并抽取正文
  → 抽取式问答模型寻找问题的答案及所在原句
  → 把每轮找到的材料交给语言模型，逐轮更新档案
  → 保存最终档案与检索原文
```

具体函数与职责：

| 函数／组件 | 做什么 | 实现时需要知道的细节 |
|---|---|---|
| `generate_initial_guess` | 先生成背景草稿 | 草稿来自模型记忆，不能直接视为已经核实 |
| `get_google_search_results` | 调用 Google Custom Search | 当前源码成功请求一次即结束，每次最多 10 条 |
| `process_search_results` | 下载正文、过滤部分站点及文件 | 过滤规则不等于完整的资料泄漏检测 |
| `get_answer_from_evidence` | 从正文抽取答案及相关句子 | 使用 `deepset/deberta-v3-large-squad2`；只看前 3,000 字符；分数低于 0.2 时跳过 |
| `incorporate_extra_information` | 更新背景档案 | 当前提示词要求尽量只追加信息，不删除旧内容 |
| `build_background_check` | 串起全过程 | 每个查询汇总可用支持句后更新；默认最后还会再次并入初始草稿 |

抽取式问答模型的用途，是从长文本里挑出“谁拥有该媒体”等问题的相关片段；它没有证明这些片段的内容在现实中正确。其输出分数也不能当作媒体可信度概率。

## 4. 论文结果应如何读

论文数据来自 Media Bias / Fact Check，划分为训练 5,209、开发 500、测试 1,000 个档案。背景档案是任务参考材料，不能直接当作当前媒体评级。

以下转录自[论文表 2](https://aclanthology.org/2024.findings-emnlp.283.pdf)，不是本项目实测：

| 作者系统 | 背景事实召回率 | 参考事实矛盾率 |
|---|---:|---:|
| GPT-3.5-Turbo | 22.7% | 6.2% |
| GPT-3.5-Turbo + Google | 26.1% | 6.3% |
| Llama 3 8B Instruct | 24.4% | 10.4% |
| Llama 3 8B Instruct + Google | 25.1% | 10.7% |

`Fact Recall` 衡量参考档案中的原子事实有多少被找回；`Error Rate` 衡量在参考原子事实集合上产生的相反判断。代码中也会保留参考档案明确否定的模板陈述，所以更准确地说，召回要求生成档案与参考档案对这些事实的支持／反驳判断一致。

因此：26.1% 不是回答准确率，6.3% 也不是全部生成内容的幻觉率。搜索提高了召回，但表中两种模型的错误率都没有下降。论文正文对检索收益的措辞较强，实际应同时报告提升幅度与绝对召回水平。

人工实验招募了 11 位研究者。模型回答比较使用 10 个问题、每题两个来源，形成 20 个问题—来源对；220 次偏好判断中，有档案回答获选 165 次，无档案回答 26 次，持平 29 次。这里的 220 是判断次数，不能写成 220 道题，也不能把偏好率写成事实准确率。其他人工结果见原始记录。

核心结论是：来源背景有助于解释冲突材料，值得进一步实验；它尚不足以证明通用问答、中文行业研究或当前项目已经获得同样收益。

## 5. 按类别分析不足与失败情形

| 类别 | 证据状态 | 失败情形及影响 |
|---|---|---|
| 背景信息遗漏 | 论文第 4.3 节人工检查报告 | 主编、所有者等实体，资金来源，事实核查历史、转载来源及多跳关联可能漏掉；档案看似完整仍可能缺少关键关系 |
| 初始知识错误保留 | 源码直接可见，后果为间接推断 | 草稿若把前任所有者写成现任，追加策略缺少明确撤回旧说法的机制；本次未测发生率 |
| 证据位置靠后 | 源码直接可见，后果为间接推断 | 资金披露位于网页 3,000 字符之后时，抽取式问答看不到它 |
| 同名来源混淆 | 拟议实现的机制风险 | 媒体、集团和同名个人可能被合并；本次没有本地错误样例 |
| 无记录被理解成无问题 | 拟议实现的机制风险 | 没搜到失实记录只表示证据缺失，不能输出“从未失实” |
| 档案滞后 | 仓库 README 明确提示资料会变化 | 旧所有权、资助或历史评价不能无时间限定地用于当前判断 |
| 自我介绍替代独立证据 | 拟议实现的机制风险 | 网站自称独立不等于独立性已获证实；应标注“自述”并检查其他材料 |

这些机制案例不计为本地端到端失败率。论文的逐例背景档案生成结果未在本次重新采集，不编造具体题号或生成轨迹。

原子事实评估器用四次模型判断投票；四票仍可能平票，当前 `Counter(...).most_common(1)` 的选择不等于有绝对多数。若替换裁判、解析或投票策略，需标注评估口径变化，不能直接宣称复现原指标。

## 7. 在当前项目中怎样落地

以下属于工程建议，尚未实现或验证。

当前 [`scout.py`](../backend/app/service/deep_research_v2/agents/scout.py) 已有 `credibility_score`，提示词按官方、学术、媒体等类型给出评分区间，入库时保留模型返回分数。这个分数提供了粗粒度参考，但在上述评分与入库路径中没有记录每个分数对应的所有权、资金和失实历史证据。

现有 [`citation_verification.py`](../backend/app/service/deep_research_v2/citation_verification.py) 明确说明，引用支持性不代表现实真实性。MBC 可以为它补充可追溯的来源背景。

建议先增加一个按需调用的来源档案服务，复用已有搜索、网页读取、正文编号与引用核验能力：

```text
Scout 发现待用来源
  → 解析真实发布者／媒体实体
  → 查询缓存，缺失或过期时补搜背景
  → 将背景事实绑定到已读取正文原句
  → 保存带版本和日期的来源档案
  → Writer 结合文章、档案与独立证据写作
  → 现有引用核验检查最终报告的支持关系
```

### 7.1 六组检索作为起点

| 要查什么 | 可用的查询方向 | 如何使用 |
|---|---|---|
| 谁拥有它 | 媒体名＋所有者／母公司／股权 | 核对主体与生效时间 |
| 谁出钱 | 媒体名＋资助／广告／订阅／赞助 | 区分商业模式和具体利益关系 |
| 它主要做什么 | 媒体名＋关于我们／编辑政策 | 自述材料保留“自述”属性 |
| 有什么公开立场 | 媒体名＋社论／立场／背书 | 记录可观察行为和归属，不凭文风猜标签 |
| 有什么失实历史 | 媒体名＋事实核查／不实报道 | 要具体文章、具体结论、时间和证据 |
| 怎样纠错 | 媒体名＋更正／撤稿／纠错政策 | 区分有纠错制度、实际纠错及严重错误 |

这是依据附录主题重新整理的中文实现起点，不是作者当前 42 模板配置的直接翻译。行业、企业和医学来源还应增加适合任务的披露、研究设计与利益冲突字段，这属于项目扩展。

### 7.2 最小数据结构

以下字段是建议协议，示例对象为虚构来源：

```json
{
  "source_id": "媒体实体编号",
  "publisher": "示例行业网站",
  "domains": ["example.com"],
  "profile_version": "版本编号",
  "checked_at": "2026-10-17T00:00:00+08:00",
  "facts": [
    {
      "category": "funding",
      "claim": "网站披露接受相关企业赞助",
      "evidence_url": "https://example.com/disclosure",
      "document_id": "已保存正文编号",
      "sentence_ids": ["s000012"],
      "provenance_type": "self_report",
      "status": "supported",
      "valid_time": null
    }
  ],
  "unknown_fields": ["最终控制人"],
  "conflicts": []
}
```

`supported` 仅表示披露正文支持这条陈述；自述资金情况仍需标注证据性质。`checked_at` 是核查时间，不能替代所有权或资助关系的有效时间。

### 7.3 实现顺序

1. **先解析实体。** 将 URL 归到实际媒体／发布者；同域博客平台的不同作者不能自动共用一份档案，同名媒体也不能仅凭名字合并。
2. **从空白档案与待查字段开始。** 模型记忆可产生查询线索，进入档案的事实必须绑定证据。这样可以明确区分假设和已找到的材料。
3. **并行检索、去重、读取。** 背景查询不再指向原研究问题；保留超时、读取失败和资料缺失状态。
4. **结构化抽取与验证。** 每条背景陈述关联 `document_id`、`sentence_ids`、来源与时间；保留冲突，不让模型随意合并互斥所有权信息。
5. **按媒体实体及版本缓存。** 研究运行保存使用过的版本，技术恢复继续使用同一快照；新的研究可按更新策略刷新。更新周期由实际变化情况决定。
6. **让档案真正影响取证。** 关键结论只有利益相关方支持时触发独立补搜；遇到矛盾时检查原始数据、方法与时间。低透明度应表现为不确定性，不自动判假。
7. **写作时说明相关背景。** 仅在背景影响当前结论时简洁披露，并能追到背景证据。背景档案本身也进入支持性审计。

对应模块可分为来源实体解析、背景检索、档案存储和写作策略四部分。新增 `source_profiles` 状态时应遵循 [`state.py`](../backend/app/service/deep_research_v2/state.py) 的图版本及旧检查点适配约定；这次仅提出方案，没有改图或状态协议。

## 8. 如何验证值得接入

以下是拟议实验，不是已运行结果：

- 建立新的中文评测集，覆盖权威来源、利益相关方、身份不透明来源、混合转载平台，以及所有权随时间变化的情形。
- 在同一问题、模型和正文条件下比较“无档案”“自动生成档案”，并用人工核实档案作为诊断参考；固定资料快照，另行测量独立补搜策略的收益与成本。
- 逐类检查所有权、资金、公开立场、失实及纠错历史。分别记录找回多少事实、写入事实有多少得到证据支持、漏掉多少重要信息，以及应保持未知时是否猜测。
- 下游检查：是否恰当解释冲突，是否把宣传误写成独立证据，是否识别多个转载其实来自同一源头，关键结论准确性是否改善。
- 同时记录每来源的检索次数、读取次数、模型用量、耗时与缓存命中情况。所有失败与中断均保留原始记录。

不能以引用支持率上升、背景事实召回上升或人工偏好上升中的任意一项，替代最终报告事实正确性的独立检查。

## 9. 局限性、结论与下一步

论文和数据以英语媒体为主；中文行业与医学场景需要额外验证。MB/FC 是有自身覆盖范围与判断口径的参考资源，背景描述又会随时间改变。生成档案依赖的网页也可能错误，无法通过无限继续搜索获得绝对可信性。

数据仓库声明采用 CC BY-NC 4.0；使用其原始数据前应核对用途与许可要求。本文没有评估将该数据直接用于商业部署的适用性。

这项工作的可复用价值是：**将来源背景变成有证据、可检查的材料，并让它影响后续取证与表述。** 当前作者代码存在明确的复现差异，应先固定实验口径再运行。对本项目，下一步可先做少量来源档案的结构化原型，验证能否准确披露资金与所有权关系，再进行固定材料的配对比较。
