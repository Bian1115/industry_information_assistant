## 推荐的处理流程

每条固定原子论断先做父句保真检查，再建立细粒度原文证据单元。对所选单元做单条NLI评分，并按实体与必要条件生成少量最小充分证据组，追加联合NLI评分。最终聚合保留全部候选反证：完整支持且没有矛盾候选可通过；支持与矛盾并存进入冲突复核；只有矛盾也要确认它是否明确表达相反事实；必要信息缺失才做定向补检索。证据完整却NLI仍unknown的项使用同一复核入口。

输出区分supported、contradiction、insufficient_support、unresolved_conflict、needs_review和execution_error。只有supported作为语义通过，未决项不自动删除原始事实，也不自动当作通过。父句与子论断不保真的情况单列invalid_claim或fidelity_pending_review，修复抽取对象。

## 证据组合应解决的问题

电容融合案例中，一个窗口说明机构与方法，另一个说明算法特点；分别评分最高支持约0.0013，联合原文达到0.9984。联合支持要求模型同时看到身份和属性。PAC-Net例中的窗口又混合了另一项研究，去掉无关条目后伪矛盾显著降低，但仍需要另一个窗口补齐CVPR2023年份。这说明证据应同时满足信息完整和主题一致。

当前`summary_sentence_evidence.selected_context`按来源保存所选片段，`summary_message_verification`主要逐窗口评分，缺少跨来源充分证据组；`summary_evidence_units`把连续带冒号的列表当成记录时，还可能把多个独立资源打包在一起。因此需要调整证据单元与组合表示，而不是仅扩大窗口。

## 原文证据单元与必要信息

普通正文保留完整主题句及不可删除的否定、条件、比较基准；有明确指代时，可加入同一实体的标题或邻句。邻句必须来自摘要实际输入范围，不能隐式扩展到未提供的全文。

编号研究条目、产品资源链接列表按独立条目切分，例如PAC-Net和语义特征检测分别成为单元；不能因为两个条目都有冒号而合并成同一记录。真正的试验记录与字段记录仍绑定记录身份，不把其字段任意拆散。表格保留表头、行标签、单位和必要脚注，避免将值与分母、条件分离。

每个证据单元保存source_id、unit_id、原文跨度、文本哈希、消息顺序及结构类型。多来源证据组保存各成员的source_spans；用于NLI的文本由程序从已验证原文片段以换行组装，不让模型改写成新的证据，也不将组装内容伪装成连续引用。

对于固定论断，识别其实际包含的必要信息，例如主体、属性或关系、来源归属、数值及单位、相对提升或最终值、比较对象、时间、适用条件、数量范围、否定、当前研究状态。所选证据必须覆盖这些信息。证据选择模型可返回已提供编号对应的覆盖项，但覆盖标记只用于寻找组合，不直接证明事实正确。

数字相同不代表关系相同，URL出现在输入里也不代表论断引用了正确的URL。最低限度的父子句保真检查必须保护精确标识和数值关系，防止组合把损坏引用送入高分放行路径。这是已有BMC缩窄窗口后损坏URL仍获0.9981支持的直接风险。

## 生成有限数量的最小充分证据组

先尝试单个完整单元。论断缺少必要信息时，再补入明确属于同一实体和适用范围的互补单元；候选组按新增必要信息覆盖、明确实体关联、较短输入排序。不得把不同论文、不同城市、不同实验条件的事实拼成支持，只因名称相似的跨消息关联转待复核。别名或代词关联需要可引用的身份桥接证据。

初版候选配置建议每组1至3个成员，从最多8个种子单元中最多生成6个追加NLI组合。它们是限制计算量的起始参数，尚未校准。种子上限仅限制组合搜索，全量所选单元及全部反证候选仍留在账本；不允许丢弃超过种子上限的高矛盾窗口后通过。

组合前逐项检查实体、记录身份、时间、条件和来源归属是否兼容。条件明确不同的单元不能直接联合支持一个同时适用的命题；条件缺失或归属有歧义时不假定兼容。多地措施合集不能被组合成每个城市实施全部措施，来源列表也不能被组合成每个来源都提供了全部结论。

组合长度按真实NLI tokenizer核算，计入premise、hypothesis、换行或分隔符以及特殊token，不能只用检索模型token数。超过512时优先寻找更短的完整证据组；若信息仍不可容纳，进入带完整原文的语义复核或待人工处理，不静默截断、删除限定或用生成摘要代替证据。

所有合法组合评分后，保留成员、必要信息覆盖、三类分数和反证关系。不因某个组合取得高支持就停止反证扫描。单条证据缺少一个条件时，neutral可能是合理结果；联合证据可以补足条件，但不能补造条件。

缓存键包含冻结claim哈希、证据成员及顺序、原文哈希、模型revision、组合规则版本；同样的原文与论断可复用评分。去重组合和重复的引用可以减少开销，但保留来源与原始顺序供复核，不能用重复引用数量当作支持强度。

## 候选判定与复核触发

| 支持与矛盾信号 | 初始状态 | 后续动作与理由 |
| --- | --- | --- |
| 至少一个覆盖全部必要信息的支持组，没有矛盾候选，保真检查通过 | supported | 完整命题有依据，正常通过 |
| 完整支持与高分矛盾同时出现 | conflict_pending_review | 检查是伪反证、条件不同，还是真正冲突 |
| 只有高分矛盾，没有完整支持 | contradiction_pending_review | 验证明确反向关系；避免漏掉重庆数值例这类单边伪矛盾 |
| 没有高分支持或矛盾，必要信息确实缺失 | insufficient_support候选 | 针对缺失字段补检索，至多一轮后重新组合 |
| 必要信息已经覆盖，但NLI仍unknown | semantic_pending_review | 避免对科技馆理念类误判反复做无效检索 |
| 父句标识或含义被子论断改变 | invalid_claim或fidelity_pending_review | 回到抽取修复，不能删除父句来迎合改坏的子论断 |
| 推理、编号协议、复核或预算失败 | execution_error或needs_review | 记录失败原因，不转换成事实矛盾或通过 |

初版也复核单边矛盾和证据完整的unknown，原因是已观察到17条暂定伪矛盾中只有9条同时高支持，单做双边冲突复核会遗漏其他失败。复核调用按论断共享预算，避免不同触发原因各调用一次。

## 冲突复核输入与裁决

复核是新的来源受限调用：提供冻结论断、父句、必要信息、原文支持候选、所有相关矛盾候选和必要身份/条件上下文。证据附编号、消息顺序、时间与原始跨度。候选按原始来源顺序呈现，不用NLI分数排序；不提供NLI概率、GPT初评、人工真值或希望它通过的提示，减少锚定。

先使用当前已有模型调用与预算基础设施；复核模型独立配置，首轮可用已有qwen3-max作为对照实现，减少接入成本。它与生成模型可能相同，因此单独的一次调用不等于独立金标。模型是否需要更换，根据人工标签上的纠错与新增错误决定；方案本身不预设更大模型一定有效。

复核要求输出可检查的短结论和证据关系，不要求长篇推理。每个命题成分的支持关系必须指向输入编号。反证必须同时满足实体、时期、条件、作用域一致，且原文明确表达相反事实；未提及、仅给产品链接、缺少某字段都不自动构成反证。

若支持组充分、原候选反证只是未提及或不同对象，返回supported，并记录被排除的反证及原因。若明确同范围反证成立，且支持候选无效，返回contradiction。若双方都有效且没有提供可验证的更正/撤回关系，返回unresolved_conflict。若必要信息仍缺失，返回insufficient_support。不能仅因某来源更新或排名更高就让它覆盖旧证据；只有来源内容和论断时期给出适用关系才能裁决。

建议输出合同如下，所有编号均由输入提供，原文由程序恢复：

```json
{
  "claim_id": "输入的claim_id",
  "decision": "supported或contradiction或insufficient_support或unresolved_conflict或invalid_claim",
  "support_map": [
    {"component_id": "输入的命题成分编号", "evidence_unit_ids": ["输入的证据编号"]}
  ],
  "counterevidence_checks": [
    {
      "evidence_unit_ids": ["输入的反证编号"],
      "entity_match": "matched或mismatched或unknown",
      "time_match": "matched或mismatched或unknown",
      "condition_match": "matched或mismatched或unknown",
      "scope_match": "matched或mismatched或unknown",
      "relation": "explicit_opposite或not_opposite或different_scope或unclear",
      "reason": "简短说明对应的原文关系"
    }
  ],
  "missing_component_ids": [],
  "reason": "简短裁决依据"
}
```

校验器拒绝越界编号、重复或缺失的必要字段、覆盖不足却supported、关键比较对象或标识不一致等情况。所有矛盾候选必须有检查记录；实体、时间、条件或作用域无法确认时必须返回unknown，不能猜测为matched。合法结构和引用绑定不能证明语义裁决一定正确，因此仍通过人工回归评估复核器。

## 复核失败处理和开销限制

初版每条论断至多一次语义复核，建议输入上限6000 token、输出1500 token、单次超时60秒，另允许一次仅修复JSON或编号协议的调用。参数作为起始预算，不作为最优值。第二次调用仍须提供相同来源与允许编号，不能把合法性修复当作反复改变语义裁决的机会。

超过预算的强反证不能静默裁掉：先去重相同原文、缩小到仍完整的主题单元；仍无法容纳全部相关冲突材料时返回needs_review或budget_exhausted。暂不引入多轮无限裁决。模型异常或真实语义冲突未解时不自动放行，不依据未决NLI标签自动改稿。

证据不足时，检索查询针对缺少的主体归属、年份、比较基准等字段，并兼顾撤回/否定信息；只索引原摘要实际输入。补检索至多一轮，重新构造候选证据组并使用同一复核预算。反证线索在旧流程中无需丢掉，复核可将其标为无关/非反向关系，但保留原始内容和裁决理由。

遥测记录每条论断新增组合数、联合NLI输入token、复核触发原因、LLM实际usage及耗时、检索请求、复核前后状态、纠错或新增错误，以及未处理候选数。不能把本地NLI token混作LLM计费量。

## 对照评测与验收口径

冻结同一批271条论断及完整实际输入，先不重新生成摘要或改变Claimify，以免评测对象变化。A原机制，B只改善证据组合，C只增加复核，D两者共同启用。复用旧请求、候选和评分时保存其哈希，新组合和新复核调用独立落盘。

最终论断级支持性要对照固定完整输入的人工真值，而不是沿用旧所选窗口的标签。16-047旧窗口缺少比较对象，完整输入中有该对象；补齐后不能仍按旧窗口的不足标签判新机制漏放。新premise产生的新单对NLI评估需要相应的人工标签；单对评测与最终论断级评测分开报告。

主指标仍保留支持/未通过的二分类：unknown、unresolved_conflict、needs_review、budget_exhausted及执行错误均未通过并单列原因，不能把误拒换名为待复核后排除来提高数字。另报自动通过/自动拒绝的覆盖率、待复核比例及已裁决子集指标，避免只展示容易样本。运行错误保持可用率统计，不以未决项证明事实矛盾。

优先检查既有9条同时高支持和高矛盾项、电容联合证据、重庆数字条件、科技馆明确语义支持；同时确保数字关系改坏、BMC标识改坏、城市范围加强和来源归属不足项不能被新机制错误放行。需要新增真实相反事实、不同年份、不同实体、冲突证据均有效、组合超长、非法编号与预算不足的机制案例。新增合成机制案例单列，不混进五题自然样本的总体分母。

初期验收要求原文定位及真实输入范围校验100%通过；确定正确项的未通过数减少，既有确定问题项不能因为组合或复核被新增放行；明确冲突和未决保留可追溯状态。复核器须报告纠正了多少旧错误、又新增多少错误。是否值得接入下一步改稿，再根据人审指标和调用成本决定。

不要承诺仅处理9条冲突就能使问题精确率很高。若上一轮257条的其余GPT标签和预测固定，9条误拒全部纠正而6个真检出、4个漏放不变，精确率只从6/43到6/34=17.65%，误拒率从37/247到28/247=11.34%。这只是理想化算术对照，不是改造测量结果；说明还要修证据完整性与其他语义误判，而且问题类基率影响精确率。

本轮五题用于开发与回归，提示词、预算、模型和阈值锁定后，用另批轨迹及人工金标作独立测试。自然样本报告反映原问题基率；错误挑战集分开评估召回、误放与失败类别，不能以提高错误样本比例后的精确率代替真实业务结果。

## 实施顺序与待测事项

第一步完成原文证据单元调整和有限组合，保留原NLI阈值，验证联合支持和混合主题案例。第二步接入冲突、单边矛盾及证据完整unknown的结构化复核，修复候选判定到最终裁决的流程。第三步运行A/B/C/D离线对照，冻结正式策略后再决定是否影响摘要提交或修复。

已测量依据：旧运行的定位、分布及13个诊断输入。设计推断：两项改造直接针对已观察到的证据分散、噪声反证与NLI语义误判。尚未测量：新策略四项指标、复核器自身准确性、新增LLM与检索成本、整体时延、生产端到端收益。本方案未宣称改善已实现。
