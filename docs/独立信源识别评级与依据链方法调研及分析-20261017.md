- 评估日期：2026-10-17（Asia/Singapore）。
- 评估对象：给定 URL、域名或发布者，自动识别主体、分类、评级并提供可追溯依据的方法与公开实现。
- 口径：本次要求比 [2026-10-11 的媒体评级调研](信源评级论文与开源项目调研及适配分析-20261011.md) 更严格，是一次新的选型分析，未覆盖旧报告。关注功能与实现机制，不进行运行效果排名。
- 数据／配置：核验论文原文、ACL Anthology、四个官方仓库及固定提交的相关文件。未安装依赖、运行第三方程序或调用模型；未改变本项目的业务代码。

## 筛选标准

1. **主体识别**：区分承载域名、真正发布者和原始出处；主体身份有证据，不仅是解析 URL。
2. **来源分类**：说明官方、媒体、学术等类型；机构属性与文档属性必要时分别表达。
3. **可靠性评级**：单独输出可靠、存疑或未知，不能从官方身份直接推出可靠。
4. **依据追溯**：评级理由对应实际证据、URL 和相关内容；模型写了一段解释不自动满足此项。
5. **不确定性处理**：缺乏证据时允许未识别、无法评级，不强制给分。

“独立完成”在这里指系统自动执行这些步骤，可以使用检索、模型和数据资源；并不额外要求纯离线或不依赖外部资源。

## 逐项分析

### 1. Media Background Checks：应优先阅读的论文

**Generating Media Background Checks for Automated Source Critical Reasoning**，Michael Schlichtkrull，**EMNLP Findings 2024**。[正式发表记录](https://aclanthology.org/2024.findings-emnlp.283/)，[作者方法原文](https://arxiv.org/html/2409.00781)，[官方仓库](https://github.com/MichSchli/MediaBackgroundChecks)。应保留 Findings 标识，不能写为主会。

方法不是直接猜一个可信度分数，而是针对来源检索所有权、资金来源、服务对象、编辑立场与历史事实核查记录，生成来源背景说明，供后续判断使用。仓库有生成与评估程序，固定提交为 `d54879563a13c90bb1613c64f392980b0b266397`。

关键限制：原文第三节明确移除了原始偏向和可信度评级；生成器 `build_background_check` 接收来源名。因此它提供评级所需的背景事实，不是“任意 URL → 验明发布者 → 分类 → 输出可靠等级”的完整实现。作者亦报告背景事实遗漏和错误，不能因有检索就假设说明可靠。

本次建议借鉴其检索问题与背景事实组织方式，再单独实现身份核验、类型体系和证据驱动的评级规则。不能把背景说明文本直接改名为可靠性评级。

### 2. MediaRef：补足背景资料检索的可复现性

**MediaRef: A Public Knowledge Store for Media Background Checks**，2026。[作者预印本](https://arxiv.org/html/2607.02383)，[官方仓库](https://github.com/nedjmaou/mediaref)。本次核验到预印本，没有核验到顶会正式发表记录。

作者构建覆盖 200 个来源的背景资料库，用于减少实时搜索 API 的依赖，支持检索后生成和更新 MBC。固定提交 `e6a902bab91fed73e6316576aefdbb8089d7d9b6` 已有知识库构建、背景检查生成及评估代码，尽管 README 仍保留代码待发布的表述，应以实际文件树为准。

它适合研究“依据从哪里来、如何重复实验”，不代表对任意新网站都能识别主体或独立评级。学术机构、期刊等出现在部分材料中，也不等于已验证通用学术分类和研究质量评级。数据许可应按仓库指向的 Zenodo 记录核验，不能据 GitHub API 未识别许可证就假设无限制复用。

### 3. FactHarbor：本轮最接近完整流程的实现参考

[官方仓库](https://github.com/robertschaub/FactHarbor)，固定提交 `4890de15a36dd86692c7279fb2652c9e5e95209d`。当前 README 和 LICENSE 指向原始软件 AGPL-3.0-only，不能沿用较旧搜索摘要中的多许可证描述。本次核验到独立来源可靠度引擎、证据包构建、结构化类型、提示词及相关测试文件，没有运行测试。

已存在的关键结构：

- `identifiedEntity`：识别的组织名，可为空。
- `sourceType`：来源类别，与 `factualRating` 分字段输出。
- `factualRating`、`score`：可靠性等级与分数，允许 `insufficient_data` 和空分数。
- `reasoning`、`evidenceCited`、`caveats`：判断说明、证据引用和局限。
- `evidencePack`：检索问题及证据项，证据项有 ID、URL、标题、搜索摘要等。

评级提示词要求依据实际证据而非模型已有印象，明确政府来源不能自动视为可靠；主体缺乏证据时不推断身份。入口 `evaluateSourceWithConsensus` 先构建证据包再进入评估，相关实现可分别检查 [引擎](https://github.com/robertschaub/FactHarbor/blob/4890de15a36dd86692c7279fb2652c9e5e95209d/apps/web/src/lib/source-reliability/sr-eval-engine.ts)、[提示词](https://github.com/robertschaub/FactHarbor/blob/4890de15a36dd86692c7279fb2652c9e5e95209d/apps/web/prompts/source-reliability.prompt.md)、[结构定义](https://github.com/robertschaub/FactHarbor/blob/4890de15a36dd86692c7279fb2652c9e5e95209d/apps/web/src/lib/source-reliability/sr-eval-types.ts)。

**不能原样认定完全满足用户要求，原因可在代码中直接定位：**

1. 来源枚举含 12 个值，包括政府和媒体，但没有独立学术类别；其中又混入已知虚假信息等评价标签，类型轴并非完全中性。
2. 引擎 `applyDeterministicQualityGates` 会按某些类型强制限制分数。字段分开不代表判断逻辑完全解耦。
3. 引擎的系统指令在第 278 行对缺证据原则保留了按清楚可辨类型评分的例外，与严格的缺证据不评级要求有张力。
4. 证据包包含搜索 URL、标题、摘要；有可追溯入口不等于已经逐条核验完整正文。结构中存在引用字段也不证明运行时引用一定正确。

因此，它适合作为来源评估服务的代码骨架；如用于本项目，应扩展分类、拆开评价性标签、消除仅按类型评级的例外，并验证证据引用。以上是静态设计分析，不是效果结论。

### 4. web-researcher-mcp：字段解耦明确，但信誉部分主要是查表

[官方仓库](https://github.com/zoharbabin/web-researcher-mcp)，固定提交 `8389463e99959198a279d1f31529b5e47152099a`，GitHub 识别许可证为 MIT。

代码把 `sourceType`、`authorityTier`、`domainCategory` 和 `domainReputation` 分开。信誉项包含 `tier`、`basis`、`note`；支持 high／mixed／low／unknown，默认数据可替换。相关 [分类器](https://github.com/zoharbabin/web-researcher-mcp/blob/8389463e99959198a279d1f31529b5e47152099a/internal/content/classify.go)、[信誉查询](https://github.com/zoharbabin/web-researcher-mcp/blob/8389463e99959198a279d1f31529b5e47152099a/internal/content/reputation.go)和 [默认表](https://github.com/zoharbabin/web-researcher-mcp/blob/8389463e99959198a279d1f31529b5e47152099a/internal/content/data/domain_reputation.json)均可追溯。

本次静态计数，默认表有 41 个域名键，其中 40 个 high、1 个 mixed，没有 low；很多条目按官方或机构身份预置较高信誉。不能把这当作独立核验内容后的可靠性判断。未知域名在底层返回 unknown，在工具输出中通常省略信誉字段。

来源分类首先依靠 JSON-LD、citation 元数据，再依靠域名启发式；这是类型识别线索，不能证明发布主体身份或实际同行评审状态。它适合作为工具输出合同和数据查询层的参考，不是完整的自主调查评级器。

## 对上一轮推荐的范围修正

RA-RAG 处理可靠度估计与检索／聚合，NAACL 2024 的新闻关系图处理来源级评分，EACL 2026 的 Web Search Analysis 评测来源可信度和引用支持度。按本轮严格定义，这些是相关组件或评测方法，不应继续统称为完整的独立识别、评级、解释工具。

另查到 NAACL 2024 主会论文 [An Interactive Framework for Profiling News Media Sources](https://aclanthology.org/2024.naacl-long.3/)，但其方法明确结合人工交互，不能作为无需人工逐项介入的完整方案推荐。

## 失败样例与风险

本次没有运行效果测试，没有新增实测误判。下表均为机制推断的未来验证案例：

| 假设输入 | 可能失败 | 必须检查的输出 |
| --- | --- | --- |
| 假冒机构站，名称和页面元数据模仿官网 | 把自称官方当成核验后的身份 | 主体与官方域名关系的独立证据 |
| 机构官网发布有利益关系的产品结论 | 身份或名单高信誉替代具体论断核查 | 来源属性与内容依据分别说明 |
| 新站点没有独立评级或历史记录 | 模型补出背景或按类型给分 | 未识别／未知／证据不足，而非默认中等可靠 |
| 转载论文的媒体页面 | 承载媒体、论文作者和原始发布者混淆 | 当前页面类型、原始研究标识及转载链 |
| 作者信息和 citation 元数据齐全但无同行评审 | 元数据启发式错误推出学术质量 | 仅记录元数据线索，另核查评审与研究状态 |
| 理由声称证据 E2 支持，实际 E2 只提到机构名 | 有证据 ID 但没有有效支持 | 核验引用的相关片段及对评级的支持关系 |

## 局限性

本次定向检索与局部代码检查不是全领域穷举，也不是对四个仓库的完整审计。四个固定提交及 18 个文件均成功留存，没有运行失败样本可以报告。没有测试外部服务可用性、数据更新程度或中文站点准确率。

论文有评测不代表工具已满足全部产品要求；提示词写了限制不代表模型稳定遵守；存在单元测试不代表本次测试已通过。评级是对特定来源、时期和领域的判断，不能直接等同于该来源所有内容的正确概率。

## 结论与下一步建议

**有高度相关研究与接近的开源实现，但本轮没有确认无需改造即可覆盖官方、媒体、学术，并严格满足全部条件的通用成品。**

阅读顺序建议为 MBC 2024 的任务与依据收集方法、FactHarbor 的证据包和结构化评估实现，再参考 MCP 的字段拆分。MediaRef 可作为复现实验的背景资料资源。

若后续接入，先定义身份状态与来源类型，再让评级器只根据独立证据判断可靠／存疑／未知，并逐条保留证据 URL、相关片段、获取时间和支持关系。验收时优先测试官方身份误报、转载归因、未知来源误评分与理由引用不匹配，再测量常规来源的效果。本次未执行接入或实验。
