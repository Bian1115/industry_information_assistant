## 建议评估并用于简历的指标

以下是后续测量方案，不是本项目已经取得的结果。优先选择检索质量、有效正文获取率及效率；用固定预算下的证据覆盖率补充多轮检索价值。

| 对象与指标 | 定义和标注口径 | 能说明什么 | 当前核查状态 |
| --- | --- | --- | --- |
| 检索 Precision@5 | 每条查询前 5 个唯一 URL 中人工判定相关的数量/5，再跨查询平均；不足 5 条按缺失位置不相关计 | 前排结果的相关性 | 无金标，尚未评估 |
| 检索 nDCG@10 | 人工按 0=无关、1=弱相关、2=相关、3=直接支持需求分级；固定增益与折扣公式，使用冻结候选池计算理想排序 | 相关结果是否排在前面 | 无等级标注，尚未评估 |
| 固定预算关键问题证据覆盖率 | 运行前独立列出关键问题；能由实际获得的有效正文支持的问题数/关键问题总数 | 分解、追踪和补搜是否找全所需信息 | 没有本次独立标注，尚未评估 |
| 有效正文获取率 | 人工确认得到目标页面可用正文的唯一 URL 数/全部待读取唯一 URL 数；失败、拒绝、超时计入分母；完整与部分正文分别报告 | 读取流程的实际可用性 | 有程序统计字段，未测人工金标率 |
| 正文抽取 Precision/Recall/F1 | 在保存 HTML/PDF 与人工正文金标上，用统一分段及匹配规则计算；Precision 衡量抽取内容的正文比例，Recall 衡量保留了多少金标正文 | 漏抽正文与混入导航、广告的程度 | 无正文金标，尚未评估 |
| 异常页检测 Precision/Recall及正常页误拒率 | 把异常页作为正类；检出异常/全部判异常为 Precision，检出异常/全部金标异常为 Recall，误拒正常/全部金标正常为误拒率；uncertain 与检查执行失败另列 | 拦截污染的收益与正常网页损失 | 仅 3 个历史负例和机制测试 |
| P50/P95 延迟 | 搜索和网页读取分开计时；明确起止点、缓存冷热、并发、重试及失败口径，报告成功请求分位数及全部请求超时/失败率 | 常见与尾部响应速度 | 仅单查询调用耗时，不支持稳定分位数 |
| 每份有效来源成本 | 实际搜索账单与相关模型 usage 成本/人工确认有效且去重的来源数；同时报告每任务调用量 | 获取有用资料的成本 | 历史费用为空，尚未评估 |

Precision@K 和 nDCG 的参考：[Stanford《Introduction to Information Retrieval》排名检索评估](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html)。网页抽取的 Precision/Recall/F1 参考：[Trafilatura 官方评估说明](https://trafilatura.readthedocs.io/en/latest/evaluation.html)。外部库基准的分数不能当成本项目的分数。

全网检索不能直接知道所有相关网页，优先测 Precision@5 和关键问题证据覆盖率。只有建立明确的相关文档金标后，才能报告 Recall@K；采用候选池金标时应称“候选池 Recall@K”，不能声称全网召回率。对于以查询改写和多轮追踪为主的模块，固定搜索服务和预算后的证据覆盖率，通常比仅比较供应商结果排序更能反映本项目逻辑的作用；这是方案选择建议，尚未通过本次消融验证。

## 当前代码统计与测量边界

`DeepScout._update_web_reader_stats` 按唯一 URL 的最后一次读取结果计算 urls_total、urls_success、success_ratio、urls_body_admitted、urls_body_pending、body_reviews_failed 等字段。程序准入率可由 urls_body_admitted/urls_total 派生，分母为 0 时应记为不可用。这属于规则和模型判定结果，不能自动替代人工有效正文率。

`success_ratio` 本身不能证明目标正文完整或支持事实；passed/partial 也不等于事实语义支持核验。正文质量拒绝、网络抓取失败、质量复核执行失败应分别统计，partial 应单列。

报告级默认 20 次上限是逻辑检索工具调用预算，预算在适配层缓存查询之前计数，供应商重试还可能增加实际请求。简历不得把这个上限写成“最多 20 次付费 API 请求”，也不能视为已证明的成本下降。实际费用、工具调用数、缓存命中与上游尝试次数应分开记录。

已测量：历史原始结果的一致性、固定回放 85.92% 字符降幅，以及历史回归结果的成功与失败数量。

间接推断：现有埋点可用于派生准入率和失效类别，现有预算、缓存及适配结构可支持后续配对实验。这些机制不证明质量或费用已经改善。

尚未评估：本次当前代码的新端到端表现，以及上表中依赖金标、大样本计时或账单的指标。

## 简历建议、结论与下一步

当前可引用的量化表述：

> 实现网页正文质量准入与验证码、脚本污染拦截，在固定历史检查点离线回放中，将 Writer 证据输入从 28.63 万字符降至 4.03 万字符，减少 85.92%；新增 22 项相关机制回归全部通过。

该表述仅在使用者确实参与对应实现时适用。不能扩写成“系统 token/费用降低 85.92%”，也不能省略固定检查点离线回放的范围。若提扩展检查，必须同时写明 3 项失败和 1 项错误。

补测后可用的模板（所有括号必须替换为真实测量值，不能直接保留为既成成果）：

> 在【N】条固定研究问题、【M】个跨网站页面上评估检索与读取链路，相较【明确基线】，Precision@5 从【A】提升至【B】，有效正文获取率从【C%】提升至【D%】，读取 P95 从【E】降至【F】；固定检索预算下关键问题证据覆盖率达到【G%】。

建议先建立 50 条研究问题和约 150 个跨站点页面作为首轮开发评测集，而非统计充分性的保证。问题覆盖资讯、政策、数据和报告；页面覆盖静态文章、动态页、文本 PDF、扫描 PDF、登录/验证码、付费预览和推荐列表。保存原始页面、人工标注及类别，分组报告，避免全部负例来自一个网站。

检索基线使用原始单查询，候选方案使用按章节生成查询及追踪补搜；冻结同一供应商、时间窗口、范围、模型和总调用预算，同时报告实际调用量。读取基线使用静态 httpx+Trafilatura/PyPDF2，候选方案增加浏览器兜底及质量准入；对同一固定页面配对比较，并报告误拒率和额外耗时。开发样本之外保留独立测试集，失败样本不可删去。

质量指标按查询/页面报告分组结果及适当的置信区间；延迟应增加独立重复请求并说明样本数，不用单条查询的单次耗时声称 P95 优化。人工标注优先，由第二位标注者复核部分样本；使用 LLM 初标时必须明确方法并人工复核，不能把在线判定器自身输出同时当作金标。

结论：目前最扎实的已有数字是固定历史检查点的证据字符降幅；检索相关性、有效正文率和稳定 P95 仍需按上述口径补测。当前可先写功能与有范围的回放结果，后续用质量、可用性和效率三类实测指标替换简历占位项。
