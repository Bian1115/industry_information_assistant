# 删除单条旧输入摘要改造及验证

验证日期：2026-10-01。对象：DeepScout单条旧输入的模型摘要生成与缓存复用分支。此次按用户要求从源码中删除该分支，不再以开关形式保留执行路径。使用本地桩验证，没有付费模型调用、真实题目重跑、服务重启或历史轨迹清理。

## 功能与配置口径

原文外置和引用化具有相同的功能：把上下文中的长原文替换为短预览或来源编号，完整原文保留并可回读。现有代码有两处实现：工具记录外置处理工具输入和输出；旧输入引用化处理LLM提示词里重复粘贴的正文。触发时机也有区别：工具记录外置按总上下文阈值执行，旧输入引用化在历史组装时逐条检查已完成的旧输入，符合精确匹配及最小长度条件就替换。本次没有调整这两处的触发顺序和阈值。

已删除 `input_history_view.py` 中的单条摘要生成、派生摘要来源写入、缓存键计算、缓存校验与复用、摘要视图渲染、单条摘要审计回调。删除 `agent_context.py` 的 `input_history_summary` 阶段标记以及不再使用的缓存统计。新代码仅记录原文引用替换事件及被替换的来源编号。

清理本地 `.env`、`.env.example` 和配置构造器中的单条摘要开关、4000 token阈值及单次摘要数量设置。新运行使用 `InputHistorySettings` 的 `input-view-v2` 配置，仅包含版本、引用化开关和最小替换长度。8份新框架消融配置模板同步移除对应字段，更新使用说明和后端README。

旧 `input-view-v1` 字段留在独立的 `LegacyInputHistorySettings` 中，仅用于读取旧配置和保持历史快照哈希。旧开关为true也不会让当前源码生成或复用单条摘要。历史缓存事件及派生来源仍保留审计和原文读取兼容；复现旧行为需使用当时冻结的源码与配置，而非仅加载旧配置。

## 已测量结果

四个测试模块：旧输入历史压缩、上下文消融配置、摘要提交与Claimify开关、智能体独立历史。共72项，64项通过，8项PostgreSQL集成测试因未显式启用而跳过。无失败样例，付费模型调用为0。

| 场景 | 结果 |
| --- | --- |
| 长旧输入存在已保存正文及其他长背景 | 正文替换为来源引用，其余背景保留，不执行单条模型摘要 |
| 总历史超过整体摘要阈值 | 只执行整体摘要并保存，历史覆盖游标正常推进 |
| 旧配置开启单条摘要，且存在旧缓存事件 | 当前源码仍保留原文或引用视图，不生成摘要、不复用旧摘要缓存，历史事件保留 |
| 原文哈希不一致或没有回读权限 | 原有检查仍拒绝替换 |
| 当前输入、未完成输入、外置或回读关闭 | 原有保留与开关行为通过回归 |
| 新运行残留旧环境开关为1 | 不能恢复已经删除的模型摘要分支 |
| 9份消融配置 | 均可加载；8份新框架模板为仅引用化配置 |
| 两份历史评测配置 | 完整字段和哈希恢复一致 |

本地 `.env` 加载得到新配置：引用化开启、整体摘要开启、历史回放agent为DeepScout，单条摘要参数不再出现在新配置中。配置哈希为 `8b6ef3cc6b6dbe0507f58c9811869a2392b1aad340e317e951c66e3c8a6e2cb6`。

两份历史快照：`通用研究中文5题-20260930` 与 `通用研究中文5题重跑-20261001-201500`，恢复后的配置与原快照逐字段一致，哈希相同。
