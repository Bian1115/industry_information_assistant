# DeepResearch追问模块论文与开源项目核查及设计分析

## 一、日期、对象和分析口径

- 核查及分析日期：2026年10月17日，Asia/Singapore。
- 对象：支持多轮研究会话的追问入口，重点是话题连续性、历史依赖、成果定位、追问改写与执行路由。
- 资料范围：重点核查2023—2025年的ACL、NAACL、EMNLP、COLING论文，补充2022年的话题切换基准；论文年份以正式出版信息为准，不采用搜索引擎的抓取时间。
- 方法：阅读正式论文页面及部分PDF方法、算法和局限性；阅读官方开源仓库及相关源码页面；只读检查本项目的会话任务协议和历史分析报告。
- 本次未运行模型、检索器、项目服务或准确率评测；没有新增端到端质量、延迟和成本测量。以下实现建议是基于资料和源码的设计推断，不能当作已证明的准确率提升。
- 本次机器可读核查记录：[资料核查记录.json](../backend/eval/data/追问模块论文与开源资料核查-20261017/资料核查记录.json)。包含资料URL、核查范围、方法边界及本地参考文件哈希。

## 二、核心判断

“是否延续话题”“是否依赖历史”“依赖哪个成果”“本轮要执行什么操作”需要分别表达。话题切换论文主要支持前两项的部分设计，对话检索论文主要支持改写与检索，框架代码主要提供流程组织机制。本次核查未发现能够直接证明本项目所有追问路由准确率的现成结果。

例如，“把刚才的结论压缩成三点”“给刚才的结论补两项正式来源”“重新研究该行业最近一年的变化”可能都延续相同研究对象，却需要不同执行路径。同一轮也可能同时要求补证据和修改正文，不能只用一个互斥路由标签描述全部动作。

## 三、优先阅读的论文

### 1. DMF：Simulating Dual-Process Thinking in Dialogue Topic Shift Detection

- 正式发表：COLING 2025，主会论文。
- [论文及正式出版信息](https://aclanthology.org/2025.coling-main.177/)，[PDF](https://aclanthology.org/2025.coling-main.177.pdf)。
- 内容：结合历史的全局话题结构与当前话语相对最近话题的局部关系，进行实时话题切换判断；使用大模型产生训练信息并蒸馏到较小模型。实验包括中文CNTD与英文数据。
- 对本项目的启发：维护多个历史话题及其成果索引，同时保留近期原文。判断“回到更早话题”时，不能只比较本轮和紧邻上一轮的相似度。
- 边界：论文的current response指当前已到达的话语，并非要求先生成系统未来答复。闲聊话题切换的标签口径仍需适配研究任务；论文没有评估本项目的报告修改、补证据、重新研究路由。本次没有核实作者官方实现地址，不把它列为已验证可复现代码。

### 2. UPS：A Unified Supervised and Unsupervised Dialogue Topic Segmentation Framework Based on Utterance Pair Modeling

- 正式发表：NAACL 2025，长文。
- [论文及正式出版信息](https://aclanthology.org/2025.naacl-long.252/)，[PDF](https://aclanthology.org/2025.naacl-long.252.pdf)。
- 内容：以话语对关系建模话题边界，并研究监督、少样本和无监督配置；监督预训练区分相邻关系与话题归属。
- 对本项目的启发：把话题关系视为有标注定义的学习任务。积累真实追问的困难正负例后，可以比较专门分类器与大模型提示方案。
- 边界：这是对话分段方法；方法中的编码器读取整段对话。在线版本必须改成仅使用当前轮及历史前缀，并重新评估，不能直接把离线分段分数当作在线追问准确率。本次没有核实作者官方实现地址。

### 3. Def-DTS：Deductive Reasoning for Open-domain Dialogue Topic Segmentation

- 正式发表：Findings of ACL 2025，需与ACL主会论文区分。
- [论文及正式出版信息](https://aclanthology.org/2025.findings-acl.1066/)，[作者代码与提示词](https://github.com/ElPlaguister/Def-DTS)。
- 内容：依次提取上下文、分类话语意图，再由意图判断话题切换；区分发展已有话题、引入相关话题和完全换题。
- 对本项目的启发：先提取对象、意图和历史依赖，再作可检查的关系判断，便于定位误判发生在哪一步。作者仓库提供提示词，适合从提示方案开始研究。
- 关键边界：原论文算法使用双向上下文，包括被判断话语之后的消息。线上追问不能获取这些未来消息。可借鉴其意图标签与结构化处理，但必须单独测量只读前缀的版本，防止数据泄漏。

### 4. IterCQR：Iterative Conversational Query Reformulation with Retrieval Guidance

- 正式发表：NAACL 2024，长文。
- [论文及正式出版信息](https://aclanthology.org/2024.naacl-long.449/)，[作者代码](https://github.com/YunahJang/IterCQR)。
- 内容：利用检索信号迭代优化会话查询改写，不依赖人工改写文本作为训练目标。
- 对本项目的启发：追问补全不仅要语义忠实，还应检查是否有利于找到目标证据。可对原始追问和改写查询的检索结果分别记录命中情况。
- 边界：“不依赖人工改写”不等于无需监督信息；方法利用相关证据段落等检索监督。检索效果提升也不能替代话题分类、目标报告定位或执行路由的评价。

### 5. ConvGQR：Generative Query Reformulation for Conversational Search

- 正式发表：ACL 2023，长文。
- [论文及正式出版信息](https://aclanthology.org/2023.acl-long.274/)。
- 内容：结合查询改写与潜在答案生成进行查询扩展，并将查询生成与检索目标关联。
- 对本项目的启发：将忠实补全问题与扩展检索词分开保存。前者用于任务契约，后者可以作为搜索候选。
- 边界：潜在答案只是检索辅助，不能写入已确认事实或用户要求；该论文不直接解决研究执行路由。

## 四、用于定义问题和准备数据的资料

| 资料 | 已核查内容 | 适用范围及边界 |
| --- | --- | --- |
| [SuperDialseg，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.249/)；[作者代码与数据](https://github.com/Coldog2333/SuperDialseg) | 基于有文档依据的对话定义分段边界，并提供数据与基线 | 适合借鉴标签定义、分段评价和角色信息；英文分段任务不能直接替代中文研究追问数据 |
| [TopiOCQA，TACL 2022](https://aclanthology.org/2022.tacl-1.27/) | 包含相关话题切换的开放域多轮问答 | 年份较早，但适合构造跨话题检索用例；文档切换不必然等于用户研究目标改变 |

自然对话中的“相关新话题”与研究产品中的“同一任务扩展范围”可能采用不同标签。因此应先定义本项目标签，再借鉴公开数据；不应直接拼接不同口径的数据训练一个二分类器。

## 五、值得读的开源实现

### 1. NVIDIA NeMo Guardrails：意图识别与可编程对话流程

- [官方仓库](https://github.com/NVIDIA-NeMo/Guardrails)，[意图生成相关源码](https://github.com/NVIDIA-NeMo/Guardrails/blob/develop/nemoguardrails/actions/llm/generation.py)。
- 配套论文：[NeMo Guardrails，EMNLP 2023 System Demonstrations](https://aclanthology.org/2023.emnlp-demo.40/)，属于系统演示论文。
- 已核查机制：生成用户意图前可以检索相似表达作为候选示例；配置支持基于嵌入的匹配与回退；对话流程由运行时控制。
- 建议借鉴：从已标注困难样例中检索少量相关示例，再结合会话状态判断意图；由显式流程消费结构化结果。
- 边界：相似度不是准确概率。当前原始短追问可能缺少对象，不能直接用相似度最近的样例确定研究路径；该项目也不是专门的DeepResearch成果继承系统。

### 2. LlamaIndex CondensePlusContextChatEngine：改写后检索

- [具体源码](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/chat_engine/condense_plus_context.py)。
- 已核查机制：将历史与当前问题整理成可独立检索的问题，然后检索上下文并回答。
- 建议借鉴：分开保存原始问题、改写问题、检索证据及最终回答，便于定位上下文理解错误和检索错误。
- 边界：这一机制没有直接证明能区分新主题、返回旧主题、纯编辑及补充研究，也没有覆盖本项目的目标成果定位。

### 3. LangChain Open Deep Research：澄清与研究任务入口

- [官方仓库](https://github.com/langchain-ai/open_deep_research)，[入口源码](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/deep_researcher.py)。
- 已核查机制：`clarify_with_user`依据消息判断是否澄清，`write_research_brief`将消息形成研究任务，再交给研究监督流程。
- 建议借鉴：研究启动前先形成明确任务输入，并将需要澄清与可执行任务分开处理。
- 维护状态：核查时官方仓库显示已于2026年8月21日归档并转为只读。
- 边界：适合作为架构参考，不能由此推断它已经提供本项目所需的完整多轮追问路由和报告版本继承。本次没有运行其端到端流程。

## 六、与本项目当前结构的对应

本次只读检查以下文件，文件哈希记录在机器可读资料中：

- [会话任务协议](../backend/app/service/session_task_service.py)：已有`topic_relation`四类关系、`depends_on_history`、`target_artifact_ref`，以及可组合的`operations`、要求变更和检索任务。
- [会话上下文构建](../backend/app/service/research_context_service.py)：已区分本轮原话与历史参考，提供成果候选、改写、未消解指代和澄清字段；特定异常路径会进入澄清。
- [父成果继承](../backend/app/service/deep_research_v2/followup_context.py)：具备父成果授权定位、有界规划上下文及白名单继承；其注释明确不共享父运行的可变执行状态。

因此，建议在现有协议上补强数据、样例选择与评价，不再增加一个只返回`is_followup`的入口。当前结构是否提高了真实准确率，本次尚未测量。

建议的逻辑链路如下，可在一次结构化模型调用内实现，不要求每步都调用模型：

```text
近期原文 + 有效要求 + 多话题/成果候选
  → 判断本轮对象、话题关系与历史依赖
  → 定位目标成果，处理无法消解的指代
  → 忠实补全本轮任务，输出可组合操作与要求变更
  → 检查产物引用、章节引用及状态一致性
  → 生成确定性执行计划
  → 执行并记录最终产物是否完成本轮要求
```

有必要继续区分“相关但新的研究问题”和“完全无关的新主题”，但不应未经定义就增加线上枚举。可以先作为离线分析标签，检查它是否改变历史要求的继承范围与成果选择，再决定是否扩展协议。

## 七、逐类分析与失败样例

以下为设计用例，不是本次跑出的模型预测，不计入准确率。

| 场景 | 输入示例 | 应检查的判断 | 常见失败 |
| --- | --- | --- | --- |
| 直接延续 | “把刚才结论压缩成三点” | 定位当前稿；复用已有内容 | 把短问题当新研究，重新搜索 |
| 同主题补证 | “给第二点补两项正式来源” | 消解第二点；生成检索及修改操作 | 只有格式修改而没有补证 |
| 同主题变更要求 | “示例语言改成TypeScript，资料截止日不变” | 继承研究对象；替换语言要求 | 输出通用语言介绍，丢失项目对象 |
| 返回早期主题 | “回到最早那份行业报告，更新市场规模” | 从历史候选中定位旧稿 | 默认选择最新报告 |
| 相关新问题 | “这个行业的上游原材料呢” | 区分任务扩展与独立子问题；判断哪些旧要求仍有效 | 仅因共享行业词就继承全部范围 |
| 明确换题 | “另一个问题，介绍一下火星探测” | 不自动继承前一研究的专属要求 | 被最近上下文牵引回旧行业 |
| 歧义指代 | “比较一下它们”且存在多个合理对象 | 判断不同解释是否会改变执行；必要时澄清 | 随机绑定最近实体 |
| 解析/关联失败 | 模型返回非法章节ID或任务JSON不可用 | 修复或进入明确失败/澄清；不能把技术失败等同新主题 | 回退后清空对象、要求和目标报告 |

历史失败参考：[第11至14轮追问话题偏移补充分析](第11至14轮追问话题偏移补充分析-20261007-145815.md)。该报告记录了“安全边界”“会话状态”“TypeScript”等短追问在旧运行中丢失原MCP工程对象的现象，并关联逐轮任务输入、状态与报告。这属于既有历史证据，本次没有重新评分、重放或确认当前版本仍有同样缺陷；也没有将历史四轮结果外推为总体错误率。

原始历史运行路径：`backend/eval/data/第20题32轮章节正文整合修复后续跑-20261006-220005/真实运行/第11轮/`至`第14轮/`，具体文件以原报告中的链接为准。

## 八、核心指标与验证方案

本次资料核查未产生准确率、F1、检索召回、延迟、成本或提升幅度，相关值均为“尚未评估”。论文自己报告的分数也没有复现为本项目结果。

后续建议分别测量：

| 层次 | 建议指标 | 解释 |
| --- | --- | --- |
| 话题关系 | Macro-F1、各类Precision/Recall、混淆矩阵 | 单独观察延续、返回、新主题、无法判断；不能只看多数类Accuracy |
| 历史依赖 | 二分类Precision/Recall及误继承、漏继承率 | 同话题不代表每个独立问题都需要改写 |
| 成果定位 | 目标成果与版本准确率、候选覆盖率 | 分开定位“候选里没有”与“候选有但选错” |
| 操作路由 | 多标签操作匹配、集合完全匹配、执行计划正确率 | 支持同轮补证和修改，不强行压成单标签 |
| 查询改写 | 对象/条件保真、未授权条件新增率、Recall@k或nDCG@k | 防止检索更好但任务含义改变 |
| 要求继承 | 新增、替换、撤销及作用范围正确率 | 特别检查旧要求被覆盖和撤销要求复活 |
| 澄清与回退 | 错误率—自动执行覆盖率曲线、不必要澄清率 | 不能靠把困难输入全部澄清提高表面准确率 |
| 端到端 | 本轮指令完成、目标报告修改正确、错误新增事实、耗时与成本 | 合法JSON和内部审稿通过不等于完成用户追问 |

建议先准备一批真实中文多轮会话，按会话而不是按轮次划分训练/开发/测试，避免同一会话泄漏。明确标签定义，对歧义样例采用双人标注及仲裁；标注时只提供当前轮及此前消息。线上回放同样禁止后续消息、后续稿件或最终答案进入路由输入。模型信心或相似度阈值需在开发集校准，不直接解释为正确概率。

可比较的方案为：现有实现；加入检索困难示例；加入显式历史话题索引；在有足够标签时加入专门关系分类器。对同一测试会话做配对比较，报告逐类结果、置信区间和失败样例。任何真实运行均需新建中文结果目录和评估报告。

## 十、结论与下一步

优先读DMF理解实时话题切换，读Def-DTS借鉴意图与结构化标签，读IterCQR理解改写如何对齐检索。准备监督数据时参考UPS和SuperDialseg。工程实现可分别参考NeMo Guardrails的意图到流程、LlamaIndex的改写到检索，以及已归档Open Deep Research的澄清到研究任务。

对本项目，下一步最有价值的工作是冻结一份按真实会话划分的中文追问集，分别标注话题关系、历史依赖、目标成果和多标签操作；先找到主要误差来源，再决定增加提示样例、话题状态、分类器还是改写训练。本次只新增资料和设计分析，不修改业务实现，不宣称准确率已提高。
