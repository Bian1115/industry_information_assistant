# 检查点恢复七项效果指标结果及分析

分析日期：2026-10-14，Asia/Singapore。

评估对象：DeepResearch 检查点恢复的技术成功率、恢复时延、重复计算、状态与交付一致性、时间/费用节省、任务质量和正常持久化开销。

本次基于已有原始实测文件进行只读复核和补充计算，没有新执行在线模型、搜索、SIGKILL、数据库或浏览器测试。新增计算包括“评测续跑段开始至首个新节点执行”、原有事实记录保留和指定业务输入/配置字段一致性。没有为缺少基线的指标补造数值。

## 数据与配置口径

主统计为 2026-10-08 四个有效真实模型样本：原题 8、25、27、28，同一冻结应用源码与模型预算口径，图版本 `single-main-v4-session-task`。故障位置相同：Writer 完整节点的 pending writes 已落库、后继完整检查点提交前 SIGKILL。Writer 章节 task 关闭。

Scout 使用 qwen-plus，其余主 Agent 使用 qwen3-max；max_iterations=2，总时限 2400 秒，搜索上限 20，累计 token 不设上限但记录。完整模型参数、上下文策略指纹、原始结果与 SHA-256 保存在本次机器结果中。

题目 28 使用排除休眠异常后的正常再次复评。不同版本的原题 26、终态补交付单例、假模型章节实验，以及 2026-10-14 的预算/租约数据库专项均单列，不混入四题成功率。旧失败和环境异常仍保留。

评测续跑段开始时间在前置证据导出后、创建服务和调用恢复路由前记录。四题实际消费的是生产恢复路由的进程内 StreamingResponse，未经过完整网络 HTTP、认证和浏览器链路。

## 恢复时延的计算与逐题结果

首节点时间由 `节点恢复执行结果.json.started_at` 与恢复模式下首条 `node_start.at` 相减。使用墙钟时间戳重算，所有样本最终墙钟/单调计时差均小于 2 秒。恢复入口服务器接收请求的独立时间点没有记录，因此本指标是“评测续跑段至首次新执行”，不冒称精确的“请求入口至首次新执行”。

交付耗时采用原运行器单调计时 `duration_seconds`，包含创建服务、路由准备、租约等待、后续研究和完成流消费，截止点是完成流消费结束；不是单独测量数据库业务事务提交瞬间。包含故障后进程导入和前置证据导出的完整恢复 RTO 不作为本次主指标。

| 原题 | 至首次新 review（秒） | 租约等待（秒） | 恢复后交付（秒） | 排除等待后交付（秒） | 内部质量分／结论 | 断点原事实→最终事实 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 8 | 39.905 | 38.979 | 662.531 | 623.552 | 6／needs_revision | 21→36，原 21 条记录均未改变 |
| 25 | 51.247 | 50.348 | 419.047 | 368.699 | 5／needs_revision | 24→24，原记录均未改变 |
| 27 | 39.928 | 37.549 | 56.904 | 19.355 | 9／pass | 25→25，原记录均未改变 |
| 28 | 45.893 | 45.004 | 327.852 | 282.848 | 9／pass | 33→33，原记录均未改变 |
| 平均 | **44.243** | **42.970** | **366.584** | **323.614** | **7.25** | 原 **103/103**条保留 |

首节点时间的描述性中位数为 42.91 秒；交付中位数为 373.45 秒，范围为 56.90～662.53 秒。排除租约等待后交付均值为 323.61 秒，即 5.39 分钟。四个异质任务各测一次，不给出可代表生产的 P95。

题目 8 补搜、分析、再写作和修订较多，最终达到修订上限；题目 25 有两次 revise，仍有需要修改的问题；题目 27 只审核一次即结束；题目 28 经过补搜和再次写作后通过。8、28 的后续 write 属于业务返工，不能误算为重新生成故障前同一份初稿。

## 重复计算与状态一致性的证据

四题恢复前均显示 `saved_result_nodes=[write]`；恢复模式首个真实节点为 review。原 Writer 初稿没有在首次审核前重新生成。这证明已保存节点结果可推进到后继节点，不等于在任意中断位置都能避免模型调用重做。

本次比较了恢复前与最终状态的事实 ID 及整条事实记录，103 条原记录均存在且相等。新增事实属于后续补搜；原记录保持不变不证明它们本身事实正确，也不证明每条外置来源全文都能读取。

每题检查九个实际存在的输入/配置字段：query、original_query、resolved_query、research_contract、context_policy、session_inheritance_config_hash、allowed_domains、hypothesis_enabled、search_backend，合计 36/36 相等。这不是全部部署模型、提示词、工具和依赖的完整冻结验证。

四题交付正文与终态检查点一致，每个 run 的正式报告和完成事件各一条。没有覆盖同一个 run 的生产并发重复恢复和全部外部工具副作用；网络事件回放不算数据库新增完成事件。

另一个终态补交付单例：3.47 秒，新增模型请求和节点执行为 0，一次重复请求后数据库未变化。该结果单独评价已经完成的图如何补齐业务交付，不能替代中途恢复时延。

另一个 2026-10-07 真实 PostgreSQL、双进程、SIGKILL 章节实验：使用假模型，恢复复用已保存前两章，只生成未保存的第三章和首尾合稿，已保存章节重复生成为 0。真实模型章节收益尚未测量。

费用直接沿用原结果的历史公开价估算，未按当前价格重新定价；原口径为北京实时非思考公开原价，缓存未折算，搜索、本地资源等不计入。这些观察值不等于实际账单或完整端到端费用。没有同版本故障后重跑对照，因此时间和费用节省率均保留为 null，而不是 0%。旧历史基线的近似时间差不纳入严格配对指标。

质量分和 pass 均来自流程自身的 Critic/质量管线。题目 8、25 以 needs_revision 结束，说明系统可以技术交付仍待修改的报告。题目 27、28 的 pass 也不是外部独立审阅。没有无故障配对质量基线，不能说恢复使质量下降 50%，也不能说质量零损失。

## 最新预算与租约机制专项：单列证据

2026-10-14 的既有专项采用真实 PostgreSQL、固定模拟模型响应，8/8 场景通过，其中包括：

- 失败节点已知消耗 100，恢复后累计 140，物理尝试为 2；失败消耗没有因图状态回退消失。
- Writer SIGKILL 后新进程恢复，已保存前两章重复生成 0；累计已知模拟 token=400，未知请求预留=120，最终预算扣账=520。未知预留不是已测量实际费用。
- 接管后旧执行器完整检查点及 pending writes 被拒绝；写事务期间自然到期时三表回滚，新执行器可继续提交。
- 并发预留上限 150、两请求各预留 80，仅允许一个。

这增加了预算持久化和过期写入保护的机制证据，不把 8 个机制场景与四题真实模型任务混算为 12/12。原专项记录了隔离 schema 清理、未部署及业务库迁移尚未应用的边界；本次没有重新验证部署状态。

## 失败样例、准备问题与局限性

1. 历史原题 26 曾因为 next 为空而被错误拒绝，尽管 Writer pending writes 已保存；修复成功不删除旧失败。
2. 历史原题 28 曾有终态图正文，但业务报告与完成事件缺失且入口拒绝，应算交付恢复失败。后续补交付属于另一个修复版本样本。
3. 题目 28 旧复评发生休眠计时异常；本次采用正常再次复评，异常不参与性能均值。一次复评在正文提取阶段失败，尚未触发 Writer 故障，单列为上游执行失败。
4. 本次首轮只读字段探查曾将整数 unresolved_issues 当作列表迭代，产生 TypeError；改为读取整数计数与 critic_feedback 问题列表后核对成功。没有触发恢复运行、改动历史文件或影响有效样本分母。
5. 四题实验是旧图版本、固定单一故障位置、各一次有效恢复；不能替代当前工作区新版本、随机崩溃、数据库故障、真实双执行器、网络/浏览器与长期恢复验收。
6. 正文哈希一致、事实保留和配置字段一致都是指定检查项；不是全部业务状态或全文证据零丢失的证明。
7. 正常持久化耗时、存储写入量、生产 P95、独立任务质量及严格配对节省率均未建立对应实验，不能从机制测试通过数推导出来。

## 已测量、间接推断和尚未评估

**已测量（历史实测，本次重算/核对）**：四题恢复交付、续跑段至首个新节点、交付耗时、初稿直接进入审核、指定状态/事实保留、正式交付一致、内部质量分，以及原模型费用估算观察值。单列终态补交付、假模型章节复用和当日预算/租约专项。

**间接推断**：复用持久化初稿和章节有助于减少重做。由此不能量化总体平均省时、省钱或质量变化。

**尚未评估**：当前版本总体成功概率、精确网络请求入口恢复就绪时延、完整生产 RTO、严格配对时间/费用节省、独立质量差、无故障持久化开销、生产 P95、完整外置状态与全部外部副作用恢复。

## 结论与下一步建议

已测场景下，恢复的正确性和成果复用有效：四题 4/4 交付，原初稿直接进入审核，103 条原事实记录保持一致，正式报告/完成事件没有多写。续跑启动主要受约 43 秒的租约等待影响；交付时长主要由后续业务工作决定。

质量与经济收益的证据还不完整：内部仅两题 pass，严格省时/费用和正常开销尚无可报告数值。下一步在当前冻结版本补无故障关/开检查点、故障后重跑、同位置恢复四组配对实验，并加入独立质量评审；再扩展故障位置和重复次数。当前报告不以新模型调用填补这些基线缺口。
