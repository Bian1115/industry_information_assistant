# 摘要上下文消息编号与原句引用修改验证

验证日期：2026-10-01，Asia/Singapore。对象为启用 Claimify 时的摘要引用定位和对输入的忠实性核验。修改后的引用候选仅来自生成当前摘要的实际输入；每条消息或工具记录沿用自己的 UUID，输入的旧摘要和中间摘要另外保存有编号的快照。摘要引用继续使用 `source_id`、`quote`、`start` 和 `end`。

本次修改源码并执行确定性机制测试，没有调用真实模型、启动数据库集成测试、修改环境配置或重启服务。当前本地配置 `AGENT_SUMMARY_CLAIMIFY_ENABLED=0`，核验开启后才会走新的上下文引用路径。

## 编号与证据范围

一轮对话可能有多条模型消息和多个工具调用，因此不以轮次作为唯一引用编号。每条历史记录有一个 UUID；同一工具调用的输入和输出分别编号。长消息分片保留原消息编号及原文偏移，不能因为分片重新编号或重排消息。

旧摘要和中间摘要作为输入时，保存为 `summary_context_source` 快照，其 UUID 同时出现在实际生成请求的 `previous_summary_source_id` 或 `summary_part_source_ids` 中。非空最新任务契约也保存输入快照。快照不作为普通历史消息再次回放，但可通过现有归属校验接口读回。

只检查本次实际提供的字符范围。若最终合并只收到多个中间摘要，引用候选就是这些输入摘要快照，不能用本次未提供的原始全文代替。原始历史仍保留；回查文献真实性是另一种核验，不能把对输入的忠实性解释为研究事实已经成立。

## 代码变化

- `backend/app/service/summary_input_context.py`：保存并编号实际输入，核对消息快照哈希与分片偏移；在实际提供的片段内定位引句和相邻上下文。
- `backend/app/service/summary_citations.py`：Claimify 引用候选改为生成该正文的实际输入，禁止自动补入未提供的旧原文；修复时继续携带对应证据；保存候选编号及输入哈希。新提示版本为 `context-summary-input-citations-v2`。
- `backend/app/prompts/摘要上下文引用补齐.txt`：明确编号是上下文消息或摘要快照编号，要求原句逐字匹配，保留支持或反对材料。唯一原句由程序计算位置；重复原句要求可核对位置。
- `backend/app/service/summary_lifecycle.py`：将生成时捕获的真实输入传给后续审计，不再为引用审计补载未提供的旧全文。沿用现有先提交正文、后可选审计的生命周期。
- `backend/app/service/agent_context.py`、`verification_checks.py`：支持保存和回读输入摘要快照；快照不加入普通回放类型。
- `backend/app/service/nli_verifier.py`：根据程序赋予的 `summary_input_context` 标记执行输入忠实性核验。未带该标记时，助手历史及输入摘要快照不能直接验证研究事实，原研究证据门禁保留。

没有新增 RAG 库、向量检索或句子编号选择协议；本次按请求修改上下文编号和原句引用，继续使用现有 `source_id + quote` 接口。

## 失败样例与验证边界

预期拒绝的例子：摘要输入只有旧摘要快照，却返回旧论文历史记录 ID；输入是“研究纳入200人。”，返回“研究纳入 200 人。”；引用位置或核验邻接上下文超出实际提供片段；引用其他子任务的输入快照；已生成正文没有实际输入快照。

已测量：上述编号、范围、精确匹配、偏移、持久化接口调用和核验控制流的确定性行为；源码差异空白检查通过。

间接推断：限定实际输入能避免把没有提供给摘要模型的历史材料用于证明本次改写；分开忠实性与研究真实性可以避免仅因对话来源类型拒绝合理的摘要追溯。没有量化这两项对真实运行的改善。
