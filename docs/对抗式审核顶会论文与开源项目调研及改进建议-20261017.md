# 对抗式审核顶会论文与开源项目调研及改进建议

调研及历史评估分析日期：2026-10-17（Asia/Singapore）。

对象：研究报告生成后的 Critic 审核、事实核验、多审核器讨论及修改闭环。这里按本项目的报告质量审核理解“对抗式审核”。本次开展论文与官方仓库资料核查，并引用历史评测；没有执行模型推理、安装外部项目、重新标注历史样本或修改业务代码。

## 一、建议先学什么

优先阅读 CRITIC 和 SAFE，分别学习“审核必须取得外部反馈”和“长报告应拆分成可验证的事实”。再看 ChatEval 与 Multiagent Debate，了解多个审核器如何讨论。Debate-to-Detect 提供较新的正反方与裁判流程，但公开实现明确使用简化提示词。

本文对本项目的工程建议是：让审核器提出可证伪的问题，再验证问题是否成立，只有成立的问题进入修改；用同一份证据复核修改结果。这个组合是根据论文机制和项目历史失败样例提出的设计推断，尚未证明能改善本项目指标。

## 三、还应读的负面证据

- [Large Language Models Cannot Self-Correct Reasoning Yet，ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html)：研究缺乏外部反馈的内在自我纠错，指出其局限及可能退化。该结论不意味着所有带工具审核或后续模型都无法改进。
- [On the self-verification limitations of large language models on reasoning and planning tasks，ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/f3c5e56274140e0420baa3916c529210-Abstract-Conference.html)：在 Game of 24、图着色、STRIPS 规划等任务中检查自我验证，并比较外部正确验证器。适合提醒工程设计重视验证反馈的可靠性，不能直接外推本项目的报告审核收益。

这些研究支持设置可靠性对照与外部检查，而非预设“轮数越多，质量越高”。本文没有将不同论文的数据集、模型和成本合并为统一效果排名。

## 六、失败样例

1. **35-R2-issue_2：要求补的来源原本已存在。** 该意见要求为德州“三统一”补官方出处，但当轮报告第56行已经附同一官方 URL。见[当轮报告](../backend/eval/data/Critic五十六条意见正确率复核-20261011-201238/题目35/第2次审核/待审报告.md)。提出来源质量或适用范围质疑仍可能有价值，但“没有引用”的主要指控不成立。
2. **46-R3-issue_2：针对未采用的旧数值提出冲突。** 历史报告记录审核器把旧事实3.75%当作当前正文仍在采用的数值。需要版本绑定和原句定位，而非直接增加辩论轮数。
3. **49-R3-issue_3：近期发布被误判为预测。** 审核基准日为2026-10-09，材料发布日期为2026-09-22；仅因“较新”就给出预测指控并标记 critical，主要推断不成立。该例沿用历史保存判定，本次没有重新核查外部业务事实。

完整意见与上下文见上述逐条判定和历史报告；不将这三个例子解释为当前实现仍必然存在相同错误。

## 七、结合当前实现的落地方案

本次静态阅读的 [critic.py](../backend/app/service/deep_research_v2/agents/critic.py) 已将整体逻辑、要求覆盖、时效与独立的可选引用核验分开；提示词允许无问题返回空数组，并已有 `requires_new_search` 和 `search_query` 契约。应在这些基础上完善问题证据和修复验收，不宜笼统认定当前实现只是“毒舌提示词”。

建议流程如下，属于待验证方案：

1. **冻结待审版本与要求。** 为正文、需求和证据快照建立版本标识。正文定位、事实限定、引用作用域都针对同一版本。自然缺陷和人工注错材料分开保存。
2. **独立提出可验证疑点。** 报告级审核关注跨章节矛盾、需求遗漏、范围外推；事实核验关注重要数字、时间状态、主体、人群和来源支持范围。首轮先独立判断，保留各自证据，之后才交换意见。
3. **复核审核意见。** 每条包含原句或对应需求、位置、问题类型、证据标识、来源片段、推断理由和最小修复动作。对缺失需求提供需求条目及覆盖检查范围；对跨章节冲突提供两处定位。先用解析、日期/数字检查等确定规则排除可检查的误指控，再对其余意见检索或裁决。缺证据、来源不可读与事实错误分别处理。
4. **只对实质分歧展开有限讨论。** 可以允许作者侧指出意见的错误前提，并提交已有反证。裁判根据可检查的证据接受、驳回或标记无法判断；不按语气、篇幅或票数判真。相同模型多次调用存在相关错误，换角色或换模型也不保证独立正确。
5. **修改后逐条验收。** Writer 提交问题ID、修改位置与处理说明；复核检查是否修复、是否保留正确重要事实、是否引入新错误。无新增有效问题或没有新证据时停止；高影响未解决问题在交付中明确限定。

一个合理的起点是每个疑点只允许一次补证和一次裁决，再做一次修改后复核；这是成本可控的试验配置，并非论文证明的最佳轮数。

## 八、怎样评估是否做得更好

使用冻结的同一待审初稿和同一搜索快照，至少比较：当前单 Critic、两个独立审核器、带意见复核的审核流程；资源允许时再加入完整多轮辩论。对比时记录模型、提示词版本、token、搜索数及耗时，并做相近成本对照，避免把额外算力收益全归因于讨论机制。

核心指标应分开报告：

- **意见 Precision**：成立的审核意见 / 全部审核意见。部分成立单列，不折算为完全成立。
- **真实错误 Recall**：被发现的金标错误 / 全部金标错误。需先建立完整或明确抽样边界的错误清单，按严重度与错误类型分组。
- **修复率**：经复核已修复的成立问题 / 交给 Writer 的成立问题。
- **新错引入率与正确内容保留率**：衡量修改是否破坏原本正确的内容；同时检查需求覆盖，避免靠删去大量事实抬高支持率。
- **端到端变化**：初稿和终稿在同一口径下的错误数、严重度及质量变化；配合任务级结果和成本报告，不用问题数量下降或总分上升替代。

注错类型可覆盖错误数字/单位/分母、时间与状态、人群/地域外推、引用不支持、跨章节冲突、需求遗漏，并加入无错误对照。注错评测只能测指定缺陷的检出；自然报告测试和保留测试集仍然必要。关键分歧应由独立人工复核或双标仲裁。

## 九、局限、结论与下一步

**已测量／已保存的历史结果**：五题56条意见的历史判定与统计，来源为本地已有文件。本次仅核对汇总、配置和报告记录，没有重做56条复核。论文会议信息与仓库说明通过公开一手页面核查；这不属于新模型效果测量。

**间接推断**：将 CRITIC 的外部反馈、SAFE 的事实粒度与多审核器讨论组合到本项目，可能比单纯增加轮数更适合处理历史误报；该推断尚未通过本项目对照实验验证。

**尚未评估**：当前版本 Critic 的准确率、完整错误召回率、外部仓库在本地的可运行性、各方案在中文研究报告上的成本及净收益、模型或角色多样性带来的因果效果。未宣称覆盖截至本日的全部论文，也未作开源项目质量排行榜。部分目录网页抓取失败后使用官方 README 核查，不据此推断仓库代码缺失。

结论：优先学习 CRITIC 与 SAFE 的证据机制，再借鉴 ChatEval 与 Multiagent Debate 的讨论协议。下一步应先为当轮意见建立可靠定位、证据复核和修改验收，在冻结材料与相近预算上测清误报、漏报和新错；随后再决定是否增加审核器与辩论轮数。
