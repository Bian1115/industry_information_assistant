# 会话 RAG 取消全文状态与引用回读：验证结果及分析

## 日期、对象与口径

- 实施与验证日期：2026-10-17，Asia/Singapore。
- 对象：启用 `SessionEvidenceRAG` 的 DeepResearch 来源入库、运行状态、章节任务、跨轮继承和报告引用证据读取。
- 目标：取消研究状态中的来源全文副本；删除全文恢复方法及其调用；取消引用阶段按原文偏移重建 quote、再与证据块比较的操作。写作和引用核验直接使用会话 RAG 中已保存的原文证据块。
- 测试口径：SQLite 内存数据库、注入的 embedding/rerank/向量后端以及模型响应；未运行真实模型、业务数据库或真实 Milvus 集成评测。RAG 机制测试中的向量为二维测试向量，主要 token 预算测试使用本地测试计数器，不代表真实模型性能。
- 原始结果保存在下列运行目录，每轮使用新目录，没有覆盖历史结果。本报告汇总同次实施的各轮补充复评，并明确记录用例口径变化。

## 最终实现

### 状态只保留来源引用

来源正文仍保存在 PostgreSQL `session_evidence_documents.payload`，证据块文本保存在 `session_evidence_chunks.content`，向量保存在 Milvus。`raw_sources` 字段继续作为本次研究的来源目录，保留文档编号、哈希、标题、URL、章节关系及可用状态。

`SessionEvidenceStore.ingest()` 返回来源引用，`SessionEvidenceRAG.ingest()` 在数据库提交后即将状态中的来源替换为引用，不再等到保存检查点时才移除全文。引用中不包含 `content`、`full_content`、`sentence_index`。即使向量建立失败，正文已经入库，状态仍保持引用形式。

Scout 的新来源首先作为局部入库输入保存到 RAG，再将引用写入研究状态。搜索结果也移除全文与句子索引，界面保留最多 200 字的来源预览。运行状态中的 `research_material_context` 仍可包含有预算的召回证据块，用于规划；它不是整份来源全文副本，也不会持久化到节点检查点。

来源引用未变化时，入库复用路径只投影查询文档元数据，不加载完整文档 payload。章节关系等元数据变化时仍允许读取已有 payload 并更新元数据；这不会恢复研究状态中的全文。

涉及：[session_evidence_store.py](../backend/app/service/session_evidence_store.py)、[session_evidence_rag.py](../backend/app/service/session_evidence_rag.py)、[scout.py](../backend/app/service/deep_research_v2/agents/scout.py)。

### 删除全文恢复和原文偏移比对

- 删除 `SessionEvidenceRAG.hydrate()`。
- 删除图节点准备、父研究载入及 Writer 章节任务中的全文恢复调用。
- `references()` 直接将证据块 `content` 作为 quote，来源信息取块的定位元数据，不调用 `store.documents()`，也不再根据 `source_spans` 从完整正文重建并比较文本。
- 历史 `sentence_ids` 引用直接映射到当前主题的句子、表格或字段记录块；表格仍提供带表头和注释的结构化单元。
- 保留来源编号、证据块编号、定位信息、用户与会话归属和有效期检查。可选 NLI 仍对拿到的证据块进行语义支持性判断。

涉及：[session_evidence_rag.py](../backend/app/service/session_evidence_rag.py)、[writer.py](../backend/app/service/deep_research_v2/agents/writer.py)、[service.py](../backend/app/service/deep_research_v2/service.py)。当前工作区另有独立的最终报告论断抽取入口，本次保留该入口，并验证它能继续通过 RAG 获取被引文档的证据块。

### 调整依赖全文的外围逻辑

新增 `source_available()`，让 Writer 的来源可用性判断和来源展示能消费已入库引用，而不要求状态重新携带正文。来源规范化保留引用中的原始内容哈希，不再把缺少正文误算为空串哈希。跨轮继承复制来源引用，证据指纹对引用使用其文档哈希。

涉及：[web_document.py](../backend/app/service/web_document.py)、[evidence.py](../backend/app/service/deep_research_v2/evidence.py)、[followup_context.py](../backend/app/service/deep_research_v2/followup_context.py)、[quality_pipeline.py](../backend/app/service/deep_research_v2/quality_pipeline.py)。

检查点继续保存研究进度与来源引用。崩溃后的图续跑、存储依赖对账及缺失块/向量补建继续保留；它们不会把完整正文灌回研究状态。正常引用阶段的原文一致性回读已经移除，入库准入和索引重建使用原文的机制继续存在。

## 失败样例与修复口径

### 第一轮：旧来源对象不再是状态中的引用对象

`PersistentSourceTests.test_existing_source_adds_section_metadata_without_reembedding` 仍修改入库前的 `src` 字典，并期待修改反映到被引用替换后的状态。新契约不保留这种对象共享关系。测试改为找到状态中的实际来源引用，增加章节，再验证数据库与块元数据更新、embedding 次数不增加。

### 第二轮：独立抽取入口及继承夹具

三个涉及引用核验的用例只模拟了 NLI 或 `verify_citations()`，没有为当前新增的最终报告独立论断抽取提供测试响应，因而未进入预期的核验调用。修复为显式注入抽取结果，再验证 RAG 证据块进入核验器；没有回退新的抽取入口。

另一个新增继承用例缺少父成果必需的 `report_hash`，触发 `KeyError`。补全父成果测试夹具后，继续检查继承状态没有全文且内容哈希未变化。

### 第三轮：误把表格证据等同于第一名

两项测试假定论断原绑定的表格一定是传给核验器的第一条。当前独立抽取入口会在被引文档内重新检索，测试向量和精排的并列排序不保证这个位置。改为按表格块编号找到对应证据，验证其 quote 与已保存块文本一致、保留表头和注释，同时继续禁止读取全文。

## 已测量、间接推断与尚未评估

**已测量**：第四轮 135/135 用例通过，无失败、错误或跳过；新增 7 项直读用例全部通过；18 个 Python 文件语法检查通过；PostgreSQL 元数据投影 SQL 编译通过；所选业务文件 `git diff --check` 通过。重启场景使用新的服务对象模拟，未对真实服务进程执行断电或 kill。

**间接推断**：减少运行状态中的全文副本和未变化引用的全文读取，应减少重复复制、序列化及读取开销；本次没有测量生产内存、数据库吞吐、真实模型 token、检索延迟或成本，不能将机制测试耗时当作产品性能提升。

**尚未评估**：真实 PostgreSQL/Milvus 集成、真实崩溃恢复、跨版本已保存章节的兼容性、真实召回与反证质量、语义核验准确率、数据库块文本损坏后的在线影响、生产并发和负载。

本次范围是启用会话 RAG 的业务路径。未绑定 RAG 的非持久化/离线兼容入口仍使用本地来源正文，它们不具备本次会话证据库的存储契约。来源元数据变化、存储依赖对账和索引补建仍可能读取数据库中的完整原文，但不会恢复到研究状态或逐引用按偏移比对。

## 结论与下一步建议

会话 RAG 路径已经实现“原文入库 → 状态保存来源引用 → 按当前问题检索历史证据块 → 写作与引用核验直接消费块文本”。全文恢复方法及原文偏移一致性比对已移除。数据库正文、证据块、向量及检查点引用继续支持持久化和续跑。

下一步若要发布部署，应在隔离 PostgreSQL/Milvus 实例运行相同场景，并补充真实进程崩溃与旧检查点恢复验证；效果评测应另外测量召回、事实准确率和性能，不能用本次机制回归替代。
