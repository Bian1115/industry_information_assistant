# 取消写作前事实提炼：实现与回归评估

## 1. 评估信息与结论

- 评估日期：2026-10-16，Asia/Singapore。
- 评估对象：当前工作区 DeepResearch 主链路中 Scout 正常检索、补搜、明确指定的深搜，以及写作前数据分析、Writer 初写/修订、原文入库和写后引用回读。
- 本次需求：取消写作前的模型事实提炼，让 Scout 收集的原文直接进入临时知识库，Writer 根据原文证据写作。
- 实施结果：主执行路径不再调用 Scout 的事实、数据点、实体、洞察和假设关系提炼；写作前数据节点也不再调用模型重新提炼数据或实体。新研究可在 `facts=[]` 时完成原文入库、章节写作和写后引用回读。
- 最终离线回归：248项登记，207项通过，41项外部存储集成测试跳过，0失败、0错误。新增13项定向回归全部通过。

本次改变的是材料处理链路；未评估真实报告质量是否提高。正常合成正文案例的 Scout 模型调用数为0；不确定网页仍可能触发原有正文质量判定，该判定不提炼研究事实。

## 3. 实现变化

### 3.1 Scout 直接保存和入库原文

文件：`backend/app/service/deep_research_v2/agents/scout.py`。

- 正常章节检索完成正文读取、准入与编号后，调用 `_store_collected_sources()`，不再调用 `_analyze_search_results()` 和 `_ingest_search_analysis()`。
- 补搜不再调用 `_analyze_supplementary_results()`；直接在来源上登记目标章节、`is_supplementary`、`critic_issue_id` 等信息，再入库。
- 补搜任务包含多个章节时，原文记录保留全部章节关系。
- 明确指定的深搜查询也只做搜索、正文读取和入库，不调用深搜事实分析。
- 已绑定会话 RAG 时，收集到的正文立即走现有 `rag.ingest()`，复用原有 chunk、Embedding 和向量存储；未绑定时保留可追溯原文状态供本地视图使用。
- 搜索结果展示和检索完成计数改用原文来源；不再用提炼出的事实作为搜索结果。
- 主路径不再执行 `scout_facts` 阶段核验；Writer 写后 `report_claims` 的引用回读和可选核验仍保留。
- 由事实分析输出的 `source_tracing_queries` / `follow_up_queries` 所驱动的自动追搜随之退出主路径；显式深搜与 Critic 定向补搜保留。

历史提炼辅助方法暂保留以兼容已有独立调用和旧测试，但应用主路径没有调用这些方法。本次没有清除历史检查点里的事实或旧审计结果。

### 3.2 数据分析节点不再重建事实摘要层

文件：`backend/app/service/deep_research_v2/agents/data_analyst.py`、`graph.py`。

- 主流程不再调用 `_extract_data()` 和 `_build_knowledge_graph()` 进行模型提炼。
- 保留已有结构化数据，以及显式启用图表时对已有数据的处理。
- 原有主图仍在数据节点之后执行 `run_deterministic_analysis()`，保留程序计算与一致性检查。
- 图拓扑及阶段恢复入口未改变。

### 3.3 Writer 可以没有事实列表，但必须有原文

文件：`backend/app/service/deep_research_v2/agents/writer.py`。

- 报告入口从检查 `facts` 非空改为检查可用原文存在。
- 章节初写移除单独的“相关事实”“已有洞察”提示词栏目，直接阅读检索返回的原文证据。
- 引用 URL 必须来自提供的原文证据。
- 真正调用章节写作模型之前检查证据视图；没有可用原文单元时抛出 `InsufficientEvidenceError`，不会只靠问题生成章节。
- 修订的新增材料目录使用关联本章的原文来源标题和 URL，不再把事实摘要拼成补充材料。
- 历史事实编号只用于兼容旧检查点原句绑定，不是新研究的前置依赖。

### 3.4 无持久化调用也能直接使用原文

文件：`backend/app/service/session_evidence_rag.py`、`deep_research_v2/writer_claims.py`。

- 正常绑定 RAG 时继续使用已有上下文检索，输出 `evidence_units`。
- 未绑定 RAG 且没有旧事实列表时，新增 `format_source_evidence()`：复用正文 chunk 切分，用本地词法相关性选择完整单元，并按证据 token 预算组装已注册的原句。
- 表格按既有结构化单元选择，再组装完整来源原句，不逐字符截断单元。
- 本地回退不调用向量或精排服务，并标记 `retrieval_mode=local_source_view`。
- 未注册正文/原句编号不会被临时伪造为可引用的正文编号。
- 已存在事实的无 RAG 历史检查点仍保留旧的证据格式兼容路径；它不再生成新事实。

### 3.5 补齐逐章入库需要的章节关联更新

文件：`backend/app/service/session_evidence_store.py`。

逐章立即入库后，同一页面可能先关联A章，随后又用于B章。旧逻辑遇到已存在文档直接跳过，会让B章关联只存在于内存。本次补齐：

- 合并已有文档的新增 `related_sections`。
- 同步该文档所有 chunk locator 的章节关联。
- 更新补搜/深搜来源信息，并递增证据 revision。
- 不修改原文内容和正文编号；只更新章节关系时不重复调用 Embedding。

`quality_pipeline.evidence_fingerprint()` 同时纳入原文内容与章节关联，避免新研究没有事实列表时，补搜原文变化仍产生相同证据指纹。

## 6. 失败样例、原因与修复

1. **初始状态字段断言错误**：新增测试原先要求不存在 `scout_citation_verification`，但初始状态本就包含该字段。改为检查 Scout 不改变它，不执行事实阶段核验。
2. **旧提示词断言**：既有测试要求提示词出现 `[f_good] 已准入的事实`。新提示词已移除事实列表，改为检查已准入原句及兼容绑定仍在，拒绝来源仍被排除。
3. **埋点夹具触发了正文质量复核**：两个URL使用完全相同正文，按既有规则会进入“跨URL重复正文”的质量判定；夹具返回的是旧事实提炼JSON，导致第二份正文未准入。将夹具改为两份独立正文，以隔离“取消事实提炼”的验证目标；正文质量判定规则未放宽。
4. **旧模型 span 假设**：复测时埋点测试仍查找名为 `DeepScout` 的模型生成 span。取消提炼后正常正文没有这次模型调用，改为验证该 span 不存在，搜索HTTP和父trace关系继续检查。

终测没有未修复的失败或错误。41项跳过中39项需要显式启用隔离PostgreSQL环境，2项需要独立Milvus集合；不能将跳过计为通过。

## 7. 测量边界与下一步

### 已测量

- 主执行路径没有调用 Scout 事实分析和事实入库函数。
- 不再将模型提炼迁移到写作前数据节点执行。
- 新研究无事实列表时仍能读取、持久化chunk、写作、回读写后引用。
- 无正文或检索为空时停止写作。
- 新章节关联同步到文档和chunk，且不重新Embedding。
- 相关离线回归及旧检查点兼容测试通过。

### 间接推断

- 正常研究不再支付被移除的预提炼模型请求，但没有实测节省的 token、费用或耗时。
- Writer直接读取原文可减少中间事实摘要造成的信息损失，但报告质量收益尚未测量。

### 尚未评估

- 正文读取长度、章节预过滤、2页×128和最终Top10的目标；这些是独立改造项，本次保持现有读取与检索参数。
- 运行中后端进程实际加载的代码；本次修改源码，未重启服务或发起真实研究。

后续可在独立测试会话运行一题真实研究，对比实际调用链、费用和报告引用；应特别检查一章多个对象/指标的检索覆盖。该后续评估尚未执行。
