# 通用研究轨迹网页加载成功数量与MinerU正文对照口径分析

评估日期：2026-10-17，Asia/Singapore。对象：此前通用研究五题35、31、46、16、49的冻结轨迹。状态：离线数量与数据留存核对完成；尚未执行MinerU-HTML效果评测。

**原始读取工具标记加载成功的有211个去重URL，计入13次缓存重复则为224次成功返回。** 同批共有289个去重URL、302条实际返回。加载成功不能直接作为正文可用；按2026-10-11收紧后的口径，可用正文或实质摘要为137/289＝47.40%。

## 数据与配置口径

- 使用2026-10-08冻结的五个完成运行；正文可用性继承2026-10-11复核标签，未重新进行语义裁判。第31题仍为旧预算，其余四题取消总token上限，不能用于同预算消融或估计全部开发集成功率。
- “原始加载成功”指`tool_raw_result.payload.value[].fetch_status == success`，同时验证这些条目都有非空`content`。这是历史工具状态，不等于已取得原始HTML，也不证明HTTP状态一定为200。
- 每题按规范化原始请求URL去重，取最后一次返回；本批跨题没有重复原始URL，因此去重后亦为289个全局唯一请求URL。没有按最终跳转URL合并，不能将289理解为289篇内容互不重复的文章。
- 逐条按`history_path + call_id + raw_result_index`回到原始返回，核对URL、状态及完整正文SHA-256；302条均通过。最终检查点中的读取状态另列，不与工具原始状态混用。
- “可用”包含实质目标正文、论文摘要或实质预览；仅目录、封面、下载链接、图链不计可用。标签为历史AI辅助判断，非人工金标；历史50个超长页面存在抽样限制。
- 本次没有重新抓取目标网页、安装或执行MinerU-HTML，没有新增裁判调用，没有修改业务代码。

| 口径 | 按返回次数 | 按原始URL去重 |

| 原始工具标记success | 224（74.17%） | 211（73.01%） |

| 目标正文或实质摘要可用 | 145（48.01%） | 137（47.40%） |
| 原始success但正文不可用 | 79 | 74 |

去重后原始状态为success 211、failed 73、rejected 5。20个非success条目也有文本，所以231个非空条目不能称为231个加载成功网页。

旧报告还出现189个“程序接纳/成功”：这是最终检查点口径，189个success、95个failed、5个rejected。相对于原始工具返回，有22个URL在检查点中因`body_quality_rejected`从success记为failed。**211与189的差异来自记录阶段及质量门禁，不能任选一个作为同一含义的成功数。**

## 失败样例与HTML输入留存

- `35-page-028`：历史工具标记success，但内容为404提示。加载成功不能作为语义成功标签。
- `35-page-010`：仅取得目标PDF附件链接；HTML主体提取后仍需读取附件正文。
- `35-page-031`：只有报告目录与页码，未取得章节论述。
- `49-page-007`：仅图片URL，未保存图片中的人口数值。
- `16-page-013`、`31-page-003`：原始成功条目使用`pypdf2`，属于PDF，不能直接当作HTML输入。

211个success条目中，历史MIME明确为`text/html`的有104个，未记录MIME的有104个（均来自浏览器sidecar），另有2个PDF和1个标记`application/msword`的条目。这只是历史元数据，尚未证明其中哪些当前可取得有效HTML；不能宣称211个均可直接送入MinerU-HTML。

本次核对的冻结材料及五个原始工具轨迹保留的是抽取后的`content`、元数据与质量记录，没有归档原始HTML/渲染DOM字段或快照路径。读取服务的`WebReadResult`与JSON缓存结构也只保存抽取结果。**这些冻结材料中可直接复用的原始HTML为0份**；这一结论不等于已扫描所有外部浏览器缓存或其他磁盘。

## MinerU-HTML对照建议

[官方README](https://github.com/opendatalab/MinerU-HTML)展示的接口以HTML字符串为输入、输出`main_html`；`use_fall_back`默认启用，错误时回退Trafilatura。因此应重新获取并冻结HTML或渲染DOM，再让现有抽取器和MinerU-HTML处理同一份输入；旧Markdown/纯文本不能重建被丢弃的DOM和正文。

建议保留289个原始URL作为固定来源集合，并用211个历史success URL作为首轮候选参考。重新抓取后先按HTML、PDF、Office及访问错误分流，真正取得有效HTML的数量作为当次抽取对照的分母。历史success且正文不可用的74个URL可单列观察修复，但不能只测这74个就推算总体提升；原本可用页面也要保留，以测量误伤。

同时报告：

1. **同HTML抽取可用率**：两方案可用正文数／同一批有效HTML快照数；分母由新采集确定。记录新增成功、成功转失败及表格关键数值保留情况。137/211＝64.93%只是历史success集合的正文基线，不能直接与重新抓取后的结果当作严格配对增益。
2. **全量URL可用率**：新方案可用正文或实质摘要数／固定289个URL；访问失败保留分母，PDF/Office单列处理，并明确这是HTML替换后的组合链路指标。
3. **模型与回退分列**：记录MinerU本体和包含默认Trafilatura回退的结果、回退命中、耗时与资源。官方ROUGE-F1不能换算成本项目正文可用率。

以上是待执行方案；本次没有新方案可用率、提升百分点、延迟或成本结果。

## 局限性、结论和下一步

**已测量**：302条返回与289个去重URL的状态、非空文本、历史可用标签计数，302条原始内容哈希匹配，22个状态重分类，以及上述冻结材料的HTML缺失。

**间接推断**：正文语义可用性继承历史AI标签；MinerU可能改善已经取得HTML但主体选择失败的条目，需要同输入对照证实。验证码、登录、错页、附件与二进制等失败不能假定由HTML抽取模型自动修复。

**尚未评估**：MinerU-HTML在本项目的任何实际效果，当前网页能否获取、模型运行环境、人工金标正文F1、全文完整性、表格保真、成本与延迟。五题选择样本不代表全部通用研究数据集。

结论：可将“历史211个加载成功URL、其中137个正文可用”作为准备试验的依据。下一步先重新采集并冻结原始输入，区分类型与访问失败，再进行相同HTML上的配对抽取及盲评；保留全部289个URL用于单独报告整体正文可用率。
