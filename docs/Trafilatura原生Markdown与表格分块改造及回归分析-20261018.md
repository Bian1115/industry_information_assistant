# Trafilatura原生Markdown与表格分块改造及回归分析

日期：2026-10-18，Asia/Singapore。对象：网页正文原生 Markdown 输出、下游表格证据分块及引用定位。性质：代码改造和离线机制回归，没有执行线上成功率、公开基准 F1 或速度评估。

## 实现结论

正文链路改为：**原始 HTML／浏览器 DOM → Trafilatura 原生 Markdown → 质量准入 → 原生 Markdown 证据分块**。不再经过 XML、BeautifulSoup 和自定义 HTML 表格重建。

- [读取服务](../backend/app/service/web_reader_service.py)使用 `output_format="markdown"`；标题、日期也由 Trafilatura 的 `extract_metadata` 提供。移除了 BeautifulSoup 类的导入及正文解析调用。`UnicodeDammit` 仍仅用于字节编码识别，不承担正文或表格转换。
- [输出预算模块](../backend/app/service/web_document_structure.py)删除 `markdown_table`、`render_html_body`、`render_trafilatura_body` 等旧转换代码，只保留原生 Markdown 的完整表格截断边界处理。
- [结构证据单元](../backend/app/service/summary_evidence_units.py)直接识别原生 Markdown；[会话分块](../backend/app/service/session_evidence_chunks.py)保留原文位置、表头状态、列数及块间关联。
- 原始响应字节和浏览器 DOM 的留存继续生效，未恢复原 HTML 到 Markdown 的转换路径。读取缓存和分块策略使用新版本号，避免复用旧转换结果；没有新增旧机制兼容或历史数据迁移路径。
- 用户的兼容性偏好已追加到 [AGENTS.md](../AGENTS.md)：未明确要求时默认不增加旧接口、旧格式或旧处理路径的兼容；认为需要时先说明并确认。

本报告描述的新实现替代 2026-10-17 报告中的 XML＋BeautifulSoup 转换方案；历史报告与原始结果未覆盖。

## 表格分块的新规则

| 原生输入情况 | 处理与关联保证 |
| --- | --- |
| 普通有表头表格 | 沿完整数据行分块，每片重复全部显式表头、分隔行及相邻注释；不截断单元格 |
| 表题也被输出成表头行，含多组分隔行 | 将连续的表头组识别为同一张表；表题与实际列名一起保留，避免丢掉后续数据行 |
| 无表头数据表 | 首行仍为数据；标记 `header_status=absent`，不生成“列1／列2”或自行指定列含义 |
| 多级表头或空白单元格等可疑结构 | 保留整表，避免拆走上级表头或跨行上下文；超出预算明确拒绝生成证据块，不向空白处补填值 |
| 表头边界不确定 | 标记 `header_status=ambiguous`，`row_range` 留空；`body_row_range` 仅表示 Markdown 正文行范围，不冒充已确认的数据行数 |
| 两张无表头表格 | 用各自原文起点生成表格 ID，不因共同空表头而混合行号或关联关系 |
| 代码围栏里的表格示例 | 不识别成实际数据表格，也不触发表格输出预算延长 |

“可疑结构”采用保守规则，包括表头缺格、正文行空格，以及第一正文行全为非数字文字等信号。纯文字数据和真实缺失值也可能因此整表保留。这是避免错误关联的保护，不是对所有网页表头语义的可靠识别。

## 失败样例及中间修复

- 原生表题样例包含“表题＋分隔行＋实际列名＋分隔行”。旧分块器按一个表头处理，会误分表或漏掉后续行；新分块器合并连续表头组，2 行数值均保留。
- 原生合并单元格输出的第二条数据仍是 `|  | 90 | 70 |`。本次不恢复成 `| 2025 | 90 | 70 |`，而是将它与原表头、上一行共同保留。小预算下整表不适配时按预期拒绝；这不是测试失败。
- 首轮 158 项中 156 项通过、2 项错误：图测试导入路径缺失；引用集成用例未隔离当前选句环节。修复运行器路径，并为该用例注入选句实现。
- 第二轮 159 项中 158 项通过、1 项错误：假召回排序未保证返回该用例要核对的表格。为“表格编号贯穿核验入口”用例明确注入表格召回，仍使用实际存储引用组装；业务检索和核验逻辑未修改。最终 159 项通过。
- 最终日志中的 Redis 连接报错来自离线网络阻断，相关图测试走既有容错路径；不能据此声称已验证真实 Redis。

## 局限性、结论与下一步

**已测量**：159 项离线机制/集成回归、4 类构造样例的原生输出一致性和原始字节校验、表头重复与首行保留、原文偏移、二次装包、复杂表格保护性拒绝，以及代码静态检查。

**间接推断**：删除自定义转换层消除了一次正文重写，但没有测量速度或资源收益。保留表头上下文有助于引用正确性，不等于已验证事实支持性。

**尚未评估**：公开数据集 F1、真实网页成功率、全部多级表头版式、超大复杂表格的覆盖损失、生产 token 预算、真实浏览器与存储服务联调。Markdown 本身不能完整表达原始 HTML 的所有合并关系；本次既不从原 HTML 恢复旧格式，也不声称完全恢复其语义。已有研究的不可变正文与历史结果未迁移。

代码目标已完成：原生输出直接进入证据链路，表格分块依据原生结构保留关联，不再为旧格式断言保留转换机制。后续应在公开数据集与业务网页上分别测量正文质量和复杂表格拒绝比例；需要任何旧机制兼容时，按 AGENTS.md 约定先确认。
