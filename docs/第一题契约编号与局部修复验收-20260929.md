## 数据与配置口径

使用 `backend/eval/data/开发集5题新版摘要轨迹-20260928-223120/实际运行/任务-8/第1轮工作历史.json`、`第1轮首次摘要前回放快照.json`，以及同次运行 `实际运行/配置快照.json`。快照有 14 条原始历史记录；5 次失败输出来自同一输入，不能视作 5 道独立样本。

重新执行当前规划入口，使用原运行最后一次规划输出作为规划模型返回值，得到任务契约；不重新规划、不在线搜索、不引入人工事实标签或后续轮次要求。真实回放保留原完整方案的 NLI 阈值（蕴含 0.85、矛盾 0.5）、180 秒摘要时限、3000 token 输出和 28744 token 硬输入上限。摘要模型使用当前项目配置的独立模型 `qwen3-max`；原失败运行使用的是 `qwen-plus`，因此本次是修复验收，不能归因成某个单独改动的消融收益。

验收只执行摘要、引用及核验并准备 Scout 下一步输入，不调用主任务、不重跑整题。历史与摘要写入独立 ReplayStore 文件，未向生产会话提交摘要。运行仍使用项目已有模型调用埋点。

## 改动

1. `architect.py` 在最终大纲生成后调用现有 `build_research_contract()`，保存到 `state.research_contract`，补入本轮原话和有效约束。现有 graph 的 HistoryScope 传递使 Scout 及摘要各分块/合并收到契约。
2. `summary_citations.py` 统一使用已有历史正文的 `source_id`，不另建别名。每个请求列出 `allowed_source_ids`；仅包含当前块及已校验旧摘要的编号。正文嵌套的搜索结果编号不能替代外层正文编号。引用补齐、程序定位及回读继续用同一 ID。
3. 分块、逐步合并、层级合并、语义修复后的正文解析，以及引用 JSON 解析，失败时在原位置修复一次。修复携带原证据、任务背景、失败输出和全部解析问题；在修复请求末尾重复正文编号清单，明确 `req_1` 等契约条目不是证据。摘要局部修复启用 JSON 输出，让模型返回带 `kind/section/claim/source_ids` 的完整分句清单，由程序渲染栏目和任务前缀；事实必须保留来源，任务性条目不得携带契约编号，空栏目占位符不当成事实。再次失败即抛出，不递归修复，不提交部分摘要或推进游标。修复调用计入既有调用、时限及 token 预算。
4. 真实回放发现常见的“事实 [编号]。”格式，现兼容编号前后两种句号位置及 `[ID1, ID2]` 多来源写法，只归一化标点和分隔符，仍逐项严格检查编号；不猜测或替换未知 ID。
5. 给摘要生成批次预留 `min(输出预算 + 1024, 硬输入预算 // 4)` token 的修复空间。本配置为 4024，正常生成组批上限 24720，修复仍受 28744 硬上限约束。按较小预算完整拆分原文，不截断证据。极端修复超限仍拒绝。
6. 兼容工具 JSON 正文中的换行/引号转义：只有候选本身是完整合法 JSON、解码引句在其字符串值中、重新编码后又精确命中该来源片段，才接受表示转换。最终偏移和保存的 quote 仍对应原始正文字符。普通文本、断开的片段、错误数字、未知来源继续拒绝。
7. 提示版本更新为 `context-summary-source-protocol-repair-v6`，组批版本为 `token-packed-single-regroup-repair-reserve-v2`；已提交摘要的元数据读取当前版本常量，避免沿用旧标签。

## 逐类分析与局限

- 已测量：原规划输出经当前规划入口可生成非空契约；机制测试验证当前原话、有效约束和最终章节编号，并验证各分块/合并收到相同契约。
- 已测量：未知编号被拒绝，包括“全局存在但不属于本批次”的编号；合法编号后的句号可解析；分块仍使用原正文 ID。
- 已测量：成功时不调用修复，失败时恰好修一次；调用预算耗尽/输入超限不会再发模型请求；引用 JSON 第二次解析失败保留原摘要和游标。
- 已测量：旧的 5 个失败输出均可复现。它们只代表同一失败输入的多次尝试。
- 间接推断：显式契约能降低把检索批次误当成完整用户意图的风险；需要更多任务的真实回放才能估计稳定收益。
- 尚未评估：事实/任务分句分类的语义准确率。`kind` 由模型声明，程序渲染前缀不代表所有事实都正确进入了 NLI；当前配置也没有启用关键事实遗漏检查。
- 尚未评估：全开发集完成率、完整报告质量、关键事实保留率、生产 SSE/前端追问、多轮长任务效果。本次没有放宽 NLI 阈值或把格式通过等同语义正确。

## 结论与下一步

规划契约已接入；正文、分块、合并、引用及回读沿用同一组原始编号；发生解析错误时只做一次局部修复，预算和原子提交保护均通过机制测试。真实材料已验证分块和合并能够越过原失败点。

当前剩余阻塞是引用阶段改写原文和遗漏关联来源。下一步应让引用补齐选择程序给出的原文连续片段或字符区间，由程序返回精确 quote，并逐个来源检查是否确有支持；然后复验 NLI、最终输出总预算和摘要提交。保持当前失败样本、原始来源和阈值，新增结果目录记录后续复评。完成这些步骤前，不宣称整题、多轮研究或消融实验已通过。
