## 评估对象与配置口径

评估当前通用DeepResearch的Critic审核及其触发的补搜、修订与复审带来的整体收益。使用既有通用中文研究集原题35、31、46、16、49，主题分别是污水治理、博物馆教育、房地产可持续发展、非接触式感知、正畸与医美共同需求。每题先完成公共首稿及引用审计，在首次Critic前冻结；关闭组从该状态正常交付，开启组继续真实生产审核与最多两轮返工。其余模型、检索、写作、上下文与引用核验配置相同，共计划十篇报告。

新独立引用核验包含报告论断提取、证据选句与NLI，实验两组共同使用Writer阶段2400秒、研究累计7200秒的时限；仅在隔离评测进程生效，不修改部署配置。每题同首稿配对有助于控制生成与搜索波动，但开启组有额外token预算，因此测量审核返工模块收益，不是等token预算收益。

运行使用独立PostgreSQL数据库、禁用登录的评测身份与独立会话；源码、提示词及固定题目已冻结。分叉适配器为新运行重新生成跨存储依赖清单并经真实租约保护的检查点写入；关闭分支的公共预算作为共享前缀基线保存，不伪装成新请求。

## 引用核验指标口径

| 输出 | 含义及边界 |
|---|---|
| status / execution_status / extracted_claims_checked | 区分支持性判定、是否执行完整；错误/不完整不当作通过 |
| units_total、单元状态分布 | 标题、段落、列表和表格行是否逐项处理；不是语义抽取召回率 |
| claims_count | 独立从最终报告抽取到的论断数N，不等同全文所有事实数 |
| supported_count、supported_rate | 支持数及其除以N；仅完整执行时计算比例，不称现实事实准确率 |
| missing_citation_count / rate | 缺行内引用数及其除以N |
| prediction_as_fact_count / rate | 被模型判为来源预测/计划在报告中被写成事实的数量及比例 |
| claim_status_counts | supported、missing_citation、invalid_citation、prediction_as_fact、unsupported_citation、contradiction、unknown等逐类数量 |
| review_count、逐条claims/evidence | 待复核数、报告定位、证据定位、错误原因及模型分数；分数尚未校准 |
| all_claims_checked=false | 保留独立提取可能遗漏的边界，不宣传完整事实核验 |

引用结果、独立抽取结果及简表会分别输出到每篇报告目录。零论断、执行失败或执行不完整的比率保持空值，避免把未知当0%。

在评测进程HTTP模型请求层记录供应商返回的输入、输出、总token，包含生成Agent、报告论断提取、证据选句、支持性NLI、历史摘要及检索Embedding/Rerank等请求；失败与SDK重试也保留。未返回usage的调用明确计为缺失，不填0。Embedding/Rerank若只返回总token，保留输入/输出分项缺失状态。

同时列出每组逻辑完整链路用量及实验实际请求用量。公共首稿及其引用核验实际只运行一次，不能将两个逻辑组的用量相加当账单。主代理在Codex对话中的自身推理token工具未提供，不能包含在API账目中；搜索/网页服务收费和货币费用另未测量。

## 评分口径

由当前Codex主代理全文审读，按深度、全面性、可读性、需求满足四维各0至10分，等权平均；另列整体逻辑、观点平衡两个辅助维度。逐题对照事先冻结的用户要求，并回查保存来源中的关键数值、预测限定与结论依据。不会以Agent内部Critic分数代替最终质量。

运行程序生成随机甲/乙标签及对应来源材料。先保存独立评分，再揭示组别进行配对分析；单一AI评审仍可能从修改内容猜到组别，不称完全盲审、人类金标或统计显著收益。
