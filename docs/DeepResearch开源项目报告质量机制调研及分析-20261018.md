## 结论与选择依据

如果主要目标是提高长报告质量，优先阅读 STORM、GPT Researcher 的多智能体工作流、LangChain Open Deep Research。它们分别提供“如何问全问题”“如何按反馈修改”“如何组织研究材料并交给写作者”的参考。

Jina 适合研究缺口驱动的搜索循环；Tongyi 适合研究专用模型训练及长程工具使用。它们对研究能力的贡献不能直接换算成长报告质量增益。没有发现可据本轮资料声称其中某项目在相同模型、检索配置和预算下全面最好。

## 逐项目分析

### 1. Stanford STORM：把资料搜集和问题设计放在正式写作之前

[STORM 官方仓库](https://github.com/stanford-oval/storm)将流程分为资料研究与写作两个阶段。研究时参考相近主题识别不同视角，再通过有来源支撑的模拟问答继续追问；之后组织大纲、填充章节并润色。

它最值得借鉴的是让问题和大纲吸收检索所得的新知识。对“某技术是否具备商业化条件”这类问题，可以分别研究技术指标、生产约束、成本、需求和反例，再决定报告结构。这个例子是本文的设计建议，未经实验。

适用：综述、背景调查、专题长文。边界：百科式广覆盖未必满足决策报告需要；论文还指出来源偏见迁移和不相关事实被过度关联的风险。官方也说明输出通常仍需编辑。

### 2. LangChain Open Deep Research：组织研究任务，保留发现与来源，再统一成文

[研究图源码](https://raw.githubusercontent.com/langchain-ai/open_deep_research/main/src/open_deep_research/deep_researcher.py)展示需求澄清、研究简报、supervisor／researcher 研究、材料整理及最终写作。研究者可以围绕明确子问题工作，最后由写作模型汇总。

[材料整理提示](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/src/open_deep_research/prompts.py#L186)强调保留相关事实和来源对应关系。这可作为减少材料交接丢失的设计参考，但提示要求不能保证模型实际无损保留。

适用：研究调度、上下文管理、统一写作入口。应保留关键数字、日期、限定条件和来源位置，另行检查最终引用。以上是适配建议，本轮未验证收益。

[官方仓库](https://github.com/langchain-ai/open_deep_research)显示已于 2026-08-21 归档，只读。适合作为架构教材；新项目采用其代码时，应自行承担维护工作。不能把旧版章节反思流程直接当成当前主图的默认路径。

### 3. GPT Researcher：按章节审稿，依据具体反馈修改

[官方多智能体文档](https://docs.gptr.dev/docs/gpt-researcher/multi_agents/langgraph)展示先做初步研究，再规划大纲；各章节研究并形成草稿，由 Reviewer 检查、Revisor 修改，再由 Writer 汇总的流程。

值得借鉴的是把审核落实到某个章节及其反馈。落地时可让反馈指出缺失要求、问题位置、需要的证据和可验收的修改结果。这个反馈契约是本文建议，不能说成该项目已完整实现本地的逐问题验收机制。

适用：有明确输出要求、需要多轮修订的报告。边界：这是其特定多智能体方案，不能概括为所有运行入口均有同样的审改流程。Reviewer 的认可也不构成逐句引用支持性的独立证据。

关于可选来源筛选，复用调研快照显示默认 CURATE_SOURCES=False，详见[已保存的前次分析](高质量DeepResearch项目信源评级机制调研及分析-20261018.md)。本轮未重新运行该开关，不将其称为默认事实核验器。

### 4. Jina node-DeepResearch：围绕未解决的问题持续搜索与阅读

[Jina 官方仓库](https://github.com/jina-ai/node-DeepResearch)展示缺口队列、搜索、阅读、回答检查和继续研究的循环。它明确说明目标是通过深度搜索找到简洁答案，不以长文章为优化目标。

可借鉴的是让下一次检索针对尚未解决的问题，并保存失败尝试，避免循环重复。预算耗尽后仍可能进入最终回答路径，因此不能把“循环停止”解释为“所有问题均解决”。

适用：作为长报告上游的研究模块参考。最终章节组织、跨章节一致性和长文质量需要另外设计与测量。

### 5. Tongyi DeepResearch：通过模型训练改善长程信息搜寻

[Tongyi 官方仓库](https://github.com/Alibaba-NLP/DeepResearch)说明其使用合成 Agent 数据、训练与端到端强化学习，并支持 ReAct 和基于 IterResearch 的 Heavy 推理模式。

它适合研究模型何时搜索、访问页面以及利用工具结果继续推理。不能据此宣称已解决长报告叙事、逐句引用核验或本地审稿问题；这些能力需分别评估。若暂不训练专用模型，应先参考其工具交互和研究行为，再判断是否值得投入训练资源。

### 补充：DeerFlow 的版本定位

[DeerFlow 官方仓库](https://github.com/bytedance/deer-flow)当前说明 2.0 已重写为通用长程 Agent harness，原 Deep Research 框架保留在 1.x 分支。若学习旧版 planner／researcher／reporter 流程，需要标清分支；本轮没有审计该旧分支，也没有把通用运行时能力算作报告质量实测证据。

## 把“质量提高”拆成可验证的问题

| 质量问题 | 可借鉴的机制 | 应观察的结果 |
| --- | --- | --- |
| 问题漏答、视角单一 | STORM 的多视角提问；研究后调整大纲 | 用户要求覆盖率、关键问题遗漏 |
| 资料交接丢失 | LangChain 的研究任务与来源保留 | 关键数字、日期、条件及 URL 在写作输入中的保留情况 |
| 多次搜索仍无进展 | Jina 的缺口驱动研究 | 新增有效证据、重复搜索、未解决问题 |
| 章节内容浅、反馈空泛 | GPT Researcher 的章节审改流程 | 有效问题发现、问题修复与引入新错 |
| 引用看起来完整但不支持正文 | 独立核验最终报告与原文的对应关系 | 引用支持率、未核验比例、缺失引用的事实论断 |
| 文字流畅但没有分析 | 显式比较、推理与边界说明 | 是否回答比较维度，结论是否可从证据推出 |

表中的最后两项是本文综合建议，不是宣称以上每个项目都已内置。引用支持性仅说明指定材料是否支撑指定论断；报告事实准确性还涉及材料本身的可靠性及未引用论断。

## 失败样例与风险

以下除注明论文发现者外，均为机制推断或合成示例，没有伪装成项目实测失败：

1. **目录完整，关键问题未回答。**“商业化分析”有五个章节，但没有回答量产是否已经实现。应检查具体问题和证据，不能只数标题。
2. **多来源其实是同一上游。**五家转载同一新闻稿，不能视为五份独立验证。来源去重应考虑内容上游。
3. **整理材料后丢失限定条件。**原文只针对某地区／某年份，报告写成普遍结论。应回查原始段落，不能只审摘要。
4. **审稿意见无法验收。**“增加深度”缺少问题位置和证据要求，可能导致只扩写。应将其改成可检查的修改任务。
5. **引用存在，但推理过度。**来源记录某项相关性，报告却写成因果结论。需要针对最终句子核验。
6. **来源偏见与错误关联。**STORM 论文明确提到这两类挑战；本轮仅核验摘要，没有重新标注其全部失败样本。
7. **预算用尽仍输出答案。**Jina README 展示预算退出路径。实际质量、失败频率及耗尽时的报告行为未在本轮测试。

## 对本地项目的建议

本轮只定向读取 [Critic](../backend/app/service/deep_research_v2/agents/critic.py)、[Writer](../backend/app/service/deep_research_v2/agents/writer.py)及[质量管道](../backend/app/service/deep_research_v2/quality_pipeline.py)部分内容。源码显示已有整体审核、章节写作与问题工作流等相关入口；[昨日实现报告](最终报告独立引用核验与Critic职责分离实现及验证-20261017.md)还记录了独立最终报告引用核验。这里不重复评估历史实验，也不宣称已完整审计今日运行链路。

建议依次做以下核查，发现缺口后再实施：

1. 先检查研究是否围绕用户关键问题展开，补搜是否真正填补缺口；以 STORM、Jina 为参考。
2. 检查写作时关键证据及其限定条件是否仍可回查，以 LangChain 的材料交接设计为参考。
3. 检查 Critic 意见是否具体、能否验收，以及返工后是否修复问题；以 GPT Researcher 的章节审改为参考。
4. 最终报告分别评价要求覆盖、分析深度、引用支持性和事实准确性，避免用单个总分代替所有能力。

这些建议不是本轮查出的确定缺陷，也没有新增硬门禁、历史兼容层或其他处理路径。

## 局限性、结论与下一步

公开提示、文档和流程图能解释设计意图，不能替代运行证据。本轮没有固定全部新读网页的提交版本；分支页面可能随时间变化。复用源码快照的 SHA 和文件映射保留在前次运行目录，不能将其与本轮在线页面混写成同一次固定版本审计。未穷尽项目生态，也未评估部署、安全、许可证依赖和长期维护成本。

优先学习 STORM 的研究前准备与多视角提问、GPT Researcher 的章节审改、LangChain 的材料交接。后续若要验证本地收益，可在固定任务、模型、搜索和阅读后端及资源限制下，每次只切换一个机制，配对比较覆盖、分析、引用、成本与耗时；由人工复核部分问题。小样本结果只能作为开发信号，不能宣称全面领先。
