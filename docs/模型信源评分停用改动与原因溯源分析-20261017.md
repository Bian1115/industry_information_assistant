## 结论

**旧的模型信源评分随 2026-10-16 的“取消写作前事实提炼”改造一起退出了主链路。** 这次改造主动将 Scout 改为读取并保存原文，让 Writer 直接检索原文写作。

信源分类与 `credibility_score` 原本包含在事实提炼的同一次模型输出中，没有独立的评级调用。取消该次提炼后，评分也就没有了执行入口。所检查材料没有记录“因来源评分准确性不好而单独停用评级”的决策或对比实验。

当日文档记录的需求是：

> 取消写作前的模型事实提炼，让 Scout 收集的原文直接进入临时知识库，Writer 根据原文证据写作。

旧入库函数在 `scout.py:1204–1205` 接收类别与分数，缺失时默认 `news / 0.5`。因此，从主路径移除事实提炼调用，结构上就会一并停止生成这些评分；当时没有将它们拆成独立服务再接到原文保存路径。

## 二、当时的原因：已记录需求与预期收益分别说明

### 直接记载的改造目标

当日报告明确要求去掉写作前的模型事实提炼，让材料流转为：

```text
读取原文 → 保存正文与chunk → Writer检索原文证据 → 写作及写后引用回读
```

它解决的是材料处理流程和 Writer 对中间事实列表的依赖。该报告第46行说明，旧辅助方法暂保留以兼容已有独立调用和旧测试，也不清除历史检查点中的事实与审计结果，所以现在仍能在代码中看到评分提示词。

### 当时列出的预期收益

当日报告第155–158行将以下内容明确标为“间接推断”：

1. 少一次预提炼阶段的模型请求，预期可减少 token、费用和耗时。
2. Writer直接读取原文，预期可减少中间事实摘要造成的信息损失。

这些是预期收益，不是已测量的提升。原报告明确说明没有实测节省多少费用／时间，也没有评估真实报告质量是否提高。

### 对“为何停用评分”的准确解释

主动移除事实提炼是有明确实施记录和测试约束的。评分随之退出，是因为它依附于同一提炼输出。**现有证据支持这条调用结构上的因果关系，不能据此推断当时曾明确决定“来源评级本身不需要了”。**

同样，不能把后来关于“来源分类与可靠性应解耦”的调研建议，倒推为本次改造当时的动机。

**已测量／直接核验：**Git版本与调用差异、当前未提交状态、当日实施说明及历史逐项测试结果。**间接推断：**评分因与事实提炼耦合而随流程退出；减少中间信息损失与模型开销是预期收益。**尚未评估：**原评级准确性、单独移除评级的影响、真实费用／延迟与最终报告质量；未核验运行中服务加载的源码版本，也未取得原始取消提炼的用户对话。

结论是：若仍希望保留来源评级，应将其从事实提炼中拆出，接入当前原文收集后的活跃路径，独立保存分类、可靠性判断、依据与未知状态。恢复整个旧事实提炼流程会同时恢复其他已移除的材料处理步骤，不能视为一个单独的“开启信源评分”开关。本次仅完成溯源，没有恢复或改造业务代码。
