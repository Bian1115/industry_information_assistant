# 药品 RAG 公开数据集调研与适用性分析

调研及分析日期：2026-11-05（Asia/Singapore）。

## 结论与核查口径

有公开资源可用于药品 RAG。需要区分两种用途：知识库语料是系统检索的说明书等原文；评测题库是评估程序输入的问题，以及用于核对回答的参考答案和证据标注。只有说明书不能直接算出答题准确率，只有问答也不一定能判断系统是否找到了正确原文。

英文原型优先考虑 DailyMed/openFDA 作为说明书来源、MedicationQA 作为题目来源；两者不是官方配套数据，必须先逐题核对证据覆盖。中文原型可从公开的 20 份说明书样本开始；Huatuo-26M 可提供候选问法，但要筛选药品问题并补齐证据。

本次是公开来源核查和适用性分析，不是模型性能实验。未调用生成模型、未建立检索索引、未下载全部数据集、未复算论文成绩。

- **已核查**：下列作者仓库或机构页面中的资源类型、声明规模、数据入口和已公开限制。
- **已测量**：没有 RAG 性能指标；来源访问结果和响应校验值由程序记录。
- **间接推断**：各资源适合建库、题目筛选或初步评测的程度，依据公开数据结构判断。
- **尚未评估**：逐条医学正确性、所有链接可用性、证据覆盖率、检索召回率、生成正确率、引用准确率及中文迁移效果。

原始来源响应与访问记录：[公开来源原始响应.json](../backend/eval/data/药品RAG公开数据集调研-20261105/公开来源原始响应.json)。这是来源核查记录，不是模型运行结果。

## 失败样例与局限性

本次没有运行模型，因而没有实测模型失败样例。已确认的数据准备障碍是 MedQuAD 药品子集答案缺失；另外，浏览工具读取部分 GitHub 页面曾超时，随后改用同一作者仓库的 raw 文件核查。来源归档程序成功保存 6 条响应；DailyMed 的独立归档请求超时，JSON 保留了错误记录，其下载方式由本次浏览工具成功读取的官方页面核查，未保存该页面完整本地快照。

以下是设计评测时需要检查的失败情形，属于机制推断，不代表本项目已经发生：

- 评估者用 MedicationQA 的题目测试 DailyMed 知识库，但题目要求的信息只存在于另一来源；系统没有找到答案时，不能直接归因于检索算法差。
- 开发者把测试题的原始问答整条放进知识库，再用同一道题测试；所得成绩可能主要反映重复问答匹配，不能代表系统读取说明书的能力。
- 系统检索到了同名但剂型、规格或厂商不同的药品文档，答案引用了真实文本，却对应了错误产品。
- 开发者把英文药品题目翻译成中文后，直接声称已验证中国市场药品问答能力；翻译不能消除药品批准范围和说明书版本的差异。

本调研不穷尽所有公开数据集；“未找到完整中文配套基准”不能解释为此类资源不存在。论文中提到数据集，也不等于已经核实数据文件可下载，因此没有将仅有论文线索的资源列作已确认可用题库。

## 下一步建议与核心指标

建议先选定语言和用途，再做小规模数据准备：

1. 开发者先选 30—50 个问题作为试验范围，记录选题规则，不把该子集称为完整基准。
2. 开发者从来源站点取得对应说明书或其他参考原文，保存原文版本、来源 URL、药品标识和章节位置。
3. 标注者逐题检查答案能否由保留的原文支持，记录问题、参考答案、文档 ID 和证据片段。没有证据覆盖的题目单列，不能悄悄删除后只报告高分。
4. 检索程序在收到测试问题后，从说明书知识库返回片段；生成模型读取问题及这些片段，生成带来源的回答。评估程序将检索结果和生成答案与独立标注比较。

后续应测量的指标及本次状态：

| 指标 | 通俗定义 | 本次结果 |
| --- | --- | --- |
| 证据覆盖率 | 全部选定题目中，有多少题在保留的原文里确实有答案依据 | 尚未评估 |
| Recall@k | 有证据覆盖的题目中，有多少题的正确证据出现在系统返回的前 k 个片段内 | 尚未评估 |
| 回答正确率 | 评估者按预先约定的逐题标准判断，有多少回答正确且完整 | 尚未评估 |
| 引用支持率 | 系统回答中的可核查论断，有多少能被其引用原文支持 | 尚未评估 |

以上建议来自数据结构与任务匹配分析，没有用本次未执行的实验为效果背书。
