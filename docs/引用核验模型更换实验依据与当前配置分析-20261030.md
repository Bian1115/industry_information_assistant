# 引用核验模型更换实验依据与当前配置分析

分析日期：2026-10-30，Asia/Singapore。评估对象：从 `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli` 更换为 `qwen3-max` 的历史实验依据，以及当前仓库的核验模型配置。本次读取历史逐条结果进行复算，没有重新调用模型、生成报告或新增人工标注，也没有修改业务代码与配置。

## 1. 结论

当前仓库的引用核验模型为 **Qwen3-max（API 请求名 `qwen3-max`）**。2026-10-05先在评估链路替换并复跑，2026-10-06完成业务核验入口接入。当前生产入口拒绝执行绑定旧 mDeBERTa 的配置；文件中保留的本地模型类用于历史离线工具，不能据此判断生产仍使用旧模型。

更换有三项实验依据：旧方案对中文复杂论断存在明显误拒和漏放；旧模型单个证据与论断的输入受512 token限制，证据分散和矛盾优先聚合会放大误判；同批741条带来源论断改用Qwen核验方案后，与最终语义复核的标签一致率从369/741＝49.80%升至620/741＝83.67%，增加33.87个百分点。

这支持“更换核验方案有实验依据”，不能解释为“模型准确率提高33.87个百分点”。当时同时改变了模型、证据组合方式和标签口径，且Qwen核验器与参照裁判同用Qwen3-max，参照并非独立人工金标。

这里的NLI是“判断证据原文是否支持一句陈述”的任务。例如，程序从保存的来源取回“试验纳入800人”，把原文和“试验纳入800名男性”交给核验模型；模型应返回信息不足，因为来源没有提供性别。该任务检查引用支持关系，不等于证明陈述在现实中为真。

## 2. 数据与配置口径

本次区分三批数据，不跨批计算提升：

1. **旧摘要核验诊断，2026-10-03分析。** 五题自然摘要共271条记录；排除10条待裁决和4条执行错误，257条进入主指标。GPT暂定参照认为247条充分支持、10条支持不足。模型为mDeBERTa，支持阈值0.85、矛盾阈值0.5，分数未经过本任务人工校准。
2. **模型替换前后同批复跑，旧评估2026-10-03至10-04，新评估2026-10-05。** 959条适用论断中，741条有来源，包括293条最终正文论断、250条Scout事实（资料搜集阶段整理出的事实）和198条预审论断。218条无来源论断不进入一致率分母；741不等于最终报告正文论断数。本次按ID核对，论断原文、保存的引用窗口和最终参照标签均相同。
3. **后续生产模块离线验收，2026-10-06回放、10-07复核。** 五篇正文共511条论断，其中293条带引用；排除63条复核unknown，230条进入二分类指标。这里的正类是“完整支持”，参照为Codex独立复核，仍非人工金标。该结果不与第一批257条摘要数据直接作提升比较。

替换复跑的旧方案逐窗口打分，再按最大分数和矛盾优先规则汇总；新方案让Qwen联合读取各来源全部保存窗口，合并重叠片段，增加partial（部分支持）类别，直接返回语义标签，不使用0.85/0.5门槛。后续生产接入则使用Qwen自报三类分数与阈值，不能把10月5日辅助筛查实验等同于当前生产实现。

## 3. 旧模型方案为何需要更换

### 3.1 旧摘要核验的报警可靠性较低

| 指标 | 复算结果 | 含义 |
| --- | ---: | --- |
| 问题检出精确率 | 6/43＝13.95% | 系统标为有问题的43条中，GPT参照只认为6条确有支持不足问题，其余37条暂定误报 |
| 正确论断误拒率 | 37/247＝14.98% | GPT认为充分支持的247条中，系统将37条标为未通过 |
| 问题检出召回率 | 6/10＝60.00% | 10条支持不足论断中检出6条 |
| 问题论断漏放率 | 4/10＝40.00% | 10条支持不足论断中放过4条 |

“误拒”描述核验标签，不表示当时系统实际删除或阻止发布了对应内容。问题样本仅10条，占257条的3.89%，因此报警精确率容易受正确样本误报影响；这不是mDeBERTa在所有任务上的通用精确率。

37条误拒中，20条被判unknown，17条被判contradiction。9条同时出现高支持窗口和高矛盾窗口，均被矛盾优先规则否决，GPT参照均认为有支持。这9条占全部误拒的24.32%，提示聚合规则也是问题来源。

### 3.2 失败样例说明模型与证据组织均有问题

- **中文政策被误判为矛盾：** 重庆政策原文明确“90分及以上系数1.0”，旧模型在原窗口上给出矛盾分数0.6051，超过0.5门槛；去除无关导语后，支持分数变为0.8887，矛盾降至0.0832。模型判断受窗口中无关内容影响。
- **必要信息分散：** 电容融合方法的两个窗口分别说明提出者和技术方法，旧模型单窗口最高支持分数约0.0013；把两段必要原文合并后，支持分数升至0.9984。这个案例表明部分失败来自证据拆散，不能全部归因于模型本体。
- **缩短证据仍不支持：** 科技馆原文明说“参与、体验、互动”，旧模型原支持分数约0.0010，缩窄证据后仍仅0.0034。小幅降低0.85支持门槛不能修复该例。
- **精确含义未受保护：** 旧链路漏放样例涉及“提升60.38%”被改成“提升至60.38%”、比较对象缺失和来源归属扩大。核验不能只认相近词语与相同数字。

旧链路当时按照512 token上限处理输入，预算包含证据、论断及特殊标记；token是模型处理文字时使用的计数单位，不等于汉字数。项目不静默截断超长输入，因此必须拆窗口或记录超限。这里的512是发布配置和项目保护逻辑采用的上限，不是已经证明的架构绝对极限，详见第9节同日补充。512限制是工程瓶颈，但第一批旧摘要诊断的实际最大输入为404 token，不能把该批全部误判解释为超长失败。

2026-10-06真实接入验证中，Qwen成功处理了一个估算为1,946 token的长证据对，完整保留尾部人数信息；支持、信息不足、明确矛盾三个合成样例均符合预期（3/3）。这证明超出旧长度范围的输入能够完成核验，不代表总体准确率100%。当前项目核验输入预算为65,536 token，是真实配置值，不是本次测得的最大有效长度。

## 4. 替换前后同批741条结果

一致率计算方式：NLI标签与保存的最终语义复核标签完全相同的条数／有来源且参与比较的论断数。

| 题目 | 样本数 | mDeBERTa方案与复核一致 | Qwen方案与复核一致 |
| --- | ---: | ---: | ---: |
| 16 非接触式感知算法 | 127 | 47/127＝37.01% | 105/127＝82.68% |
| 31 中外博物馆教育 | 179 | 100/179＝55.87% | 141/179＝78.77% |
| 35 市政污水与雨污协同 | 119 | 57/119＝47.90% | 99/119＝83.19% |
| 46 房地产可持续发展 | 190 | 106/190＝55.79% | 173/190＝91.05% |
| 49 正畸与医美共同需求 | 126 | 59/126＝46.83% | 102/126＝80.95% |
| 合计 | 741 | **369/741＝49.80%** | **620/741＝83.67%** |

五题均提高，但同一题内的论断并非独立样本，不能据此外推所有领域。新旧标签相同417条、变化324条；324条不能称为“修正324个错误”。新方案仍有121条与参照不一致。

例如35-body-053，新Qwen筛查把旧标准报批稿判断为足以支持“仍未实施”，而最终语义复核为partial，显示模型仍可能忽略来源时效；49-body-009，新Qwen发现19–33岁与20–33岁的年龄范围不一致，但判contradicted，最终复核为partial，说明“明确矛盾”和“信息不足”之间仍有标签分歧。这些为历史记录中的判定，不是本次重新进行外部事实核查。

## 5. 换用Qwen后是否已经足够可靠

后续生产模块在230条可判断且带引用正文论断上的离线结果为：

| 指标 | 结果 |
| --- | ---: |
| 完整支持识别精确率 | 131/169＝77.51% |
| 完整支持识别召回率 | 131/143＝91.61% |
| 完整支持识别F1（综合精确率与召回率） | 83.97% |
| 与独立复核二分类一致率 | 180/230＝78.26% |
| 未完整支持问题检出召回率 | 49/87＝56.32% |

该模块仍漏放38条未完整支持项，其中37条为部分支持、1条为原文矛盾。因此91.61%表示保留正常引用的能力，不能说“检出了91.61%的问题引用”。这批结果用于说明换模型后仍有不足，不作为当初10月5日替换实验的一部分，也不与13.95%的问题检出精确率直接对比。

## 6. 当前模型与执行边界

- [配置对象](../backend/app/service/context_policy.py)：`NLISettings.model_id`默认`qwen3-max`，输入预算65,536，输出上限4,096，每批最多4对，支持／矛盾／复核分数门槛分别0.85／0.5／0.8。
- [模型入口与请求](../backend/app/service/nli_verifier.py)：`get_nli(settings)`只允许新运行使用Qwen；`QwenNLI.predict()`明确发送`model="qwen3-max"`、`temperature=0`、`enable_thinking=false`和JSON输出要求。
- [核验提示词](../backend/app/prompts/Qwen引用支持性核验.txt)：程序将来源原文和待核验陈述交给Qwen，模型判断支持、信息不足或矛盾，并返回理由。分数是模型自报值，不是经过校准的正确率。
- 当前本地`backend/.env`的`RESEARCH_WRITER_CITATION_VERIFICATION_ENABLED=true`；[首跑开关解析](../backend/app/service/deep_research_v2/citation_verification.py)读取该默认值，显式请求与历史运行保存的开关仍有各自作用。因此不能断言每个既有会话都执行了核验。

以上确认的是当前仓库和本地配置，本次没有检查正在运行进程已加载的代码版本，也没有发起远端请求确认API别名的实时路由或可用性。

## 8. 局限性与下一步

- **已测量：** 历史逐条标签和原始计数复算；741条论断、保存证据及参照一致性核查；当前仓库的模型请求名与本地预算核查。历史的1,946 token长证据与3/3合成样例来自当时真实调用，本次未重跑。
- **间接推断：** 中文语义误判、证据拆散及矛盾优先聚合共同解释了旧方案的不理想表现；同批方案对比与长输入验证为更换提供依据。
- **尚未评估：** 固定证据处理、输出口径和评分流程后的纯模型增益；独立人工金标下的准确率；新任务泛化；当前线上运行效果、进程加载状态和API实时可用性。

下一步如需证明“模型本体更好”，应在独立人工标注的固定证据—论断数据上比较候选，同时固定证据组织与聚合流程；分别报告误拒、漏放、无法判断、延迟与成本。当前可直接采用的表述是：“旧mDeBERTa核验方案暴露明显误拒、漏放和短输入限制，因此替换为Qwen3-max；同批741条样本的机器评审标签一致率从49.8%提高到83.7%，但该提升包含模型与证据处理方案的共同变化。”

## 9. 2026-10-30同日补充：旧模型能否调长输入

补充对象：512 token限制的性质。口径变更：将“旧模型一次最多处理512 token”明确为“旧发布配置与项目链路按512 token限制输入”，不改变任何历史指标。本次仅核查配置与实现，未加载模型做扩长推理，也未更改旧模型配置或恢复旧生产入口。

本地固定版本`8adb042d524ecd5c26d3e3ba0e3fbcf7e2d0864c`的`config.json`保存`max_position_embeddings=512`，`tokenizer_config.json`保存`model_max_length=512`。项目`LocalNLI.predict()`检查`min(settings.max_length, self.model.config.max_position_embeddings)`：即使只将项目参数改成1024，实际限制仍为`min(1024,512)=512`，超出时由程序返回`input_too_long`，模型不会收到该条输入。

但该模型同时配置`position_biased_input=false`、`relative_attention=true`、`position_buckets=256`。通俗地说，模型使用文字之间的相对距离信息，并非必须为每个绝对序号查一张仅有512项的位置表。根据[模型发布配置](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli/raw/main/config.json)及[Transformers v4.44.2对应实现](https://github.com/huggingface/transformers/blob/v4.44.2/src/transformers/models/deberta_v2/modeling_deberta_v2.py)，可以推断存在尝试更长输入的技术空间；不能因`max_position_embeddings=512`这个字段就断言超过512必然发生位置表越界。这里引用固定版本官方实现说明结构，不代表已经验证本地安装版本的扩长运行结果。

因此，可在独立离线实验中调整输入保护与分词长度策略，尝试768、1024等长度，并保留原始冻结模型文件。能送入更多文字与核验质量改善是两个不同目标；扩大输入还会增加计算和内存开销。不能只修改配置数值就宣称模型已经可靠支持长文本，也不能直接假定修改长度必然需要重训。

- **已核查：** 本地两份模型配置及项目长度检查逻辑；结果补充到同目录机器可读核查文件。
- **间接推断：** 该相对位置结构存在超出512输入的实验空间。
- **尚未评估：** 旧模型768／1024等长度能否在本地实现上跑通、是否减少误拒漏放、实际时间与内存成本。没有“旧模型扩长方案对Qwen方案”的受控比较。
- **结论边界：** 长度是当时方案的实际限制，但不能单凭它证明必须换模型；更换依据还包括既有误拒、漏放及同批方案比较。若要判断扩长能否替代换模型，应固定同一批论断、完整证据和参照标签，对512窗口方案与扩长方案开展新实验。
