## 定位结果：已确认事实与机制推断

### 已确认：错位在模型输出中已经存在

第 13、14、17—24 轮共 10 轮，原始模型响应里的 `resolved_query` 已经逐字等于上一轮用户原话。归档输入的 `original_query`、本轮分句及 query SHA-256 均正确，最终任务只是保留了模型给出的错误文本。

这排除了“评估脚本把轮次配错”“读取历史时把上一轮设成当前问题”以及“校验阶段才把问题改成上一轮”这三种解释。证据：[错位根因证据.json](../backend/eval/data/研究入口本轮问题错位修复与同轨迹复评-20261017-135458/错位根因证据.json)。

### 已确认：原输入布局与校验缺口

原实现把本轮原话放在单条长用户消息的开头，之后拼接整个会话历史和候选报告。最近候选的 `query` 又是上一轮原话，出现在更靠后的参考材料中。模型没有收到一条独立且位于最后的当前任务消息。

`validate_decision` 只在 `depends_on_history=false` 时强制恢复本轮原话；依赖历史时直接接受模型的 `resolved_query`。现有协议检查了字段类型、候选授权、操作路径和搜索章节，但没有识别“输出逐字复制历史问题且与本轮不同”这一可确定的异常。因此错位文本和伴随的旧操作、旧修改指令可以进入执行链。

### 间接推断：长参考材料与旧 query 干扰当前任务锚定

输入布局为模型误选上一轮任务提供了条件，且坏响应通常连同操作和修改指令一起滞后一轮。该解释与轨迹吻合，但**尚无成功的真实配对生成或单变量消融**，不能声称已经证明模型注意力、提示顺序或缓存中某一个因素是唯一原因。

本次修复同时处理当前任务的输入锚定和可确定错位的执行校验，不采用“仅把 `resolved_query` 改回原话、保留旧 operations”这一会掩盖错误的做法。

## 代码修复

实现位置：[research_context_service.py](../backend/app/service/research_context_service.py)。

1. 历史、记忆和候选报告先作为参考材料提供，**本轮原话及分句放到最后一条独立用户消息**；系统消息明确最后一条才是当前任务。
2. 提示要求 `resolved_query` 保留本轮动作和约束，并核对操作、变更、修改指令及搜索任务都针对本轮。回查最初要求不等于回退基稿，“当前稿”默认指最近已交付稿。
3. 增加精确复用检测：如果改写不同于本轮，却与某条历史用户问题或候选报告的 query 相同（忽略空白），不接受该整份任务。一般改写不按字符串相似度拒绝；用户本轮主动重复同一问题也允许。
4. 首次检测到错位时，要求模型**重新生成整份任务**，最多重判一次；保留两次原始响应及命中的历史来源。
5. 重判仍错位，或已发现错位后重判返回无效协议，进入澄清状态、保留历史依赖，不执行错误研究。共享预算耗尽仍向上抛出，不能用 fallback 绕过预算。
6. 初判、重判、章节修正都计入共享预算；任务指标累计这些调用的已知 token 用量，未知 usage 不补零。

本次修改没有调整首轮无历史 fallback，也没有通过改标签或修改固定题集来提高指标。补丁：[本次代码改动.patch](../backend/eval/data/研究入口本轮问题错位修复与同轨迹复评-20261017-135458/本次代码改动.patch)；修改前后源码与哈希见运行目录。

## 失败样例、机制测试与真实调用中断

- **第 14 轮：** 本轮要求 TypeScript 替换 Python，旧响应仍处理第 13 轮连接/会话术语。新机制识别整个任务错位，并要求重新生成所有动作字段，而非只更换问题字符串。
- **第 17 轮：** 旧问题字段滞后，但字数变更字段捕获了 900。仍须重判整份任务，避免混合字段不一致；本次没有把它描述成所有字段都错。
- **第 24 轮：** 本轮新增“迁移与验收”，旧响应要求整理三个待验证问题、保持现有结构。新机制识别复用，持续失败时停止执行错位任务。
- **新增 9 项回归：** 当前请求位于末条消息、整份重判、持续错位、无效重判、用户主动重复、合法指代补全、摘要后仅候选 query 可用、预算耗尽、全部调用计账。另与会话路由、句子溯源、章节修正回归共同运行，共 87 项，83 通过、4 个原有用例按配置跳过。
- **首次真实回放失败：** 运行器缺少型号预检，修复前后两组共 46 个初始请求均返回 `model_not_found`。这些原始请求与错误完整保留，但排除语义准确率统计。运行器已增加账户型号目录和最小生成请求预检，避免再次整批调用不可用型号。
- **替代型号最小请求失败：** `qwen3.8-max` 返回 `Arrearage`，未启动替代型号的整批回放。供应商没有返回成功预测或 usage，调用用量/费用未知，不记作零。

## 局限性与结论

**已测量：** 输入与原始响应错位的证据、精确复用检测 10/10、未复用样例误报 0/4、持续错位的执行闭锁 10/10、87 项机制回归、旧型号 404 和替代型号账户拒绝。

**间接推断：** 将当前任务放到最后并明确参考材料边界有望减少任务滞后；这需要成功的真实配对生成验证。已有故障回放只证明检测与失败处理机制，不证明提示修改的收益。

**尚未评估：** 修复后新的话题/操作/目标/语义准确率、第二次真实生成的纠错成功率和额外耗时、非精确复用的语义漂移、完整要求满足率、真实 30+ 轮连续生成及最终回答质量。样本仍为单主题相关会话，不能据此测量全部主题切换与指代消解能力。

修复代码与已知错例防护验证已经完成。用户要求的真实准确率复评仍需恢复可调用的模型账户后完成；现阶段不能给出新的准确率或声称已超越历史的 58.3% 联合正确率。下一步是以同一可用型号完成两组配对预测，逐轮复核语义等价改写和修改指令，再报告分类、目标、问题忠实度和完整任务满足率。
