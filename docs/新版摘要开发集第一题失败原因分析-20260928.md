## 核心结果与失败链条

本题12次模型请求，包括规划3次、Scout主任务4次、分块摘要5次；执行20次搜索和5次网页读取工具调用。5次摘要尝试、0次采用，整体摘要覆盖游标始终为0；fact_extraction、最终摘要合并、citation_completion及summary_verification均未执行。

失败链条：

```text
新增资料使上下文超过摘要阈值
 → 开始生成首批摘要
 → 摘要输出不符合分句及来源编号协议
 → parse_draft立即拒绝，尚未到引用补齐／NLI或定向修复
 → 保留完整历史，靠工具外置继续下一次主请求
 → 相同首批摘要反复失败，游标不推进
 → 外置后仍超硬预算，停止任务
```

## 具体输出问题

五次分块摘要的输入哈希完全相同，均为同一首批材料，输入25,666 token，没有超过摘要输入预算。此前实时进度中“4次分块调用”是调用次数，不代表4个不同分块已成功；最终核对为同一首批调用5次、全部失败。

### 实际首先触发的错误

`parse_draft`把每个非空栏目中的每一行当作一个分句，要求末尾带真实来源编号，或者以“推断／建议／待确认／待办”开头。五次输出的SESSION INTENT首行都是以“The user aims…”开头的英文目标描述，没有来源编号或规定前缀，因此立即抛出“无来源分句必须明确标记推断、建议、待确认或待办”。英文输出本身不是拒绝原因。

### 被第一个错误遮住的其他问题

- 中间摘要使用`[source_1]`、`[source_41515860]`等标记，而输入提供的是`d175bceb-9542-4581-abe1-24aa84741ff7`等原始记录UUID。五次输出分别有10、10、4、10、7个不同标记，与本次输入真实来源编号的交集均为空。部分编号形似检索结果序号或文献标识，但当前不存在将其映射回原始记录的程序映射，不能算合法引用。
- 存在多句合写一行、使用列表符号、若干事实及待办完全无编号等问题。ARTIFACTS写成“None created or modified…”而不是空栏目要求的字面值`None`，会继续作为普通分句校验。
- 仅解决第一行或放宽无编号规则不足以让引用可靠；编号错误也需要被处理，不能通过直接跳过解析来宣称成功。

### 任务背景没有明确进入这批摘要输入

首批包含11条工具记录（6个工具输入、5个工具输出），`previous_summary`为空、`latest_contract={}`，没有原始用户请求记录。模型只能从检索词和材料推测任务目标。

输出中出现“The user has not yet requested synthesis…only retrieval”等描述，但用户原请求明确要求梳理技术路线、适用材料和研究问题。这是可直接核对的任务目标误述。缺少任务背景很可能增加这种误述风险，但本次没有做对照实验，不能证明它单独导致全部格式错误。

压缩前数值是本地组装和计数，不是发给供应商的请求大小。已使用本地Qwen分词器重建最后一次完整输入，结果与日志的28,962完全一致，超预算3,218 token。

最终请求仍包含25条工具输入、25条工具输出、4条旧模型输入和4条旧模型输出。工具外置与旧输入资料引用化均生效；四条旧输入引用化后分别为2,587、1,624、2,478、1,706 token，均低于4,000的单条摘要阈值，因此没有触发单条输入摘要。

分项独立文本计数：旧输入8,395、旧输出2,172、工具输入1,752、工具输出预览4,716 token；当前任务与系统提示单独计数5,783 token。分项不含全部JSON/聊天封装，不能直接相加等同于完整请求。离线暂时去掉旧输入后请求为19,818 token，仅说明这部分对总量的贡献；不能据此主张直接删除旧输入，后者可能丢失约束和进度。

因此当前问题不是工具外置没有执行，而是整体摘要一直未能替换历史，记录数量及剩余文本不断增长。

## 修复优先级建议（本次未实施）

1. 对齐中间摘要输出协议：为原始记录建立程序维护的短编号映射，明确模型必须使用允许编号；输出后验证并映射回真实来源，防止示例编号或文献ID混入。按结构化分句生成，避免一个自然语言段落同时承载多个断言。
2. 让首批摘要明确收到原始任务及有效约束，将背景与待压缩证据区分，避免从搜索关键词反推用户要求。对SESSION INTENT和NEXT STEPS定义可执行的来源或非事实标注规则。
3. 在中间摘要格式失败时增加一次有预算的局部格式修复，报告具体栏目、行与不合法编号；当前修复循环位于最终引用/NLI之后，首批parse_draft失败根本进不到它。不能靠重复相同输入5次代替针对性修复，也不能为了通过而捏造来源。
4. 先用本次固定首批输入验证生成、合并、引用补齐、NLI、摘要采用能完整走通，再单独重跑第一题。来源范围与材料科学题适配是另一个问题，应独立验证；直接加大窗口不会修复编号和任务背景问题。
