## 一、当前实际运行路径

`graph.py:288` 将初搜绑定到 `DeepScout.process`；`:292`、`:294` 将补充检索和审核返工检索也绑定到同一入口。

初搜路径为：

```text
DeepScout.process
  → _research_section
  → 搜索候选与来源范围过滤
  → _enrich_results_with_full_text：规则排序、读取、正文检查、原文保存
  → _store_collected_sources：保存原文及章节关系
  → Writer 从已保存原文中检索证据并写作
```

`scout.py:1335–1389` 的章节研究完成读取后直接保存原文；`scout.py:643–678` 的补搜也直接保存原文。保留的显式深搜方法在 `:1457–1470` 同样只读取和保存。

`_store_collected_sources` 的注释明确说明“不生成事实、数据点或假设证据摘要”。`writer.py:633` 表明事实 ID 仅为历史检查点原句绑定保留；`:699` 调用 `evidence_prompt` 获取正文证据。`session_evidence_rag.py:420` 也明确区分新研究原文与历史事实的兼容路径。

这里可能调用大模型做正文检查或写作，但这两类调用不构成来源信誉评级。

## 二、读取前：确定性的候选阅读优先级

实现位于 [`quality_pipeline.py`](../backend/app/service/deep_research_v2/quality_pipeline.py) 的 `candidate_source_score`，由 `scout.py:938` 降序排序后交给网页读取工具。

| 判断条件 | 优先级变化 |
| --- | --- |
| 域名命中 `LOW_QUALITY_DOMAINS` | 直接返回 -100，不叠加后续规则 |
| hostname 以 `.gov.cn` 或 `.edu.cn` 结尾 | +80 |
| 网站名或标题含“官网、官方、年报、annual report、监管、统计局”之一 | +50，只加一次 |
| URL 字符串以 `.pdf` 结尾，忽略大小写 | +20 |
| 网站名或标题含“文库、论坛、自媒体、博客”之一 | -30，只扣一次 |
| 未命中其他条件 | 基础分为 0 |

域名集合在 `evidence.py:15`，包含豆丁、道客巴巴、book118、360doc、头条、CSDN、知乎、搜狐、简化拼写域名 `jianhu.com`、百度百家号等代码中列出的域名。此处只转述硬编码策略，不判定这些平台所有内容的真实质量。

这个整数只控制有限读取预算内的先后顺序，没有调用模型，也没有读取后可信度分数反馈重排的逻辑。PDF 判断是字符串后缀判断，带查询参数的 PDF 不一定命中。

## 三、读取后：正文准入，不输出信誉评分

`web_document.py:82` 的 `assess_body` 用规则检查空正文、验证码、错误／登录页、导航／推荐列表、脚本污染、预览或付费提示等。

`scout.py:803` 的 `_check_source_body` 进一步处理不确定正文：仅对 `uncertain` 页面进行一次有界 LLM 检查，要求判断页面类型、目标文档一致性及完整性，返回 `passed / partial / rejected` 和可保留的正文块编号。模型执行失败仍保留不确定状态。

`scout.py:1009` 只允许读取成功且正文质量为 `passed` 或 `partial` 的结果继续进入原文存储，保存 URL、最终 URL、正文哈希、正文编号和句子索引；启用 RAG 时将正文入库并在状态保留引用。

因此，`reader_verified=True` 或正文 `passed` 只说明符合相应读取／正文准入条件。它们不证明发布者身份、来源信誉或论断真实性。

RAG 的 `session_evidence_ranking.py` 比较的是研究问题或待核验论断与证据片段的相关性；其中 `relevance_score` 也不等于来源可靠性分数。

## 四、保留的旧机制：模型分类与可信度分数

主提示词 `scout.py:187` 要求在每条 `extracted_facts` 中返回 `source_type` 与 `credibility_score`，模型材料包含标题、URL、网站名、日期、摘要及实际展示的编号正文。评分标准仍写在 `scout.py:254`：

| 旧提示词类别 | 规定的可信度区间 |
| --- | --- |
| 官方来源（政府、央企） | 0.9–1.0 |
| 学术来源（论文、研究机构） | 0.8–0.95 |
| 权威媒体（央媒、财经媒体） | 0.7–0.85 |
| 行业报告（券商、咨询） | 0.7–0.9 |
| 一般新闻 | 0.5–0.7 |
| 自媒体 | 0.2–0.5 |

这张表是提示词约束，不是基于独立背景证据计算的公式。主提示类型只有 `official / academic / news / report / self_media` 五个标签，权威媒体与一般新闻共用 `news`；补充和深搜提示的枚举还缺少 `self_media`，也没有完整重复六类分数表。

旧入库函数 `_ingest_search_analysis` 在 `scout.py:1204` 对缺失类型默认 `news`、缺失评分默认 `0.5`，`:1244` 继续把该分数填入数据点 `confidence`。该入库函数直接接收模型给出的分数；原句编号与 URL 的绑定检查并不验证分数合理性。

**当前调用状态：**三个 `_analyze_*` 方法与 `_ingest_search_analysis` 都有定义，但在扫描的生产 Python 文件中直接调用数均为 0。不能再沿用“正常研究读取后会由模型逐条打分”的描述。外部调用者或历史检查点仍可能接触这些字段，本次没有验证那些运行。

## 五、保留的规则分层及界面展示

`evidence.py:41` 的 `source_tier` 独立于 0–1 分数，规则为：

| 条件 | 层级 |
| --- | --- |
| 命中低质量域名集合 | `low` |
| 类型为 `official / academic / report / filing / regulator`，或域名后缀为 `.gov.cn / .edu.cn` | `primary` |
| 其他 | `secondary` |

事实／数据视图对来源不可用或绑定无效的项会标为 `low`／未通过读取验证；派生数据有效时继承输入中的最低层级。该层级不读取 `credibility_score`，也不真正调查页面是否为原始出处，所以 `primary` 不能解释为已经核实的原始研究或高信誉来源。

前端步骤详情组件 `step-detail-panel/index.tsx:120` 仍支持把输入字段 `credibility` 乘 100 显示为“可信度”：≥0.8 为绿，≥0.5 为橙，其余为红。这是展示逻辑；该组件字段名与后端 `credibility_score` 也并不相同。本次未运行浏览器或检查线上事件，不声称现行新研究必然产生或展示该百分比。

## 六、失败样例、局限性与下一步建议

本次没有新增实测失败样例。以下仅为机制推导的风险示例：

- 陌生网站标题自称“官方年报”会获得候选阅读加分，但没有因此核实网站主体。
- 大学官网活动新闻可因域名得到 `primary`；这不代表它是同行评审研究。
- 旧提示词把官方类别与高分直接关联，不能据此证明具体论断真实；旧默认 0.5 也不表达“缺证据／未知”。
- 只看到评分提示词或百分比组件，容易误判新主链路已经执行了评级；本次调用链核查直接纠正这一解释风险。

核查范围是本地当前工作区及直接调用语法。没有运行端到端研究，没有核验部署版本、动态反射、外部插件调用、历史运行或真实网页；也不能由静态不存在直接推导线上绝对不存在。源码片段与哈希保留在原始记录中，后续改动应按新版本重新核对。

建议先在代码和产品说明中明确区分“阅读优先级”“正文可用性”“片段相关性”“来源可靠性”。若要恢复或新增实际来源评级，应接在当前原文入库后的活跃路径，独立保存评级对象、身份／文档分类、评级依据与未知原因，并使依据可回查；不能只修改当前无调用的旧事实评分提示词。之后再用人工标注来源集评估身份误报、分类质量、未知处理及依据支持性；数值分数若要表达概率，另做校准评测。
