# Writer 编号引用输出与程序原句回读实现

评估日期：2026-10-02。对象：Writer 输出正文及可核验论断对应的正文/原句编号，不重复输出原句；引用核验时由程序读取保存的正文。

## 协议与实施范围

新生成的章节、报告首尾、审核修订及用户修订沿用统一 claims 协议：

```json
{
  "claim": "本次正文中的可核验原子论断",
  "evidence": [
    {"document_id": "doc_已提供的正文编号", "sentence_ids": ["s000001", "s000002"]}
  ]
}
```

Writer 仍然阅读输入中的原句以选择支持证据，但输出引用不再含 `quote` 或 `evidence_id`。找不到对应编号时保留论断，并返回 `evidence: []`；不从事实摘要伪造原句。正文行内来源链接和现有报告其他字段沿用既有格式。

修改 `backend/app/service/deep_research_v2/agents/writer.py` 的章节、首尾及修订示例，并更新 `writer_claims.py` 的共用说明及规范化处理。即使模型额外返回原句，规范化后的新引用也只保存正文/原句编号；未知或非法编号保留供核验诊断。

## 程序回读与核验

修改 `citation_verification.py`：报告论断引用按 `document_id` 找到唯一正文，再通过现有 `resolve_sentences` 校验正文内容哈希、索引、质量和句子编号。核验请求中的原句由程序截取自保存正文，不采信模型重复输出的引句。

连续选中句按原始位置连同间隔组成证据；不相邻句子分组，不拼接成不存在的连续原文。支持同一论断引用多个正文，每个正文单独解析自身的句子编号。未知/歧义正文编号、无效句子编号、内容或索引变化均产生绑定错误，不能被标为有效引用。

回读文本只在核验请求构建时派生。保存的核验结果移除原句 `quote` 并保留编号和核验结论。核验默认开关未改变；关闭时不回读、不加载 NLI。已保存旧检查点的 `evidence_id/quote` 引用仍可读取核验，新 Writer 输出不再使用旧协议。

逐类结果：

- 生命周期：章节、首尾及修订后的编号引用可保存、恢复并通过 API 和事件交付；未受影响章节的引用保留。
- 输出规范：新引用去掉额外的 `quote` 和旧事实编号，不丢弃未知或非法新编号。
- 位置读取：没有 Writer 引句或事实编号，程序仍能按正文/原句编号构建实际原文证据。
- 无效引用样例：空编号、未知正文、不存在的句子、重复句号、错误类型、被修改正文/索引、拒绝质量来源和歧义正文均不能解析为有效证据。
- 多句多来源：相邻句保留原文间隔，不相邻句不跨缺失句拼接；不同正文中相同 `s000001` 不串用。
- 核验调用：开启时桩收到程序回读的原句，结果保存为编号；关闭时不触发回读或 NLI。
- 历史兼容：旧检查点的引用可继续读取；规范化的新 Writer 输出只保留新字段。

本次无失败测试。上述无效引用是预期拒绝样例，不代表运行故障。

## 局限性、结论和下一步

已测量的是协议、原句定位、核验接口输入、保存和修订生命周期。间接推断：不重复输出原句可减少 Writer 的引用输出量，但不能根据本地桩给出实际 token 节省比例。

尚未评估真实 Writer 模型的编号选择正确率、引用支持率与实际耗时。结论：编号引用输出及程序按需原句回读已经实现并通过回归。下一步可在真实运行中检查未知编号比例、引用核验结果与输出 token；是否启用引用支持性核验继续遵循已有配置。
