# 审核模型自动生成标准与细则可行性分析

分析日期：2026-11-01，Asia/Singapore。

分析对象：让报告审核模型根据研究任务生成审核标准、检查细则，再据此评价报告质量的可行性，以及与当前项目审核链路的关系。

本次属于机制分析：阅读当前工作区源码、既有复核报告和两篇论文，没有调用项目审核模型，没有执行新评测，没有改动业务代码。下面提出的流程尚未实现，不能作为质量提升的实测结果。

## 1. 结论

可以让审核模型生成标准和细则，也可以由同一型号模型执行后续评分。建议把这两项职责分为两次独立调用：第一次根据用户需求制定检查表，第二次读取已经固定的检查表和待审报告进行评价。

针对当前项目，优先采用“固定通用维度、根据任务生成细则、评分前固定口径”的设计。完全自动生成维度、权重、通过线也可以研究，但需要独立样本验证；模型自己认可自己提出的规则，不能证明这些规则合理。

这里的“标准”指评价方向和合格条件，例如报告应充分回答用户问题；“细则”指可以逐项检查的要求，例如用户要求比较两个方案时，报告是否在相同条件下比较二者成本，是否说明不确定性。

## 3. 当前实现与建议方案的区别

当前审核模型在同一次请求中接收用户问题、大纲和报告，再按固定提示词评分。源码中没有单独生成并保存任务专用审核细则的步骤。

建议由系统设计者固定四个维度、计算方法和通用底线，让模型负责把本题需求变成明确的检查项。当前60分通过线是已有工程规则，其最优性没有由本次分析证明；生成细则本身也不能验证该通过线。

| 层级 | 建议由谁确定 | 举例与边界 |
| --- | --- | --- |
| 通用评价维度 | 系统设计者 | 可读性、全面性、深度、指令遵循度 |
| 任务专用检查项 | 模型根据用户需求生成 | 比较任务要检查对象是否齐全、比较条件是否一致 |
| 检查项满足条件和评分档位 | 模型起草，经过校验和独立样本校准后固定 | “完整比较”“只列出两者但未比较”“遗漏一方”应有不同判定 |
| 总分计算与通过规则 | 程序按预先确定的规则执行 | 不让评分模型临时决定权重或修改通过线 |
| 外部事实的来源支持 | 来源核验模块结合保存的来源原文判断 | 模型只看到报告时，不能声称已验证外部事实 |

这里的“校准”是开发者拿独立评审已经判定过的样例，检查模型的标准是否能得到相近判断，再在另一批未参与调整的样例上验证。

## 4. 建议的数据流和执行时机

1. **任务确定后，程序发起标准生成请求。** 程序把用户原始问题、明确约束、固定维度和研究大纲发送给标准生成模型，此次不提供待审报告。大纲只能辅助理解，用户要求优先；大纲遗漏不能成为审核遗漏的理由。
2. **模型返回任务专用检查表。** 每项包含编号、所属维度、具体要求、要求来源、满足与部分满足条件、重要程度，以及需要什么证据。模型区分用户明示要求、完成任务必需条件、可选改进建议；可选建议不能自动成为拒绝交付的条件。
3. **程序校验并保存检查表。** 程序检查字段、编号、维度和评分配置；如果要求来源不成立或内容超出任务，应修正检查表。字段校验无法自动证明语义合理，开发阶段仍需要人工抽查或独立评审。建议将通过校验的检查表、版本、提示词和生成配置保存为运行记录中的文件或数据库记录，后续调用按版本读取；仅留在程序内存中不能作为跨进程复用记录。
4. **报告生成后，程序发起评分请求。** 程序把固定检查表、用户问题和当前报告发送给审核模型。模型逐项提供判断、报告位置、证据片段和理由，再形成维度分与问题清单。未知、部分满足、不满足应明确区分，缺少来源原文不能直接认定外部事实错误。
5. **程序计算总分并执行返工分支。** 程序按预先固定的计分方式汇总结果，并依据问题严重程度和补搜要求决定下一步。若采用逐项数值评分，必须先确定项内权重、维度内归一化方式和不可判断项处理方法，避免检查项多的维度无意中获得更大权重。
6. **报告修订后，程序复用原检查表。** 审核模型对修改后的全文重新检查，仍可发现新引入的事实或逻辑问题。固定标准不等于只能复查旧问题；它约束的是验收要求，避免每轮临时增加任务。若标准确实漏掉用户明确要求，应保存新版本，并用同一新版本重评需要比较的报告。

标准生成与评分可以使用同一型号模型，拆分请求用于控制输入和固定口径，不等于两次判断在统计上独立。用于衡量整个系统质量的最终评测，仍需独立评审、固定样本和来源证据。

## 5. 具体示例与逐类分析

以下是假设任务，用于说明流程，不是已执行评测：用户要求“比较A、B两种技术在同等处理能力下的建设成本、运行成本和适用条件”。

| 维度 | 模型应生成的细则示例 | 审核时应查看什么 |
| --- | --- | --- |
| 全面性 | 两种技术均覆盖建设成本、运行成本和适用条件 | 报告中的对应内容；不能因为有表格就直接判定完整 |
| 指令遵循度 | 比较时采用相同处理能力；不能直接把不同规模的绝对成本用于高低排名 | 用户要求和报告中声明的比较条件 |
| 深度 | 对成本差异解释原因，并说明规模、能耗等条件变化对结论的影响 | 报告论证、数据口径与结论是否相符 |
| 可读性 | 明确解释建设成本与运行成本，结论容易定位 | 定义、章节组织、表格说明及结论表达 |

一条细则可以写成：“审核模型检查成本比较段落；两种技术使用相同处理能力，或报告明确说明换算方法和剩余差异，视为满足；只分别列数值且无法判断规模是否一致，视为证据不足；已知规模不同却直接据绝对成本下结论，视为不满足。”这是任务约束的展开，没有凭空要求报告必须增加某个品牌或某个国家。

同一个缺陷可能同时影响全面性和指令遵循度。设计者需要预先确定主归属及跨维度影响规则，避免同一个遗漏被多个相似细则重复处罚。报告没有要求的行业排名、固定来源数量或统一成本比例，不应被模型随意加入为硬性条件。

## 6. 失败样例与风险

### 6.1 历史样例：把可选扩展变成必需条件

既有复核记录中，`31-R2-issue_4` 要求在美英法日之外至少增加一国，而原题只要求代表性国家。后续写作加入德国章节，但引用与博物馆主题不匹配。历史复查又曾根据标题和表格出现认定扩国任务完成。详见第2节原始结果。

这说明模型生成的要求可能扩张任务，检查表也可能退化为“有没有某段内容”。建议每项细则记录任务依据，并检查内容是否有效回答问题。该样例来自旧版审核，不证明当前版本仍有同样错误率，也不证明新增标准生成步骤一定能消除错误。

### 6.2 设计风险：先看答案再定标准

如果标准生成模型已经看到待审报告，它可能围绕报告已有章节制定检查项，遗漏报告没有覆盖的用户需求；也可能把自己偏好的扩展内容加入验收条件。这是机制风险推断，本次没有测量发生频率。

### 6.3 设计风险：每轮改规则，分数失去比较基础

原稿按五项检查，修订稿按八项检查，即使总分都采用百分制，也不能直接据分差认定改善。同一道题的候选报告、原稿和修订稿应使用相同检查表与计算方法；不同题目的动态检查表即使同为百分制，也不能自动保证任务难度与分数含义一致。

### 6.4 设计风险：模型既出标准又证明标准正确

标准生成和执行评分共享盲点时，两次输出互相一致仍可能一起错。换一个模型可以提供额外意见，但不自动形成真值；可靠的来源证据和独立评审仍是判断依据。

## 7. 核心指标及后续验证方法

本次新增质量指标均为“尚未测量”，不填造数值。建议在同一组冻结报告上，对比固定细则与任务生成细则；若专门研究完全动态标准，可作为第三组。保持评分模型、报告输入和调用配置可比，单独统计生成细则带来的额外成本。

| 指标 | 如何测量 | 本次状态 |
| --- | --- | --- |
| 必需需求覆盖率 | 独立评审先列出用户必需需求，再统计检查表覆盖多少 | 尚未测量 |
| 无依据要求比例 | 独立评审判断生成细则中有多少超出用户要求且非完成任务必需 | 尚未测量 |
| 问题意见正确率 | 判断模型提出的问题有多少获得报告及来源证据支持 | 尚未测量 |
| 重要问题发现率 | 独立评审先标出报告中的重要问题，再统计模型发现多少 | 尚未测量；只复核模型已提出的意见无法得到该指标 |
| 同一报告重复评分波动 | 固定检查表重复评分；另行重复生成检查表以测量标准生成的波动 | 尚未测量 |
| 原稿与修订稿质量变化 | 独立评审在相同标准下盲评两稿，并记录修订引入的新缺陷 | 尚未测量 |
| 调用成本与耗时 | 保存标准生成、评分和返工调用的用量与耗时 | 尚未测量 |

调整标准的数据与最终验证的数据应分开。同一道题的多个修订版本应放在同一数据分组，避免相近报告同时出现在调整集和验证集中。用于决定系统是否进步的评审，不应只照搬该系统自行生成的细则。

## 8. 论文依据与证据边界

- [G-Eval，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.153/)：给定评价任务和标准，让模型生成详细评价步骤，再评价文本。它支持“既定标准下自动展开步骤”这一设计方向，不能被描述为无约束地自动决定全部质量标准。
- [AutoCalibrate，LREC-COLING 2024](https://aclanthology.org/2024.lrec-main.237/)：利用带人工标签的示例让模型起草评分标准，再筛选、优化标准。它为“模型可以起草标准，但应结合外部判断校准”提供研究依据。

两篇论文的任务和数据与本项目长篇研究报告不同，论文结果不能直接当作本项目收益。本文的四维细则设计、版本固定和验证方法属于结合当前代码提出的工程建议。

## 9. 已测量、间接推断和尚未评估

- **已测量：** 本次没有新增模型质量测量。当前输入、维度和计分机制通过源码阅读确认；历史失败仅引用已有复核结果，没有重新标注。
- **间接推断：** 在不提供待审报告的情况下先制定细则、固定版本、要求任务依据，有望减少评分随报告内容或轮次变化的问题，实际收益仍需实验。
- **尚未评估：** 自动生成细则的可靠性、对真实缺陷发现的提升、评分稳定性、报告净质量收益、额外调用成本，以及完全动态维度与固定四维方案的优劣。

下一步建议先实现“固定四维＋每题生成细则＋同题复用”的最小实验，在固定报告上验证是否减少无依据要求并提升问题识别，再决定是否扩展到自动生成维度和权重。本次仅保存分析，没有实施该改造。
