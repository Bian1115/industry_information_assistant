## 逐类分析

### 1. 模型接口 SSE

`packages/llm/llm-deepseek/src/sse.ts` 使用 `TextDecoderStream` 与 `EventSourceParserStream`，将协议拆帧交给专门的解析器。事件与心跳注释都会通知 activity 回调；函数校验 JSON、事件类型一致性，并将提供方 error 事件转为错误。

值得学习的是解码、拆帧、事件校验与业务翻译的职责分离。该文件本身不实现浏览器重连、事件落盘、补发或 Agent 恢复。注释明确说明未终止的尾部不能被当成完整事件，完成判断由 translator 负责。

### 2. 浏览器连接与恢复

`packages/client/connection/README.zh.md` 明确：普通 Remote 调用使用 HTTP POST，流通过 `/api/remote.mux` WebSocket 承载。连接恢复采用 generation 概念，只有 ready 后才发布可用连接；旧连接失效后重建，迟到 ready 不能重新激活已取消的连接。文档给出了带抖动的退避重试及握手超时。

这些设计可作为重连状态机的参考，但不能由此推导它实现了 SSE `Last-Event-ID` 补发，也不能由连接恢复推导后端执行已经恢复。此次未追完 Gateway 与 Session 同步全链路，不对事件零丢失作结论。

### 3. 检查点策略

`packages/session/session-checkpoint-policy/src/index.ts` 的 `apply` 安装三个边界：

1. 在有对应会话的模型流构造前，先 `await ctx.sessions.flush(session)`。
2. 顶层 Agent 工具执行前，先刷新调用记录；刷新期间若取消，返回执行前中止结果，不进入工具正文。嵌套工具复用外层调用边界。
3. `agent/pre-step` 时先刷新前一步提交的响应与工具结果，再进入后续逻辑。

其价值在于把“什么时候必须持久化”与“存储后端怎么写”分开。flush 拒绝会阻止后续模型或工具执行，而不是带着未持久化状态继续产生副作用。相关保证依赖持久化后端与正确的组合配置，不能仅加载策略插件就推导所有对象均已持久化。

### 4. 恢复语义与边界

持久化文档说明，恢复通过事件日志重建历史，并补齐中断轮次的结束记录。没有持久调用记录的请求与“已有调用但没有结果”的状态被区分；后者使用 `TOOL_OUTCOME_UNKNOWN`。这保留了不确定性，避免框架自动重复外部操作。

这不是任意程序指令位置的恢复，也不是模型生成到一半的 token 级续传。文档明确：活跃模型 attempt 中的瞬态帧可能在崩溃后丢失；中断轮次先被关闭，不直接在原轮次内部恢复。检查点也不承诺外部副作用恰好执行一次，仍需工具侧幂等键或外部状态核验。

### 5. 故障测试阅读价值

`packages/session/session-checkpoint-policy/tests/crash-recovery.e2e.ts` 包含两个测试场景：模型派发后强杀进程，验证完整请求已记录；工具产生副作用后强杀进程，验证调用存在且缺失结果被修复为未知。测试使用子进程、故障标记与 `SIGKILL`，Windows 下跳过。

这些是已阅读的上游测试定义，未在本机执行，不能报告为通过。它们适合学习如何将崩溃窗口变为可重复检查的断言。

## 失败样例与未保证场景

以下为源码或文档描述的故障语义，不是本次实测失败：

| 场景 | 阅读得到的处理方式 | 不可推导的保证 |
|---|---|---|
| 模型接口返回非法 JSON 或事件类型不一致 | SSE 解析器抛出 `MALFORMED_RESPONSE` | 不代表所有网络异常均能自动恢复 |
| 工具执行前 flush 失败 | 不进入工具正文 | 不代表磁盘或存储永久故障能被修复 |
| 外部写操作完成，但结果尚未持久化就崩溃 | 恢复为未知结果，不由恢复机制自动重试 | 不保证外部操作恰好一次 |
| 模型响应尚未完成就崩溃 | 瞬态输出可能丢失 | 不保证逐 token 恢复 |
| 浏览器连接断开 | 重建连接与 generation | 本次未证明历史事件零丢失或 SSE 游标补发 |

## 局限性

本次是学习路径评估，不是性能或可靠性基准。未完整审计会话核心、JSONL 后端、Gateway、模型 translator，未执行上游测试或比较其他框架的恢复成功率。线上 master 会变化，阅读应以固定提交为准。外部文档中的历史 SSE 表述不能直接套用到当前 WebSocket 链路。

## 下一步建议与阅读入口

建议按“检查点策略 → 崩溃测试 → 持久化协议与实际后端 → SSE 解析与 translator → 前端连接状态机”的顺序阅读。应用到本项目时先明确三个问题：哪些状态必须先落盘才能执行工具；结果未知时如何核验；前端重连需要状态快照还是事件补发。无需为了学习引入整个插件体系或旧接口兼容层。
