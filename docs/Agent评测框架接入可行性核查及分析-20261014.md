## 框架选择与官方依据

优先Langfuse：官方实验SDK支持本地或平台数据集、自定义task与评分器，以及实验比较和CI/CD接入，适合扩展已有导出代码。[官方实验文档](https://langfuse.com/docs/evaluation/experiments/experiments-via-sdk)

DeepEval可作为后续选项：其Agent评测支持端到端与组件评分、轨迹埋点和pytest/CI流程；当前建议先统一已有评测，再判断是否需要第二套工具。[官方Agent评测文档](https://deepeval.com/docs/getting-started-agents)

LangSmith也支持LangGraph评测，可在有平台偏好时进一步验证适配；本次没有做平台效果或成本对照。[官方图评测文档](https://docs.langchain.com/langsmith/evaluate-graph)

## 失败样例与局限性

本次未执行任务，未产生运行失败样例。以下是接入验收应覆盖的场景，属于待测设计：有trace但没有评分；评分未关联正确任务；失败任务从成功率分母中消失；裁判无法判断时被记成正确；报告正文与评分输入版本不一致。

源码核查没有证明运行时可用，也没有验证所有节点的轨迹覆盖。报告事实真实性、来源支持性和任务完成度应分别评分；Agent内部Critic输出与独立评测结论应分别记录。官方现行接口仍需与项目固定SDK和服务版本做兼容验证。

## 下一步建议

1. 固定项目评测集与配置快照，先用少量代表性任务验证链路。
2. 将真实研究入口适配为实验task，输出报告、来源、状态与运行标识。
3. 复用独立评分，加入任务完成、事实/引用、工具结果、Token/耗时、失败/恢复指标，并保留裁判无法判断的状态。
4. 核对本地原始结果与平台实验记录一一对应，再使用相同数据集对比版本。
5. 每次正式评测创建新的中文结果目录和分析报告，不覆盖历史。
