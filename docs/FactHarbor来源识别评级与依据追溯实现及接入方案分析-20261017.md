## 结论

建议把 FactHarbor 的**独立背景调查、证据包、结构化评估和可复现记录**迁移为当前 Python 主链路中的来源评估服务，而不是直接采用它的分数或整套事实裁决流程。

必须作四处调整：分类与评级分服务、分字段、分判定；新增学术文献识别及状态核验；以程序规则强制证据不足为未知；把评级依据接到本项目已有的正文版本和原句定位上。

当前项目已经统一为 DeepResearch 主链路，旧医学编排只保留历史展示和导出。学术识别应作为通用来源能力加入，不能依据旧目录或历史 Paper 接口误判为现成的医学检索能力。

## 一、FactHarbor 的实际执行链路

以下路径均相对 FactHarbor 仓库；原始内容和固定提交已在源码快照中保存。

| 阶段 | 实现入口 | 实际职责 |
| --- | --- | --- |
| 请求和预算 | `apps/web/src/app/api/internal/evaluate-source/route.ts:190` | 内部密钥检查、域名请求解析、请求级配置、限流、超时与用量记录 |
| 背景检索 | `sr-eval-evidence-pack.ts:680` | 围绕来源寻找第三方信誉、监管、编辑与主体信息，组装证据包 |
| 证据质量 | `sr-eval-enrichment.ts:139`、`evidence-quality-assessment.ts:373` | 估计相关性、证明力与证据类别，允许预算不足时跳过 |

特别需要修正上一轮仅看提示词 Markdown 的理解：**主要运行评估提示词由 `sr-eval-prompts.ts:getEvaluationPrompt` 生成**；Markdown 中的证据质量模板还被 enrichment 使用。只修改 Markdown 的来源评级说明，不能保证改变实际主评估行为。[实际提示词生成器](https://github.com/robertschaub/FactHarbor/blob/4890de15a36dd86692c7279fb2652c9e5e95209d/apps/web/src/lib/source-reliability/sr-eval-prompts.ts#L148)

### 1. 来源识别不是一个已经独立完成的身份认证器

输入是域名。程序先从域名派生品牌关键词和变体，检测语言并生成检索词；搜索结果再经域名排除、品牌提及检查和 URL 去重。`resultMentionsSource:144` 只做文本匹配，不证明同名主体就是目标发布者。

最终组织名 `identifiedEntity` 与来源类型 `sourceType` 由评级模型共同生成，第二模型还会细化组织身份。代码并没有在评级之前提供一个独立、确定的“URL—机构—账号—原始出处”认证阶段。[背景包构建与主体线索](https://github.com/robertschaub/FactHarbor/blob/4890de15a36dd86692c7279fb2652c9e5e95209d/apps/web/src/lib/source-reliability/sr-eval-evidence-pack.ts#L680)

检索顺序也值得调整：事实核查站点及可靠性查询优先占据证据额度，主体身份相关查询在预算剩余时才执行。对于新学术站点或陌生机构，这可能先收集到带评价色彩的提及，却没有足够身份信息。这个风险来自阶段顺序，未在真实站点上测量。

### 2. 有证据包，但主要是搜索结果级证据

最终包项包含 `id/url/title/snippet/query/provider`。评级模型能用 E1、E2 等编号引用，返回包中保留原 URL，具备追溯入口；但默认包并没有正文版本、支持句编号和内容哈希。

原实现排除目标自身域名的结果，有助于减少自我背书，但也会丢掉用于身份核查的官网介绍和规范页面。接入时应拆成两类证据：**身份线索可以来自官方自述并由独立登记交叉确认；可靠性判断不能仅由自述成立。**

不同域名也不等于独立证据。相同集团网站、转载同一篇评级或引用同一研究的页面，需要按原始上游和组织关系去重。

### 3. 质量标签有价值，但不是强制证据准入

质量评估输出相关性、high／medium／low 证明力和证据类别。缺失的分类项会补为低证明力、未分类，并暂按相关处理；若质量步骤失败，流程可继续使用没有质量标签的原始包。

`filterByRelevance:332` 还允许已知事实核查域名的条目绕过模型的“不相关”判定。对我们的用途，评价机构身份不应替代目标关联检查：某核查网站上的无关文章不能证明当前来源可靠或不可靠。[质量评估与过滤](https://github.com/robertschaub/FactHarbor/blob/4890de15a36dd86692c7279fb2652c9e5e95209d/apps/web/src/lib/source-reliability/evidence-quality-assessment.ts#L332)

### 4. 分类与评级只有字段分离，尚未逻辑解耦

结构定义中分别有 `sourceType`、`factualRating`、`score` 和 `bias`，这是可取之处。但来源枚举含政府、媒体、平台等组织／发布属性，也混入已知虚假信息、宣传等评价性标签；没有独立学术类别。

同时存在两层耦合：

1. `source-reliability-config.ts:44` 定义部分来源类型的分数上限，`applyPostProcessing:127` 强制执行。
2. 实际 TS 提示词 `sr-eval-prompts.ts:194` 允许在默认规则应返回证据不足时，因类型清楚而按该类型的特征给分；政府机构也被列为例子。

所以，尽管另有规则要求不能因政府身份直接判可靠，**缺证据时仍可按类型给分的例外，与本项目目标直接冲突**。迁移时必须同时删除提示词例外、类型分数表和相关后处理，不能只拆 JSON 字段。[类型约束](https://github.com/robertschaub/FactHarbor/blob/4890de15a36dd86692c7279fb2652c9e5e95209d/apps/web/src/lib/source-reliability-config.ts#L44)

### 5. 依据追溯校验主要是“编号存在”，不是“内容支持”

`evidenceCited` 可包含论断、依据文字、证据 ID、URL 和时间。`countUniqueEvidenceIds` 检查引用编号是否属于包；`computeFoundednessScore` 汇总编号、URL、时间和独立评估数量等信号。

这些检查不能证明被引页面真的支持评级理由。更关键的是，后处理发现高分依据薄弱、引用数量不足时，只追加 caveat，没有把分数强制改成空值。`evidenceCited` 在结构中也是可选字段。因此不能把“有评估结果”解释为已经通过依据核验。[运行后处理](https://github.com/robertschaub/FactHarbor/blob/4890de15a36dd86692c7279fb2652c9e5e95209d/apps/web/src/lib/source-reliability/sr-eval-engine.ts#L110)

### 6. 未知处理的可用设计和缺口

值得保留：类型支持 unknown；评级支持 insufficient_data；评分与 SQLite 缓存均允许空值。`DEFAULT_UNKNOWN_SOURCE_SCORE` 也是空值，并未统一强制未知为 0.5。

接入时必须补强以下行为：

- 空证据的未知要求主要写在提示词；服务器没有在每条返回路径统一强制“无合格证据就不评分”。
- 双模型结束后的低置信度检查只记录日志，仍可继续返回分数；不能当成强拒绝机制。
- 第二模型使用同一证据包，不是新增独立调查。单模型成功也会标记 consensusAchieved，不能解释为多个评估者已达成一致。
- `buildResponsePayload:180` 未包含 identifiedEntity，部分单模型／提前返回路径不会像多模型尾部一样补入身份。适配器不能假设成功响应必有主体。
- 缓存查找和同步取值会跳过子域的空分数、寻找父域分数；开启根域兜底时，子域未知可能变成继承的已评级状态。论文页、机构新闻、个人主页和用户托管区不应因此共享评级。
- 预取消费视图主要保留分数、置信度和共识标记。若直接只传这三项，会丢掉评级依据和具体作用范围。

此外，名为 calibration 的后续模块会调整论断的 truth／confidence；这不是来源分数已完成统计校准的证据。首期不建议接入这种分数传播。

## 三、建议的数据与服务边界

### 1. 三类对象分别保存

| 对象 | 回答的问题 | 不应承担的判断 |
| --- | --- | --- |
| PublisherIdentity | 谁发布、该 URL／账号是否归该主体 | 不能因身份已确认就判内容可靠 |
| DocumentClassification／AcademicRecord | 这是什么文档，是否匹配真实文献，属于哪一版本 | 不能因有 DOI／学术形式就给高信誉 |
| SourceReliabilityAssessment | 在什么领域、时期、对象范围内，独立证据支持何种可靠性判断 | 不能替代该文章的事实核查或研究质量评价 |

分类至少拆 `publisher_type` 和 `document_type`。前者可有政府、媒体、学术出版者、学术机构、学术仓储、企业、个人、平台和未知；后者可有论文、预印本、研究报告、机构新闻、政策／公告、新闻报道、评论、转载和未知。界面上的“官方／媒体／学术”是清晰的展示分组，不必硬塞成彼此互斥的唯一事实。

“已确认某大学发布的活动新闻”可以同时是学术机构发布、机构新闻文档；不能自动显示成学术研究。企业官网转载论文同样需要保留当前承载页与原始研究的关系。

### 2. 来源评估记录独立、可版本化

建议新增 `SourceAssessmentService`，复用现有 LLMClient、WebSearchService、WebReaderService、ToolRuntime 和运行预算。接口接收 `source/document/context`，输出身份、分类、学术状态、可靠性、证据引用和处理状态。

在图状态保存 `source_assessments` 和 `source_assessment_bindings`：每条评估有独立 ID、策略版本、证据集哈希与评估时间；绑定表关联 `source_id/document_id → assessment_id`。不要给每条 fact 复制一个来源分数。

这是为了适配现有“正文不可变＋存储依赖哈希”的机制。不能直接无限扩展旧文档的补写白名单，再让已发布快照无提示地引用更新后的评级。旧报告绑定旧评估，新评估生成新 ID；缓存只能复用同一主体、范围、策略和有效证据版本。

首期可把评估结构作为图检查点业务状态持久化；要跨运行共享时，再增加独立评估存储／缓存。背景正文继续使用现有证据文档能力，但必须有独立用途标记或集合、显式文档范围与依赖引用，避免进入写作的业务证据池。接入时扩展 externalize／hydrate／storage manifest 对这类引用的处理，保留用户、会话、topic 和清理生命周期隔离。

### 3. 评级器没有类型到分数的通道

来源分类可以决定调查问题，例如查学术出版者的出版记录、查政府机构的职责和公开纠错；但分类标签不能作为加减分条件。

评级器输入应是已确定的评级对象与**经过准入的事实证据**，不接受 Scout 的自由分数。可靠性先只输出 `reliable / questionable / unknown`；有明确负面记录时归入存疑并展示具体事实。数值 score 可先全部保持空值，避免人为给类别再配一张分数表。

来源评级、文章语义支持度、研究方法质量三者分别记录。论文被撤稿首先是该文献完整性事实，不能自动推断整个出版者不可靠；出版者信誉良好，也不能抹掉单篇论文的撤稿或证据缺陷。

## 四、学术来源识别的实现设计

### 1. 先发现线索，再查登记记录，最后匹配当前页面

1. 阅读时提取 DOI、PMID、PMCID、题名、作者、刊物、年份、论文版本和正文中相关链接。HTML citation 元数据、JSON-LD 和 PDF 首页都只是候选线索。
2. 按标识查询适用的登记／索引接口，核对返回标识、题名、作者、文献类型与当前文档是否一致。不能只确认 DOI 能打开。
3. 保存 API 原始响应、获取时间、响应哈希和匹配结论；标识冲突时标为待核实，不采纳“已验证学术来源”标签。
4. 分别记录文献类型、版本／发表状态、同行评审状态和撤稿／更正状态。没有查到信息应记录未核查或未知，不能补成正常。

本次取得的 [Crossref 类型接口](https://api.crossref.org/types) 同时包含 journal-article、posted-content、dataset、report 等多种类型，说明 DOI 本身不足以证明论文类型。可参照 [Crossref REST 文档](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)设计登记元数据适配器。Crossref 未匹配也不自动等于标识虚假，可能属于其他登记体系。

医学相关可使用 NCBI PublicationType／标识／更正关系，以及 Europe PMC 的文献元数据。此次通过 [PubMed 官方 DTD](https://dtd.nlm.nih.gov/ncbi/pubmed/out/pubmed_250101.dtd)核验了相应结构，通过 [Europe PMC 字段接口](https://www.ebi.ac.uk/europepmc/webservices/rest/fields?format=json)取得检索字段。未调用具体论文查询，实际字段映射及缺失行为仍需实现时验证。

### 2. 明确几种不能互相替代的状态

| 输入或结果 | 可以确认 | 不能因此确认 |
| --- | --- | --- |
| edu 域名／研究机构官网 | 在额外身份核验后可确认机构属性 | 当前文档是论文、内容可靠 |
| 页面声明 ScholarlyArticle／citation 元数据 | 页面自述有学术形式 | 真实文献身份、同行评审 |
| DOI 与元数据匹配 | 某登记对象与当前内容相匹配 | 同行评审、研究质量、事实正确率 |
| 预印本记录匹配 | 当前文献版本是预印本 | 已通过同行评审；也不能直接判不可靠 |
| PubMed／Europe PMC 记录匹配 | 对应索引记录及返回的文献属性 | 自动达到高质量研究标准 |
| 未取得撤稿信息 | 本次没有完成或没有获得相关核查信息 | 从未撤稿、没有问题 |

历史 `frontend/src/api/medical.ts` 已有 DOI、publication_types、is_preprint、retraction_status 等界面字段，可借鉴命名；其后台现为历史只读接口，不能当作可直接调用的新文献检索服务。

## 五、证据不足必须由程序强制成为未知

### 1. 硬性结果约束

无论模型输出多高分，统一后置校验：

```text
目标身份或评级范围存在未解决冲突 → rating=unknown
没有符合政策的独立可靠性证据 → rating=unknown
理由中的依据未通过实际引用校验 → rating=unknown
证据过期、查询受限或本次评估不可完成 → rating=unknown
rating=unknown → score=null，必须带 reason_codes
```

不要机械照搬“至少三条搜索结果”或“模型自报置信度超过 0.5”。三个转载页面仍可能只有一个上游；一次官方登记也只证明身份。证据政策应描述需要哪些事实及独立性，并区分可靠性和身份所需材料。

有合格独立证据记录真实争议时，可以评为存疑；没有证据可判断时是未知。不能把未知当作中等质量或低质量。

### 2. 业务状态和执行状态分别返回

| 场景 | 类型／身份 | 可靠性 | 执行状态／原因 |
| --- | --- | --- | --- |
| 识别为真实政府官网，没有独立信誉证据 | 已确认官方 | 未知 | completed / insufficient_independent_evidence |
| 文献登记匹配，同行评审未确认 | 学术文献已确认，评审状态未知 | 来源信誉未知 | completed / insufficient_independent_evidence |
| 背景查询失败／预算不足 | 保留此前已确认的分类 | 未知 | failed 或 skipped_budget；不伪装为完整评估 |
| 新网站缺身份材料 | 身份／分类未知 | 未知 | completed / identity_unresolved |
| 实际查到相互矛盾的可靠性证据 | 保留分类 | 存疑，或在不足以判断时未知 | 展示矛盾事实和支持关系 |
| 子域缺证据但主域有高分 | 只保留已验证的主体关系 | 当前范围仍未知 | scope_not_covered；不得自动继承分数 |

未知记录可以有短期重查策略，但不能为了命中缓存而把空值变成父域分数。评级范围至少包含主体／文档、主题及有效时期。

### 3. 老数据迁移

旧 `credibility_score` 保留为历史机制输出，标记 `legacy_unverified`，不升级为新体系的已评级结果。新的评级视图默认 unknown；只有新证据支持并完成校验才产生新评估。

`Fact.credibility_score`、数据点 confidence 和前端数字合同需逐一梳理。过渡期允许空值并标明用途，不能用 0.5 保持接口“看起来兼容”。未执行核验的旧结果与新结果应能区分。

## 六、评级依据如何接到现有证据追溯

建议每个用于身份、分类或评级的断言保存以下信息：

- 断言内容、所属维度及所评对象。
- 证据 URL、最终 URL、获取时间、来源发布主体和独立上游分组。
- `document_id`、`content_sha256`、`sentence_ids` 或适用于 API 记录的 JSON Pointer。
- 已保存原文片段与引用关系；语义支持性状态单独保存。
- 评估策略版本、输入证据集哈希、模型输出与程序校验结论。

网页引用复用 `web_document.resolve_sentences` 和 `quote_matches_sentences`。这能证明片段来自指定版本，仍不能独自证明片段支持评级，应另检验主体匹配、时间范围、否定／条件和断言支持关系。

API 元数据保存原始 JSON 响应，并通过 JSON Pointer 定位字段，不能把 API 响应硬装成 HTML 句子编号。两类定位共享同一评估引用合同，但使用不同 locator。

调查者 A 对目标来源 B 的评价，是“B 受到了怎样的评价”的证据，不直接证明 B 发布的每个结论。多页面重复引用 A 时按一个上游计；若评价只针对某一时期或主题，不扩大到全域。

背景证据应使用独立目的标记／集合。用户限定来源域名时，背景调查也不能自行越界；若授权范围内不足以评级，返回 unknown 并说明 scope_restricted。不得将用于评级的外部介绍页面自动添加为研究正文引用。

## 七、推荐接入顺序和改动清单

### 第一阶段：完整表达分类与未知，不改变结论计算

1. 定义独立的身份、文档分类、学术状态、可靠性与处理状态合同，增加评估 ID 和绑定关系。
2. 移除 Scout 所有主提取／补搜提示中的类型分数表与自由评分；补充提示的类型枚举也同步统一。
3. 在读取后生成分类与初始 unknown 结果；只在合格背景证据完成后产生已评级结果。
4. 替换旧 news／0.5 默认值；将 source_tier 的阅读优先级与可靠性明确分开。
5. 打通事件、检查点、终态交付和界面恢复；界面分别显示来源类别与“可靠性未知／证据不足”。

### 第二阶段：学术核验与来源背景调查

1. 增加学术元数据适配器，扩展 `WebReadResult` 或独立元数据采集结果，避免 HTML 清洗后丢掉标识线索。
2. 在 `DeepScout._enrich_results_with_full_text`／`_store_collected_sources` 后，由独立服务按来源批量调查；同一主体去重，限制查询与读取额度。
3. 复用 ToolRuntime 记录来源调查的搜索、读取、API 和模型用量；阶段预算不足可跳过调查并保持未知。
4. 改造会话存储、外置／恢复和 manifest，单独保留背景证据及评估依赖，不覆盖正文版本。

### 第三阶段：验证后再影响排序或写作策略

先用影子模式记录分类、未知、依据和错误；通过验收后再考虑来源选择与写作限定。未知不自动排除：正文可读、片段支持、相关性良好的未知来源仍可作为待核实材料，但不能被写成权威结论。

不要把源站信誉直接乘入事实真值或数据计算 confidence；也不直接采用 FactHarbor 对论断百分比的调整公式。对无法核实的关键结论，使用显式限定与补查，不能用数值混合掩盖缺证据。

| 模块／文件 | 建议改动 |
| --- | --- |
| 建议新增 `source_assessment_service.py` 等 Python 模块 | 身份核验、分类、学术元数据、背景证据和评级政策分层 |
| `web_reader_service.py` | 保留实际获取到的学术元数据线索与最终 URL；自述和登记核验结果分开 |

## 八、建议验收样例与指标

以下是设计样例，**本次全部未执行，不构成实测失败集**。

| 样例 | 预期结果 |
| --- | --- |
| 官网介绍可核实，缺独立可靠性材料 | 官方分类成立，评级未知 |
| 固定目标和证据，仅改变分类标签 | 可靠性结果不因标签变化而改变 |
| 大学官网活动报道 | 学术机构＋机构新闻，不是论文 |
| 期刊论文标识与元数据匹配 | 学术文献身份成立，可靠性与研究质量另判 |
| 预印本标识匹配 | 预印本成立，不自动确认同行评审或判低可靠 |
| 正文 DOI 对应另一篇题名／作者 | 标识冲突；学术身份待核实，不给可靠评级 |
| 论文转载在媒体或企业网站 | 当前承载主体与原始论文分开 |
| 真实撤稿关系 | 当前文献完整性告警，不自动惩罚全站 |
| 没查撤稿／服务失败 | 未核查，不显示未撤稿 |
| 模型在空证据时输出高分 | 程序覆盖为 unknown，score=null |
| 引用不存在的 E9／原句编号 | 拒绝该依据；无法满足评级政策则未知 |
| 引用存在但内容不支持理由 | 不通过语义支持校验，不作为评级依据 |
| 三个网页转载同一评级 | 独立上游数为一，不当三份独立证据 |
| 子域未知、父域高评级 | 不自动继承父域分数 |
| 后补评级并恢复检查点 | 返回同一评估版本、原因与依据，不变为 50% |
| 查询超时／受来源范围限制 | 未知与具体处理原因明确，任务其他可用证据不受伪评分污染 |

应测量分类精确率／召回率、官方身份误报率、学术记录匹配率、未知场景拒绝评分率、错误非未知率、引用存在与片段匹配率、理由支持率、独立证据去重、缓存范围串用率及恢复一致性。分类“覆盖更多”不能以未知场景胡乱评级为代价；以后若引入数值概率，另做校准评测。
