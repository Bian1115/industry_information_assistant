# 摘要读取处理后上下文与旧来源回查改造验证

评估日期：2026-10-01。评估对象：整体历史摘要实际输入、旧提示词正文引用替换及来源可追溯性。

## 问题与结论

改造前，主研究请求从 `views` 组装历史，工具原文外置、旧提示词正文引用替换都只改变这份视图；整体摘要却把原始 `candidates` 传给模型，因此重新读到了已从研究请求中移除的正文。现已让摘要读取同一轮处理后的历史内容。

“来源已被摘要覆盖，正文副本仍在”指引用匹配未成功。以题35为例：工具结果第16条已由首轮摘要覆盖，覆盖游标为16；后续旧提示词第17条还包含这份网页正文。旧程序只检索游标之后的工具结果，找不到第16条，因而保留第17条中的正文。并非成功替换后又恢复了原文。工具记录外置与提示词副本引用替换操作的是不同历史记录，不能仅靠其中一项消除两份正文。

## 代码改造与配置口径

- `backend/app/service/agent_context.py`：整体摘要传入处理后的记录；摘要格式及引文检查基于实际提供的内容，覆盖游标和原始增量哈希仍以原始历史为准。
- `backend/app/service/summary_history_view.py`：发生变化的内容保存为 `summary_view_source` 不可变快照，附原始来源ID、哈希、序号及类型。未变化的记录复用原快照。派生快照不参加普通历史回放。
- `backend/app/service/agent_history.py`、`input_history_view.py`：只在有可匹配资料栏目的旧输入时，回查同run、agent、subtask及配置上下文中已覆盖的 `tool_output`；仅用于本地精确匹配，不将整个旧工具历史重新加入模型请求。采用引用前仍逐条执行受控回读与哈希校验。
- `summary_citations.py`、`verification_checks.py`：派生快照保留原始来源类型；旧引用回查按派生快照的原始序号校验历史范围。Claimify仍限定于实际摘要输入的片段，不能以移除的正文作为本次输入证据。

`summary_input_prepared` 及已保存摘要元数据的 `summary_input` 记录处理前后token数、节省量、输入哈希及原始/派生来源映射。完整原文继续保留并可回读。Claimify开关、300秒独立超时、正文先提交与独立计时维持既有配置。
