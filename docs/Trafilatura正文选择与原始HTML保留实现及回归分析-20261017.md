# Trafilatura正文选择与原始HTML保留实现及回归分析

日期：2026-10-17，Asia/Singapore。对象：当前网页读取服务的正文选择、静态 HTML／浏览器 DOM 留存及表格兼容。类型：代码改造与离线机制回归；没有执行真实网站成功率、公开基准 F1 或速度对比。

## 实现结果

1. [网页读取服务](../backend/app/service/web_reader_service.py)直接把未经 BeautifulSoup 删除节点或重写的 HTML 交给 Trafilatura，开启表格提取，使用 XML 结构化结果确定正文范围。移除了 `article/main/table` 命中就提前采用 BeautifulSoup 的分支，以及提取为空时直接接受整页 body 的回退。缺少提取依赖或提取失败时保留明确失败，不再以整页文字冒充正文。
2. BeautifulSoup 仍用于读取标题、日期及渲染**已被 Trafilatura 选中的结构**，不负责选择正文区域。[结构适配器](../backend/app/service/web_document_structure.py)把选中节点输出为现有证据链路使用的 Markdown。
3. 表格仅在全部非空单元格文字完整、顺序一致且唯一匹配原表时，使用原表的合并单元格与表头信息进行渲染。匹配保留单元格边界；匹配不可靠时只渲染提取器保留的表格内容，不补回被过滤的行或其他表格。这样保留旧证据分块所需的表题、多级表头、行列映射及注释格式，同时保持正文选择权属于 Trafilatura。
4. 已取得的静态响应体在解码前保存原始字节；浏览器渲染所得 DOM 单独按 UTF-8 保存。两者不混称为同一份原始响应。
5. 本地 Crawl4AI 和 sidecar 均从 DOM 进入同一提取逻辑。[sidecar](../backend/crawl4ai_sidecar.py)新增 `html` 返回字段，原 Markdown 字段保留兼容，但主读取器不再直接采用它作为正文。
6. 缓存键加入提取策略版本 `trafilatura-xml-body-v1`，旧正文缓存不会掩盖新逻辑。Trafilatura 依赖下限调整为 `>=2.2.0,<3.0.0`，原因见下文兼容测试。

## 原始 HTML 在哪里

- 默认目录为 `WEB_READER_CACHE_DIR/原始HTML/`；未配置缓存目录时，位于系统临时目录下的 `industry-web-reader-cache/原始HTML/`。
- 文件名区分“响应原始HTML”和“浏览器DOM”，包含版本化 URL 键及内容 SHA-256；不同内容分别保留，相同内容刷新保存时间。
- 结果的 `body_quality.html_snapshots` 提供 `kind`、`source_url`、`content_type`、`sha256`、`bytes` 和绝对 `path`。引用随缓存、正文质量检查及既有 Scout 的质量元信息传递，不把整页 HTML 塞入模型上下文。
- 提取失败、质量拒绝和浏览器回退失败时，已取得的快照仍可追溯。磁盘写入失败会记录 `error` 和日志，正文读取继续。
- 快照按 `WEB_READER_CACHE_TTL_SECONDS` 清理，默认 7 天；失败页面快照也采用该期限。清理仅处理指定目录中符合命名规则的文件，跳过不相关文件和符号链接。长期归档需另行保存，不应把缓存引用视为永久附件。

HTTP 错误在响应体尚未读出前即抛出的场景，本轮没有新增该错误响应体的采集；未取得 DOM 或超出字节上限的 DOM 也不会被存成成功快照。

## 已测量、间接推断与尚未评估

**已测量**：84 项主回归、失败阶段记录、表格构造样例输出、原始字节与哈希一致性、缓存/异常路径中的引用保存、Python 语法及差异格式检查。

**间接推断**：统一正文选择能消除旧的 `article/main/table` 快捷分支；保留原始响应和 DOM 能支持后续定位提取遗漏。这些是代码与机制层面的结论，不代表真实网页质量已提高。

**尚未评估**：公开数据集正文 F1、中文和不同页面类型总体效果、真实在线可用率、真实浏览器/sidecar 跨进程联调、PDF/OCR 端到端效果、P50/P95、内存和磁盘成本。没有比较新旧链路速度；也未验证其他 Trafilatura 2.x 版本。

## 使用与下一步

代码完成后，需要按更新后的依赖要求启动后端，并重启使用本项目脚本的 Crawl4AI sidecar，使其返回 HTML。只有 Markdown 而无 DOM 的旧 sidecar 响应不再被当作成功正文。当前任务没有重启任何运行中服务。

后续可在固定 HTML 的公开数据集和业务 URL 在线轨道分别复测。原始 HTML 已可保留，但快照是诊断缓存，若用于长期对照，应复制到对应评估运行目录并冻结指纹。
