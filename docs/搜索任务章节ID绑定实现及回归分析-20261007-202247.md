# 搜索任务章节ID绑定实现及回归分析

评估日期：2026-10-07，Asia/Singapore。最终相关回归完成时间：20:40:04。

评估对象：会话层生成的定向补证搜索任务，与所选已交付报告真实大纲章节之间的关联。此次只修改该链路并执行离线回归，没有续跑第20题实验，没有调用真实模型、搜索接口或写入业务数据库。

## 问题及修改后的链路

此前 `search_tasks[].target_section` 可以填写章节标题或ID，会话层未校验它是否属于所选报告。历史中的“协议与定位”等旧标题因此可能被带入新一轮任务，直到执行层匹配当前大纲时才失败。问题出在搜索任务的章节关联，并不意味着当前 `research.outline` 生成错误。

修改后，链路为：

1. 报告交付时，将 `research.outline` 中真实的 `{id, title}` 目录保存到助手消息的 `references_data.outline_sections`，同时记录交付检查点ID。章节正文中的Markdown标题不再作为会话模型的章节ID来源。
2. 索引候选报告时，先按用户、当前会话、有效期、已完成交付等条件筛选，再读取目录。旧报告没有该元数据时，只读其检查点：必须属于同一会话、状态已完成且正文哈希与授权候选一致。不初始化检查点表、不保存检查点、不运行研究图。读不到目录时不编造ID。
3. 会话模型同时看到候选报告的真实章节ID与标题。字段仍叫 `target_section`，但定向补证只允许填写所选报告目录中的单个章节ID，不能填写旧标题或其他报告的章节ID。明确对整篇报告补证时可保留空字符串。候选目录仍受3500 token预算约束，优先容纳最近报告，再容纳早期及其他报告，呈现顺序仍按时间排列。
4. 会话任务成为 `ready` 前，程序检查每个非空ID是否属于所选报告。若不合法，最多追加一次局部模型修正，只能改章节ID，不能改所选报告、搜索关键词、补证目标或研究要求。修正使用现有会话模型，并计入共享请求和token预算。原始响应、修正响应及最终有效响应均保留在任务溯源中。
5. 修正失败或目录不可用时，任务进入澄清状态，不将依赖旧报告的补证请求降级为新话题研究。预算耗尽按原预算异常上抛，不绕过限制。
6. 执行层继承实际父报告后，再对真实 `research.outline` 核对ID。合法任务写入 `pending_research_tasks` 后由补证流程处理。空字符串在这里展开为实际大纲全部章节ID；标题匹配已删除。

改变研究范围或新增实质章节走 `replan`，需要Architect生成新的大纲与检索计划，此时不把尚未创建的新章节强行绑定到旧报告目录。

## 失败样例与复评说明

业务故障样例：模型选择正确的当前报告，搜索关键词要求核实会话状态和无状态条件，却将 `target_section` 填为历史标题“协议与定位”。新增测试使用包含 `sec_2 / 一次请求怎样完成` 等实际目录的夹具复现这一类型：首次校验拒绝标题，第二次Mock响应只把关联改为 `sec_2`，任务随后成为 `ready`，原关键词与补证目标保持。修正仍填写旧标题时，在第二次响应后进入澄清，不第三次重试。

2026-10-07 20:35扩展回归出现一次测试失败：140项中135项通过、1项失败、4项跳过。失败为“候选预算应只留下最近报告”的断言，实际仍可容纳两份报告。原因是测试的 `CharCounter` 按约四个字符估算一个token，旧样本仅填充3000字符，没有超过3500 token的合并预算；章节ID实现并未因此失败。

20:40复评将该预算样本改为按同一计数器构造边界，并先断言“旧候选单独可容纳、与最近候选合并后超预算”，再验证最近候选被保留。七模块复评全部通过，旧失败结果保留，未覆盖历史运行数据。

## 已测量、间接推断与尚未评估

**已测量：** 上述离线机制和相关回归。目录含真实ID；错误标题和不属于所选报告的ID被拒绝；修正只能改变关联字段且最多一次；共享预算不被绕过；执行层再次按实际父大纲校验。授权筛选在SQLite夹具中通过，旧检查点兼容和交付元数据通过Mock验证。

**间接推断：** 先提供当前报告目录、再强制ID归属，可以拦截此前“历史旧标题被作为关联目标”的故障类型。原理和离线断言支持该推断，但不是原32轮实验真实续跑结果。

**尚未评估：** 真实模型是否选择语义最合适的合法章节ID；旧报告检查点的真实PostgreSQL读取；新目录的真实事务落库；第12轮补证实际完成情况及后续30+轮稳定性。合法ID保证存在性与报告归属，不能单独保证语义选择正确。若原目录或检查点不可用，仍会澄清；目录较大时还受候选索引预算限制。
