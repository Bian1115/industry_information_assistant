# DeepResearchBench随机题32轮单会话实验结果及分析

评估对象：当前项目在同一个持久化会话中连续执行30轮追问，并追加2轮验证延长。
实验准备日期：2026-10-05；实际首轮：2026-10-05 23:38:58 至2026-10-06 00:00:01（UTC+8）；终态分析及草稿补充核对日期：2026-10-06。下述终态分析补充同一次运行，未改配置重跑。

**结论：本次未能验证30+轮。32轮数据已准备，但真实运行在第1轮因Writer“历史回读次数超限”停止，尝试1轮、交付0轮，第2—32轮未执行。另已测得10次内部正文质量检查触发本地上下文保护。40次实际发给供应商的模型请求全部成功，无供应商上下文窗口拒绝。**

## 第1轮及失败样例分析

### 辅助正文检查先触发本地上下文保护

2026-10-05 23:40:27，DeepScout的“判断是否读到了目标文档正文”调用估算75155 tokens，高于本地65536预算。后续同类调用最大805006 tokens。这些调用带入本次研究累计材料，未采取有效缩减；异常被正文读取路径捕获，转为质量检查失败，主研究继续。

它们没有生成供应商请求，因此不是供应商窗口拒绝。但严格的“所有内部调用都不超限”要求已经在第1轮失败。正文质量检查失败还可能影响材料可用性，这次没有做反事实对照来量化其质量影响。

### 最终停止来自Writer回读额度

失败调用 `1d8586c1-2f49-4e57-83bf-5f4b33713b91` 的估算输入由46463缩减到27506 tokens；这一步没有触发上下文硬预算。模型先后请求：

1. 对来源 `abb3c79b-d44a-438d-b0a9-c76835576956` 回读0—4000字符。
2. 对同一来源回读4000—9862字符，覆盖剩余部分。
3. 请求另一来源 `5ee96f89-84f1-422a-8583-542a0fbd0754` 的0—8000字符。

前两次成功，第三次因默认每次Agent调用最多2次回读，被BaseAgent直接抛出`ValueError("历史回读次数超限")`，研究终止。对应三次供应商实际输入为27511、29516、32874 tokens，均成功返回。本次不是重复读取同一片段造成的死循环，也不是供应商输入窗口耗尽。

## 压缩率及其边界

Writer一次采用摘要的调用，整体输入视图由99381降到10484估算tokens，保留比例10.55%，减少89.45%。该数值同时包含材料引用、成果卸载和历史摘要三个阶段，**不是单独的语义摘要压缩率**。

进入摘要前的历史原文84478 tokens，经摘要输入准备缩减至50421 tokens，减少40.31%；摘要请求实际输入56359 tokens，生成摘要1679字符。摘要生成并提交成功，但Claimify关闭、内容状态为unverified、遗漏核对未执行，不能由缩减幅度推出信息保真或回答正确。完整阶段记录在第1轮工作历史中；会话层SummarizationMiddleware压缩率本次尚未测量。

## 测量边界和局限性

- **已测量**：题库排除和随机抽样、离线机制检查、首轮真实研究、40次SDK请求及usage、10次本地上下文拦截、回读门禁失败、内部压缩及草稿要求核对。
- **间接推断**：源码和轨迹说明入口支持构造32轮；本次终态由内部回读资源限制导致，原始46463-token视图仍有机会在预算内恢复。恢复输入是否有效须新运行验证。
- **尚未评估**：第2—32轮、30+轮整体能力、会话摘要效果、整体事实正确率、压缩保真率及修复后的表现。
- 单题小样本；实时搜索未冻结；另一开发集实验同时运行，可能共享模型速率、数据库和网页读取资源。当前40次请求没有错误，但无法据此得出独立性能基线。
- 本次通过CLI复用生产业务服务和数据库会话链路执行；未覆盖前端交互、HTTP传输或已有后端进程是否加载最新代码的验证。
- 失败草稿和内部Critic评分不等于交付答案；缺失用量不能按0计，本次40次已发送请求恰好全部返回usage；本地阻断调用不能算供应商成功或失败请求。

## 结论与下一步建议

当前项目可以构造并启动所需的单会话实验，**本次实际未达到30+轮、不超限和正确回答的验证目标**。首轮已经暴露两类研究内部问题，无法把结果解释为“会话窗口只能支持1轮”。

建议先修正文质量检查的上下文：以当前URL/正文块为输入，隔离研究主历史，并为超长正文分批检查、明确部分覆盖范围。随后修Writer回读门禁的恢复路径：保留本章必要原句；达到回读限额时，若完整原始输入仍在硬预算内，可恢复原始输入重试，或提供明确的受控失败说明，避免直接终止整轮。仅增大额度是否足够没有验证。

修复后使用同一份32轮query，在新用户/session和新运行目录重跑，保留这次失败记录。若再测试会话摘要开启条件，应另立对照，并按实际消费模型的可用输入窗口核对触发阈值；当前配置的850000-token触发点不能直接当作主模型或65536本地预算下的安全阈值。会话摘要与Agent内部材料管理需分别测量。

## 逐项失败原因补充（2026-10-06，同一次运行）

此处应用户要求细分失败原因，未启动新评测或修改业务代码。机器可读清单见[失败原因逐项清单-20261006.json](/Users/bxy/projects/industry_information_assistant/backend/eval/data/随机题32轮单会话实验-20261005-233109/失败原因逐项清单-20261006.json)。第1项是整轮停止的直接原因，第2—3项为内部故障，第4—6项为未交付草稿的问题。

1. **Writer历史回读门禁直接终止研究。** 单次Agent调用最多回读2次；两次读完同一9862字符资料后，请求另一来源触发历史回读次数超限。 压缩前46463 tokens低于65536预算，仍直接抛异常。恢复完整输入的兜底效果尚未重跑。
2. **Scout正文质量检查继承本次研究累计历史。** 当前检查正文块已限12000字符，仍回放研究主历史；10次本地超限，最早75155、最大805006估算tokens，预算65536。 首次研究内即出现，不是30轮会话历史积累；被阻断调用未发给供应商。
3. **把检查执行异常处理成正文不合格。** _check_source_body捕获一般异常后设置rejected和quality_review_failed，进一步标记fetch_status=failed及body_quality_rejected。 可能错弃合格材料；哪些页面实际上合格及其净质量影响尚未独立验证。
