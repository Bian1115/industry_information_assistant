# 候选来源子集引用修改与验证

评估日期：2026-09-29。对象：摘要分句的 `source_ids` 从必须全部引用的清单明确为候选来源池。本次仅修改该协议及相关控制流，不延续主任务的其他修复或真实研究回放。

## 行为变化

摘要给出候选 A、B，引用补齐可只返回 A 的真实引句。程序不再要求引用覆盖全部候选编号；选中的引用仍须通过来源归属、原文定位及当前配置启用的语义核验。没有任何可定位引用仍然拒绝；可定位但 NLI 拒绝的摘要仍不返回成功。

实现保留全部候选批次的证据收集，不因第一批已经出现候选编号就提前结束。旧摘要缓存没有给出任何引句时，仍回读原文；已有引句时不为未选中的旧候选强制补引用。若已有引句但语义核验失败，仍沿用现有受限语义修复/拒绝流程，并不保证自动找遍所有潜在证据后必定成功。

代码位置：`backend/app/service/summary_citations.py`。同步更新 `backend/app/prompts/摘要正文生成与合并.txt` 与 `backend/app/prompts/摘要最终引用补齐.txt`，提示版本为 `context-summary-candidate-sources-v7`。未更改 NLI 阈值、消融开关或主任务配置。

使用内存历史、确定性文本及模型/NLI 桩；正常流程测试开启语义核验，关闭额外事实遗漏检查和字段检查以隔离候选池行为。没有真实 API 调用，没有在线检索，没有评估 NLI 模型本身的判断准确率。

## 逐类验证

| 场景 | 结果 |
| --- | --- |
| A、B 候选，仅 A 提供引句且模拟 NLI 通过 | 成功，最终引用仅含 A，偏移对应原文 |
| 所有候选均返回空引用 | 拒绝，摘要版本及游标不变 |
| 引句可定位，但模拟 NLI 拒绝 | 拒绝，保留核验拒绝事件 |
| 同一候选分多批，首批已有引句 | 后续批次仍处理，选出的引句一起交核验 |
| 首批空引用，后批有证据 | 可以使用后批候选 |
| 未选中的旧候选 | 不强制额外调用补齐全文引用 |
| 旧缓存无证据、原文存在引句 | 回读原文并精确定位 |
| 非候选来源或编造引句 | 继续拒绝 |

## 局限、结论与下一步

已测量：候选子集的接纳、批次处理、旧来源回读与核验拒绝控制流均通过测试。首轮错误属于测试夹具不完整，修正夹具时未放宽生产来源检查。

间接推断：该变化可避免仅因未引用全部候选而拒绝摘要；遍历全部批次可能增加调用次数，仍受既有预算限制。

尚未评估：真实模型引用质量、真实 NLI 支持性、完整摘要提交率与研究任务成功率。关闭 NLI 的消融组仍沿用其原配置，不能将该组的格式/定位通过称为语义核验通过。来源子集合法也不能证明引句支持整句结论。

本次协议修改及机制回归通过。后续真实运行应分别统计最终选中来源、原文定位结果和语义核验结果，不能把候选未选中直接计为漏引失败。
