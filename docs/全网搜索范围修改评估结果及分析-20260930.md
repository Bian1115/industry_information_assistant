# 全网搜索范围修改评估结果及分析

## 评估日期与对象

- 评估日期：2026-09-30（Asia/Singapore）。
- 评估对象：网页深度研究的默认搜索范围，以及搜索、正文读取、追问资料继承、报告来源检查和工作台展示的一致性。
- 目标：解除当前 `who.int,nih.gov` 两站限制，默认全网搜索；保留可选的网站范围配置。

## 修改与配置口径

1. `backend/.env` 和 `.env.example` 的 `RESEARCH_ALLOWED_DOMAINS` 已改为空值。未配置或留空表示全网；非空仍表示指定网站范围，子域自动包含。
2. 运行状态的 `allowed_domains=[]` 表示全网。默认搜索发送主题关键词，不自动添加 WHO/NIH 的 `site:` 条件；模型自带的 `site:` 条件仍会清除，避免自动收窄默认搜索。
3. 搜索结果和报告检查允许其他网站的 HTTP/HTTPS URL。正文读取、深读与追问资料继承使用同一范围；内网、本机地址及其他读取安全检查继续执行。
4. 部署未限定网站时，请求可指定网站；部署已有范围时，请求只能收窄范围。原有指定网站检索、结果过滤与报告来源检查仍保留。
5. 工作台将空范围显示为“全网搜索”；审核提示明确空列表的含义。
6. 修改本地配置后需重启后端，新研究使用新范围。已保存的研究恢复时仍沿用检查点里的原运行范围。本次未重启正在运行的后端，也未改写历史检查点。

## 失败样例与执行异常

- 首次使用 `python -m pytest` 启动失败：项目虚拟环境没有安装 pytest（`No module named pytest`）。该尝试未运行测试，未生成预期 XML；随后改用 `unittest` 完成回归，没有安装新依赖。
- 回归测试没有真实失败样例。测试中使用的反例包括：全网模式过滤重复 URL、FTP 和无效 URL；读取器拒绝 `127.0.0.1`、`10.0.0.1` 和 `localhost`；指定网站模式拒绝域外结果与报告链接；空报告继续被门禁阻止。
- 日志中的超时、数据库写入失败等为既有测试主动注入的异常，相应测试通过，不属于本次功能失效。

## 局限性与证据边界

- **已测量**：99 项回归测试通过、4 项跳过；前端可构建；一次真实博查请求可接受旧范围之外的 10 条结果；默认全网与可选限制的机制分支通过。
- **间接推断**：初搜、换源、深搜和补搜共享入口，因此可采用同一全网逻辑；假实现覆盖支持对运行兼容性的判断。
- **尚未评估**：多问题检索召回率、来源权威性、真实网页正文可读率、完整模型研究报告质量、在线多轮运行、真实 ToolRuntime 链路、PostgreSQL 集成测试、后端重启后的在线请求和历史运行迁移。真实检索只有一个问题、一次请求，不能推断总体质量提升。

## 结论与下一步建议

默认全网搜索已完成代码与本地配置修改，真实检索确认结果不再限于两个网站；指定网站模式仍保留。重启后端后新建研究即可使用新配置；恢复旧研究不会自动扩大历史范围。下一步可按实际研究主题验证完整检索、正文读取和报告交付，单独记录来源质量与失败页面；本次不将未测量的质量指标视为已通过。
