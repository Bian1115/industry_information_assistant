# 摘要事实分句与独立模型改造验证

- 评估日期：2026-09-28；首次测试 23:25:56，修复后复评 23:26:51。
- 评估对象：历史摘要的事实分句引用、非事实正文保留，以及摘要独立使用 `qwen3-max` 的调用路由。
- 数据与配置口径：本地 unittest、内存历史存储和模型桩；无线上模型请求、无真实 NLI 推理、无开发集重跑。涵盖增量、引用分离、分块合并策略；引用测试使用确定性短文本。

## 改动内容

继续使用四栏目自然语言摘要加 `CLAIMS` JSON。事实分句进入 JSON，保留原文编号 `source_id`、连续引用 `quote`，唯一引句的位置仍由程序计算。研究发现、数字/日期、可核对的操作结果和资源路径均属于需要引用的事实。

目标、要求、计划、策略、推断、建议、待确认问题和待办保留在自然语言正文，用对应中文前缀标明，不进入事实 JSON 或 NLI。解析和旧摘要合并同步支持这一口径；契约检查仍读取包括这些内容在内的完整摘要分句，避免将“3000字”等用户要求当成需要原文证明的研究数值。

模型默认由 `get_summary_model()` 返回 `qwen3-max`，可通过 `LLM_MODEL_SUMMARY` 显式配置；生成、合并、引用补齐及相关摘要核验模型调用沿用同一次摘要流程选定的模型。显式模型覆盖通过单次请求参数传递，不修改所属 Agent 的模型；重试也保持该模型。提示词版本更新为 `context-summary-factual-citations-v5`，旧增量模式更新为 `context-summary-factual-claims-incremental-v4`。

## 逐类结果与失败样例

1. 事实与任务正文分离：新增用例验证混合摘要只为事实补齐引用，目标、3000字限制、建议和待办在增量合并后继续保留；纯任务摘要允许 `CLAIMS: []`，未标记的事实不能静默遗漏。
2. 契约检查：新增用例验证不在 JSON 中的字数要求仍传入约束检查。首轮测试直接修改冻结的 `HistoryScope` 产生错误，改为创建替换实例后通过；此错误来自测试构造。
3. 独立模型：新增用例验证底层请求使用 `qwen3-max`、下一次普通调用仍使用 Scout 的模型，并验证瞬时连接错误重试不会切换为全局备用模型。旧增量摘要路径也验证了独立选模。
4. 引用分离及回读：保留伪造引句、错误来源、缺失引用、不连续拼接、错误偏移、失败不推进游标等测试。原回读用例以“待确认”作为待引用分句，按新口径已不应触发引用；改用事实“旧结论存在限定条件”后继续验证回读行为。
5. 摘要保存：首轮发现保存元数据仍写旧提示词版本，已同步为新版本后通过。
6. 分块预算、独立历史、旧输入历史压缩：相关本地回归通过；数据库隔离和持久化集成测试未启用。

复评沿用同一测试范围，更新了两处测试构造/预期以及遗漏的提示词版本元数据；未更换评估数据集或执行线上采样。

## 局限性与结论

- **已测量**：程序路由、结构解析、事实引用流程、任务正文保留、局部失败保护和模型重试行为。
- **间接推断**：减少对纯任务性内容的引用要求，有望减少无意义的引用调用和格式失败；尚不能量化收益。
- **尚未评估**：`qwen3-max` 实际区分事实与非事实的准确率、引文质量、线上成功率、费用、延迟，以及数据库集成行为。前缀识别是协议检查，不是语义真实性保证；提示词明确禁止把事实改成建议以逃避引用。

本地机制验证通过。下一步可在固定历史快照上进行线上复跑，检查事实漏标、错误引用及实际模型用量；若要比较 Plus 与 Max，应单独控制模型变量。现有运行进程需要加载新代码后才会使用本次改动。
