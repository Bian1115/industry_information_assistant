# 上下文250k与64K输入预算调整及验证

## 结果

根据用户最新要求，将默认 context_window 设为 250000 token（250k 按十进制解释），max_input 设为 65536 token，安全余量保持 1024 token。Writer 输出上限/预留保持 6000 token。

Writer 实际可用输入预算为：

```text
min(max_input, context_window - output_tokens - safety_tokens)
= min(65536, 250000 - 6000 - 1024)
= 65536
```

## 修改范围

- backend/app/service/context_policy.py：集中定义默认值，并同步 InputBudget 与环境变量回退配置。
- backend/app/service/agent_context.py：旧输入预算入口使用相同默认值，避免两套入口不一致。
- backend/.env.example：同步窗口、输入预算和相关说明。

Writer 的两处默认输出配置原本已为 6000，无需重复修改。其余 Agent 的输出上限保持当前配置。实际 backend/.env 未修改；本地读取结果确认 Writer 使用上述新预算。显式环境覆盖或消融配置文件仍优先于默认值。

## 输出预留与安全余量

输出预留是为模型生成回复留出的 token 空间。Writer 的 6000 同时是其单次模型调用的最大输出配置，正文、结构化字段和证据内容共用它；不表示每次必定输出 6000 token，也不是预先发送 6000 个占位 token。

安全余量 1024 是本地预算计算额外扣除的缓冲，用于减少本地 tokenizer 计数与服务端消息包装/计数差异带来的超限风险。它不是模型输出，也不是额外填充内容。

由于当前 max_input 更小，Writer 的实际输入仍受 65536 限制；250000 的窗口值不是允许单次输入达到 250000。
