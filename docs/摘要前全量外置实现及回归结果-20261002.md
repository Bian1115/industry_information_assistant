# 摘要前全量外置实现及回归结果

评估日期：2026-10-02。对象：历史上下文达到压缩阈值后，将全部已完成的超长工具记录外置，将旧输入里的重复正文引用化，再判断是否需要摘要。

## 实现与配置口径

修改 `backend/app/service/agent_context.py`，沿用 `input_history_view.py` 的历史正文匹配与引用替换机制。原始记录不截断，处理后的回放视图同时用于主调用和摘要输入。当前提示词、事实提取输出、任务约束沿用现有流程。

达到处理前上下文的软压缩阈值时，摘要前外置全部已结束工具调用中超过 `tool_content_tokens` 的记录，保留 `preview_chars` 预览和来源回读引用。取消最早 N 轮限制，以及排除最后一个轮次的规则；仅有工具终态记录也能外置。在途工具输入不外置。

沿用 `artifact_offload`、`early_offload` 和 `recent_offload` 开关、既有正文匹配规则和摘要阈值。`early_tool_rounds` 字段保留用于旧配置快照兼容，不再限制摘要前外置轮数。先按已有规则引用化历史正文，再外置长工具记录；根据两者处理后的总输入量决定是否摘要。没有加入新的模型提取步骤。

## 逐类验证与原缺陷样例

- 五个已完成工具轮次及其正文副本：全部长工具记录外置，旧输入中五份正文引用化；压缩前超过摘要阈值，处理后低于阈值，摘要模型未调用。首次待分析正文与已提取结果保留，原始资料可回读。
- 最新轮次与缺少工具输入的终态记录：均可外置；原实现按最早 N 轮且排除最后一轮，会留下长原文。
- 引用化先降低输入量的样例：处理前已达到软阈值，因此仍完成全部长工具记录外置。原实现可能因引用化后低于软阈值而不执行外置。
- 压缩后仍有长任务背景：摘要继续执行，但实际输入不包含原始长工具正文及其副本，背景保留。
- 在途工具调用：保留完整输入，不提前外置。原始记录、已外置回放持久性及各功能开关的既有回归均通过。

本次没有失败用例。现有两项“只外置最早 N 轮”的断言已按新的预期更新为“全部已完成轮次”。

## 局限性与结论

已测量的是上下文处理顺序、发送内容、摘要触发条件和原始记录保留。间接推断：减少摘要中的长正文重复输入可降低摘要消耗，但不能据此给出真实节省比例。

尚未评估真实任务成功率、真实 tokenizer 下的 token 用量、费用和端到端耗时。引用替换继续要求资料栏目与已保存原文匹配；无法匹配的文本保留。历史评测冻结副本及运行结果未修改；新旧运行比较时应注明外置策略已经改变。

结论：请求的摘要前全量外置流程已实现并通过本地回归。下一步可在用户安排的真实运行中记录摘要调用次数、摘要输入 token、历史回读消耗与任务质量，确认整体收益。
