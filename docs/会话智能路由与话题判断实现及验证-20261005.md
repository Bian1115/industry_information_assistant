## 一、已实现的行为

### 会话层一次判断，程序选择执行路径

新增 `backend/app/service/session_task_service.py`，扩展 `ResearchContextService`，用一个严格类型的决策结果表达：

- 话题关系：延续、回到更早主题、新话题、无法确定。
- 是否依赖历史，与话题关系独立；只有存在历史依赖时允许补全问题。同话题完整问题及新话题保持用户原话。
- 可组合的操作：表述编辑、补证据、结构变化、新研究；每项操作与要求变更都要引用本轮用户原话。
- 目标成果、修改指令、搜索任务、要求变更、假设与未消解指代。

用户和会话权限在成果索引查询与实际成果载入时分别检查。索引保留最早4份和最近24份已交付报告，去重后按时间排序；判断器只看到有界索引，不能指定索引以外的报告。目标报告的交付正文和检查点正文使用同一种正文 SHA256 校验，防止编辑错误版本。

决策由程序重新校验并编译为三条路径，图里没有重新加入内部 LLM 追问路由节点：

| 任务 | 执行路径 | 行为 |
| --- | --- | --- |
| 纯篇幅、语气、格式编辑 | edit：Writer → Critic | 传入目标报告与章节、当前有效要求、已有证据；新建本次 run |
| 定向补证，或补证加编辑 | augment：Scout → 分析 → Writer → Critic | 传入搜索任务和目标章节；补搜结果重开相关章节并进入后续写作 |
| 结构/研究范围变化、组合结构任务、新研究 | replan：Architect → Scout → 分析 → Writer → Critic | 按完整任务规划；对明确选中的旧成果可以复用资料 |

Critic 的本次研究修订、补搜和返工额度保留。所有执行节点共用已有阶段保护、预算、取消、检查点、历史存储和交付流程。工作历史仍是 `run_id＋智能体＋子任务` 边界，没有恢复跨 run 自动回放。

### 当前要求先提交，再跳过 Architect

新增 `deep_research_v2/session_task_execution.py`，复用 `contract_updates.py` 的字段类型、原话依据与版本规则。会话输出的 `set` 在实际父契约下展开为 add/replace；remove 对已取消项幂等。原数据和父契约不就地修改。

快捷路径进入前，本轮契约已提交，Writer/Scout 不会拿到等待 Architect 才能确认的 pending 要求。改变对象、时间、地域、问题或指标/计算要求时，即使模型建议编辑，程序仍要求重新规划。旧成果缺少完整章节材料时回到规划路径并记录原因。

新话题不自动加载最近报告，不沿用旧主题字数和网站范围，并从研究输入中移除旧话题对话与长期记忆。本轮用户显式提出的要求继续保留；原始会话数据没有删除。未指定网站时，连续任务可继承所选目标报告的范围；显式传入的本轮范围保持优先。

### Writer 支持大幅压缩和后续审核修订

新增 `_edit_existing_report`，直接消费用户编辑指令，不要求先有 Critic 反馈。同步更新章节标题、正文、主张、引用和最终报告，避免只改 final_report 后续又由旧草稿拼回长文。

用户编辑不使用原 Critic 修订接口的“至少300字符且保留原章节55%”限制。明确字数上限通过已有正文计数检查；相对缩短检查新正文短于原正文，不擅自生成数值上限。非法章节、超长、未缩短或发布门禁失败时最多修复一次，仍无效则拒绝提交。压缩后的 Critic 文字修订也沿用用户编辑模式与当前篇幅要求。

事实与有效引用保留写入编辑提示；未知URL处理、来源范围发布检查和可选引用核验仍执行。没有新增逐项事实的强制语义验证，因此这里不能宣称所有真实编辑结果都已证明事实不变。

### 定向补证复用 Scout 补搜能力

会话搜索任务包含 query、目标章节和补证目标。服务端用实际大纲映射章节标题/ID，找不到唯一目标则停止，不发起搜索。空章节目标映射到已有全部章节。任务保留独立 ID 与 `origin=user_followup`，不伪装成 Critic 意见。

旧正文和可追溯来源通过成果白名单复制，旧 run 的节点重试、耗时、审核结论、搜索次数和完成状态不继承。Scout 已有正文门禁、补搜、章节重开、分析与报告回写继续使用。

### 澄清、成本和恢复

初始决策目标不明确时，HTTP 入口保存普通会话澄清答复，发送 `session_clarification` 事件，前端显示问题并清除本次研究状态；不取得研究租约，不把澄清当作研究报告完成。重复 turn 可回放同一澄清答复。实际材料准备时遇到不适用来源或不明章节也会停止执行，以 `needs_clarification` 错误口径呈现，不静默猜测。

决策失败时，明显含历史指代的输入要求澄清；可独立执行的输入保留原话走完整研究路径。会话判断的模型调用加入已有整任务预算，标记 `component=session_task`；预算耗尽不得通过降级绕过。判断请求关闭 SDK 隐式重试，调用失败保留未知用量的预留。

记录模型、候选数量、供应商输入/输出 token（缺失为null）、提示token估算、判断耗时及状态。供应商实际用量与估算区分保存，没有伪造未知成本为零。决策、目标版本和策略哈希冻结到 run；技术恢复校验并沿用，不重新查询最新成果或重新判断。

图版本为 `single-main-v4-session-task`，兼容已有普通 v1/v2/v3 主图续跑；此前被删除内部路由启用的旧检查点继续明确拒绝恢复。

## 五、首次失败和修复

首次后端运行178项，有1项失败、6项错误和5项跳过。结果没有覆盖：

- 六项新入口测试均因哈希口径不同而在目标校验处停止：旧 `parent_artifacts` 的报告元数据哈希是 JSON 编码文本的摘要，新的交付索引哈希是原正文 SHA256。改为对检查点正文直接计算同口径哈希；保留旧元数据指纹供兼容审计，版本不符仍拒绝。
- 一个旧 resolver 测试仍返回旧 `is_follow_up` 协议，严格新协议拒绝该输出。更新测试到话题/依赖/操作协议，并保留检索记忆ID过滤行为，非法记忆ID仍不能进入使用记录。

第二轮为199项、194通过、5跳过。补上前端澄清显示、共享预算、审核后的短文修订和实际成果权限查询后，第三轮及最终轮为222项、217通过、5跳过。

## 六、局限性与下一步

**已测量**：上述机制、真实图入口、中断恢复、权限SQL与前端协议。源码实现和配置说明已更新。

**间接推断**：纯编辑和定向补证可减少重复规划/检索；新话题隔离可减少旧要求污染。判断模块本身也有成本，错误路径可能导致返工，尚不能承诺实际节省比例或质量改善。

**尚未评估**：真实话题关系混淆矩阵、指代消解/改写/路径选择准确率、实际目标报告命中率、信息保留与证据支持、真实token/费用/延迟、30轮首次超限。

有界索引只保证最早及最近窗口，超出索引或提示预算的中间成果可能需要澄清；当前没有新增全会话主题检索索引。输出格式编辑继续使用现有报告章节组装器，完全不同的输出结构可能需要规划路径或后续专门支持。来源不适用、章节不明等准备失败会阻止执行，不能算作成功回答。

会话摘要的“累计摘要＋近期原文＋未摘要增量完整覆盖”仍未在本次实现；现有语义摘要与预算裁剪继续使用。路由不替代这项会话记忆改造。本次也不改变研究内原有摘要触发策略。

现用数据库此前核查仍缺已有历史迁移，后端没有重启。本次没有新增schema迁移，没有将测试schema当成现用数据库验收；具体备份、迁移和应用步骤沿用 [研究内历史隔离与追问路由删除实现及多轮会话链路方案](研究内历史隔离与追问路由删除实现及多轮会话链路方案-20261005.md) 第四节。
