# 网页读取链路公开数据集调研与评估方案

分析日期：2026-10-17，Asia/Singapore。评估对象：当前工作区网页读取链路及公开数据集的适用性。性质：资料核查、代码静态分析与评测设计，**未执行新的网页读取效果评测**，没有当前链路的新分数。

建议优先使用 **WebMainBench 的 545 页子集和 WCXB**，分别检查结构保留与不同页面类型的正文提取；Scrapinghub 适合快速回归，Webis 的历史合并集适合论文对照。在线访问成功率需要另外使用业务 URL 测试，不能由离线正文分数替代。

## 数据、配置口径和原始材料

本轮核查发布方仓库、数据卡和文件目录，保存说明快照及输入指纹。除下载 Scrapinghub 的金标文件核对记录数外，没有下载各基准的全量 HTML，没有调用浏览器、OCR、模型或付费评测服务，没有运行现有单元测试。规模、语言与标注质量如未注明为本地统计，均为发布方声明。

原始材料位于 [网页读取链路公开数据集调研-20261017](../backend/eval/data/网页读取链路公开数据集调研-20261017/)：

- [资料来源与输入指纹.json](../backend/eval/data/网页读取链路公开数据集调研-20261017/资料来源与输入指纹.json)：下载 URL、HTTP 状态、字节数、SHA-256，以及本轮读取的三个业务源码文件指纹。
- [数据集适用性与评估建议.json](../backend/eval/data/网页读取链路公开数据集调研-20261017/数据集适用性与评估建议.json)：候选数据集、适用范围、未测边界及建议指标。
- 各基准的中文命名说明快照；[WebMainBench文件清单.json](../backend/eval/data/网页读取链路公开数据集调研-20261017/WebMainBench文件清单.json)；[Scrapinghub金标结构.json](../backend/eval/data/网页读取链路公开数据集调研-20261017/Scrapinghub金标结构.json)。这些是资料输入，不是本项目预测结果。

代码分析基于本轮工作区文件，并非已提交版本或线上部署快照。参数只核查代码默认值，没有读取实际部署环境配置：最短正文 500 字符、输出上限 30000 字符、静态超时 15 秒、最大响应 10 MiB、重试默认 2 次；是否启用浏览器/OCR 服务须在实际运行时单独记录。

WebMainBench 的文件目录本轮返回 HTTP 200：全量文件约 1.35 GB，545 子集约 109 MB，表明已有公开文件入口；这不等于已验证完整下载或所有样本可解析。HF 在线预览显示 schema 转换错误，不能据此认定原始 JSONL 不可用。WCXB 对比表仍将 WebMainBench 标成不公开，本轮以发布方当前文件入口为准。

另有 [LiveWeb-IE](https://github.com/sbY99/LiveWeb-IE)，官方覆盖 15 个网站、8 类领域，以查询和目标属性评估在线信息抽取。它需要另接字段提取环节，难以直接隔离正文读取质量，且官方注明仅限非商业研究，因此不作为本项目首批方案。

## 与当前代码的对应关系

当前 [web_reader_service.py](../backend/app/service/web_reader_service.py) 包含下载、编码识别、HTML/PDF 分流、浏览器与可选 OCR 回退、缓存及质量校验。

特别是 `_extract_html` 并非所有页面都直接由 Trafilatura 提取：存在 `article/main` 或表格时，会先通过 BeautifulSoup 与结构渲染函数提取；没有结果才尝试 Trafilatura。因此评测应封装**整个当前提取函数**，不能用单独跑 Trafilatura 的分数代表本项目。以上为源码观察，未由效果实验验证。

离线至少区分两份输出：正文清洗/截断后的内容，以及质量门禁后的接纳状态。门禁拒绝坏页可降低污染，但不等于增加取得正文的页面数；短但正确的页面也可能被最短长度阈值拒绝。

## 建议的首轮执行口径

1. 冻结代码、依赖版本、数据文件哈希和评测配置。先接入 WebMainBench 545 子集，再从 WCXB dev 按 7 类固定种子抽取约 200 页；如完成调参，再使用保留的 test 评价泛化。样本量为建议，尚未抽样。
2. 离线输入冻结 HTML，调用当前提取逻辑；禁止在离线评分时重新获取原 URL。输入 WebMainBench 前去掉 `cc-select` 等金标标记，仅把参考正文提供给评分器，避免标注泄漏。
3. 分开跑生产长度上限与放宽上限两种口径，报告被截断的页面比例；默认 30000 字符可能使长页召回率受预算限制。不要静默截短参考正文后把结果称为全文召回率。
4. 将正常页、复杂页、短正文、长正文、中文、其他语言、表格页分别汇总；抽取失败保留在总体分母。英文单词级评分不能直接套用到无空格中文。
5. 在线另用项目实际 URL 集，在接近的时间窗通过完整 `read_url` 路径测试。固定代理、允许域名、超时、并发和重试；冷缓存与热缓存分列，保存每跳状态、最终 URL、原始字节、静态 HTML、浏览器 DOM、提取正文和失败原因。网页变化与原网址失效单列，不能把旧金标直接当今天网页的真值。

## 失败样例的判定设计

本轮没有生成当前链路的新失败样例。下列为后续必须覆盖的**机制案例**，不是已发生的实验结果：

| 案例 | 预期归因 | 应观察的指标 |
| --- | --- | --- |
| 取得目标 HTML，但遗漏中间论述或整条列表 | 提取漏失 | Recall、必含片段命中率 |
| 正文混入导航、推荐、Cookie 提示 | 提取污染 | Precision、必排片段误含率 |
| 表格数值齐全但行列对应丢失 | 结构损坏 | TEDS、关键单元格与表头对应 |
| 合法短公告被最短长度阈值拒绝 | 准入误拒 | 正常页误拒率、短正文分层 |
| HTTP 200 返回验证或软 404 页 | 响应成功但正文不可用 | 异常页误接纳率、端到端可用率 |
| 50000 字符正文只返回前 30000 字符 | 输出预算影响 | 截断率、生产预算下的召回率 |

已有项目样例可从 [通用研究289网址同HTML与MinerU对照主报告](通用研究289网址同HTML与MinerU对照-20261017-首轮结果及分析.md) 追溯。本轮没有复算该运行，也不引用已存档初评的分数作为当前结论。

## 局限性、结论与下一步

**已测量/核查**：8 个资料请求均返回 HTTP 200，Scrapinghub 金标文件含 181 条记录，WebMainBench 文件目录给出的文件名/体积，以及本轮源码输入指纹。

**间接推断**：依据标注形式和当前源码，WebMainBench、WCXB 更适合定位正文及结构问题；默认长度上限、页面类型与质量门禁可能影响结果。该适用性排序不是本项目性能排名。

**尚未评估**：当前代码在这些基准上的质量、完整性、中文分数、在线访问能力、渲染/OCR 效果、资源开销和正常页误伤。公开网页基准也不能覆盖全部 PDF、Office 附件、图中数据、登录状态和实时反爬问题。WebMainBench 官方规模与语言表存在版本口径疑点，实际运行须重计行数和语言分布；本轮未验证全量文件。

下一步可先完成离线适配与小规模校验，再正式运行 WebMainBench 545 子集及 WCXB 分层样本；同时维护业务 URL 在线轨道。两个轨道分别出分，才能判断当前问题主要来自页面获取、正文选择、结构转换还是准入门禁。
