# 引用核验开关实现与回归

评估日期：2026-10-02。对象：DeepResearch 主研究链路的可选引用支持性核验。

## 使用方法与默认行为

Scout 暂不判断事实是否被原句语义支持。主研究链路新增两个独立调用参数，默认均为 `false`：

| 参数 | 核验位置 | 默认值 |
| --- | --- | --- |
| `scout_facts` | Scout 首轮检索、补充检索完成后，检查提取事实与其绑定原句 | `false` |
| `report_claims` | Writer 完成报告组装及每次重写后，检查当前 claims 与原句 | `false` |

通过 `POST /research/stream` 的请求体选择。例如，只开启报告论断核验：

```json
{
  "query": "分析项目进展",
  "session_id": "00000000-0000-0000-0000-000000000001",
  "turn_id": "00000000-0000-0000-0000-000000000002",
  "citation_verification": {
    "scout_facts": false,
    "report_claims": true
  }
}
```

省略 `citation_verification` 即关闭两个阶段；仅给其中一项时另一项仍关闭。参数严格要求 JSON 布尔值，拒绝 `"false"`、`1` 和未知字段。Python 调用可把同样的字典传给 `DeepResearchV2Service.research(citation_verification=...)`。

其他业务调用点可复用 `service.deep_research_v2.citation_verification.verify_citations(claims, enabled=False, settings=None)`，由调用者先按保存的正文解析 `references`，再决定本次是否开启。`verify_stage_citations(state, stage)` 提供主研究链路的编号解析和状态保存。

开关关闭时，不解析核验材料，不加载核验模型，不调用核验推理，也不产生通过率。返回 `status=not_executed`。正文质量检查、分句编号、来源准入及编号绑定检查继续执行；它们不是语义支持性判断。

当前提供的是 API/程序调用参数。运行配置保存在检查点；续跑沿用已保存开关，拒绝在同一次恢复调用中改变开关。无配置的历史检查点按关闭处理。摘要的既有核验开关继续独立控制摘要流程。

## 核验结果与边界

开启后复用现有本地 NLI 核验器，判断保存原句与声明论断的支持性。模型参数在首跑冻结，优先采用上下文策略中已配置的 NLI 参数；该配置缺失时采用 `NLISettings` 的固定默认参数。摘要核验开关不会隐式打开主研究链路核验。

Scout 的证据由保存正文中的原句编号解析。Writer 当前的 `document_id/sentence_ids` 声明由程序回读原句；连续原句保持原始间隔，不相邻原句分别核验；历史 `evidence_id/quote` 声明需满足对应事实的原句绑定。不接受未知正文、重复或非法句子编号、已修改正文索引或被拒绝的正文。审计保留编号、引句哈希和模型结果，不重复存储引句正文。

结果保存及交付字段：

- `citation_verification_config`：本次开关配置。
- `scout_citation_verification`：Scout 事实审计。
- `citation_verification`：当前报告审计，包含输入指纹和报告哈希。
- `status`：关闭为 `not_executed`；开启后可能为 `passed/rejected/incomplete/error`。
- `declared_claims_checked`：本次声明的论断是否完成核验。`all_claims_checked` 始终为 `false`，不声称模型完整提取了正文所有论断。

没有 claims 时记录 `incomplete`，不将空集合当作通过。模型缺失、推理超时或执行错误记录 `error`，执行不完整不记录通过。支持与矛盾结果按现有 NLI 聚合规则判断；存在无效绑定时不能由其他有效引用掩盖。

核验目前是审计模式：记录结果并提示待复核项，不自动删除事实、删句、改稿或拦截发布。报告质量评分和发布的确定性门禁分别保留自身含义。Critic 保留核验器结果，不能把已核验记录重置成“未执行”。报告重新生成或章节重新开放时，先使旧核验状态失效，再核验新版本。

## 回归口径与原始结果

本次是离线机制回归，模型推理和 LLM 输出使用模拟；没有执行真实模型调用、新的端到端研究或数据库写入。未重启正在运行的后端，源码需由后续启动加载。

原始机器记录：[回归结果.json](../backend/eval/data/引用核验开关-20261002/回归结果.json)。全组日志：[测试日志.txt](../backend/eval/data/引用核验开关-20261002/测试日志.txt)。开关最终验证：[开关最终验证日志.txt](../backend/eval/data/引用核验开关-20261002/开关最终验证日志.txt)。机器记录包含测试文件、测试数、退出码及最终源码哈希。

已测量：14 组共 **249 项测试通过**，其中开关专项 **22 项**，Writer 编号引用专项 **20 项**，正文质量与编号证据 **33 项**。其他组覆盖网页缓存、读取器、事实关系、假设追溯、派生数据、补搜、报告评分、质量门禁、限定网站及终态交付、上下文配置、追问恢复。`git diff --check` 通过。

关键类别及失败样例的预期行为：

| 类别 | 回归结果 |
| --- | --- |
| 默认关闭与两阶段独立 | 核验关闭时调用次数为 0；只开启报告时 Scout 不核验，反之亦然 |
| 配置传递与恢复 | API 参数传入 service；新运行冻结配置/模型参数；恢复不改变开关 |
| 引用错绑 | 未知事实、未知正文、改写引句、未绑定句子、非法编号均不能核验通过 |
| 支持/矛盾 | 模拟支持返回 passed；模拟矛盾返回 rejected，保留事实与报告 |
| 空输入与执行失败 | 空 claims 返回 incomplete；模型缺失/超时/错误不会伪装成 passed |
| 生命周期 | 首轮和补搜使用相同 Scout 开关；Writer 核验当前版本；Critic 保留审计；重写使旧审计失效 |
| 保存与交付 | 检查点、状态读取和完成事件保留独立结果，审计不重复存储原句 |

间接推断：默认关闭路径不会增加 NLI 模型加载和推理成本，因为解析及模型入口均被开关短路；尚未测量整个研究运行的实际耗时差异。

尚未评估：真实 NLI 对领域事实的支持性判断准确率、真实核验时延/资源开销、完整评测集开启后的质量变化，以及 claims 抽取的完整性。249 项通过不能解释为这些指标已达标。

结论：可以在主研究链路的调用点分别选择引用核验，Scout 当前默认不做语义判断。需要评估真实核验效果时，可在新的运行中仅打开目标阶段，比较结果及运行成本。
