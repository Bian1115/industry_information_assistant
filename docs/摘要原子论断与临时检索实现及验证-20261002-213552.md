# 摘要原子论断与临时检索实现及验证

评估日期：2026-10-02。评估对象：候选论断及消息编号之后的Claimify原子化、逐论断引用映射、候选不足时的内存混合检索，以及旧生命周期配置兼容。

## 1. 实现范围

新增流程为：自然语言摘要及模型返回的论断a/候选消息编号b → 绑定摘要位置 → Claimify筛选、消歧、拆解得到c → 在b中选择相关证据单元编号 → 程序恢复原文 → NLI；证据缺失或中立且推理完成时，才从本次摘要实际输入建立临时索引并补充检索。

每条c保存稳定claim_id、parent_claim_id、父论断a、初始模型论断、栏目、摘要中的父论断起止位置和原句、绑定方式、Claimify输入句及其在父论断中的位置、原候选来源编号。引用保存source_id、sentence_id、quote及位置；表格保存source_spans，明确区分组装证据和连续原句。消歧后的c不要求是摘要的连续子串。

只抽取已成功绑定的父论断。摘要全文用于指代消歧，不作为自身的支持证据。无可核验事实、无法消歧、运行失败、证据不足分别记录，不把这些情况自动视为核验通过。

## 2. 临时索引和初始参数

临时索引可以作为只服务本轮摘要核验的临时RAG证据库。正文按句切分，短表整体入索引，长表沿完整数据行切分并重复真实表头、标题、单位及注释。复用已有结构化证据切分器；原始表格位置以多个source_spans恢复。单行连同必要表头超过预算时显式报错，不拆断行或静默截断。

|配置|初始值|
|---|---|
|向量模型|text-embedding-v4|
|维度|1024，内存中的归一化向量使用float32数组|
|证据单元预算|1024个Qwen token|
|关键词召回|BM25，中文单字/双字及英文词/数字，各查询最多40条|
|向量召回|归一化向量点积即余弦排序，每查询最多40条|
|粗排融合|等权RRF，k=60；同证据ID合并，融合后最多60条|
|平分规则|按稳定证据目录顺序，不根据支持/反对标签重排|
|精排模型|qwen3-rerank|
|精排结果|最多12条，依服务返回的原始index关联证据，不能把排序后的分数直接配回旧顺序|
|邻句|精排命中句前后各1句，再交模型选编号；不跨消息，不递归扩大邻句|
|向量批次|每批10条|
|单次构建/查询超时|60秒|
|索引单元上限|20000，超出显式失败|

参数文件：[初始检索配置](/Users/bxy/projects/industry_information_assistant/backend/eval/configs/摘要原子论断临时检索初始配置-20261002.json)。这些是工程初值，尚未测量已有轨迹上的Recall@K，也未证明是最优参数。

首次候选选择保留的证据与新增检索选择合并，不因精排丢弃已有反证和条件。原有NLI明确矛盾不会被“再检索到支持”覆盖；运行错误不会触发伪装成证据不足的检索重试。

## 3. 索引生命周期与接口

索引首次遇到证据不足时才创建，同一轮中的所有原子论断复用它。向量、文本单元及BM25统计只保存在内存中，不创建向量数据库集合或索引文件。正常结束、构建/查询失败、超时和取消均通过finally清空索引并关闭异步HTTP客户端。原始历史及必要核验审计仍按项目已有机制保存，临时索引清理不删除这些原记录。

本地现有部署的兼容/embeddings端点可用，但兼容/reranks返回404。已验证同域的原生/api/v1/services/rerank/text-rerank/text-rerank对qwen3-rerank和gte-rerank-v2均返回200。默认保持qwen3-rerank，改用原生请求和响应协议；显式填写/reranks地址时使用兼容协议。没有自动切换到其他模型、跨区域端点或纯关键词降级。

可通过SUMMARY_RETRIEVAL_API_KEY覆盖密钥，默认复用DASHSCOPE_API_KEY。SUMMARY_RETRIEVAL_EMBEDDING_URL和SUMMARY_RETRIEVAL_RERANK_URL分别覆盖完整接口地址；必须匹配账号区域。本次没有修改实际.env或重启已有任务。

接口参考：[百炼向量文档](https://www.alibabacloud.com/help/en/model-studio/embedding)、[百炼排序文档](https://www.alibabacloud.com/help/en/model-studio/text-rerank-api)。当前同域原生qwen3-rerank的可用性以本次实际接口结果为依据。

## 4. 启用方式

直接入口调用verify_message_output时传claimify_atomic=True；verify回调表示底层NLI，不能再次执行证据选择。

生产新运行显式设置AGENT_SUMMARY_CLAIMIFY_ENABLED=1及AGENT_SUMMARY_ATOMIC_CITATIONS_ENABLED=1。atomic_citations写入冻结的summary_lifecycle配置；旧快照未包含该字段时保持旧哈希和旧抽取顺序。没有切换当前已经运行的任务。生产仍沿用正文先提交、随后审计的生命周期，不因本次改动改成核验前阻塞提交或自动删改正文。

已有轨迹评测增加--claimify-atomic、--retrieval-config、--quality-model和--max-requests。--quality-model qwen3-max可单独替换参考检查点和内容保留评审模型，摘要生成模型不随之改变。Claimify增加请求，应按实验预算显式调整每题请求上限。

例如从backend运行：

```sh
PYTHONPATH=app .venv/bin/python eval/scripts/评估已有轨迹摘要与引用.py \
  --output eval/data/已有轨迹原子论断评估-自定义唯一时间 \
  --claimify-atomic \
  --retrieval-config eval/configs/摘要原子论断临时检索初始配置-20261002.json \
  --quality-model qwen3-max \
  --max-requests 400
```

400仅是显式预算示例，本次没有运行该五题评测。需要复用旧评测行为时不传--claimify-atomic。

## 6. 失败样例及修复口径

首次新增17项测试有1项失败：测试期望证据选择列表按精排顺序返回，但选择列表按原消息顺序恢复、排名另存审计。修正测试为检查选中证据集合和审计排名，未改变实际引用对应规则；后续110项及最终113项回归通过。

首次真实模型联调中，合成tool_output记录的实际原文是JSON，而测试将其内部content的片段偏移错误地设成0。Claimify拆解成功，证据定位按原文一致性检查拒绝，两条均记录candidate_mapping错误。随后按source_text定位绝对偏移补正测试输入，实际NLI联调通过。没有放宽原文位置校验。首次错误记录保留在[初次真实联调](/Users/bxy/projects/industry_information_assistant/backend/eval/data/摘要原子论断临时检索机制验证-20261002-213552/真实模型原子论断引用核验冒烟.json)。

## 7. 尚未评估及下一步

尚未重跑已有中文五题轨迹、比较qwen-plus/qwen3-max内容保留评审，或基于人工标注测量原子论断召回、错误支持率、真实冲突复核一致率、遗漏率、总延迟及费用。更强模型可能改善局部判断，但不能直接升级为金标准。

NLI仍使用原有mDeBERTa及未经本数据校准的阈值/聚合规则。本次解决核验对象原子化、引用重新对应和证据不足的召回；尚未实现支持/矛盾冲突的独立复核模型。RRF和精排衡量相关性，不证明支持关系。索引中旧/中间摘要仅作为实际输入的可追溯记录，不能因此证明外部事实。

建议下一步固定同一批输入和人工检查点，对比旧路径与新路径，并分别统计父论断到子论断映射、候选检索、引用定位、语义核验和内容遗漏；在这些指标上调节40/40/60/12的初始数量。
