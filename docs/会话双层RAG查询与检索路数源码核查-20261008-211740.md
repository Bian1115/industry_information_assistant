# 会话双层RAG查询与检索路数源码核查

核查日期：2026-10-08T21:17:40.480297+08:00。对象：当前会话临时双层RAG。口径：静态源码及默认配置，不新跑评测、不调用模型、不继续32轮实验。

## 查询分别如何构成

第一层（研究材料）：规划、整篇编辑使用会话层形成的完整任务，优先session_task.resolved_query，其次resolved_query/query/original_query。逐章写作/修订使用当前完整任务＋章节标题＋章节描述。召回段落、表格和结构化记录，段落metadata带小节信息；目前不额外生成section聚合正文。

第二层（引用材料）：对每条原子论断分别使用claim字符串查询，包含该论断本身的主体、时间、数字、单位及条件，不用整篇报告统一查询。召回句子、表格及结构化记录。

目前没有独立的LLM关键词提取，也没有多query扩展。词法路对同一查询做中文单字/相邻双字、英文词及数字分词；语义路直接对同一完整查询embedding。不能把Scout另外生成的联网搜索query当作临时库的两层检索query。

## 两层共用的两路流程

1. BM25词法召回最多40个。
2. text-embedding-v4/1024维向量召回最多40个，Milvus使用COSINE。
3. 两路按chunk ID去重、等权RRF融合，常数60，截取最多60个。
4. qwen3-rerank精排；第一层默认8个，第二层默认5个。
5. 默认补取前后各1个同正文邻居，再按第一层8192、第二层每条论断2000 tokens的JSON预算装包。最后模型发送前还会检查剩余输入空间。

40/40/60目前是session_evidence_rag.py中的常量；8/5、邻居半径和材料预算支持SESSION_EVIDENCE配置。精排、相邻chunk补取和原绑定按编号回读均不是第三路检索。

第二层先精确回读Writer已有绑定，再对整个当前会话主题执行上述两路检索，追加去重后的候选。seed_document_ids仅记录在审计中，当前没有对绑定正文优先排序或只查首层命中文档，避免将其他正文中的反证完全排除。

## 范围、失败与局限性

检索始终按用户/会话/主题、有效generation、单元类型及允许来源过滤。空库返回空结果；embedding/Milvus调用异常时使用词法候选并记录错误；精排失败沿用RRF结果顺序。这些是代码中的失败处理路径，本次没有再次故障注入。

已核查：查询来源、两路算法、融合精排参数及失败分支。间接推断：词法与语义检索可能互补。尚未评估：此配置的语义Recall@k、引用质量、回答正确率及真实费用。本次没有新增失败样例测量，之前的机制验证和11份历史正文分块失败见[实现报告](/Users/bxy/projects/industry_information_assistant/docs/会话临时双层RAG实现与验证结果-20261008-2057.md)。

结论：两层的查询粒度不同，但正常情况下每层均为BM25＋向量两路混合检索。下一步若要增加关键词提取、结构化实体查询或多query扩展，应单独实现并用标注相关性数据比较，不将本次静态核查当作检索效果验证。
