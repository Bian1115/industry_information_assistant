# Docker 容器化入门实践教程

日期：2026-10-12（Asia/Singapore）。练习目标：亲手将一个 Python 接口打包为镜像，启动容器，通过浏览器访问，并查看运行日志。基础镜像首次下载所需时间取决于网络。

## 练习文件

独立练习位于 [`实践/Docker容器化入门`](../实践/Docker容器化入门/)。它只使用 Python 标准库，不需要数据库、模型 API Key 或额外的 pip 依赖。

| 文件 | 作用 |
| --- | --- |
| [`服务.py`](../实践/Docker容器化入门/服务.py) | 提供 `/` 和 `/health` 接口 |
| [`Dockerfile`](../实践/Docker容器化入门/Dockerfile) | 描述镜像的基础环境、代码和启动命令 |
| [`.dockerignore`](../实践/Docker容器化入门/.dockerignore) | 仅允许练习代码和 Dockerfile 进入构建上下文 |
| [`compose.yaml`](../实践/Docker容器化入门/compose.yaml) | 保存容器的端口、环境变量和资源配置 |

当前项目的根目录 Compose 已经定义 PostgreSQL、Redis、Milvus 等中间件；这次练习使用独立的 Compose 项目名称 `industry-docker-practice` 和本机端口 `18080`。以下 Compose 命令均须在练习目录执行。

## 第一步：确认 Docker 可用

```bash
docker --version
docker compose version
docker info
```

如果 `docker info` 无法连接 Docker 引擎，先启动 Docker Desktop，再重试。

## 第二步：进入练习目录并阅读代码

```bash
cd /Users/bxy/projects/industry_information_assistant/实践/Docker容器化入门
cat 服务.py
cat Dockerfile
```

Dockerfile 中：

- `FROM python:3.11-slim`：使用带有 Python 3.11 的基础镜像。你的电脑上的 Python 版本不会决定容器内版本。
- `WORKDIR /app`：后面的命令在容器内 `/app` 目录执行。
- `COPY`：将代码放入镜像。修改宿主机代码后，需要重新构建镜像才会包含修改。
- `USER`：以普通用户运行练习服务。
- `EXPOSE 8080`：说明应用使用的容器端口；它不会自动把端口发布到电脑上。
- `CMD`：容器启动时运行的命令。

## 第三步：构建自己的镜像

```bash
docker build -t industry-docker-practice:local .
docker image ls industry-docker-practice
```

`-t` 指定镜像名称和标签，末尾的 `.` 指当前目录为构建上下文。首次构建可能下载 Python 基础镜像；后续通常可以复用缓存。

## 第四步：启动容器

```bash
docker compose up -d
docker compose ps
```

`-d` 表示后台运行。打开 [http://localhost:18080](http://localhost:18080)，预期看到：

```json
{
  "message": "你好，我已经通过 Docker Compose 启动了！",
  "hostname": "容器自己的主机名",
  "python": "3.11.x"
}
```

`hostname` 和 Python 的补丁版本以实际运行结果为准。健康接口为 [http://localhost:18080/health](http://localhost:18080/health)，应返回 `{"status": "ok"}`。

也可以在终端访问：

```bash
curl http://localhost:18080/
curl http://localhost:18080/health
```

端口配置 `127.0.0.1:18080:8080` 表示：通过本机的 `18080` 端口访问容器里的 `8080` 端口，仅绑定本机回环地址。服务代码在容器内监听 `0.0.0.0`，这样 Docker 转发进来的请求才能访问它。

## 第五步：查看日志和容器内部

```bash
docker compose logs --tail=20 api
docker compose exec api python --version
docker compose exec api ls /app
```

你会看到接口访问日志、容器内的 Python 版本以及打包进去的代码。镜像是打包后的模板，容器是从模板启动的实例。

## 第六步：修改一句话并重新部署

打开 `compose.yaml`，把 `DEMO_MESSAGE` 改成你自己的句子，然后执行：

```bash
docker compose up -d
```

刷新浏览器，观察返回内容变化。这一轮只修改运行配置，不需要重新构建镜像。

接着修改 `服务.py`，例如在根接口的 `payload` 里添加 `"lesson": "我的第一次容器化部署"`，然后执行：

```bash
docker compose up -d --build
```

刷新页面，观察新字段。`--build` 会先构建镜像，再启动或更新容器。这个练习没有挂载源码目录，因此单独修改本机代码不会自动改变容器里的代码。

## 第七步：停止与恢复

```bash
docker compose stop
docker compose start
```

`stop` 停止容器，`start` 启动已有容器。练习结束后，删除这次练习的容器和网络：

```bash
docker compose down
```

镜像仍保留，可再次 `docker compose up -d`。这个练习不保存业务数据；后续练习数据库时，需要理解 volume 的持久化行为。

## 可选：不用 Compose，手动启动同一个镜像

先在练习目录执行 `docker compose down` 释放 `18080`，再运行：

```bash
docker run -d --name industry-docker-practice-manual \
  -p 127.0.0.1:18080:8080 \
  -e DEMO_MESSAGE="这是我手动启动的 Docker 容器" \
  industry-docker-practice:local
docker logs industry-docker-practice-manual
```

打开同一个网址。完成后停止并删除手动创建的练习容器：

```bash
docker stop industry-docker-practice-manual
docker rm industry-docker-practice-manual
```

手动方式展示 `docker run` 的端口和环境变量参数，Compose 将这些参数保存为可重复使用的配置文件。切换回 Compose 时执行 `docker compose up -d`。

## 下一步

完成以上步骤后，可以继续：给这个接口增加 Redis 并通过服务名连接、练习数据库 volume、把同一镜像部署到一台服务器。整个行业信息助手的前后端容器化还需要另外处理依赖、数据库迁移、环境变量和前端 API 地址；本练习只验证小型接口的容器部署。
