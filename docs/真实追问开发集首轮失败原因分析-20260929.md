# 真实追问开发集首轮失败原因分析

分析日期：2026-09-29。评估对象：已停止的 `开发集5题真实追问轨迹-20260929-212128`，重点是原题8第1轮自然失败及原题25第1轮中止前的异常开销。

本次为该运行的补充分析，未重启采集、未调用模型/搜索/NLI。新增口径为：按供应商usage核算各阶段tokens、对保存的摘要输出离线重放格式/编号解析器、比对完全相同的摘要请求哈希。原报告保留，不覆盖原始运行结果。

## 1. 结论

原题8最终触发的是生产服务每次研究运行的 **300000 token 总预算**，不是单次上下文超限。上游主要问题是摘要初稿反复不符合分句类型/来源编号协议，修复仍有失败；整次摘要不提交后，下一次压缩又从相同旧历史块重做。已知token消耗中约82%用于摘要生成与修复，仍未采用任何最终摘要。

目前不能将失败归因于刚修改的追问契约更新，也不能判断引用候选修复或NLI效果：两题都没有交付首轮，未进入实际追问；已记录摘要阶段均停在分块生成/格式修复，没有进入最终引用补齐和NLI。

## 4. 首题的失败链条

### 4.1 初稿几乎把修复调用变成必经步骤

原题8有6份已完成的summary_chunk初稿，离线重放均无法直接通过parse_draft；因此执行了6次summary_chunk_parse_repair。原题25的6份初稿也都触发修复，其中5份修复输出已完成并通过解析，第6份修复在用户停止时取消。

主要初稿错误包括：

- 把用户约束编号 `[req_1]`、`[req_2]` 当作原文证据编号。原题8修复请求seq=36明确报“未知编号req_1/req_2/req_3”。
- 用户要求、计划、待办没有按协议加明确的类型前缀，例如“需进一步检索……”直接作为普通分句输出，解析器按事实检查后要求来源。
- “尚未找到”“当前仅完成初步检索”等否定结论或执行状态没有来源编号；这些句子不能因为在SUMMARY/NEXT STEPS栏目就自动豁免依据。

运行时提示词已明确告知 req 编号不是证据编号、任务性内容需要类型前缀。故不是程序忘记提供任何协议说明，而是“首稿四栏目Markdown＋依赖前缀识别类型”的生成遵守率在本次轨迹中很差，模型仍混用任务要求与事实。

### 4.2 两次局部修复仍然失败

本地重放6份已完成修复：4份格式/编号解析通过，2份失败。这里“通过”不代表已完成最终引句定位或NLI。

第一次失败（summary_output seq=48；summary_error seq=50）包含：

```json
{
  "kind": "fact",
  "claim": "尚未找到明确涉及MatBench、OQMD数据集上GNN或贝叶斯优化在成分-性能映射中表现的实证研究。",
  "source_ids": []
}
```

同一输出还包含“主动学习、机器人合成平台、成本约束整合等关键问题在当前结果中未见直接证据”，同样是fact且无来源。它们断言检索/证据缺失，程序因此拒绝，报“修复后的事实须携带来源且不得使用任务性前缀”。

第二次失败（summary_output seq=97；summary_error seq=99）把“Graph Neural Networks、MatBench、OQMD等实体已在任务中明确要求覆盖”标为fact，但不给来源；还把“当前仅完成初步检索，尚未分类或回答问题”标为无来源fact。

这同时暴露了语义边界：用户要求应从契约提取为requirement；具体已经完成/未完成的工作是有历史记录可追溯的执行状态；“没有研究证据”则必须限定到实际检索范围，不能因为某一块输入没出现就推断全部历史或整个领域没有。

特别排除一个误诊：多份修复仍输出了 `claim="None"` 空栏目占位符，但本次版本会跳过无来源的None占位符。首题seq=38、77、143含此类占位符且解析通过，None不是这次两次拒绝的直接原因。

### 4.3 整轮失败导致成功块重复生成，放大开销

运行快照 `summary_hierarchy.py` 将各块成功结果先保存在局部summaries列表，后续任一块抛错即退出；`agent_context.py` 只有完整摘要生成、后续校验及保存成功后才推进summary_version和covered_seq。

保持最终提交原子性是合理的，但缺少可复用的中间块缓存：前面已经通过格式/编号校验的块随整轮失败被丢弃。下一次Scout输入又触发压缩时，旧游标未推进，重新包含相同旧块。

证据是相同input_hash的请求重复出现：

| 相同块 | seq | 每次原始输入tokens | 观测 |
| --- | --- | ---: | --- |
| 第一块 | 30、69、135 | 22060 | 同一完整请求生成3次，后接3次修复；修复均通过解析 |
| 第二块 | 40、79、145 | 12580 | 同一请求发起3次；前两次有输出，第3次被预算取消 |

首题共发起7次块生成、6次格式修复；其中最后一次块生成被取消。已完成生成消耗119847 tokens，修复消耗136412 tokens。修复请求携带原始材料、错误输出和错误清单，部分输入达到2.4—2.6万tokens；“局部修复”指修复范围有限，不代表输入量小。

### 4.4 外置维持了单次可运行，但没有减少已发生的调用累计消耗

两次完整记录的Scout上下文视图：

| context_view seq | 压缩前tokens | 最终入模tokens | 单次输入预算 | 摘要是否采用 |
| --- | ---: | ---: | ---: | --- |
| 51 | 74958 | 25306 | 25744 | 否 |
| 100 | 100192 | 19200 | 25744 | 否 |

摘要失败被记录后，程序通过旧输入引用化和工具内容外置把当前请求降到预算内，Scout继续执行。因此这次并非“上下文依然放不下”直接终止；继续执行又带来下一轮压缩，重复的摘要和修复累计消耗最终越过300000 token限制。

## 5. 两个次要但明确的问题

### 5.1 Architect对普通要求过度要求“权威定义替代方案”

两题Architect都调用3次。原题8两次重试的明确原因相同：req_1、req_3缺少fallback_if_unverified；原题25也因同类检查重试。

从保存的首份规划输出可见，原题8 req_1是“2020年以来”的时间范围，req_3是“准确度保留数据集/划分/指标、不跨条件排名”的输出规范。它们不是需要寻找官方分类定义的要求，模型输出空fallback有其合理性，但当前 `_validate_requirement_coverage()` 对所有要求一律检查非空fallback，导致额外调用。

该项首题消耗10683 tokens，仅约3.42%，不是主要预算来源；但还可能诱导模型为普通输出维度编造不必要的权威框架查证任务，应独立修正。

### 5.2 首次规划仍会把模型选择的实体升级为用户必需覆盖对象

用户首轮只要求梳理材料配比优化路线，并未点名MatBench、OQMD、钙钛矿太阳能电池等。保存的契约却将这些列入required_entities；原因是旧 `build_research_contract()` 在模型未给required_entities时回退使用key_entities。

这解释了后续摘要为何写成“这些实体已在任务中明确要求覆盖”，并不断强调尚未找到它们的证据。近期改动保护了追问中已经提交的契约，但未整体替换首次规划协议，这条旧回退仍存在。

另外，材料科学题受who.int、nih.gov来源范围限制，轨迹出现大量不相关WHO记录。该范围不匹配可能增加检索噪声，但本次没有对照实验，不能据此量化质量损失，更不能把未检索到结果写成领域内不存在研究。

## 6. 建议的修复顺序

1. **摘要首稿与修复统一为结构化分句协议**：一开始输出kind、claim、source_ids，由程序渲染四栏目，减少Markdown前缀和引用位置的隐式规则。用户约束、待办与执行进度明确区分；研究事实继续要求原文依据。不能把无来源事实自动改成建议来绕过校验。
2. **缓存已通过格式/编号检查的中间块**：以原始块内容、完整请求/提示词版本、契约、策略及作用域生成键。后续块失败只重做缺失/失败块；缓存不代表最终引用/NLI已通过，不提前推进全局覆盖游标，也不跨不相容配置复用。
3. **控制重复摘要的预算**：摘要调用也计入研究总预算本身合理；应在昂贵调用前检查剩余预算，为修复和主任务留空间。对相同输入的相同失败设有界重试/退避，避免每次上下文构建重新支付全部成本。策略调整需要单独评测，不能假定关闭摘要必然成功。
4. **修正首次规划校验和约束归属**：仅对需要验证权威定义的明确框架类要求检查替代方案；模型自行选择的实体留在规划建议中，不回填用户必需对象。
5. **最后再评估预算是否需要增加**：提高30万上限可能暂时推迟失败，但不会修复协议错误和重复计算，也不能保证能完成后续轮次。

## 7. 已测量、推断和未评估边界

已测量：两题usage分组、18/15条模型请求、首题两次摘要拒绝、初稿与修复解析重放、相同input_hash重复、单次上下文视图及自然终态。原题25只有主动中止，不能列为第二例自然预算失败。

间接推断：统一结构化首稿和中间块缓存应能减少修复/重复调用；首次契约实体提升及来源范围偏窄可能增加无效检索和摘要混淆。具体收益需要同源离线实验或新的受控运行，不能由本次两条首轮轨迹估算成功率。

尚未评估：后续追问路由、契约补丁的真实模型准确率、最终引用候选筛选/NLI、完整研究质量、人工关键事实保留率、修改方案后的成本收益。本次仅分析已停止轨迹，没有自动应用以上修复，也没有重跑开发集。
