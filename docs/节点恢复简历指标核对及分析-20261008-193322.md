分析日期：2026-10-08，Asia/Singapore。评估对象：DeepResearch 多 Agent 长任务的纯节点检查点恢复、待合并节点输出恢复与终态交付补偿。本次仅核对既有测量，不新执行模型、故障注入、数据库恢复或正常基线。

## 数据与配置口径

开发集原题8、25、26、27、28，各使用首轮问题，各分配一个指定故障点。原五题均实测 SIGKILL；max_iterations=2，Scout 使用 qwen-plus，其余主 Agent 使用 qwen3-max，评测实例关闭 Writer 章节 task，保持纯节点恢复。

本次合并三份证据：原五题初测，26题原断点的真实恢复复评，28题增加终态交付补偿后的真实恢复复评。它们来自不同代码版本，不能称为同一版本一次运行的成功率。失败项重试报告中的28题仍失败；该运行冻结的路由与服务哈希不同于终态补偿成功复评。本次保留这些失败记录，按各场景的成功测量列出覆盖情况。

26、28复评沿用原 run 与数据库检查点，没有再次从头运行或重新注入 SIGKILL。真实生产路由函数与 StreamingResponse 被调用，检查点及业务交付使用 PostgreSQL；未经过网络 HTTP 服务器、认证中间件或浏览器。

## 逐题分析及失败样例

| 原题 | 故障位置 | 成功测量及分析 |
|---|---|---|
| 8 | 部分搜索完成后 | 节点恢复成功，恢复23.69分钟。当前搜索节点重做，后续存在返工；比历史完整执行多6.42分钟，不能宣称所有样本均省时 |
| 25 | 第三章生成后 | 节点恢复成功，恢复8.97分钟。已完成的规划、初始搜索与分析复用，未提交的Writer节点及三章重新生成；估计省3.87分钟，不能称为章节级恢复 |
| 26 | 写作完整检查点提交前 | 原入口因空next拒绝。修复后从review继续，原初稿不重跑；随后两轮write属于审核返工。真实复评交付成功，新增23次模型调用，流程内质量判断仍needs_revision |
| 27 | 写作完整检查点提交后 | 原五题实测恢复60.06秒，其中租约等待44.38秒，仅执行一次审核；没有完整历史成功基线，不计算省时 |
| 28 | 终态检查点完成、交付事务提交前 | 原入口拒绝且报告、完成事件缺失。补偿复评3.47秒完成单次交付，无新增模型调用；重复请求仅回放已有完成事件 |

原失败项揭示两类入口缺口：已持久化的pending writes仍待图推进，却被空next误判为完成；图真正结束后业务交付缺失，缺少终态补偿。二者分别通过恢复准入修复与复用幂等交付事务解决。

## 证据边界、结论与下一步

已测量：五个指定故障位置的SIGKILL、各场景既有成功恢复记录、26/28真实数据库断点恢复、28终态交付耗时与新增调用、单次重复恢复请求的幂等回放。正文一致只表示技术交付一致，不代表独立事实质量评分。

间接推断：26题相较历史完整运行估计省时58.9%，同类终态补偿能够避免再次执行模型。

尚未评估：同版本五题全部再次注入故障、每题每位置组合、重复故障稳定性、并发负载、HTTP认证与网络、浏览器SSE断网重连、独立内容质量和总体成本下降。

结论：优先将“5类故障覆盖、终态补偿3.47秒、零新增模型调用、重复请求无重复交付”作为简历指标；58.9%仅在明确单例历史对照口径时采用。下一步若需要总体可靠性或平均性能指标，应在冻结版本上做重复故障测试，并补严格配对基线。本次未修改源码、简历或技能工作区。
