# 第一题摘要范围与引用失败补充分析

评估日期及补充复评日期：2026-09-29。

本报告是对同次验收的补充只读分析，不新增运行样本，不调用模型，不修改业务代码，不覆盖此前验收报告。新增口径：区分字符串匹配、空白归一化后的文本对应、来源关联完整性、摘要语义一致性与任务约束来源；归一化仅用于诊断，没有放宽生产核验。

## 评估对象、数据与配置

对象为开发集第一题（原题 ID 8）的 `固定输出引句定位复验`。它复用了请求参数和正文完全匹配的 12 条已保存真实模型输出，后续新增 3 次模型调用；不是重新生成全部内容的端到端运行。

原始数据：

- `backend/eval/data/第一题契约编号与局部修复验收-20260929/固定输出引句定位复验/真实模型回放/工作历史.json`
- 同目录的 `真实模型验收结果.json`、`重建任务契约.json` 和 `验收配置.json`。
- 本次分析脚本、原材料 SHA256、逐条检查及分块输出保存在 `backend/eval/data/第一题摘要范围与失败补充分析-20260929/补充诊断.py`、`补充诊断结果.json`、`诊断日志.txt`。

沿用该运行的 `qwen3-max` 摘要模型、3000 token 输出预算、28744 token 硬输入预算和 180 秒摘要时限。保留 NLI 门禁，当前失败在调用 NLI 之前；不将“尚未运行”解释为“不支持”或“已通过”。

## 摘要提示词并非只提取事实

当前 `backend/app/prompts/摘要正文生成与合并.txt` 要求保留四栏目：会话目标、摘要、资源、下一步。其正文包含两类内容：

| 内容 | 保留在摘要正文 | 标注来源并进入 CLAIMS / NLI |
| --- | --- | --- |
| 研究结论、数字/日期、否定结论 | 是 | 是 |
| 已完成操作、访问资源、失败结果 | 是 | 是，引用相应可核对记录 |
| 用户目标、输出要求 | 是 | 否；可进入独立的约束一致性检查 |
| 计划、策略、建议、待办、显式推断与待确认问题 | 是 | 按当前协议不进入事实引用链路 |

正常摘要生成阶段输出四栏目正文与事实来源编号，不输出引句或 CLAIMS。只有局部修复使用带 `kind/section/claim/source_ids` 的 JSON 分句清单，由程序渲染回四栏目。最终引用补齐再从摘要中筛选事实分句，生成 CLAIMS。

实际最终候选摘要解析后有 **15 个分句：8 个带来源的事实分句，7 个不带来源的任务性分句**。空栏目 `None` 不计为分句。这说明本次并非只保留了事实。

注意：分句类型由模型声明，程序主要检查前缀和结构，不构成独立的语义分类验证。含事实判断与建议的混合句仍可能被整体标成 todo 而绕过事实引用。

## 核心指标与直接失败点

| 项目 | 同次运行已测量结果 |
| --- | --- |
| 分块 | 4 块，各经一次局部修复后通过格式与编号检查 |
| 合并 | 1 次，经一次局部修复后通过格式与编号检查 |
| 引用补齐 | 处理到第 4 个事实分句；前 3 个通过引用结构、原文定位等前置检查 |
| 第 4 句局部修复 | 1 次；仍被原文匹配拒绝 |
| NLI / 最终约束语义检查 | 0 次，未执行到 |
| 摘要版本 / 覆盖游标 | 0 / 0，未提交候选摘要 |
| 主任务请求准备 | 25334 tokens，使用原历史视图；请求准备成功不等于摘要提交成功 |

直接异常是 `引用原句不在本次提供的连续原文片段中`。失败分句称，当前逆向设计研究主要涉及光学超构表面、分子多目标优化，且未覆盖指定材料体系。

返回的两条英文 quote 原样匹配均为 false，一次 JSON 重新编码后匹配也为 false。但将来源 JSON 字符串值中的实际/字面量换行统一为空白后，两条 quote 都能找到对应文本。

例如来源含 `Metasurfaces\ncomposed\nof...`，模型返回 `Metasurfaces composed of...`。因此更准确的归因是 **模型把原文逐词换行重新排版成空格，导致严格字符定位失败**，不能据此直接断言模型编造了整段内容。此前修复只处理可验证的 JSON 编码差异，没有处理这种词间空白重排。

这项归一化对应关系不证明 quote 支持整句结论；尤其不能证明后半句“未覆盖指定材料体系”。

## 来源关联还有一个独立问题

该句关联了两个原始编号：

- `89c78717-cdb7-495f-bea4-e0d01b883381`：搜索工具输出。
- `b701c0f1-3b45-47d6-89df-16c8958d40c3`：工具输入，里面带有文献/检索材料，不能仅因它是 tool_input 就断言没有证据。

修复输出的两条引用都标到了第一个编号，第二个没有返回。程序后续要求关联来源集合与已补齐引用集合一致，因此即使修复空白匹配，仍需处理第二个来源的证据关联。

**实际先触发的是逐字匹配错误；来源未补齐是补充分析识别出的后续阻塞，不是此次最先抛出的异常。**

协议也需要澄清：引用提示词称 source_ids 为“候选”，而实现要求全部关联 ID 都得到引用。若它们是候选池，应根据证据确定最终引用集合；若是已确认的必要支持来源，就应在摘要阶段把关联做准确。不能简单删除漏引来源来宣布成功。

## 比格式错误更深的摘要问题

### 1. 分块的局部缺失被带入全局摘要

第一块已保留“一项关于 bcc 固溶体合金的主动学习设计研究……”；第四块却写“关键实体如……主动学习……均未在当前结果中出现”。最终合并同时保留了这两句话。

这是直接可观察到的摘要内部矛盾。分块输出中的“当前结果”没有明确限定为“本块”；合并也没有消解相互冲突的出现/未出现判断。轨迹支持这一错误传播路径，但没有用受控对照实验量化它的独立影响。

此外，列举光学或分子研究的两段原文不能单独证明一个检索集合没有其他材料研究。否定结论需要明确检索范围、已检查材料和覆盖依据；尚未执行 NLI，不能声称该否定结论已经被语义核验判错。

### 2. 规划选题被描述成用户硬性指定

原用户 query 没有点名“高熵合金、固态电解质、钙钛矿太阳能电池”等对象。规划结果选择的实体却进入了契约 `required_entities`，摘要随后称其为“用户指定”。

现有 `build_research_contract()` 在缺少显式 required_entities 时，会从规划输出的 key_entities 填入该字段。接入契约后，这种角色混合传到了摘要：合理的规划覆盖对象被赋予了用户硬约束的口吻。需要区分用户明确要求与规划建议，不应将规划模型自行选择的实体自动归因于用户。

### 3. “任务性分句”仍可能混入事实判断

最终候选里有 todo：`当前检索结果不足以支撑任何critical_questions的回答，必须补充相关高质量文献。`

前半句是关于当前证据充分性的判断，后半句才是待办。当前渲染器会给整句添加“待办：”，引用流程按前缀跳过，无法保证前半句得到核验。事实与建议应拆开；不能仅凭 kind/todo 前缀证明整句不含事实。

## 结论与建议顺序

1. 保留目标、约束、进展、事实与待办的摘要范围；不改成只抽取事实。
2. 优先校正内容：限制分块否定结论的作用域，合并时检查出现/未出现冲突，区分用户硬约束与规划对象，拆分事实与待办混合句。
3. 为引用提供可读的规范化正文及到原文的字符映射；模型选择连续片段，程序还原精确原文和偏移。不能仅删除空白后接受任意模糊匹配。
4. 明确 source_ids 是候选还是必要支持集合，逐条检查关联，不把“编号合法”当成“证据支持”。
5. 正常生成与修复可考虑统一结构化协议。本次四块和一次合并都需要额外修复，格式可靠性和调用成本仍有改进空间。
6. 完成前置定位后，再实测 NLI、约束一致性及最终摘要提交；不能以格式检查通过替代语义验收。

已测量：上述计数、直接异常、两种精确匹配失败及诊断归一化匹配、来源漏引、摘要内相互冲突的文本、原 query 与 required_entities 的差异。

间接推断：分块作用域、契约语义混合和候选/必选协议差异增加失败风险，需要后续独立对照验证。

尚未评估：完整事实保留率、分类准确率、NLI 支持性、整题质量与全开发集成功率。本次只分析，不修改代码或重新运行研究。
