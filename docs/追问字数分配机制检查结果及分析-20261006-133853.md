## 数据与配置口径

输入两条典型追问：“请缩短到3000字”“请扩展到7000字”。离线夹具分别提供active_constraints.max_body_chars=3000/7000，并使用四章大纲：协议与定位、一次请求怎样完成、最小实现与部署、边界与来源。这不是追问判断模型的实际输出。

从当前Writer源码提取_writing_budget和正文计数函数，使用ResearchConfig默认值计算，避免初始化模型客户端。配置为target_report_chars=7500、min_section_chars=300、max_section_chars=500、summary_chars=250、outlook_chars=150。业务构造入口将ResearchConfig这些值传给Writer。

## 已测量核心指标与逐例分析

| 预算字段 | 缩短到3000（夹具） | 扩展到7000（夹具） |
|---|---:|---:|
| 整篇target_body_chars | 3000 | 7000 |
| 摘要 / 结论 / 展望 | 250 / 200 / 150 | 250 / 200 / 150 |
| 结构预留 | 82 | 82 |
| 安全余量 | 150 | 350 |
| 每章目标 / 上限 | 500 / 500 | 500 / 500 |
| 四章目标合计 | 2000 | 2000 |

函数先扣结构和5%安全余量，再扣首尾预算，剩余平均分给各章；但是章节目标=min(固定max_section_chars=500,平均额度)，导致两个例子都卡在500。本项是预算输出，不是模型实际生成长度。

## 会话转换和校验现状

会话任务判断提示词允许将显式字数写成requirement_changes中的max_body_chars，要求保留用户原话quote。纯篇幅修改可走edit并继承原报告要求。相对“短一点”不应凭空产生硬字数。

Writer已将整篇预算写入编辑及分章提示词，正文计数不计参考文献、空白、Markdown链接URL及部分Markdown符号。当前check_body_length只拒绝高于max_body_chars的正文；全篇修复路径主要做超长缩写。没有整篇目标接近度检查。因而“2000字报告 <= 7000字上限”不能证明完成了“扩展到7000字”。

## 失败样例与因果边界

1. 3000和7000得到相同的四章目标合计2000，预算不能表达长篇扩展。
2. 将“扩展到7000”只保存成max_body_chars，会允许任何更短报告通过长度上限检查；这是源码可推断的条件，不是本次真实模型输出。
3. 追问的“目标长度”“最多长度”和“缩短/扩展方向”应分开表达，否则上限和目标混淆。

## 建议链路和分配示例

会话层模型负责识别意图、目标数字和用户明确限制，更新本轮契约；保留来源、范围及章节要求。程序负责根据大纲与重要程度生成预算，模型负责在预算内编辑内容，程序负责计数并提供超出或不足的反馈。纯篇幅修改由Writer处理；要求增加新事实的扩展需要补证，不能靠编造或重复凑字。

建议区分target_body_chars和max_body_chars。“不超过3000”只设上限；“扩展到7000”包含目标及扩展方向，可配置软目标允许范围。当前仅支持max_body_chars的契约字段，下面是建议方案，并未实现或实测。

示例用同一四章权重20%/25%/40%/15%，先预留摘要、结论、标题及安全余量，剩余按权重分配：

| 部分 | 3000目标示例 | 7000目标示例 |
|---|---:|---:|
| 摘要、结论、标题及安全余量 | 600 | 1000 |
| 协议与定位 | 480 | 1200 |
| 一次请求流程 | 600 | 1500 |
| 最小实现与部署 | 960 | 2400 |
| 边界与来源 | 360 | 900 |
| 总预算 | 3000 | 7000 |

这只是分配示例；权重应根据现有章节篇幅、用户强调内容与必要证据调整。每章预算必须随总目标变化，固定500不应继续覆盖用户目标。实际正文不必正好等于目标数，标题和安全余量不能算作新增正文。目标允许误差属于可配置编辑策略，不能擅自声称是用户明确提出的硬约束。

缩短保留结论、证据和引用，删除重复；扩展优先增加已有证据的解释、推导与工程示例。输出完成后按相同正文计数口径检查；扩展不足则在已有证据范围内补写，超长则定向压缩。长报告宜分章生成再拼接，并独立检查模型输出token上限，不能把max_tokens当字数控制。

## 局限性、结论和下一步

**已测量**：给定数字约束和固定四章时，当前预算函数的准确数学输出；保留源码和哈希。
**间接推断**：固定单章上限及仅全篇上限校验不适合保证扩展目标。
**尚未评估**：会话模型对两条真实原话的解析正确率、Writer实际输出、新目标字段及新分配策略效果。

结论：当前代码有整篇预算和超长拒绝机制，但不能仅靠修改max_body_chars完成“扩展到7000”的目标。建议增加目标长度语义、动态章节额度和扩展不足修复，再用同样两条追问验证。此次未实现修改，也未重新运行32轮实验。
