# 当前网页读取链路公开基准评估结果及失败分析

评估与补充复评日期：2026-10-18，Asia/Singapore。对象：本项目冻结的网页读取实现，WebMainBench 545 页子集和 WCXB 开发集固定分层样本。**两版均完整运行 745 页；质量均值使用 739 页有效参考，新增付费 API 调用为 0。**

最新冻结版是 `trafilatura-native-markdown-v1`。它的正文提取 Precision 较高，主要短板是正文遗漏、非文章页面、短页门槛和表格保真。原生 Markdown 相比开始时的 XML 再渲染版，正文均分基本持平，多行多列表格的单元格 F1 与行列关系有所改善，但仍有明显缺口。

## 数据与配置口径

- [WebMainBench 数据](https://huggingface.co/datasets/opendatalab/WebMainBench)：完整读取 545 行校准子集，只将 `groundtruth_content` 用作参考。实际语言标签为英文 416、中文 27、未知 94，其他语言 8；页面类型 `style` 全部为空。不能将全量数据集的语言比例套用到这个子集。
- [WCXB 数据](https://github.com/Murrough-Foley/web-content-extraction-benchmark)：从 dev 按 7 类近似等额抽 200 页；article、collection、documentation、forum 各 29 页，listing、product、service 各 28 页。每类排序后使用 `20261018+类别序号` 的种子打乱，**在评分前冻结选样**，test 未用于本轮调参或评分。
- WCXB 200 页中有 6 页 `main_content` 为空，且必含/必排片段也为空。200 次读取尝试全部保留，**正文质量均值排除这 6 页，采用 194 页**。未按结果好坏补抽或删题；编号见最终核验和空金标复核记录。
- 两版采用同一批去除标注的 HTML，739 个有效样本逐页 SHA-256 配对一致。移除 `cc-select`、标注 class 与注入样式，未将正文金标或其选择标记传给读取器。
- 参数：最短正文 500 字符，默认字符预算 30000；另取同一次抽取的放宽上限结果，诊断预算损失。表格延伸保护可能令输出略超预算，不强行截断到等长。
- Python 3.11.14；Trafilatura 2.2.0、BeautifulSoup 4.15.0、lxml 6.1.2。其他版本、参数来源与源码哈希全部保存。

本轮是**已获得 HTML 条件下的离线链路复放**：执行冻结 `_extract_html`、正文清理、字符预算及 `_validate_body`，通过 `_read_uncached` 保留程序结果；下载阶段由冻结字节替代，浏览器请求仅计数并返回不可用。全程阻止 socket 连接，没有运行浏览器、OCR 或 LLM 裁判。因此本文的“接纳”是离线静态轨道的状态，不是线上 URL 成功率，也没有测到真实 JavaScript 渲染和反爬恢复。

## 版本冻结和同次复评

初次冻结为 `trafilatura-xml-body-v1`。运行期间，工作区另有并行工作将读取实现改成原生 Markdown；本评估没有修改业务读取文件。因此又冻结 `trafilatura-native-markdown-v1`，使用同样输入补跑全部 745 页，以它作为本文主要结果。

复评冻结后，工作区预算函数又增加了代码围栏保护。保留冻结源码后，对全部 745 页保存的完整抽取结果分别应用两版预算函数，涵盖提取后与读取清理后两次预算处理，结果逐页零差异。因此这个后续补丁未改变本轮样本的生产输出、门禁状态和评分；这不代表已验证补丁在所有网页上的等价性。见[运行后预算补丁等价核验](../backend/eval/data/网页读取链路公开基准评估-20261018-原生Markdown复评/运行后预算补丁等价核验.json)。

同次评分复核日期为 2026-10-18，具体变更是：

1. 嵌套 HTML 表格取叶子表，另外报告至少 2 行、2 列且 4 个非空单元格的子集，减少单格文章布局对结果的干扰。
2. 支持原生 Markdown 中没有 GFM 表头分隔线的管道表，按原有管道行列解析，避免将其误判成散文。
3. 参考中没有某类行列关系的页面，不参与该关系指标的宏平均；6 页空正文金标不参与正文质量均值。

原始评分、表格口径修正前结果及空金标口径修正前汇总均有存档，未覆盖历史运行。最终两版采用相同评分口径。见[配对比较](../backend/eval/data/网页读取链路公开基准评估-20261018-原生Markdown复评/两版配对比较.json)、[本次评分口径复核](../backend/eval/data/网页读取链路公开基准评估-20261018-原生Markdown复评/同次运行评分口径复核记录.json)、[首轮空金标复核](../backend/eval/data/网页读取链路公开基准评估-20261018-首轮/空金标评分复核记录.json)。

## 正文完整性与噪声核心指标

正文先规范化为可见文本，使用 Unicode 规范化、英文词与汉字词元的多重集合计算逐页 Precision、Recall、F1，然后做宏平均。另报连续 5-gram Recall 和编辑相似度，减少词袋指标对顺序损坏的不敏感。**Recall 是参考词元召回，不是“完整网页比例”；1−Precision 也不是经过语义标注的真实噪声率。**

| 最新冻结版输出口径 | 数据集/有效页数 | Precision | Recall | F1 |
| --- | --- | --- | --- | --- |
| 生产预算、门禁前 | WebMainBench545 / 545 | 92.27% | 73.34% | 77.85% |
| 离线最终接纳输出，未接纳计空 | WebMainBench545 / 545 | 81.79% | 66.37% | 70.14% |
| 生产预算、门禁前 | WCXB分层200 / 194 | 82.31% | 58.14% | 62.14% |
| 离线最终接纳输出，未接纳计空 | WCXB分层200 / 194 | 73.54% | 56.10% | 59.22% |

WebMainBench 离线接纳 472/545，WCXB 接纳 162/200；后者 6 页空参考单独保留状态，不能把这个状态比率当成正文质量。非空预测上的“参考外词元比例”分别为 7.22%（542 页）和 14.15%（186 页），仅是污染代理指标。

WCXB 使用官方字面片段检查：必含片段命中 376/891＝42.20%；必排噪声片段残留 16/756＝2.12%，出现在 13/194 页（6.70%）。将 Markdown 转为可见文本并归一化空白后，必含命中 436/891＝48.93%；噪声仍为 16 个、13 页。字面命中受格式与换行影响，不能将两版必含片段的下降全都解释为正文丢失。

参考自身也存在 11 个必含片段字面不在主参考、3 个必排片段却出现在主参考的冲突。首轮敏感性核对剔除这 3 个冲突噪声标记后仍为 16/753，13 页，未改变主要噪声结论；没有静默修改官方标注。WCXB 原始 word F1 另行保存，并逐页与官方实现核对 200 页全部一致，不能与本项目可见文本 F1 或 WebMainBench 官方综合榜单混用。

## 表格保留

元数据标为含表格的有 179 页，但校准参考中可解析的叶子表为 80 页、199 张；其中符合多行多列条件的有 **57 页、102 张**。本文主表格结论以这 57 页为分母。它仍混合数值表、词典、参数说明、元信息和代码行号表，不能等同于行业财务表格专用评测。WCXB 的主参考为纯文本，本轮不为它编造结构金标。

| 门禁前、生产预算下的表格指标 | 首轮 XML 再渲染 | 最新原生 Markdown |
| --- | --- | --- |
| 严格非空单元格完全匹配 Recall | 50.09% | 51.15% |
| 严格单元格 F1 | 45.86% | 52.17% |
| 横向相邻单元格关系 F1 | 41.10% | 45.27% |
| 纵向相邻单元格关系 F1 | 39.91% | 47.16% |
| TEDS 风格内容与结构相似度 | 44.03% | 51.60% |
| 纯结构 TEDS 风格相似度 | 47.05% | 54.39% |
| 预测中没有可识别表格的页面 | 21/57 | 20/57 |

严格单元格匹配要求规范化后整格相等，局部改字、空白或内容搬移会降低分数。行列关系检查相邻格的对应关系；多表通过词元相似度和 Hungarian 匹配配对，阈值 0.1。树编辑指标使用本地 APTED，显式考虑行列跨度；这是本项目诊断指标，**不是 WebMainBench 官方 TEDS 榜单复现**。为控制开销，超过 250 节点或单项超过 3 秒的配对不计算树编辑指标；3 页因节点上限被排除，TEDS 均值分母为 54 页，其他表格指标仍使用全部 57 页。

最新输出中，表格词元在全文里的 Recall 为 69.00%，真正位于预测表格内的 Recall 为 52.74%。这解释了为何“还能找到数字或词语”不足以证明表格保留。

## 字符预算与准入门槛

| 数据集 | 放宽上限 Recall | 生产预算 Recall | 发生截断页数 |
| --- | --- | --- | --- |
| WebMainBench545 | 77.08% | 73.34% | 48 |
| WCXB分层200 | 58.65% | 58.14% | 7 |

放宽上限只改变输出预算，不更换抽取算法。WebMainBench 受长文预算影响更明显；即使放宽上限仍有缺口，不能把所有遗漏都归因于截断。

此外，最新版本有 25 页 WebMainBench 和 1 页 WCXB，门禁前 F1≥85%、非空但少于 500 字符，最终在本离线轨道未接纳。这是短页门槛的明确信号；线上浏览器有无补救尚未测量，不能外推为同数量的线上误拒。

## 局限性、结论与下一步

**已测量**：739 页有效参考的正文与片段指标、745 次尝试的程序状态、57 页多行多列表格指标、预算影响、固定 HTML 的两版配对差异。739 个有效配对的输入指纹一致，全部 745 页输入未残留 `cc-select`，评分无异常；前 3 页还验证了离线适配与生产提取函数直接调用一致。

**间接推断**：论坛与列表等非文章类型需要不同主体选择策略；短页可考虑长度与结构质量联合准入；表格应保留单元格内部段落与跨度。当前 `include_comments=False` 可能与论坛多帖漏失有关，但本轮没有做参数消融来证明因果。

**尚未评估**：真实 HTTP 可达率、反爬与浏览器渲染、PDF/Office/OCR、图片中的数字、真实网页更新、模型对结果的理解、独立人工语义噪声率。本轮只测 HTML；精确匹配依赖参考和规范化规则，语言小样本、布局表和参考中的垃圾拼接内容都会影响泛化。两个数据集分布不同，不能将它们简单合成一个“整体成功率”。

建议先处理非文章页面主体范围和短正文门槛，并将表格单元格/关系回归固定下来；对预算受限长页提供可追溯的分段读取。随后再用业务 URL 建立在线轨道，才能把“拿不到页面”和“拿到后提取不好”分开归因。本轮结果支持原生 Markdown 在部分表格关系上的改善，尚不支持宣称整体正文质量或线上可用率显著提升。
