# 旧输入历史引用化与单条摘要改造验证

评估日期：2026-09-28。评估对象：旧`llm_input`的资料引用化、单条摘要派生视图、缓存复用、原文保留与总体预算控制。此次没有重跑线上五题，没有调用付费模型，没有修改真实.env、重启服务或提交Git。

## 改造行为与配置口径

原始消息仍完整保存在原有历史表中。后续请求仅改变回放视图：先将能够精确对应到已保存工具正文的资料替换为来源编号及回读偏移，再对仍超过单条阈值的输入生成摘要。当前输入、未完成调用和中断输入不做单条压缩。

引用替换仅处理现有“已读取正文”“摘要/搜索摘要”“文档内容”栏目。工具来源必须属于同一run/agent/subtask、时间早于该输入，正文或前缀逐字匹配，且通过内容哈希与实际读取权限检查。无法确认来源时保留原文，不按相似度删文。匹配之外的全部文本保持原样。

单条摘要使用已有摘要、引用补齐和核验链路。已经引用化的内容先以`input_history_source`独立保存，带原始输入ID、哈希和资料索引，再根据该快照生成摘要；无引用替换时直接基于原始输入。它属于任务输入派生资料，不能当作新的医学证据来源。整体历史摘要仍读取原始历史，不反复总结单条摘要。

成功结果保存为独立`input_history_view`，不覆盖原消息，也不推进整体摘要的覆盖游标。缓存绑定源记录、去重视图、资料索引、配置、模型、提示词和当前约束，并在读取时校验哈希、来源与引文。格式或核验失败、摘要没有缩短时保留原视图；权限、持久化和取消异常继续上抛。

新增`input_history`配置的工程初值：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| version | input-view-v1 | 历史输入视图版本 |
| reference_materials | true | 资料引用化，还受artifact_offload总开关及可回读能力控制 |
| summarize_long_inputs | true | 单条摘要，还受semantic_summary总开关控制 |
| min_reference_tokens | 128 | 可替换资料的最小长度，且替换需确实缩短 |
| summary_trigger_tokens | 4000 | 去重之后单条输入的摘要触发阈值 |
| max_summaries_per_request | 2 | 每次主模型请求准备时最多尝试生成的新摘要数 |

其余记录不会因达到生成次数上限被丢弃；后续整体摘要阈值和硬预算仍检查完整请求。全局摘要采用前改为与当前已缩短视图比较，防止替换后反而增加上下文。

8个新框架消融配置冻结同一组参数，并由原外置/摘要总开关控制。去摘要组不生成、不使用缓存摘要；无压缩基线两条路径都不执行。旧快照缺少该字段时保持原哈希与行为；显式null的快照也保持其哈希。新建环境配置运行默认启用，现有冻结运行不追溯切换。可通过两个子开关进行补充消融。

## 机制回归结果及失败修正

首次执行131项，121项通过、1项失败、1项错误、8项跳过。失败为新测试构造的总历史不足以触发整体摘要；增加记录数量后验证真实触发路径。错误为新增可选字段显式null时被序列化器删除，导致旧快照模拟的哈希不一致；修正为区分字段缺省与显式null。首次输出未覆盖。

同日补充4项测试并复评：135项，127项通过、0失败、0错误、8项跳过。跳过均为需显式启用独立PostgreSQL的集成测试。模型输出使用桩，不能当作真实模型质量评测。

覆盖的机制包括：

- 只替换资料栏目，保留任务文本及当前输入；无来源、不匹配、来源时间晚于输入时保留。
- 来源JSON中的引号和换行转义对应正确回读偏移；哈希损坏、权限不符时拒绝采用。
- 未完成/中断输入保护，原始消息与全局覆盖游标保持不变。
- 摘要独立保存、缓存命中、当前约束改变后失效、去摘要组禁用复用。
- 去重派生快照实际通过现有摘要正文与引用补齐入口，引用能够定位到可读取的派生来源。
- 无效摘要回退、摘要尝试数量限制、取消传播、整体长度触发整体摘要、硬预算仍拒绝超长输入。
- 既有独立历史、分块预算、消融配置、引用核验链路和本地NLI机制回归。

任务25替换比例最高，任务8替换后单条最大为3,088 token。所有17条输入引用化后都低于4,000 token，所以这批真实记录没有触发单条摘要；单条摘要路径的验证来自机制测试，不能据此报告真实生成成功率。

另一个首次摘要前快照口径：任务8/25/26/27均没有旧输入记录；任务28有2条，从7,212 token降至3,697 token。该结果说明引用化不能替代原先的工具正文分块修复：首次失败点可能根本尚无可处理的旧输入。

## 已测量、间接推断与尚未评估

**已测量**：最终机制测试127通过/8跳过；17条真实输入的89处精确替换及token变化；替换外文本不变；原始记录不变；离线替换不调用模型API。

**间接推断**：资料引用化能够减少这批历史输入的重复正文占用；缓存能够避免相同输入与相同配置下反复生成同一摘要。不能把输入文本缩短比例等同于整任务费用、延迟或成功率的改善。

**尚未评估**：真实单条摘要的信息保留率、数字日期与旧约束处理质量、NLI真实放行质量、4000/128阈值最优性、真实回读次数与最终报告质量、线上五题完整多轮成功率、PostgreSQL端到端集成。当前服务未重启；旧运行仍遵循冻结配置。

## 局限与下一步

自动引用化保守地识别现有资料栏目，且只使用当前加载历史中可找到的工具来源。已被全局摘要覆盖、未加载的工具记录，或改写过的正文不能保证匹配；不会为提高替换率盲删文本。未来可在构造提示词时直接记录精确来源区间，扩大覆盖范围。

单条摘要仍可能丢失信息，需通过真实模型和人工标注验证；在线核验通过不等于医学事实正确。单条摘要失败会保留视图，后续仍可能因总预算超限而报错。

本次实现已完成并通过离线机制验证。下一步应冻结源码与新配置，在相同快照上分别验证“仅引用化”“仅单条摘要”“两者同时开启”，测量信息保留、总请求token、回读开销和最终任务完成率，再决定是否调整初始阈值。
