## 数据结构与最终实现

`detail`是前端`ResearchDetailData`类型的对象，定义在[研究详情组件](../frontend/src/pages/chat/component/research-detail/index.tsx)。页面的`researchDetailsRef`以步骤类型为键保存这些对象。它包含步骤标识、搜索结果、图谱、图表、章节`sections`和报告正文`streamingReport`。

本次按用户要求，以`researchDetailsRef.current.get('writing')`作为报告面板的详情来源：

1. 删除页面独立的`medicalReport/setMedicalReport`状态。
2. `GraphWorkbench`及现有医学记录工作台接收`detail`，正文读取`detail.streamingReport`。结果接口返回的正文先写入写作详情，面板不直接读取`bundle.final_report`作为另一个正文来源。
3. 首次发起收到`section_content`，按章节ID更新`detail.sections`，从章节集合生成`detail.streamingReport`，递增页面版本以更新报告面板。同章节新序号到达时，更新该章节而不继续叠加旧正文。
4. `report_chunk`、`report_draft`及`research_complete`通过`updateReportDetail`更新写作详情；没有提前章节的完成事件也会创建该详情。
5. 结果读取、刷新及恢复投影写入同一写作详情。运行中的旧快照仍保留已收到的较长正文，避免空快照抹掉过程正文；该判断沿用原有长度口径。
6. 切换研究版本、新建研究或切换会话时清空当前详情，防止复用上一份报告。报告面板的memo显式依赖`researchDataVersion`，保证只有正文详情变化时也会更新。

修改涉及页面、两个报告工作台、详情类型注释及相关测试/预览夹具；没有修改后端接口、协议格式或检查点逻辑。

## 失败样例与复评说明

初次27项中，既有19项通过，新增8项均在调用实际工作台函数时失败，代表报错为`GraphWorkbench ... React is not defined`。原因是新增VM测试用自定义`jsx`函数替换渲染边界，但未配置JSX Fragment标识；组件中的`<>...</>`被编译为引用不存在的`React.Fragment`。

修正测试编译选项`jsxFragmentFactory`并提供对应VM标识后，相同27项全部通过。没有为使测试通过而改变业务实现或恢复旧正文状态。初次失败属于测试运行器配置错误，不能算作线上SSE或正文交付失败。
