## 原有机制与本次修改

修改前，`CitationVerificationOptions` 的两个阶段默认均关闭，仅能通过请求打开。Writer 已在报告组装和修订流程调用 `verify_stage_citations(state, "report_claims")`，无需另外添加 Writer 核验器。

本次在 `citation_verification.py` 增加首跑配置解析，在 `service._graph_input()` 首跑入口使用它，并更新 API 描述、`.env`、`.env.example` 和后端说明：

```dotenv
RESEARCH_WRITER_CITATION_VERIFICATION_ENABLED=true
```

未传 `citation_verification` 时读取部署开关；显式对象完整决定两阶段，未指定阶段仍为关闭。因此 `{"scout_facts":true}` 只开 Scout，`{}` 或 `{"report_claims":false}` 都关两阶段。非法环境布尔值拒绝执行，不静默切换。

运行首跑保存开关和 NLI 参数，技术续跑继续读取该快照，不受后来环境变化影响。阶段执行函数与历史检查点的无配置默认仍为关闭。已有研究不会被追溯修改，也没有为旧报告补做核验。

当前审计按 Writer 给出的 `document_id/sentence_ids` 从已保存正文回读原句，避免接受模型编造的引句。非法绑定记录 `invalid_citation`。正文非空与来源范围检查仍是独立的确定性检查；语义审计不自动改变其发布结果。

## “严格依据证据写作”还缺哪些能力

以下来自源码检查与机制推断，没有在本轮用真实 Writer 报告测量：

1. **正文覆盖**：只检查 Writer 自报的 claims；少报一条或把强论断改成较弱声明，都可能避开核验。提示词要求覆盖全部事实，不能代替独立覆盖检查。建议从最终正文、执行摘要、结论、展望和表格独立抽取原子论断，再对齐声明和原文跨度。
2. **抽取保真**：独立抽取也可能改变论断，须保留正文位置和主体、时间、数字、单位、否定、比较与条件，先判断子论断是否忠实于原句，不能为了让核验通过而删掉限定词。
3. **充分证据组合**：当前不同非连续片段分别核验；存在多原句或多来源联合才充分的命题。单对低支持不能直接解释为内容错误。
4. **冲突解释**：当前聚合规则为“任一高支持且无高矛盾”；应进一步确认反证是否同实体、同时间、同条件。没有提及不是明确反证，真实来源冲突也不能仅由更新日期裁决。
5. **计算与推断**：程序推导数值应核验输入来源、单位、公式与计算结果；意见和趋势推演应标为推断、列出前提。普通 NLI 不替代这些检查。
6. **边界与性能**：NLI 分数未校准；中文长句、术语、数值范围、表格和跨句指代需要人工标注验证。模型超时、资源繁忙、超长或超过256对是执行问题，不能当成事实错误。

即使所有声明均 supported，仍不能证明正文无遗漏、现实事实正确或每个多余引用都恰当。`passed` 与 `needs_review` 也应分别读取：有一条充分支持同时有其他不足引用时，聚合可能通过但仍需要复核。

## 建议的失败论断处理策略

本节是基于文献与当前机制的工程建议，**未实施、未测量收益**。建议流程：独立抽取与保真对齐→核验原引用→诊断失败原因→有限证据复核→局部修订→重新抽取并核验。先复核证据完整性，再决定是否改变正文。

| 失败类型 | 优先动作 | 仍未解决时的处理 |
| --- | --- | --- |
| 编号不存在、引用选错，但内容可能正确 | 在已保存原文范围内重新定位编号；核验新绑定 | 明确记录引用无效，不改成 supported |
| 多句联合可支持，单句不足 | 补齐同实体、同时间和同条件的最小充分原句组，再核验 | 进入证据不足或待复核；不能把被拼接片段伪称为连续原文 |
| 证据只支持较弱命题 | 精确指出被夸大的范围、因果、程度或人群限定，局部收窄正文并复核 | 保留可证实部分，将证据不能支持的子论断移出正式结论 |
| 明确与证据矛盾 | 确认主体/时间/条件一致后，修正年份、数字或关系并复核 | 不把矛盾事实继续作为结论；保存修改前文本与诊断 |
| 检索不到充分证据 | 若它是用户任务必需信息，进行一次定向补证；新增来源经过正文读取和准入后才能使用 | 表述“现有证据不足以支持X”；对非关键附加事实可删除，对核心问题保留证据缺口说明 |
| 真实来源冲突 | 并列展示冲突及各自适用口径，查更正/版本关系 | 标记未决，避免挑选有利来源强行通过 |
| 原子抽取改坏正文 | 修复抽取与位置对齐 | 标记 invalid_claim 或待复核，不为了错误的抽取结果改正文 |
| NLI低置信、超长、超时、模型繁忙 | 同范围语义复核或受控重试；报告执行失败类型 | 标记未核验/待复核，不判内容为假；暂时审计模式仍按现有流程交付 |
| 建议、归因推演、程序计算 | 显式标为推断/计算，检查其前提、原始输入、公式和单位 | 不伪造一条来源原句来支持推导结论 |

单纯在无证据句前加“可能”“据悉”不能修复引用支持性；措辞收窄仍须有相应证据。建议首版只允许一次补证和一次局部修订，按正文跨度修改，并在修订后对修改段落及摘要/结论的关联重述重新核验，防止新错误。重拼正文后重算报告哈希和引用目录，不能沿用旧版本的通过审计。

这一分流建议与本仓库既有[证据组合与冲突复核方案](引用核验证据组合与冲突复核改造方案及验收口径-20261003.md)相衔接；本轮没有重新计算该历史评估的指标，也没有把摘要失败比例当作 Writer 误拒率。

## 局限性、结论与下一步

- **已测量**：开关默认与覆盖、冻结配置、现有83项机制回归、四条构造论断的真实NLI路径、原对象保留和服务重启。
- **间接推断**：新进程中的新研究将由已验证的首跑代码冻结为 Writer 开启；健康检查与 OpenAPI 读取本身不能代替实际整题研究。
- **尚未评估**：正文独立抽取与覆盖、语义核验校准、中文长报告误拒/漏放、真实 writer 成本、自动补证与修复、论文系统的本地复现。
- 所有自动处理分流均为方案，当前行为仍只审计，失败结果不会自动触发删句、改稿或发布拦截。

下一步优先采集少量真实 Writer 报告，由人工独立列出需要证据的原子论断并标注原文支持关系。按漏报、错误绑定、部分支持、矛盾、联合证据、推断/计算、执行失败分层，再比较“只审计”“复核后局部修订”“过滤失败语句”三种策略。

至少同时统计：论断覆盖率、核验精确率与召回率、误拒/漏放、关键内容保留、修订引入的新错误、用户问题完成度、引用精确率、时延和模型调用/token成本。过滤方案必须同时看重要信息召回，避免仅靠删除大量内容获得更高支持比例。指标、人工金标、原始模型返回和修订轨迹都应按新运行落盘。
