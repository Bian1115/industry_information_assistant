# 摘要分句编号与引用编号协议改造验证

改造与评估日期：2026-10-02。评估对象：摘要程序分句、候选消息编号选择、程序恢复原句及 Claimify 原子化核验的接口。结果目录：[摘要分句编号引用协议验证-20261002-231352](../backend/eval/data/摘要分句编号引用协议验证-20261002-231352)。

## 协议与职责

采用程序给摘要分句编号、模型仅返回分句编号及引用消息编号的方案。正文生成仍输出已有三栏目自然语言摘要；引用选择阶段不再要求模型抄写、改写或提取原句。

新链路为：程序分句并保存位置 → 模型关联候选消息编号 → 程序恢复原句及位置 → Claimify 筛选、消歧、拆解 → 为子论断分别选择证据并运行 NLI，证据不足时沿用临时检索。

输出格式只有：

```json
{"citations":[{"sentence_id":"输入中的完整摘要分句编号","source_ids":["本批输入中的相关消息编号"]}]}
```

模型不返回栏目、claim、text、quote、字符偏移或排除原因。程序目录保存每个分句的原文、栏目、起止位置和摘要哈希。相同句子在不同位置有不同编号；同一摘要在多个证据批次中保持相同编号。摘要文本变化后编号随哈希变化，拒绝旧摘要的编号误用。

必须恰好返回每个分句一次，缺少相关消息时返回空来源数组。纯目标或待办也保留编号映射，由 Claimify 继续筛选，避免引用选择模型通过省略行丢掉待核验事实。缺证据不等于没有事实，更不等于核验通过。

这能消除新路径中“模型原句与摘要原句不一致”的位置绑定环节。程序分句是标点边界划分，不等于语义原子化；一句仍可能有多个事实或指代，Claimify 的职责仍然必要。

## 实现范围

- [新分句编号目录、解析及合并](../backend/app/service/summary_sentence_citations.py)：校验固定编号、完整覆盖、重复项及本批消息范围，按稳定编号合并来源，恢复原文和位置；绑定阶段没有模型调用。
- [新引用选择提示词](../backend/app/prompts/摘要论断与消息编号.txt)：只输出编号，逐一覆盖目录。
- [引用请求构造及证据分批](../backend/app/service/summary_message_verification.py)：传入分句目录，证据分块不重新编号；无上下文证据时也发出一个空证据批次，保留缺证据的分句。
- [原子化生产审计](../backend/app/service/summary_atomic_citations.py)：采用新编号协议，子论断来源链保存父分句编号和摘要哈希。
- [绑定入口](../backend/app/service/summary_claim_binding.py)：新编号协议直接恢复原文，语义绑定和定向修复调用次数均为 0。
- [已有轨迹评测入口](../backend/eval/scripts/评估已有轨迹摘要与引用.py)：`--claimify-atomic` 路径使用编号协议，候选数量按程序分句数记录，原子论断数量单独记录。

生产仍由已有的 `claimify_enabled` 和 `atomic_citations` 配置选择审计路径，本次未修改这些开关的值。编号协议的公共核验入口要求 `claimify_atomic=True`，避免将目录里的纯计划直接送入普通事实 NLI。

旧文本型协议保留显式回放能力：[旧版提示词](../backend/app/prompts/摘要论断与消息编号旧版.txt)。未启用原子化的历史评测及 [补跑超限轨迹脚本](../backend/eval/scripts/补跑超限轨迹摘要.py) 显式使用 `numbered=False`。历史结果和冻结配置未覆盖。新生产原子化路径不再要求候选模型输出原句。

## 已测量结果

15 个相关模块共 203 项机制测试通过，0 失败、0 错误、0 跳过。修改的 8 个 Python 文件语法检查通过。真实模型调用次数为 0。

新增 [14 项编号协议测试](../backend/test/test_摘要分句编号与引用映射.py) 覆盖：

1. 相同句子在不同位置的唯一编号、稳定性和准确偏移。
2. 新模型输入目录与仅编号输出职责。
3. 恢复原文无需精确文本匹配、语义判断或模型修复。
4. 未知或其他摘要的编号拒绝。
5. 遗漏、重复和额外正文/quote 字段拒绝。
6. 引用仅限当前证据批次提供的消息编号。
7. 跨批候选合并及无证据空数组保留，坏批次不产生部分更新。
8. 无证据上下文仍保留全部摘要分句。
9. 证据长文本分批时摘要编号保持一致，输入预算检查有效。
10. 编号路径要求 Claimify 筛选后核验。
11. 复合句拆成两条原子论断，分别对应 m1、m2；纯待办被 Claimify 排除且不进入 NLI，子论断保留父编号及原句。
12. 无效分句编号在 Claimify 和 NLI 调用前失败。
13. 生产审计模拟调用确实请求及接收仅编号输出，原文和引用映射完整。
14. 显式旧协议回放仍可运行。

上述调用均使用模型桩。绑定模型调用次数为 0 是本协议的机制测量；核验通过是模拟结果，不能解释为真实准确率。

## 首次失败与修正

首次新增测试为 14 项，13 项通过、1 项失败。失败的生产审计夹具用字符数量代替 token 数量，并沿用 32768 窗口和 20000 输出预留，使 17725 字符的 Claimify 拆解提示词超过剩余输入预算，系统正确返回未完成。

仅将该模拟夹具的窗口显式设为 65536、输入上限 64000；生产预算及检查逻辑没有修改。随后全部 203 项回归通过。首次结果仍保留，不能把它解读为真实 tokenizer 下的生产超限测量。
