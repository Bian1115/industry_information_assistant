# 已有轨迹模型动态路由核验结果及分析

评估日期：2026-11-01，Asia/Singapore。

评估对象：研究报告经过审核后，由模型意见和程序规则共同决定的“补搜、直接修订、质量通过”三种动作。这里不讨论会话入口路由，也不讨论不同大模型之间的选型路由。

**本轮对两批历史轨迹的20次审核新增逐轮动作标注。剔除6次返工额度用完的强制停止，再将4次存在两种合理动作的状态单列，剩余10次唯一动作可判定样本：正确路由比例30.00%，错误放行率100.00%（仅1次放行），补搜精确率33.33%，补搜召回率75.00%，直接修订精确率不适用，直接修订召回率0.00%。**

这些数字依赖本轮单一AI审读者的判断，不是人类金标，也不是当前新版模型的准确率。两批运行的模型与审核职责不同，合并数字仅用于描述这份历史样本，分批结果在下文列出。若接受4次非唯一样本中的任一合理动作，动作命中率为50.00%（7/14）；此时“补搜可接受性精确率”为53.85%（7/13），不能把它解释为“必需补搜精确率”。

## 二、如何恢复真实路由，避免把不同对象混在一起

提取脚本先从每题的`智能体原始历史.json`配对审核模型的输入、实际请求和输出，再从`完整检查点历史.json`取得审核前后状态。每轮以**当时完整报告**为判断对象，核对它确实进入了模型请求，并核对审核前后检查点中的报告一致。

程序读取的来源正文不直接采用最终材料全集。脚本先读取审核前检查点中的来源ID及正文SHA256，再从保存正文中恢复对应内容：20轮累计625条来源记录全部恢复且哈希匹配，按正文哈希去重为269份。后轮新增材料不会被拿去解释前轮为什么“不需要补搜”。这证明材料版本对齐，不表示269份正文的全部事实均经独立核实。

实际动作以审核后检查点为准：

1. `re_researching`表示程序把任务交给Scout补搜。
2. `revising`表示程序直接交给Writer利用已有资料修订。
3. `completed`且`quality_verdict=pass`才算质量通过。
4. 未通过、返工次数达到上限后`completed`，单列“额度停止”。

13次补搜均找到对应时间窗口内的真实搜索工具调用，调用数量与待执行任务数量一致。原始历史按智能体上下文分组，脚本使用事件时间定位后续调用，不能按JSON数组相邻位置推断执行先后。模型查询和工具实际查询分别保留；部分`site:`限制没有出现在实际查询字符串中，本轮不把数量一致宣称为查询语义完全一致。

本次统计单位是**一份报告审核后的下一步动作**。同轮有两条补搜意见，仍只算一次补搜路由。补搜之后Writer再写报告，也不算选择了“直接修订”。

## 三、独立动作标注口径

评审者是本轮Codex主代理，阅读了原题、当轮报告、已有来源和模型输出，也参考了历史意见复核。因此是新增动作标注，但**非盲评、非人类金标、非双人独立标注**。没有把历史意见正确率直接换算成路由正确率。

| 标签 | 判定原则 |
|---|---|
| 通过 | 核心要求已经满足，没有阻断问题；可选扩展不阻断。 |
| 直接修订 | Writer利用已有资料即可修正关键逻辑、范围、单位、引用或结构；允许撤回用户未要求的无支持断言。 |
| 补搜 | 保留原题核心要求时，仍缺必要的比较、实证或关键政策依据；需Scout继续获取材料，再交给Writer。 |
| 补搜 / 修订均可 | 继续补证据合理，利用已有资料改写并明确结论边界也合理；不强迫指定唯一标签。 |

“已有引用不支持”不自动等于必须补搜。例如无依据的18%降本数字不是原题要求的交付内容，Writer可以删除；用户明确要求评估“目前最好的算法”时，不能只把“最好”改成“举几个例子”就认为核心要求完成。

同样，评审不能因为全球联合需求统计暂缺，就强制要求模型给一个比例。正畸与医美题既可以继续查找同一样本的联合调查，也可以清楚说明现有材料无法估计该比重、修正过度推断。这类分歧保留为可接受动作集合。

本轮报告状态均存在阻断问题；没有独立标为应直接通过的样本。因此尚不能评估“本应通过却被返工”的过度拦截能力。

## 四、六项指标：主口径

主口径包括10次“未被额度强制停止、且能给出唯一动作标签”的审核状态，占14次可执行决策的71.43%。4次动作非唯一状态不放进标准三分类的精确率、召回率分母。

| 指标 | 分子 / 分母 | 结果 | 本次含义 |
|---|---:|---:|---|
| 正确路由比例 | 3 / 10 | **30.00%** | 程序最终选择的动作等于独立动作标签。 |
| 错误放行率 | 1 / 1 | **100.00%** | 程序判通过的报告中，仍有阻断问题的比例；只观测到一次放行。 |
| 补搜精确率 | 3 / 9 | **33.33%** | 这9次实际补搜中，3次被标为确需补搜。 |
| 补搜召回率 | 3 / 4 | **75.00%** | 4次被标为需补搜的状态中，3次触发了补搜。 |
| 直接修订精确率 | 0 / 0 | **不适用** | 没有一次实际选择直接修订，不能写成0%或100%。 |
| 直接修订召回率 | 0 / 6 | **0.00%** | 6次已有材料足以修正的状态，都没有进入直接修订分支。 |

精确率看“已经选了这个动作，其中多少选得对”；召回率看“确实需要这个动作的状态，其中多少被正确送过去”。这里的召回率是**动作类别召回率**，不是报告中所有真实问题的发现召回率。

混淆计数如下，行表示评审认为应该采取的动作，列表示程序实际动作：

| 应采取的动作 \ 实际动作 | 通过 | 补搜 | 直接修订 | 合计 |
|---|---:|---:|---:|---:|
| 通过 | 0 | 0 | 0 | 0 |
| 补搜 | 1 | 3 | 0 | 4 |
| 直接修订 | 0 | 6 | 0 | 6 |

**主要观察是把可直接修订的报告送去补搜，而不是程序分支没有执行。** 6/6应直接修订状态被补搜；在此样本上，补搜触发得多并不代表补搜选择准确。

## 五、多种动作均合理时，结果如何变化

4次非唯一状态为20261009的49题第1、2轮，以及20261017的31题第1、2轮；程序均选择补搜。

- 正畸与医美：补联合需求证据合理；诚实说明无法估计、撤回强共现结论并提出调查方案也合理。
- 博物馆教育：可以补充保留国别和各类教育实践；也可利用已有2026年论坛实例、分类资料重组报告，解释案例代表性，删除用户没有要求的扩国内容。

允许动作集合中的任意动作时，14次可执行决策中7次命中，**动作可接受率50.00%**。实际13次补搜中7次属于可接受动作，**补搜可接受性精确率53.85%**。这四次没有被证明“非补搜不可”，所以此宽口径不能替代主口径的必需补搜精确率；必需补搜召回率仍为3/4，直接修订召回率仍为0/6。

如果另一位评审坚持给4次状态各指定唯一标签，共有16种组合。将这14次全部纳入后，路由正确比例可在21.43%—50.00%之间，补搜精确率可在23.08%—53.85%之间，补搜召回率可在75.00%—87.50%之间。这是**标签选择的敏感性范围，不是统计置信区间**。完整枚举保存在[非唯一路由口径敏感性.json](../backend/eval/data/已有轨迹动态路由核验-20261101/非唯一路由口径敏感性.json)。

还有一个需要第二位评审重点复核的唯一标签：16题第2轮。本次保留“目前最好的算法”这一要求，认为仍需比较依据，标为补搜。如果认为当时新增论文已足够供Writer重写，改标直接修订，**它仍是错误放行**，但必需补搜召回率会从3/4变为3/3，直接修订召回率变为0/7。这里不隐藏动作标签的主观边界。

## 七、失败样例与模型/程序区别

### 1. 有材料可改，程序却重复补搜

20261017污水第2轮，模型原始总评为pass，当轮新问题只要求修正摘要范围。但程序问题账本仍保留前轮LCC与成本比例问题，继续发出两条原查询。轨迹既保存了`pending_research_tasks`，也保存了实际搜索调用；不能仅从当轮`requires_new_search=false`推断程序直接修订了。

独立审读认为，当轮最重要的问题是第3章“应急无可靠统计”、第5章“10%—15%”及预算核价建议互相冲突。Writer可以撤回未经支持的比例，并按原题整理本地测算框架。历史账本的严格摘录匹配还会让语义上已经完成的修改无法关闭，从而持续触发旧问题。这一历史机制在20261018已记录修改，本次不把它当成当前未修复问题。

### 2. 唯一实际放行，仍缺任务核心依据

20261009非接触感知第2轮得到程序pass，但报告仍使用“顶尖”“最高准确率”，没有说明领先算法的选择标准；把不同任务的检测率、相对精度增益和距离偏差并列，也不足以证明最优。已有ShadowSense来源明确包含掌触、拳打、拥抱等接触动作，更需要划清“传感器不接触”和“用户动作非接触”的范围。

所以本轮把它判为错误放行。1/1只能说明这一例不该通过，不能宣称真实系统总体错误放行率就是100%。

### 3. 搜索方向可以接受，不表示每个搜索词选对

49题实际搜索主要围绕医美年龄分布、正畸动机、隐形矫治市场份额；这些词未直接解决“同一批20—30岁女性同时存在两种需求”的分母问题。31题补德国资料后出现普通学校材料，亦不等于博物馆教育证据。即便宽口径将整轮“补搜”视为可接受，也不代表整轮查询、读到的网页或改写结果合格。

### 4. 原始模型pass不等于实际放行

20轮原始模型输出中有17次`verdict=pass`；程序最终只质量放行1次，其余受到问题严重程度、历史问题账本和返工上限等规则影响。

为便于诊断，本次另按“原始pass优先，否则看新问题是否要求补搜”的明确规则映射原始模型建议。这个映射得到17次通过、3次补搜、0次直接修订；17次原始pass均对应本轮标注中的阻断问题。其宽口径动作命中为2/20。**这不是程序实际路由指标，也不是重新运行模型的结果。** 原始输出中pass和问题列表可能互相矛盾，不能用17次原始pass取代1次真实质量通过作主表分母。

## 八、已测量、间接推断和尚未评估

**已测量**：20轮报告与实际模型请求、审核前后检查点对齐；625条当时来源记录恢复及哈希匹配；13次真实补搜执行；本轮逐轮动作标注与六项指标复算；6次额度停止分离；非唯一标签16种分配的敏感性；原始模型结论与程序实际动作的区别。

**间接推断**：重复问题账本和对“缺资料”的过度判断可能造成无必要补搜；选择直接修订可能减少成本。轨迹能说明动作和材料状态，不能证明替代分支实际能一次修好，也不能测出本应节省多少Token或时间。

**尚未评估**：当前四维百分制协议的真实路由效果、人类标注一致性、跨领域泛化、应通过样本的过度拦截、直接修订的真实精确率、各条搜索任务命中缺口的比例、同一报告三条分支的实际质量收益和成本。

主要局限是5个不同问题、7次任务运行的相关多轮小样本；合并结果跨版本；标注非盲评且带有修复路径判断；没有逐条穷举全部事实，也没有人工金标。因而不报告把每轮当独立随机样本的置信区间或模型优劣显著性。

结论：这批历史运行能执行补搜分支，但对“是否真的需要新资料”的区分不够好；程序实际放行也至少有一个任务满足性不足的样例。下一步应先复核本轮动作标签，尤其16题第2轮及四个非唯一样本，再用当前协议重放冻结报告；补充应通过和应直接修订的真实样本，才能完整评价三类动作。若要声称降成本或提升报告质量，还需在同一输入上实际执行替代分支对照。
