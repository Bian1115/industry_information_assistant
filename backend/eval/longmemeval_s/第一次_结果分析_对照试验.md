# LongMemEval-S 原始会话对照实验执行计划

## 1. 实验目的

通过两个原始会话对照组，定位当前端到端准确率较低的主要原因：

1. **Oracle Raw Session**：直接使用数据集标注的答案相关会话原始消息回答问题。
2. **Retrieved Raw Session**：使用当前记忆系统检索出的会话，但将这些会话的原始消息交给回答模型。

现有压缩记忆结果作为第三个对照组：

3. **Compressed Memory Baseline**：继续使用当前 summary、insight、topics、preference 记忆片段。

三组实验的因果解释：

- `Retrieved Raw - Compressed`：当前检索选择不变，观察恢复原始消息后的收益，估计记忆压缩与上下文重建损失。
- `Oracle Raw - Retrieved Raw`：上下文都使用原始消息，观察理想会话选择相对当前检索选择的收益，估计检索选择损失。
- `100% - Oracle Raw`：在理想证据条件下仍然存在的回答模型、提示词和 Judge 残余误差。

## 3. 实验变量

### 3.1 必须保持不变

以下配置在三个实验组之间必须完全相同：

- 固定 LongMemEval-S 100 题清单和题目顺序。
- 数据集 SHA 和 manifest question ID digest。
- 回答模型、temperature、最大输出 token。
- Judge 模型、Judge 提示、Judge 最大输出 token 和重试策略。
- Question date 的渲染方式。
- 回答指令：只能依据给定证据，不得向回答模型泄露 reference answer。
- 题目并发数只影响运行时间，不进入质量比较。
- 每次运行创建独立目录，不允许覆盖已有结果；只有显式 `--resume` 可以断点续跑。

### 3.2 唯一主动变量

| 实验组 | 会话选择 | 提供给回答模型的内容 |
|---|---|---|
| Compressed Baseline | 当前 Top-5 记忆检索 | summary/insight/topics/preference |
| Retrieved Raw | 基线中冻结的 `retrieved_session_ids` | 对应会话的原始 turns |
| Oracle Raw | 数据集中的 `answer_session_ids` | 对应会话的原始 turns |

## 4. 会话选择协议

### 4.1 Oracle Raw Session

1. 从固定数据集读取题目的 `answer_session_ids`。
2. 按 ID 映射到 `haystack_session_ids / haystack_sessions / haystack_dates`。
3. 保留 `answer_session_ids` 的原始顺序，去除重复 ID。
4. 对 `_abs` 题同样使用数据集提供的 `answer_session_ids`。这些会话是用于证明信息不足或条件不匹配的诊断会话，不能简单传空上下文，否则会人为降低 abstention 难度。
5. Answer 字段只允许在 Judge 阶段读取，回答提示构建阶段不得访问。

### 4.2 Retrieved Raw Session

主实验禁止重新进行 live retrieval，必须使用正式基线 `questions.jsonl` 中已经冻结的 `retrieved_session_ids`：

1. 校验基线 `questions.jsonl` SHA256。
2. 按基线中每题的 `retrieved_session_ids` 读取会话集合。
3. 保留首次命中的会话顺序并去重。
4. 将会话 ID 映射回数据集中的原始 turns 和 session date。
5. 所有映射失败必须作为基础设施错误终止运行，禁止静默跳过。

冻结检索快照可以保证 Retrieved Raw 与现有基线是逐题配对的，避免 Milvus、embedding 或记忆重建造成检索漂移。live retrieval 可在主实验完成后作为稳定性复验，不能替代主实验。

## 5. 原始上下文渲染协议

两个 Raw 实验必须使用同一个 renderer。每个会话按照以下结构输入：

```text
[session 1; session_id=<source_session_id>; date=<haystack_date>]
user: <原始用户消息>
assistant: <原始助手消息>
...
```

要求：

1. 会话内 turns 严格保持原始顺序。
2. 保留原始角色、原文和 session date。
3. 不进行摘要、翻译、改写或事实抽取。
4. 不插入 reference answer、question type 或 Judge rubric。
5. 提示中保留 `Question date`，用于时间推理。
6. 为每道题记录 `session_count`、`turn_count`、`context_chars` 和 `context_sha256`。
7. 上下文超过硬限制时应报错，禁止静默截断。第一版硬限制设为 120,000 字符。

已完成的规模预检：

| 实验组 | 平均字符数 | P95 | 最大字符数 | 平均 turns | 最大 turns |
|---|---:|---:|---:|---:|---:|
| Oracle Raw | 25,933 | 58,653 | 109,105 | 21.2 | 72 |
| Retrieved Raw | 31,287 | 50,550 | 65,217 | 27.9 | 69 |

当前固定 100 题均低于 120,000 字符，且所有选中会话 ID 都能映射到原始数据。

## 6. 建议实现方式

不要直接改动已经稳定运行的 `run_longmemeval_regression.py` 主流程。新增独立脚本并复用其中的数据校验、模型调用、Judge 和结果聚合函数：

- 新增：`backend/eval/scripts/run_longmemeval_raw_ablation.py`
- 新增测试：`backend/eval/tests/test_longmemeval_raw_ablation.py`
- 可选公共模块：`backend/eval/runtime/longmemeval_common.py`

核心函数建议：

```python
select_oracle_sessions(dataset_row) -> list[RawSession]
select_retrieved_sessions(dataset_row, baseline_row) -> list[RawSession]
render_raw_context(raw_sessions) -> RenderedContext
answer_raw_context(dataset_row, rendered_context) -> AnswerResult
score_answer(dataset_row, hypothesis) -> JudgeResult
compare_paired_runs(baseline, retrieved_raw, oracle_raw) -> ComparisonReport
```

建议 CLI：

```bash
cd backend

# 只做离线映射、长度和泄漏检查，不调用模型
.venv/bin/python eval/scripts/run_longmemeval_raw_ablation.py prepare \
  --baseline eval/data/longmemeval_s/results/20260822_172508_full100_e2e_k5/questions.jsonl

# Oracle Raw
.venv/bin/python eval/scripts/run_longmemeval_raw_ablation.py run \
  --context-mode oracle-raw \
  --workers 4 \
  --run-name <timestamp>_oracle_raw_full100

# Retrieved Raw
.venv/bin/python eval/scripts/run_longmemeval_raw_ablation.py run \
  --context-mode retrieved-raw \
  --retrieval-snapshot eval/data/longmemeval_s/results/20260822_172508_full100_e2e_k5/questions.jsonl \
  --workers 4 \
  --run-name <timestamp>_retrieved_raw_full100

# 三组配对比较
.venv/bin/python eval/scripts/run_longmemeval_raw_ablation.py compare \
  --baseline eval/data/longmemeval_s/results/20260822_172508_full100_e2e_k5 \
  --retrieved-raw eval/data/longmemeval_s/results/<retrieved-run> \
  --oracle-raw eval/data/longmemeval_s/results/<oracle-run>
```

以上是计划中的目标接口，实现阶段可保持参数语义不变并调整具体命令组织。

## 8. 评分协议

### 8.1 主指标

- 全部 100 题 QA Accuracy。
- 可回答 94 题 QA Accuracy，作为主要诊断指标。
- 6 道 abstention 单独报告，不与可回答题混合解释。
- 按 `question_type` 报告准确率。
- 回答拒答率、provider refusal 数量和运行错误数。

### 8.2 配对指标

定义：

- `C`：Compressed Baseline 可回答题准确率，当前为 21.28%。
- `R`：Retrieved Raw 可回答题准确率。
- `O`：Oracle Raw 可回答题准确率。

输出：

- 压缩/上下文重建损失：`Delta_compression = R - C`。
- 检索选择损失：`Delta_retrieval = O - R`。
- Oracle 残余误差：`Residual = 100% - O`。
- `C 错 -> R 对` 的题目数和清单。
- `R 错 -> O 对` 的题目数和清单。
- `O 仍错` 的题目数和清单。
- 每个题型分别计算以上三个量。

使用题目级 paired bootstrap 计算准确率差的 95% 置信区间，并使用 McNemar 检验辅助判断配对差异。样本只有 100 题，报告必须同时展示绝对题数，不能只展示百分比和显著性。

### 8.3 Judge 审计

为了保持与现有基线兼容，主报告继续使用相同 Claude Judge 协议。同时新增审计层：

1. 对数值、日期和短答案做归一化确定性匹配。
2. 保存新实验的 Judge 原始 `yes/no`。
3. 对三组答案不一致的题进行盲审，不向审查者展示实验组名称。
4. 已知基线中存在 `Wednesday` 对 `Wednesday` 被误判为 `no` 的案例，因此同时报告原始 Judge 分数和审计修正分数。

若要引入新的 Judge 版本，必须同时重新评分 C、R、O 三组答案，不能只重评其中一组。

## 9. 分阶段执行

### 阶段 A：离线实现与测试

完成会话选择、raw renderer、结果目录、断点续跑和比较器。

必须覆盖的离线测试：

1. 100 题所有 Oracle 和 Retrieved session ID 都能映射。
2. turns 顺序和 session date 保持不变。
3. renderer 输出和 SHA 在重复运行时完全一致。
4. 使用 sentinel reference answer 验证回答 prompt builder 不读取 `answer` 字段。
5. 超过 120,000 字符时明确失败，不静默截断。
6. `_abs` 题使用数据集的诊断会话，而不是空上下文。
7. 同名目录拒绝覆盖，显式 `--resume` 只跳过成功题。
8. 基线 SHA 不一致时停止 Retrieved Raw 实验。
9. 配对比较要求三组 question ID 集合完全一致。

### 阶段 B：5 题 smoke test

建议固定覆盖以下类型：

- temporal-reasoning：`0db4c65d`
- multi-session：`37f165cf`
- knowledge-update：`1cea1afa`
- single-session：`0862e8bf`
- abstention：`982b5123_abs`

Smoke 验收：

- 两种 context mode 各得到 5 个唯一结果。
- 没有会话映射错误、上下文截断或 reference answer 泄漏。
- 每题均保存 context digest、回答和 Judge 标签。
- 至少人工检查 temporal、multi-session 两题的原始上下文确实包含日期或待聚合事实。

### 阶段 C：Oracle Raw 100 题

先运行 Oracle，因为它是回答模型的证据上限。如果 Oracle 明显偏低，可在花费 Retrieved Raw 成本前先检查提示词、上下文长度和 Judge。

正式验收：

- 100 个唯一 question ID。
- 100 个非空 hypothesis 和 Judge 标签。
- 0 个上下文映射错误和静默截断。
- provider refusal 单独记录并参与质量评分，不记为基础设施错误。

### 阶段 D：Retrieved Raw 100 题

在 Oracle 基础设施通过后运行。必须引用冻结基线 SHA，不允许临时重新检索。

正式验收与 Oracle 相同，并额外要求：

- 每题 `selected_session_ids` 与基线 `retrieved_session_ids` 一致。
- 去重后的会话顺序一致。

### 阶段 E：三组配对分析

生成总表、分题型表、配对翻转清单和置信区间，并人工审计以下题目：

- Baseline 错而 Retrieved Raw 对。
- Retrieved Raw 错而 Oracle Raw 对。
- Oracle Raw 仍然答错。
- 三组 Judge 标签存在分歧。

## 10. 结果判读规则

以下阈值作为第一版默认诊断规则，可在运行前固化到 `comparison_config.json`：

| 结果 | 主要判断 |
|---|---|
| `O >= 70%`，`R` 距 `O` 不超过 10 个百分点，且 `R-C >= 15pp` | 记忆压缩/上下文重建是主要问题 |
| `O >= 70%`，且 `O-R >= 15pp` | 当前检索选择是主要问题 |
| `O < 50%` | 回答模型、raw prompt、上下文长度或 Judge 仍有主要问题 |
| `R-C` 和 `O-R` 都较大 | 压缩和检索需要同时优化 |
| 总体提升小，但 temporal/multi-session 提升大 | 时间元数据和多会话聚合是独立瓶颈 |

阈值只用于工程决策，不替代逐题配对分析和置信区间。最终结论应优先参考可回答题和各题型表现。

## 11. 预计成本与时间

模型调用规模：

- Oracle Raw：100 次回答 + 100 次 Judge。
- Retrieved Raw：100 次回答 + 100 次 Judge。
- 如重新统一审计三组：额外最多 300 次 Judge，建议只对分歧题和抽样题调用。

基于当前端到端运行速度、raw context 更长和 4 并发设置：

- 离线实现与测试：约 2–4 小时。
- Smoke test：约 15–30 分钟，包括人工上下文检查。
- 两次完整模型运行：预计共 30–90 分钟，取决于长上下文延迟和 Relay 重试。
- 配对分析与人工审计：约 1–2 小时。

运行前 `prepare` 必须输出预计总字符数和请求数；具体费用取决于当前模型计费配置，本计划不使用未经验证的价格估算。

## 12. 完成定义

只有同时满足以下条件，实验才算完成：

1. Oracle Raw 和 Retrieved Raw 都有各自独立、不可覆盖的 100 题结果目录。
2. 两组均为 100 个唯一题号，0 个映射错误和静默截断。
3. 三组使用同一数据集、问题、回答模型和主 Judge 协议。
4. Retrieved Raw 明确绑定并校验冻结检索快照 SHA。
5. 输出 C、R、O 总体和分题型准确率。
6. 输出 `R-C`、`O-R`、Oracle 残余误差和配对翻转题目。
7. 单独报告 answerable、abstention、provider refusal 和 Judge 审计结果。
8. 生成 `comparison.md`、`comparison.json` 和逐题配对文件。
9. 根据第 10 节规则给出下一步工程决策，不在实验完成前修改正式记忆系统。
