# deepagents独立端到端对照

这是独立研究系统对照，使用deepagents原生图与中间件。复用项目的博查搜索、网页/PDF读取及来源域名过滤，不经过业务研究图、数据库、历史摘要、NLI或Critic。每题使用新的StateBackend，框架文件仅位于该题虚拟状态；实际结果单独写入输出目录。

框架按[官方入口](https://docs.langchain.com/oss/python/deepagents/quickstart)构建。当前固定deepagents 0.7.19；依赖放在专用环境，不能安装进业务 `.venv`。这是系统整体对照，不能当作“只移除了某项上下文压缩”的消融组。

## 安装与配置

从项目根目录执行：

```bash
uv venv backend/.venv-deepagents --python backend/.venv/bin/python
uv pip install --python backend/.venv-deepagents/bin/python -r backend/requirements-deepagents锁定.txt
```

本次接入已完成专用环境安装；现有环境无需重建。直接依赖见 `backend/requirements-deepagents对照.txt`，完整版本见 `backend/requirements-deepagents锁定.txt`。

读取 `backend/.env` 中的 `DASHSCOPE_API_KEY`、`DASHSCOPE_BASE_URL`、`BOCHA_API_KEY`，只在独立CLI进程生效，不改写文件或业务配置。默认使用 `端到端研究.json`；需比较其他模型、预算、单价时复制一份中文命名配置，通过 `--config` 指定。

默认参数：qwen3-max、temperature=0、每次最多输出6000 token、模型窗口声明32768、每题900秒、40次模型调用、30次搜索请求、30次网页读取、图递归上限100。窗口声明用于框架原生压缩配置，运行前需核对实际供应商容量；这些初值不代表与业务组预算已自动对齐。工具请求次数按实际请求计数；重定向/读取服务内部重试仍另见网页快照。模型SDK重试设为0。

`allowed_domains` 非空时使用显式配置；为空时读取业务的 `RESEARCH_ALLOWED_DOMAINS`。不允许静默退化成全网搜索。search_web逐域检索，本地过滤结果；read_web及重定向使用相同范围和原有URL安全检查。

## 预检与运行

先用现有DeepResearch Bench题目冻结配置，不调用模型或搜索：

```bash
backend/.venv-deepagents/bin/python backend/eval/scripts/run_deepagents_bench.py \
  --ids 1 --limit 1 \
  --output backend/eval/data/deepagents独立对照/首题预检-20260928 \
  --dry-run
```

检查运行配置.json后，可以用完全相同参数增加 `--resume` 并移除 `--dry-run`，开始实际付费模型/搜索运行：

```bash
backend/.venv-deepagents/bin/python backend/eval/scripts/run_deepagents_bench.py \
  --ids 1 --limit 1 \
  --output backend/eval/data/deepagents独立对照/首题预检-20260928 \
  --resume
```

指定数据集使用 `--dataset`，每行至少包含 `id`、`prompt`，按语言筛选还需 `language`。默认中文，可选 `--language en` 或 `all`。不重写原始用户prompt；通用研究提示词单独冻结。不要在两个进程中同时续跑同一输出目录。

续跑跳过完成题目，失败题目创建新attempt，不覆盖旧记录。配置、题目、源码和完整依赖版本需与运行配置完全一致；发生变化时新建目录。单题中断后从该题重跑，不从图中间节点恢复。

## 输出与质量评分

- `运行配置.json`：实际配置、题目、提示词、来源范围、完整依赖、源码哈希、模型端点；无API密钥。
- `逐题结果.jsonl`：保留DRB兼容的 `id/prompt/article`，附加状态、模型、耗时、用量、搜索/读取计数、来源和原始目录。
- 每题每次尝试：`调用记录.jsonl` 包含模型输入输出、工具调用和搜索/读取快照；`最终状态.json` 包含虚拟文件；`研究报告.md` 和 `结果.json`。
- `汇总.json`：任务成功/失败、所有attempt累计开销、缺失用量和中断记录。未知用量或单价不按零处理。
- 每次运行/预检生成 `docs/deepagents独立对照运行分析-时间戳.md`，记录口径、逐题状态及局限。

结果格式可交给现有 `backend/eval/scripts/evaluate_race_fact_claude.py`；实际评分在其原有环境执行，例如：

```bash
backend/.venv/bin/python backend/eval/scripts/evaluate_race_fact_claude.py \
  backend/eval/data/deepagents独立对照/首题预检-20260928/逐题结果.jsonl --limit 1
```

该步骤会使用评分器自己的服务和费用，本次接入未执行。已有评分脚本按非空article取样，正式比较必须同时报告失败率；不能仅比较成功生成的题目。

## 成本与公平性

成本从所有模型回调统计，覆盖实际返回的用量；最终上下文里的消息条数不用于替代整任务用量。未返回用量的调用、失败/中断请求会使 `usage_complete=false`。配置中的 `input_price_per_million`、`output_price_per_million`、`search_price_per_request` 默认null，明确填写对应currency的单价后才计算估算费用；缓存价、阶梯计费、CPU以及额外OCR/浏览器服务费用未建模，估算值不等于账单。

对比时固定题号、用户约束、模型、temperature、来源范围、读取设置、工具请求和输出预算、时间上限及评分器。线上搜索结果动态变化，本组保存快照但没有实现固定工具回放。框架内部规划和上下文管理与业务组不同，应明确这是整体系统对照。无新增业务记忆、NLI和固定任务契约注入，不将其标记成完整业务方案。

本次只验证真实deepagents图配合模拟模型与网页服务的机制、预检和导出；未调用真实付费模型，未评估报告质量，也未验证全部内置委派/长上下文压缩路径。
